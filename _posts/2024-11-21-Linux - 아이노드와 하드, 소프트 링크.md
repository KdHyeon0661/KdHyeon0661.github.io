# 아이노드와 하드/소프트 링크

## 아이노드(inode)란 무엇인가

파일 시스템에서 **아이노드(inode)** 는 파일의 메타데이터(속성 정보)를 저장하는 구조체다. 파일의 실제 내용(데이터)이 아니라, 파일에 대한 정보를 담고 있다.  
디렉토리는 파일 이름과 아이노드 번호를 매핑한 표일 뿐이며, 파일의 정체성은 아이노드에 있다.

### 아이노드에 포함되는 정보

| 항목 | 설명 |
|------|------|
| 파일 타입/권한 | 정규파일, 디렉토리, 링크 등 |
| 소유자/그룹 | UID, GID |
| 크기 | 바이트 단위 |
| 시간 정보 | atime(읽기), mtime(수정), ctime(속성 변경) |
| 링크 수 | 같은 아이노드를 가리키는 이름의 수 |
| 데이터 위치 | 디스크 상의 블록 위치 |
| 확장 속성 | xattr, ACL, chattr 플래그 등 |

> **핵심**: 파일 이름은 디렉토리에 저장되고, 파일의 실체는 아이노드다. 파일 이름을 삭제해도(언링크) 아이노드가 살아 있고 참조 중이면 내용은 유지된다.

---

## 하드 링크: 같은 아이노드의 또 다른 이름

하드 링크는 이미 존재하는 파일에 **또 다른 이름**을 붙이는 것이다.  
`ln` 명령으로 생성하며, 같은 파일시스템 내에서만 가능하다.

```bash
ln a.txt b.txt
ls -li a.txt b.txt
```

- `a.txt`와 `b.txt`는 **같은 아이노드 번호**를 가진다
- **링크 수**(`st_nlink`)가 2로 증가한다
- 내용, 권한, 소유자를 공유하며 이름만 다르다

### 제약사항
- **서로 다른 파일시스템 간에는 불가능**하다 (아이노드 번호는 파일시스템 내부에서만 의미가 있음)
- 일반적으로 **디렉토리에 하드 링크를 만들 수 없다** (순환 참조 방지)
- 원본 파일을 삭제해도 다른 이름이 남아 있으면 파일은 유지된다

### 삭제와 영속성
`rm a.txt`는 디렉토리 엔트리만 제거하고 링크 수를 1 감소시킨다.  
링크 수가 0이 되고 **열린 파일 디스크립터(FD)가 없을 때** 비로소 실제 데이터 블록이 삭제된다.

---

## 소프트 링크(심볼릭 링크): 경로를 가리키는 별도 파일

소프트 링크는 **대상 파일의 경로 문자열**을 저장하는 특별한 파일이다.  
`ln -s` 명령으로 생성한다.

```bash
ln -s a.txt link.txt
ls -li a.txt link.txt
readlink link.txt      # → a.txt
```

- `link.txt`는 **새로운 아이노드**를 가진다 (파일 타입은 심볼릭 링크)
- 데이터 블록에는 문자열 `a.txt`가 저장된다
- 원본 파일이 삭제되면 **깨진 링크**가 된다

### 장점
- **다른 파일시스템도 참조 가능**하다
- 디렉토리에도 링크를 만들 수 있다 (바로가기처럼)

### 단점
- 경로 해석이 추가되므로 하드 링크보다 접근 오버헤드가 있다
- 원본 삭제 시 링크가 깨져 추적이 어려울 수 있다

---

## 하드 링크 vs 소프트 링크 비교

| 항목 | 하드 링크 (`ln`) | 소프트 링크 (`ln -s`) |
|------|------------------|----------------------|
| 아이노드 | 공유함 (같음) | 별도로 가짐 (다름) |
| 데이터 블록 | 원본과 공유 | 링크 경로 문자열 저장 |
| 링크 수 증가 | 있음 | 없음 |
| 원본 삭제 영향 | 다른 이름 남아 있으면 안전 | 깨진 링크가 됨 |
| 파티션 제약 | 있음 (동일 파일시스템만) | 없음 |
| 디렉토리 링크 | 일반적으로 불가 | 가능 |

---

## 실무 진단 명령어

```bash
# inode, 링크 수, 권한 등 확인
stat a.txt

# 심볼릭 링크의 대상 확인
readlink link.txt

# 삭제됐지만 열려 있는 파일 확인 (디스크 공간 누수 진단)
lsof +L1
```

---

## 자주 겪는 문제: 파일은 삭제됐는데 디스크 공간이 줄지 않음

프로세스가 파일을 열고 있는 상태에서 파일 이름이 삭제되면(예: 로그 파일이 `rm` 되거나 `logrotate` 처리) **디스크 공간은 반환되지 않는다**.  
파일 디스크립터가 닫히거나 프로세스가 종료되어야 공간이 반환된다.

**확인 방법**:
```bash
lsof +L1 | grep deleted
```

**해결 방법**: 해당 프로세스를 재시작하거나 파일 디스크립터를 닫는다.

## 원자적 파일 교체 패턴

설정 파일이나 실행 파일을 안전하게 갱신할 때는 임시 파일에 쓴 후 `mv`로 교체하는 패턴을 사용한다.

```bash
# 임시 파일에 안전하게 쓰기
echo "new config" > config.new

# 권한 맞추기
chmod 0644 config.new

# 원자적으로 교체 (같은 파일시스템 내에서 rename은 원자적)
mv config.new config.yml
```

`rename()` 시스템 호출은 같은 파일시스템 내에서 **원자적**으로 동작하므로, 파일을 읽는 중간에 깨진 상태를 보지 않는다.

---

## 아이노드 고갈: `df -i`

디스크 공간은 남았는데 "No space left on device" 오류가 발생한다면 **아이노드가 고갈**되었을 가능성이 있다.

```bash
df -i
```

아이노드 고갈은 매우 작은 파일이 수백만 개 이상 생성될 때 발생한다.  
해결 방법은 불필요한 작은 파일을 삭제하거나, 파일시스템을 생성할 때 inode 밀도를 높여 재생성하는 것이다.

---

## 파일 시스템별 특징 간략 비교

| 파일시스템 | 하드 링크 | 심볼릭 링크 | 비고 |
|------------|----------|------------|------|
| ext4 | 지원 | 지원 | 리눅스 기본, 안정적 |
| XFS | 지원 | 지원 | 대용량에 강함 |
| btrfs | 지원 | 지원 | 스냅샷, COW |
| FAT/NTFS | 제한적 | 제한적 | 리눅스에서 사용 시 주의 |

---

## 핵심 명령어 요약

| 작업 | 명령어 |
|------|--------|
| 하드 링크 생성 | `ln 원본 링크` |
| 소프트 링크 생성 | `ln -s 대상 링크` |
| inode 정보 확인 | `ls -li`, `stat` |
| 링크 대상 확인 | `readlink 링크` |
| 삭제된 열린 파일 확인 | `lsof +L1` |
| 아이노드 사용량 확인 | `df -i` |

---

## 결론

- **아이노드**는 파일의 실체이며, 파일 이름은 디렉토리가 아이노드를 가리키는 방식이다.
- **하드 링크**는 같은 아이노드에 다른 이름을 붙이는 것이며, 동일 파일시스템 내에서만 가능하다.
- **소프트 링크**는 경로 문자열을 저장하는 별도 파일로, 파일시스템 경계를 넘을 수 있다.
- 파일을 삭제해도 열려 있는 파일 디스크립터가 있으면 공간이 반환되지 않으므로 `lsof +L1`으로 확인한다.
- 설정 파일 갱신은 임시 파일에 쓰고 `mv`로 원자적으로 교체한다.
- 디스크 공간이 남아도 파일 생성이 안 되면 `df -i`로 아이노드 고갈을 점검한다.

이 개념들을 이해하면 파일 시스템 관련 문제의 원인을 빠르게 파악하고, 보다 안정적인 시스템 운영이 가능해진다.
