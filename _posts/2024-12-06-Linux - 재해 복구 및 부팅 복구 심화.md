# 재해 복구 및 부팅 복구 심화

## 부팅 실패의 주요 원인

부팅 실패는 다양한 원인으로 발생한다. 주요 원인을 미리 파악해 두면 진단이 훨씬 수월하다.

- GRUB 설정 손상 또는 삭제
- 커널 이미지 또는 initramfs 누락
- `/etc/fstab` 오류로 루트 파일시스템 마운트 실패
- 파일시스템 손상
- 하드웨어 문제 (디스크 고장, 메모리 불량)

---

## 체계적인 부팅 실패 진단 흐름

문제 발생 시 다음 순서로 접근하면 원인을 빠르게 좁힐 수 있다.

1. **GRUB 메뉴 확인**  
   GRUB 메뉴가 나타나면 이전 커널로 부팅을 시도한다.  
   메뉴가 보이지 않으면 Shift 키(BIOS) 또는 Esc(UEFI)를 연타해 표시한다.

2. **GRUB 편집 모드로 커널 파라미터 수정**  
   부팅 항목에서 `e` 키를 눌러 편집 모드로 진입한다.  
   `linux`로 시작하는 줄 끝에 `systemd.unit=rescue.target` 또는 `emergency`를 추가하여 최소 환경으로 부팅한다.

3. **복구 모드 진입 후 로그 확인**  
   `journalctl -xb`로 상세 부팅 로그를 확인하고, 실패 지점을 찾는다.

4. **라이브 USB로 부팅하여 시스템 마운트 후 점검**  
   부팅 자체가 불가능하면 라이브 미디어로 부팅해 디스크 상태, 파일시스템, GRUB 설정 등을 검사한다.

---

## GRUB 복구

### GRUB 재설치 (UEFI 기준)

```bash
# 라이브 USB로 부팅 후
sudo mount /dev/sda2 /mnt          # 루트 파티션
sudo mount /dev/sda1 /mnt/boot/efi # EFI 시스템 파티션
sudo mount --bind /dev /mnt/dev
sudo mount --bind /proc /mnt/proc
sudo mount --bind /sys /mnt/sys
sudo chroot /mnt
grub-install --target=x86_64-efi --efi-directory=/boot/efi --bootloader-id=ubuntu
update-grub
exit
sudo umount -R /mnt
sudo reboot
```

- BIOS 레거시 시스템에서는 `grub-install /dev/sda`로 설치한다.
- `update-grub`은 `/etc/default/grub`과 `/etc/grub.d/`를 참고해 `grub.cfg`를 생성한다.

---

## chroot 환경에서의 복구 절차

chroot는 루트 디렉터리를 변경하여 손상된 시스템의 환경에 진입해 복구 작업을 수행할 때 사용한다.

### chroot 준비 단계

```bash
# 라이브 USB로 부팅
sudo fdisk -l                     # 파티션 확인
sudo mount /dev/sda2 /mnt         # 루트 파티션 마운트
sudo mount /dev/sda1 /mnt/boot    # 부트 파티션 (별도인 경우)
sudo mount /dev/sda1 /mnt/boot/efi # UEFI의 경우 ESP 마운트
sudo mount --bind /dev /mnt/dev
sudo mount --bind /proc /mnt/proc
sudo mount --bind /sys /mnt/sys
sudo mount --bind /run /mnt/run   # 필요한 경우
sudo chroot /mnt /bin/bash
```

### chroot 내부에서 수행할 수 있는 복구 작업

- **비밀번호 재설정**: `passwd root`
- **GRUB 재설치**: `grub-install /dev/sda`, `update-grub`
- **initramfs 재생성**: `update-initramfs -u -k all`
- **fstab 복구**: `vi /etc/fstab`로 잘못된 마운트 옵션 수정
- **패키지 재설치**: `apt install --reinstall linux-image-$(uname -r)`

## initramfs 재생성

initramfs는 루트 파일시스템 마운트 전 필요한 드라이버와 도구를 포함한다. 손상 시 부팅이 멈출 수 있다.

```bash
# Debian/Ubuntu
sudo update-initramfs -u -k all        # 모든 커널 업데이트
sudo update-initramfs -c -k 5.15.0-91  # 특정 커널 새로 생성

# RHEL/Fedora
sudo dracut -f                         # 현재 커널 initramfs 재생성
sudo dracut -f --kver 5.14.0-427       # 특정 버전 재생성
```

### initramfs 내용 확인

```bash
lsinitramfs /boot/initrd.img-$(uname -r) | head
```

## 핵심 명령어 요약 (복구)

| 작업 | 명령어 |
|------|--------|
| GRUB 설치 (UEFI) | `grub-install --target=x86_64-efi --efi-directory=/boot/efi` |
| GRUB 설정 재생성 | `update-grub` (Debian/Ubuntu), `grub2-mkconfig -o /boot/grub2/grub.cfg` (RHEL) |
| chroot 진입 | `mount --bind /dev /mnt/dev && chroot /mnt /bin/bash` |
| initramfs 재생성 | `update-initramfs -u -k all` (Debian), `dracut -f` (RHEL) |

# 시스템 감사 및 보안 점검

## auditd: 커널 수준 감사 로그

auditd는 시스템 호출, 파일 접근, 사용자 활동 등을 기록하는 데몬이다. 보안 사고 분석과 침입 탐지에 핵심적인 도구다.

### 설치 및 기본 설정

```bash
sudo apt install auditd        # Debian/Ubuntu
sudo systemctl enable --now auditd
```

### 주요 auditctl 규칙 예시

```bash
# 파일 접근 감시 (쓰기, 속성 변경)
sudo auditctl -w /etc/passwd -p wa -k passwd_changes

# 특정 사용자 명령 실행 감시
sudo auditctl -a always,exit -S execve -F uid=1000 -k user_commands

# 로그인 실패 감시
sudo auditctl -w /var/log/faillog -p wa -k login_failures
```

### 로그 조회 (ausearch)

```bash
sudo ausearch -k passwd_changes      # 특정 키워드
sudo ausearch -ts recent             # 최근 이벤트
sudo ausearch -m USER_LOGIN -i       # 사용자 로그인 이벤트
```

영구 규칙은 `/etc/audit/rules.d/audit.rules`에 저장한다.

## AIDE (Advanced Intrusion Detection Environment)

AIDE는 파일 무결성 검사 도구로, 중요 파일의 해시와 메타데이터를 저장하고 변경 사항을 탐지한다.

### 설치 및 초기화

```bash
sudo apt install aide
sudo aideinit                     # 초기 데이터베이스 생성
```

설정 파일 `/etc/aide/aide.conf`에서 감시 대상과 제외 패턴을 지정할 수 있다.

### 검사 실행

```bash
sudo aide --check
```

정기 검사는 cron으로 자동화한다.

## chkrootkit / rkhunter (루트킷 탐지)

루트킷 탐지 도구는 시스템에 악성 코드가 설치되었는지 확인한다.

### chkrootkit

```bash
sudo apt install chkrootkit
sudo chkrootkit                     # 실행 (시간 소요)
```

### rkhunter

```bash
sudo apt install rkhunter
sudo rkhunter --check               # 검사
sudo rkhunter --propupd             # 속성 데이터베이스 업데이트
```

## 로그 분석 기초

로그는 시스템 상태와 보안 사고의 가장 중요한 증거다.

### 주요 로그 파일 위치

| 로그 파일 | 설명 |
|----------|------|
| `/var/log/syslog` (Debian) / `/var/log/messages` (RHEL) | 시스템 전반 로그 |
| `/var/log/auth.log` (Debian) / `/var/log/secure` (RHEL) | 인증 관련 로그 |
| `/var/log/kern.log` | 커널 로그 |
| `/var/log/nginx/access.log` | 웹 서버 접근 로그 |

### journalctl 활용

```bash
# 시스템 전체 로그
journalctl -b                     # 현재 부팅 로그
journalctl -u ssh                  # 특정 유닛 로그
journalctl -p err                  # 에러 레벨 이상
journalctl --since "1 hour ago"
```

### grep으로 빠른 필터링

```bash
# SSH 로그인 실패 횟수
sudo grep "Failed password" /var/log/auth.log | wc -l

# 비정상적인 로그인 시도 (IP 수집)
sudo grep "Failed password" /var/log/auth.log | awk '{print $(NF-3)}' | sort | uniq -c
```

## 침입 탐지 개념

침입 탐지는 시스템의 비정상적 행위를 감지하고 대응하는 과정이다. 크게 두 가지 방식이 있다.

- **시그니처 기반 탐지**: 알려진 공격 패턴(악성코드 시그니처)을 매칭
- **이상 행위 탐지**: 정상 기준 대비 벗어난 행위 감지 (예: 비정상 시간대 로그인, 대량 파일 삭제)

### 침입 탐지 체크리스트 (초중급용)

1. **인증 로그 확인**: `auth.log`에서 반복된 실패 로그인, 비정상적인 시간대 로그인
2. **프로세스 점검**: `ps auxf`로 의심스러운 프로세스 확인
3. **네트워크 연결**: `ss -tulpn`으로 열린 포트, 비정상적인 외부 연결
4. **파일 무결성**: `aide --check`로 중요 파일 변경 여부
5. **시스템 호출 감사**: auditd 로그에서 비정상적 파일 접근 패턴

### 간단한 알림 스크립트 예시

```bash
#!/bin/bash
# 로그인 실패 10회 이상 시 경고
FAIL=$(sudo grep "Failed password" /var/log/auth.log | wc -l)
if [ "$FAIL" -gt 10 ]; then
    echo "경고: 로그인 실패 횟수 $FAIL" | mail -s "Security Alert" admin@example.com
fi
```

## 정기적 보안 점검 자동화

cron을 이용해 주기적으로 보안 점검을 실행할 수 있다.

```crontab
# 매일 새벽 3시 보안 점검
0 3 * * * root /usr/local/bin/security_check.sh
```

`security_check.sh` 예시:
```bash
#!/bin/bash
# 간단한 보안 점검 스크립트
echo "=== 보안 점검 $(date) ==="
# AIDE 검사
aide --check
# 루트킷 검사
rkhunter --check --skip-keypress
# auditd 로그 요약
ausearch -ts yesterday
```

| **침입 탐지** | `ps auxf`, `ss -tulpn` | 프로세스/네트워크 상태 확인 |

## 결론

재해 복구와 보안 점검은 리눅스 시스템 관리의 양대 축이다.

- **부팅 실패 시** 체계적인 흐름(GRUB → chroot → initramfs)을 따라 복구한다.  
  GRUB 복구는 라이브 환경에서 파티션 마운트 후 `grub-install`과 `update-grub`으로 처리한다.  
  chroot를 이용해 손상된 시스템 환경에 진입하여 패스워드 재설정, 패키지 재설치 등 복구 작업을 수행한다.  
  initramfs는 커널 업데이트 후 반드시 재생성하며, 손상 시 부팅 실패 원인이 될 수 있다.

- **시스템 감사**는 auditd로 중요한 이벤트를 기록하고, AIDE로 파일 무결성을 정기적으로 검사한다.  
  chkrootkit, rkhunter 등으로 루트킷을 탐지하고, 로그 분석(특히 인증 로그)을 통해 침입 징후를 조기에 발견할 수 있다.

- **침입 탐지**는 단순히 도구 실행에 그치지 않고, 로그 패턴 변화, 비정상적인 프로세스, 네트워크 연결을 지속적으로 모니터링하는 습관이 중요하다.

이러한 절차와 도구들을 정기적으로 수행하면 시스템의 안정성과 보안 수준을 크게 향상시킬 수 있다.
