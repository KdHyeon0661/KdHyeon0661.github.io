# C# 멀티스레딩과 비동기 병렬 처리

C#에서 동시성(concurrency)은 크게 두 가지 성격의 작업으로 나뉩니다. 하나는 CPU를 계속 사용하는 **CPU 집약적 작업**이고, 다른 하나는 네트워크나 파일 입출력처럼 대기 시간이 발생하는 **I/O 바운드 작업**입니다. 이 둘을 구분하지 않고 같은 방식으로 처리하면 성능이 떨어지거나 응답성이 나빠집니다.

---

## 동시성의 두 가지 얼굴

**CPU 집약적 작업**은 이미지 처리, 복잡한 수학 계산, 암호화 등 코어를 계속 사용하는 작업입니다. 이런 작업은 여러 코어에 작업을 분할하여 동시에 실행(병렬 처리)함으로써 전체 실행 시간을 줄일 수 있습니다.

**I/O 바운드 작업**은 데이터베이스 쿼리, 웹 API 호출, 파일 읽기/쓰기처럼 외부 응답을 기다리는 동안 CPU가 아무 일도 하지 않는 작업입니다. 이런 경우 스레드를 블로킹 상태로 두면 메모리와 스레드 풀 자원이 낭비됩니다. 대신 비동기 프로그래밍을 사용하여 대기 시간 동안 스레드를 반환하고, 작업이 완료되면 다시 실행을 재개합니다.

```csharp
// CPU 집약적 작업 예시
Parallel.For(0, 1000000, i => { 
    var result = Math.Sqrt(i) + Math.Pow(i, 2); 
});

// I/O 바운드 작업 예시
async Task<string> FetchDataAsync(string url)
{
    using var client = new HttpClient();
    return await client.GetStringAsync(url);
}
```

두 코드는 모두 “동시에 실행”된다는 점에서 비슷해 보이지만, 내부 동작 방식이 완전히 다릅니다. 병렬 처리는 스레드를 여러 개 사용해 CPU를 최대한 활용하고, 비동기 처리는 적은 수의 스레드로 I/O 대기 시간을 효율적으로 활용합니다.

---

## 스레드와 스레드 풀

### 스레드 직접 생성의 한계

과거에는 멀티스레딩이 필요할 때 `Thread` 클래스를 직접 인스턴스화하여 사용했습니다. 하지만 이 방식은 스레드 하나를 생성할 때마다 약 1MB의 메모리가 할당되고, 커널 모드와 유저 모드를 오가는 컨텍스트 스위칭 비용이 큽니다. 따라서 수백 개의 스레드를 만들면 시스템 자원이 빠르게 고갈될 수 있습니다.

```csharp
var thread = new Thread(() => {
    Console.WriteLine($"스레드 ID: {Thread.CurrentThread.ManagedThreadId}");
    Thread.Sleep(1000);
});
thread.IsBackground = true;
thread.Start();
thread.Join();
```

이러한 직접 생성은 실시간 처리나 특정 코어에 바인딩해야 하는 극히 제한적인 경우에만 사용하는 것이 좋습니다.

### 스레드 풀의 구조와 이점

스레드 풀(ThreadPool)은 미리 일정 개수의 스레드를 만들어 풀에 보관해 두고, 작업이 들어오면 대기 중인 스레드에 작업을 할당합니다. 작업이 끝난 스레드는 파괴되지 않고 다시 풀로 돌아가 다음 작업을 기다립니다. 이렇게 하면 스레드 생성/파괴 비용이 사라지고, 시스템 자원을 효율적으로 사용할 수 있습니다.

```text
[스레드 풀의 작업 처리 구조]

작업 큐 (Task Queue)
 [작업 A] [작업 B] [작업 C] [작업 D]
         │
         ▼ (할당)
+-----------------------------------+
| ThreadPool                        |
|  [스레드 1 (작업 A 실행 중)]      |
|  [스레드 2 (작업 B 실행 중)]      |
|  [스레드 3 (대기 중)]             |
+-----------------------------------+
         ▼ (작업 완료 후 스레드 반환)
```

C#에서 스레드 풀에 작업을 요청하는 가장 간단한 방법은 `ThreadPool.QueueUserWorkItem`입니다.

```csharp
ThreadPool.QueueUserWorkItem(state => {
    Console.WriteLine($"스레드 풀 작업 실행: {Thread.CurrentThread.ManagedThreadId}");
});
```

하지만 이 방식은 작업의 완료를 추적하거나 예외를 처리하기 어렵습니다. 이런 한계를 극복하기 위해 등장한 것이 `Task`입니다.

---

## Task: 비동기 작업의 객체화

`Task`는 “미래에 완료될 작업”을 객체로 표현한 것입니다. 스레드 풀 위에서 실행되면서도 작업의 상태(진행 중, 완료, 오류)를 추적할 수 있고, 여러 작업을 조합하는 다양한 메서드를 제공합니다.

```csharp
// 반환값이 없는 작업
Task backgroundTask = Task.Run(() => {
    Console.WriteLine("백그라운드 작업 실행");
});

// 반환값이 있는 작업
Task<int> calculationTask = Task.Run(() => {
    Thread.Sleep(1000);
    return 42;
});

int result = await calculationTask;
```

`Task`의 진가는 여러 비동기 작업을 동시에 실행하고 그 완료를 기다리는 등의 흐름 제어에서 드러납니다.

```csharp
async Task ProcessDataAsync()
{
    var task1 = LoadUserDataAsync();
    var task2 = LoadProductDataAsync();
    var task3 = LoadOrderDataAsync();

    await Task.WhenAll(task1, task2, task3);

    var userData = await task1;
    var productData = await task2;
    var orderData = await task3;
}
```

`Task.WhenAll`은 세 작업을 모두 병렬로 시작하고, 모두 완료될 때까지 대기합니다. 이 대기 시간 동안에도 스레드는 블로킹되지 않습니다.

## async/await: I/O 블로킹 해결의 핵심

### 상태 머신의 동작 원리

`async`와 `await`는 컴파일러가 복잡한 상태 머신(State Machine)을 자동으로 생성해 주는 문법입니다. `await`를 만나면 현재 스레드는 스레드 풀로 반환되고, I/O 작업이 완료되면 다시 스레드 풀에서 남은 코드를 실행합니다.

```csharp
public async Task<string> GetDataAsync(string url)
{
    try
    {
        var response = await _httpClient.GetAsync(url);
        response.EnsureSuccessStatusCode();
        return await response.Content.ReadAsStringAsync();
    }
    catch (HttpRequestException ex) when (ex.StatusCode == HttpStatusCode.NotFound)
    {
        return string.Empty;   // 404 오류는 빈 문자열로 처리
    }
}
```

이 패턴을 사용하면 수천 개의 동시 요청이 들어와도 스레드 풀에 있는 소수의 스레드만으로 처리할 수 있습니다.

### ConfigureAwait의 역할

기본적으로 `await` 이후의 코드는 원래의 컨텍스트(예: UI 스레드)로 돌아가려고 합니다. WPF나 WinForms에서는 UI 컨트롤을 조작하기 위해 이 동작이 필요합니다. 하지만 라이브러리나 ASP.NET Core 같은 서버 애플리케이션에서는 굳이 원래 컨텍스트로 돌아갈 필요가 없습니다. 이때 `ConfigureAwait(false)`를 사용하면 불필요한 컨텍스트 스위칭을 방지하고 데드락 위험도 줄일 수 있습니다.

```csharp
public async Task ProcessItemsAsync(IEnumerable<string> items)
{
    foreach (var item in items)
    {
        var data = await DownloadItemAsync(item).ConfigureAwait(false);
        await ProcessItemAsync(data).ConfigureAwait(false);
    }
}
```

라이브러리 코드에서는 항상 `ConfigureAwait(false)`를 사용하는 것이 좋은 습관입니다.

## 병렬 처리: CPU를 최대한 활용하기

CPU 집약적 작업에는 병렬 처리가 적합합니다. C#에서는 `Parallel` 클래스와 PLINQ를 제공합니다.

### Parallel 클래스

`Parallel.For`나 `Parallel.ForEach`는 데이터를 여러 청크로 나누어 멀티 코어에 분배합니다. 아래는 원주율을 근사 계산하는 예제입니다.

```csharp
public double CalculatePiParallel(int iterations)
{
    double sum = 0.0;
    object lockObj = new object();

    Parallel.For(0, iterations, () => 0.0, (i, state, localSum) =>
    {
        double x = (i + 0.5) / iterations;
        return localSum + 4.0 / (1.0 + x * x);
    },
    localSum =>
    {
        lock (lockObj) sum += localSum;
    });

    return sum / iterations;
}
```

이 코드는 다음 수학 공식을 병렬로 계산합니다.

$$
\pi \approx \sum_{i=0}^{N-1} \frac{4}{1 + x_i^2}
$$

($$x_i = \frac{i + 0.5}{N}$$, $$N$$은 반복 횟수)

각 스레드는 자신만의 `localSum`을 유지하며 계산하고, 마지막에만 잠금(lock)을 사용해 전체 합에 반영합니다. 이렇게 하면 잠금 경합이 최소화되어 성능이 향상됩니다.

### PLINQ

PLINQ는 LINQ 쿼리를 병렬로 실행할 수 있게 해줍니다. 대용량 컬렉션을 처리할 때 선언적인 코드로 병렬화를 적용할 수 있습니다.

```csharp
public IEnumerable<AnalysisResult> AnalyzeLargeDataset(IEnumerable<DataPoint> data)
{
    return data.AsParallel()
               .WithDegreeOfParallelism(Environment.ProcessorCount)
               .Where(point => point.IsValid())
               .Select(point => AnalyzePoint(point))
               .Where(result => result.Score > 0.7)
               .ToList();
}
```

데이터가 작을 경우 병렬 분배 오버헤드가 오히려 성능을 떨어뜨릴 수 있으므로, 수천 개 이상의 요소를 다룰 때 효과적입니다.

## 동기화 기법

여러 스레드가 같은 데이터를 동시에 수정하면 데이터 경합(Data Race)이 발생합니다. 이를 방지하기 위해 임계 구역을 보호하는 동기화 메커니즘이 필요합니다.

### lock과 ReaderWriterLockSlim

`lock`은 가장 단순한 동기화 도구로, 한 번에 하나의 스레드만 코드 블록을 실행하도록 보장합니다.

읽기 작업이 압도적으로 많고 쓰기 작업이 드문 상황에서는 `ReaderWriterLockSlim`이 더 효율적입니다. 읽기 스레드는 동시에 여러 개가 접근할 수 있고, 쓰기 스레드만 독점적으로 락을 얻습니다.

```csharp
public class ThreadSafeCache<TKey, TValue>
{
    private readonly Dictionary<TKey, TValue> _cache = new();
    private readonly ReaderWriterLockSlim _lock = new();

    public TValue GetOrAdd(TKey key, Func<TKey, TValue> valueFactory)
    {
        _lock.EnterReadLock();
        try
        {
            if (_cache.TryGetValue(key, out var value)) return value;
        }
        finally
        {
            _lock.ExitReadLock();
        }

        _lock.EnterWriteLock();
        try
        {
            if (!_cache.TryGetValue(key, out var value))
            {
                value = valueFactory(key);
                _cache[key] = value;
            }
            return value;
        }
        finally
        {
            _lock.ExitWriteLock();
        }
    }
}
```

### SemaphoreSlim으로 처리량 제어

`lock`은 단일 스레드만 허용하지만, 세마포어는 N개의 스레드까지 동시 접근을 허용합니다. 외부 API 호출 시 초당 요청 수를 제한하거나, DB 커넥션 풀을 관리할 때 유용합니다.

```csharp
public class RateLimitedApiClient
{
    private readonly SemaphoreSlim _throttler = new SemaphoreSlim(5);

    public async Task<string> CallApiAsync(string endpoint)
    {
        await _throttler.WaitAsync();
        try
        {
            return await _httpClient.GetStringAsync(endpoint);
        }
        finally
        {
            _throttler.Release();
        }
    }
}
```

### 동기화 도구 비교

| 도구 | 용도 | 특징 |
|------|------|------|
| `lock` | 간단한 임계 구역 보호 | 모니터 기반, 재진입 가능 |
| `ReaderWriterLockSlim` | 읽기 많은 상황 | 다중 읽기/단일 쓰기 허용 |
| `SemaphoreSlim` | 동시 접근 수 제한 | 비동기 지원, 경량 |
| `Interlocked` | 원자적 단일 연산 | 락 없이 간단한 카운터 등에 사용 |

## 취소 메커니즘: CancellationToken

서버 애플리케이션이나 장기 실행 작업에서는 사용자가 취소하거나 타임아웃이 발생했을 때 작업을 중단할 수 있어야 합니다. C#에서는 협력적 취소(Cooperative Cancellation) 모델인 `CancellationToken`을 표준으로 사용합니다.

작업 코드는 주기적으로 토큰을 확인하고, 취소 요청이 들어오면 `OperationCanceledException`을 던져 종료합니다.

```csharp
public async Task RunWithTimeoutAsync()
{
    using var timeoutCts = new CancellationTokenSource(TimeSpan.FromSeconds(30));

    try
    {
        await LongRunningOperationAsync(timeoutCts.Token);
    }
    catch (OperationCanceledException)
    {
        Console.WriteLine("작업이 타임아웃되어 취소되었습니다.");
    }
}

async Task LongRunningOperationAsync(CancellationToken token)
{
    for (int i = 0; i < 100; i++)
    {
        token.ThrowIfCancellationRequested();
        await Task.Delay(1000, token);
    }
}
```

취소는 강제로 스레드를 중단시키는 것이 아니라, 작업 코드가 협조적으로 중단 지점을 마련해 주어야 합니다. 따라서 모든 비동기 메서드는 `CancellationToken`을 받아 하위 호출까지 전달하는 것이 좋은 습관입니다.

## 정리

C#의 동시성 프로그래밍은 단순히 코드를 동시에 실행하는 것을 넘어, 시스템 자원을 효율적으로 활용하는 설계 기술입니다. 핵심 원칙은 다음과 같습니다.

- **도구 선택**  
  CPU 집약적 작업은 `Parallel`, `Task.Run`으로 병렬 처리하고, I/O 바운드 작업은 `async`/`await`를 사용해 스레드 블로킹을 피합니다.

- **상태 공유 최소화**  
  여러 스레드가 같은 가변 상태를 수정하려 하면 동기화 비용이 커집니다. 가능하면 불변(immutable) 객체를 사용하거나, 스레드 간 상태를 공유하지 않는 구조로 설계합니다.

- **에러 처리와 복원력**  
  비동기 코드의 예외는 호출부에서 반드시 처리해야 합니다. 여러 작업을 `Task.WhenAll`로 실행할 때는 `AggregateException` 가능성을 염두에 두고 예외를 처리합니다.

- **성능 측정**  
  병렬화가 항상 정답은 아닙니다. 프로파일러로 실제 병목 지점을 확인한 후에만 해당 부분에 병렬 처리를 도입합니다.

동시성 코드는 복잡성을 수반합니다. 단순함을 유지하고, 추상화 계층을 이해하며, 상황에 맞는 가장 가벼운 도구를 선택하는 것이 고성능 C# 애플리케이션을 만드는 핵심입니다.
