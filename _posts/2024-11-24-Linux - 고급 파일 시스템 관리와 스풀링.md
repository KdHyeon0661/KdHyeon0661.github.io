# 고급 파일 시스템 관리와 스풀링

## 스풀링(Spooling)의 이해

스풀링은 **"Simultaneous Peripheral Operations On-Line"** 의 약자로, 느린 장치(프린터, 원격 서버 등) 앞에 **임시 저장소(대기열)**를 두고 작업을 비동기로 처리하는 기술이다.

스풀 시스템은 크게 세 가지 요소로 구성된다.
- **프로듀서(Producer)**: 작업을 스풀 디렉토리에 제출하는 애플리케이션
- **스풀 디렉토리(Spool Directory)**: 작업이 대기하는 임시 저장소
- **컨슈머(Consumer)**: 큐에서 작업을 꺼내 실제 처리하는 데몬

### 주요 스풀 디렉토리와 관리 명령

| 서비스 | 스풀 경로 | 관리 명령 |
|--------|----------|----------|
| cron | `/var/spool/cron` | `crontab -e`, `crontab -l` (직접 파일 수정 금지) |
| at | `/var/spool/at` | `atq`, `atrm` |
| Postfix | `/var/spool/postfix` | `postqueue -p`, `postsuper -d` |
| CUPS(프린터) | `/var/spool/cups` | `lpstat -o`, `cancel` |

> **중요**: 스풀 디렉토리의 파일을 임의로 삭제하기 전에 **해당 서비스의 관리 명령**을 먼저 사용하라. 무단 삭제는 데이터 손실로 이어질 수 있다.

## 안전한 스풀 큐 관리

### 상태 확인 (읽기 전용)

```bash
# 메일 큐 확인
postqueue -p
mailq

# 프린터 큐 확인
lpstat -o
lpq
```

### 큐 제어 (서비스 명령 사용)

```bash
# Postfix: 지연 큐 강제 재시도
postfix flush

# 특정 메시지 삭제 (MSGID는 postqueue -p로 확인)
postsuper -d <MSGID>

# 프린터 작업 취소
cancel <JOB-ID>
```

### 문제 발생 시 안전한 정리 절차

스풀이 지나치게 쌓여 서비스에 영향이 있을 때는 다음 순서로 처리한다.

```bash
# 1. 서비스 중지
systemctl stop postfix

# 2. 스풀 백업
tar -czf /root/spool-backup-$(date +%F).tar.gz /var/spool/postfix

# 3. 정책에 따라 정리 (예: 10일 이상된 파일)
find /var/spool/postfix/deferred -type f -mtime +10 -delete

# 4. 서비스 재시작
systemctl start postfix
```

## 용량 및 아이노드 문제 진단

### 기본 확인

```bash
# 디스크 사용량
df -h

# 아이노드 사용량 (작은 파일이 많을 때 중요)
df -i
```

### 큰 디렉토리 찾기

```bash
du -xh --max-depth=1 /var | sort -h
ncdu /var   # 대화형 탐색 도구
```

### 삭제했는데 공간이 줄지 않을 때

프로세스가 파일을 열고 있는 상태에서 파일이 삭제되면(로그 파일 등) 디스크 공간이 반환되지 않는다.

```bash
# 삭제된 파일을 열고 있는 프로세스 확인
lsof +L1 | grep deleted
```

해당 프로세스를 재시작하면 공간이 반환된다.

### 저널 로그 정리

```bash
journalctl --disk-usage
journalctl --vacuum-size=1G
journalctl --vacuum-time=7d
```

## 파일 시스템 점검과 복구

### ext4 (e2fsck)

```bash
# 마운트 해제 후 점검
umount /dev/sda1
e2fsck -f /dev/sda1     # 강제 점검
```

루트 파티션은 라이브 CD나 복구 모드에서 점검해야 한다.

### XFS (xfs_repair)

```bash
umount /dev/sdb1
xfs_repair -n /dev/sdb1   # 점검만 (수정 없음)
xfs_repair /dev/sdb1      # 실제 복구
```

> 파일시스템 타입별로 전용 도구를 사용해야 한다.

### Btrfs (scrub)

```bash
# 온라인 점검 (마운트된 상태에서 가능)
btrfs scrub start -Bd /mnt
```

## 파일시스템 튜닝과 마운트 옵션

### 예약 블록 조정 (ext4)

루트가 아닌 데이터 전용 파티션은 예약 블록을 줄일 수 있다.

```bash
# 현재 예약 블록 비율 확인
tune2fs -l /dev/sda1 | grep "Reserved block"

# 1%로 조정
tune2fs -m 1 /dev/sda1
```

### 마운트 옵션 예시 (/etc/fstab)

```
# 루트 파티션
UUID=xxx  /          ext4  defaults,relatime       0 1

# 데이터 파티션 (접근 시간 갱신 안 함)
UUID=yyy  /data      ext4  noatime                 0 2

# SSD (TRIM 활성화)
UUID=zzz  /ssd       ext4  discard,errors=remount-ro 0 2
```

- `relatime`: 접근 시간 갱신 최적화 (기본)
- `noatime`: 접근 시간 기록 안 함 (성능 향상)
- `discard`: SSD TRIM
- `errors=remount-ro`: 오류 시 읽기 전용 재마운트

## 자동화와 모니터링

### 용량 임계치 알림

```bash
#!/usr/bin/env bash
THRESH=90
df -hP | awk -v t=$THRESH 'NR>1 && $5+0 >= t {print $6, $5}'
```
크론에 등록하여 메일로 알림을 보낼 수 있다.

### fstrim (SSD)

```bash
systemctl status fstrim.timer
systemctl enable --now fstrim.timer
```

## 결론

스풀링과 파일시스템 관리는 시스템 안정성과 직결되는 중요한 영역이다.

- **스풀은 서비스가 관리하는 대기열**이다. 파일을 직접 조작하기 전에 반드시 서비스 명령(`postqueue`, `lpstat`, `cancel`)을 먼저 사용하라.
- 용량 문제는 디스크 공간(`df -h`)뿐 아니라 **아이노드 고갈**(`df -i`)과 **삭제된 열린 파일**(`lsof +L1`)도 의심해야 한다.
- 파일시스템 점검은 **각 타입별 전용 도구**를 사용하고, 가능하면 마운트를 해제한 후 진행한다.
- `noatime`, `discard` 같은 마운트 옵션과 예약 블록 조정으로 성능과 효율을 높일 수 있다.
- 정기적인 모니터링과 자동화 스크립트로 문제를 예방하고, 발생 시 빠르게 대응하는 습관을 들이자.
