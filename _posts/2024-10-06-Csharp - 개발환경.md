# C#과 .NET 개요

C#은 마이크로소프트에서 개발한 현대적인 객체 지향 프로그래밍 언어입니다. 정적 타입 언어로서 컴파일 시점에 타입 안정성을 확보하며, .NET 플랫폼 위에서 동작합니다. C# 자체는 언어 사양을 의미하고, .NET은 이를 실행하는 런타임, 라이브러리, 도구를 포함한 통합 생태계입니다.

---

## .NET 생태계의 구조

.NET은 언어, 런타임, 라이브러리, 도구가 계층적으로 구성되어 있습니다. 아래는 그 구조를 도식화한 것입니다.

```
.NET 생태계
├── 지원 언어: C#, F#, Visual Basic
├── 런타임: .NET 런타임 (CoreCLR)
│   ├── 가비지 컬렉터 (GC)
│   ├── JIT 컴파일러
│   └── 기본 클래스 라이브러리 (BCL)
├── SDK: dotnet CLI, 컴파일러, 템플릿
├── 애플리케이션 모델
│   ├── ASP.NET Core (웹 API, 웹앱)
│   ├── MAUI (크로스 플랫폼 UI)
│   ├── WPF / WinForms (Windows 데스크톱)
│   └── 콘솔, 백그라운드 서비스
└── 도구 체인: NuGet, IDE 통합
```

C# 컴파일러는 소스 코드를 **중간 언어(IL, Intermediate Language)** 로 변환합니다. 이 IL은 특정 CPU나 운영체제에 종속되지 않으며, 실행 시점에 런타임 내부의 **JIT(Just-In-Time) 컴파일러**가 현재 환경에 맞는 기계어로 변환합니다. 이러한 구조 덕분에 C#은 한 번 작성한 코드를 Windows, Linux, macOS 등 다양한 환경에서 실행할 수 있습니다.

---

## C#과 .NET의 관계

C#은 언어이고, .NET은 실행 플랫폼입니다. C# 코드는 .NET이 제공하는 **기본 클래스 라이브러리(BCL)** 를 활용하여 파일 접근, 네트워크 통신, 컬렉션 처리 등을 수행합니다. 예를 들어 `Console.WriteLine` 같은 코드는 BCL에 정의된 기능을 호출하는 것입니다.

주의할 점은, C# 언어 버전과 .NET 런타임 버전이 별도로 관리된다는 것입니다. 프로젝트 파일(`.csproj`)에서 `TargetFramework` 요소를 통해 사용할 .NET 버전을 지정하며, 이에 따라 사용 가능한 C# 언어 기능이 결정됩니다. 최신 C# 기능을 사용하려면 해당 기능을 지원하는 .NET SDK 버전이 필요합니다.

## 개발 환경 구성

C# 개발을 시작하는 데 필요한 것은 **.NET SDK**와 **텍스트 편집기(또는 IDE)** 입니다.

### .NET SDK 설치

[dotnet.microsoft.com](https://dotnet.microsoft.com)에서 운영체제에 맞는 .NET SDK를 다운로드합니다. SDK에는 런타임, 컴파일러, `dotnet` 명령줄 도구, 프로젝트 템플릿, 빌드 도구 등이 포함되어 있습니다.

설치 후 터미널(또는 명령 프롬프트)에서 다음 명령어로 정상 설치를 확인합니다.

```bash
dotnet --version
```

버전 번호(예: `8.0.4`)가 출력되면 준비가 완료된 것입니다.

### 편집기 선택

- **Visual Studio 2022 Community (Windows 전용)**: 무료 IDE로, 솔루션 관리, 디버거, 프로파일러, 리팩토링 도구가 통합되어 있습니다. 대규모 프로젝트나 엔터프라이즈 개발에 적합합니다.
- **Visual Studio Code (Windows, macOS, Linux)**: 경량 편집기입니다. **C# Dev Kit** 확장을 설치하면 솔루션 탐색기, 디버깅 통합 등 IDE 수준의 기능을 사용할 수 있습니다. 초중급 개발자에게 권장합니다.
- **JetBrains Rider (상용)**: 성능과 생산성이 뛰어난 크로스 플랫폼 IDE입니다.

### VS Code 확장 설치

VS Code를 사용할 경우 다음 확장을 반드시 설치합니다.

- **C# Dev Kit**: Microsoft에서 제공하는 확장 패키지로, C# 확장, 디버거, 솔루션 관리 기능을 함께 설치합니다.

설치 후 `.csproj` 또는 `.sln` 파일을 열면 프로젝트가 자동으로 인식되고, IntelliSense, 코드 탐색, 디버깅이 활성화됩니다.

## 프로젝트 생성과 실행

### 새 프로젝트 만들기

콘솔 애플리케이션은 가장 기본적인 프로젝트 형태입니다.

```bash
mkdir MyApp
cd MyApp
dotnet new console
```

이 명령은 `Program.cs`와 `MyApp.csproj` 파일을 생성합니다.

### 빌드와 실행

```bash
dotnet build
dotnet run
```

`dotnet build`는 프로젝트를 컴파일하여 `bin/Debug/` 폴더에 출력물을 생성합니다. `dotnet run`은 빌드 후 실행 파일을 실행합니다.

### 프로젝트 파일 구조

`.csproj` 파일은 프로젝트 설정을 담고 있습니다.

```xml
<Project Sdk="Microsoft.NET.Sdk">
  <PropertyGroup>
    <OutputType>Exe</OutputType>
    <TargetFramework>net8.0</TargetFramework>
    <ImplicitUsings>enable</ImplicitUsings>
    <Nullable>enable</Nullable>
  </PropertyGroup>
</Project>
```

- **TargetFramework**: `net8.0`은 .NET 8을 대상으로 함을 의미합니다. `net6.0`, `net7.0` 등으로 변경 가능합니다.
- **ImplicitUsings**: `enable` 시 `System`, `System.Collections.Generic` 등 자주 사용하는 네임스페이스를 자동으로 포함합니다.
- **Nullable**: `enable` 시 nullable 참조 타입에 대한 컴파일러 경고가 활성화됩니다.

## 디버깅 환경

VS Code에서 디버깅을 사용하려면 디버그 구성 파일이 필요합니다. **C# Dev Kit** 확장이 설치된 상태에서 프로젝트를 열면, **실행 및 디버그** 탭에서 **.NET Core** 구성을 자동으로 생성할 수 있습니다.

- 중단점: 코드 줄 번호 왼쪽을 클릭하여 설정합니다.
- 디버깅 시작: `F5` 키를 누릅니다.
- 변수 조사: 디버깅 중에 마우스를 변수 위에 올리거나 왼쪽 **변수** 패널에서 값을 확인합니다.
- 단계 실행: `F10`(한 단계씩), `F11`(함수 내부 진입) 등을 사용합니다.

`launch.json` 파일을 직접 수정하여 프로그램 인수, 환경 변수 등을 설정할 수 있습니다.

## 패키지 관리

NuGet은 .NET의 패키지 관리자입니다. 오픈소스 라이브러리를 프로젝트에 추가할 때 사용합니다.

```bash
dotnet add package Newtonsoft.Json
```

이 명령은 `csproj` 파일에 `<PackageReference>`를 추가하고 패키지를 다운로드합니다. 이후 빌드 시 자동으로 종속성이 복원됩니다.

패키지는 `using` 지시문으로 가져와서 사용합니다.

```csharp
using Newtonsoft.Json;
```

## 런타임 동작 이해

C# 코드가 실행되는 과정을 간단히 설명하면 다음과 같습니다.

1. 소스 코드(`.cs`)를 C# 컴파일러가 IL(중간 언어)로 변환합니다.
2. IL은 `.dll` 또는 `.exe` 파일로 저장됩니다.
3. 실행 시 런타임이 IL을 로드합니다.
4. 메서드가 처음 호출될 때 JIT 컴파일러가 IL을 기계어로 변환합니다.
5. 이후 동일한 메서드는 변환된 기계어를 재사용합니다.

이러한 방식은 애플리케이션 시작 시 일정한 성능 비용이 발생합니다. 일부 시나리오에서는 **AOT(Ahead-Of-Time) 컴파일**을 사용하여 배포 전에 모든 코드를 기계어로 변환함으로써 시작 시간을 단축할 수 있습니다. 특히 $$O(n)$$ 복잡도를 가진 초기화 로직이 많은 서비스에서 AOT는 유용합니다.

## 마무리

C# 개발 환경은 .NET SDK 하나로 대부분 구성됩니다.

- .NET SDK 설치와 `dotnet` 명령어 사용법
- 프로젝트 생성, 빌드, 실행 기본 흐름
- 편집기(Visual Studio 또는 VS Code)에서 디버깅하는 방법
- NuGet을 통한 패키지 참조 추가
- 기본적인 프로젝트 파일(`.csproj`) 구조 이해

C# 언어의 세부 문법보다는, 코드가 작성되어 실행되기까지의 전체적인 흐름과 도구 사용법을 먼저 익히는 것이 안정적인 개발 기초를 다지는 길입니다. 이후 실제 프로젝트를 진행하면서 필요한 언어 기능을 자연스럽게 학습할 수 있습니다.
