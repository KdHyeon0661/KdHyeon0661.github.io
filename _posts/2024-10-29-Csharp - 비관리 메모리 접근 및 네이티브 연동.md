# C# 비관리 메모리 접근 및 네이티브 연동

C#은 기본적으로 안전한 관리 코드 환경을 제공하지만, 성능이 중요한 시나리오나 기존 네이티브 라이브러리와 통합해야 할 때는 비관리 메모리와 직접 상호작용해야 합니다. 이러한 작업은 복잡하고 오류가 발생하기 쉽지만, C#은 이를 위한 강력한 도구들을 제공합니다. 이 글에서는 초중급 개발자를 기준으로 비관리 메모리 접근, 네이티브 코드와의 상호 운용, 그리고 안전성을 유지하면서 성능을 극대화하는 방법을 설명합니다.

---

## 관리 메모리와 비관리 메모리

### 관리 메모리

관리 메모리는 가비지 컬렉터(GC)가 자동으로 할당, 이동, 해제합니다. 타입 안전성이 보장되며 일반적인 C# 객체, 배열, 문자열 등이 여기에 속합니다. 편리하지만 GC의 오버헤드가 있을 수 있습니다.

### 비관리 메모리

비관리 메모리는 개발자가 직접 할당하고 해제해야 합니다. GC의 통제를 받지 않기 때문에 성능 최적화가 가능하지만, 메모리 누수나 댕글링 포인터 등의 위험이 있습니다. 네이티브 코드(C/C++), 운영체제 API, 하드웨어 직접 접근 등에 사용됩니다.

### 비관리 메모리가 필요한 상황

- **성능**: 대량 데이터 처리 시 복사 오버헤드를 제거할 수 있습니다.
- **상호 운용**: 기존 C/C++ 라이브러리를 사용해야 할 때 필요합니다.
- **제어**: 특정 메모리 레이아웃이나 정렬 요구사항을 충족해야 할 때 사용합니다.
- **시스템 호출**: 운영체제 API를 직접 호출해야 할 때 필요합니다.

## P/Invoke: 네이티브 DLL 함수 호출하기

P/Invoke(Platform Invocation Services)는 관리 코드에서 비관리 DLL의 함수를 호출할 수 있게 해줍니다.

### 기본 예제: Windows MessageBox

```csharp
using System.Runtime.InteropServices;

class NativeMethods
{
    [DllImport("user32.dll", CharSet = CharSet.Unicode)]
    public static extern int MessageBox(
        IntPtr hWnd, 
        string text, 
        string caption, 
        uint type);
}

// 호출 예
NativeMethods.MessageBox(IntPtr.Zero, "안녕하세요", "테스트", 0);
```

### 주요 DllImport 속성

- `CharSet`: 문자열 인코딩 지정 (Unicode, Ansi)
- `CallingConvention`: 함수 호출 규약 (StdCall, Cdecl 등)
- `SetLastError`: true로 설정하면 `Marshal.GetLastWin32Error()`로 오류 코드를 가져올 수 있습니다.

### 오류 처리

```csharp
[DllImport("kernel32.dll", SetLastError = true)]
public static extern IntPtr LoadLibrary(string lpFileName);

IntPtr handle = LoadLibrary("mylib.dll");
if (handle == IntPtr.Zero)
{
    int errorCode = Marshal.GetLastWin32Error();
    string message = new System.ComponentModel.Win32Exception(errorCode).Message;
    Console.WriteLine($"오류: {message}");
}
```

## 비관리 메모리 할당과 해제

비관리 메모리를 사용할 때 가장 중요한 것은 할당한 메모리를 반드시 해제하는 것입니다.

### Marshal 클래스 (전통적 방식)

```csharp
IntPtr memory = IntPtr.Zero;
try
{
    memory = Marshal.AllocHGlobal(1024);  // 1KB 할당
    
    // 데이터 쓰기
    byte[] data = { 1, 2, 3, 4, 5 };
    Marshal.Copy(data, 0, memory, data.Length);
    
    // 데이터 읽기
    byte[] readData = new byte[5];
    Marshal.Copy(memory, readData, 0, 5);
}
finally
{
    if (memory != IntPtr.Zero)
        Marshal.FreeHGlobal(memory);  // 반드시 해제
}
```

### NativeMemory 클래스 (.NET 6+)

```csharp
using System.Runtime.InteropServices;

unsafe
{
    nint memory = (nint)NativeMemory.Alloc(1024);
    try
    {
        Span<byte> span = new Span<byte>((void*)memory, 1024);
        span.Fill(0xFF);
        span[0] = 0xAA;
    }
    finally
    {
        NativeMemory.Free((void*)memory);
    }
}
```

`NativeMemory`는 `nint` 타입과 함께 사용할 수 있으며, `Span<T>`로 래핑하면 안전하게 메모리에 접근할 수 있습니다.

## 구조체 마샬링

네이티브 코드와 데이터를 교환할 때는 구조체의 메모리 레이아웃이 정확히 일치해야 합니다.

### 기본 구조체 마샬링

```csharp
[StructLayout(LayoutKind.Sequential, Pack = 1)]
public struct Point
{
    public int X;
    public int Y;
}

// 비관리 메모리로 변환
Point point = new Point { X = 10, Y = 20 };
IntPtr ptr = Marshal.AllocHGlobal(Marshal.SizeOf<Point>());

try
{
    Marshal.StructureToPtr(point, ptr, false);
    Point result = Marshal.PtrToStructure<Point>(ptr);
}
finally
{
    Marshal.FreeHGlobal(ptr);
}
```

### 고정 크기 배열과 공용체

```csharp
// 고정 크기 배열
[StructLayout(LayoutKind.Sequential)]
public struct Person
{
    [MarshalAs(UnmanagedType.ByValTStr, SizeConst = 32)]
    public string Name;
    
    [MarshalAs(UnmanagedType.ByValArray, SizeConst = 3)]
    public float[] Scores;
}

// 공용체(Union): 같은 메모리 위치를 여러 타입으로 해석
[StructLayout(LayoutKind.Explicit)]
public struct DataUnion
{
    [FieldOffset(0)] public int Integer;
    [FieldOffset(0)] public float Float;
    [FieldOffset(0)] public byte Byte1;
    [FieldOffset(1)] public byte Byte2;
}
```

## SafeHandle로 리소스 누수 방지

`SafeHandle`은 비관리 리소스의 수명을 안전하게 관리하는 추상화입니다. 예외가 발생해도 정리가 보장됩니다.

```csharp
public sealed class SafeFileHandle : SafeHandleZeroOrMinusOneIsInvalid
{
    private SafeFileHandle() : base(true) { }
    
    public SafeFileHandle(IntPtr handle, bool ownsHandle) : base(ownsHandle)
    {
        SetHandle(handle);
    }
    
    protected override bool ReleaseHandle()
    {
        return CloseHandle(handle);
    }
    
    [DllImport("kernel32.dll")]
    private static extern bool CloseHandle(IntPtr hObject);
}

// 사용
using (var handle = new SafeFileHandle(nativeHandle, true))
{
    // handle 사용
} // 자동으로 ReleaseHandle 호출
```

## Span<T>와 Memory<T>로 안전하게 접근하기

`Span<T>`는 비관리 메모리를 안전하게 다루는 현대적인 방법입니다.

```csharp
unsafe
{
    nint memory = (nint)NativeMemory.Alloc(1000);
    try
    {
        Span<byte> buffer = new Span<byte>((void*)memory, 1000);
        
        // 안전하게 데이터 조작
        buffer.Fill(0xCC);
        buffer.Slice(0, 100).Fill(0xFF);
        
        // 배열 복사
        byte[] source = { 1, 2, 3 };
        source.CopyTo(buffer.Slice(200, 3));
        
        // 다른 타입으로 해석
        Span<int> intView = MemoryMarshal.Cast<byte, int>(buffer);
        intView[0] = 0x12345678;
    }
    finally
    {
        NativeMemory.Free((void*)memory);
    }
}
```

`Span<T>`는 스택 전용이므로 비동기 메서드에서는 `Memory<T>`를 사용할 수 있습니다.

## 문자열 인코딩 처리

네이티브 코드와 문자열을 교환할 때는 인코딩을 정확히 맞추는 것이 중요합니다.

```csharp
// UTF-16 (Windows 기본)
[DllImport("user32.dll", CharSet = CharSet.Unicode)]
public static extern int MessageBoxW(IntPtr hWnd, string text, string caption, uint type);

// ANSI (레거시)
[DllImport("user32.dll", CharSet = CharSet.Ansi)]
public static extern int MessageBoxA(IntPtr hWnd, string text, string caption, uint type);

// UTF-8로 전송 (수동 변환)
static unsafe void SendUtf8String(string text)
{
    byte[] utf8Bytes = Encoding.UTF8.GetBytes(text + "\0");
    fixed (byte* ptr = utf8Bytes)
    {
        NativeProcessString(ptr);
    }
}

[DllImport("native.dll")]
static extern void NativeProcessString(byte* utf8String);
```

### StringBuilder로 출력 매개변수 처리

```csharp
[DllImport("kernel32.dll", CharSet = CharSet.Unicode)]
public static extern int GetCurrentDirectory(int bufferLength, StringBuilder buffer);

string GetDirectory()
{
    int length = GetCurrentDirectory(0, null);
    StringBuilder sb = new StringBuilder(length);
    GetCurrentDirectory(length, sb);
    return sb.ToString();
}
```

## 교차 플랫폼 고려사항

플랫폼별로 라이브러리 이름과 호출 규약이 다를 수 있습니다.

```csharp
private static string GetPlatformLibraryName(string baseName)
{
    if (RuntimeInformation.IsOSPlatform(OSPlatform.Windows))
        return $"{baseName}.dll";
    else if (RuntimeInformation.IsOSPlatform(OSPlatform.Linux))
        return $"lib{baseName}.so";
    else if (RuntimeInformation.IsOSPlatform(OSPlatform.OSX))
        return $"lib{baseName}.dylib";
    return baseName;
}

// 동적 로딩
IntPtr lib = NativeLibrary.Load(GetPlatformLibraryName("mylib"));
NativeLibrary.TryGetExport(lib, "myFunction", out IntPtr funcPtr);
var func = Marshal.GetDelegateForFunctionPointer<MyDelegate>(funcPtr);
NativeLibrary.Free(lib);
```

## 결론: 안전성과 성능의 균형

비관리 메모리와 네이티브 연동은 C#의 강력한 기능이지만, 신중하게 사용해야 합니다.

### 권장사항

1. **필요할 때만 사용하세요**  
   대부분의 애플리케이션은 관리 코드만으로 충분합니다. 성능 문제가 확인된 후에만 도입하세요.

2. **가장 안전한 도구부터 선택하세요**  
   먼저 `Span<T>`/`Memory<T>`를 고려하고, 정말 필요한 경우에만 `unsafe` 코드와 포인터를 사용하세요.

3. **리소스 관리를 철저히 하세요**  
   `SafeHandle`을 활용하고, 할당과 해제를 짝을 맞추세요. `using` 문과 `try-finally`를 잊지 마세요.

4. **플랫폼 차이를 고려하세요**  
   Windows, Linux, macOS는 ABI가 다릅니다. 구조체 정렬, 호출 규약, 문자열 인코딩을 플랫폼에 맞게 조정하세요.

5. **철저히 테스트하세요**  
   비관리 코드는 디버깅이 어렵습니다. 단위 테스트와 통합 테스트로 안정성을 확보하세요.

현대적인 C#에서는 `Span<T>`, `Memory<T>`, `NativeMemory`, `SafeHandle`과 같은 안전한 추상화를 통해 저수준 제어의 이점을 누리면서도 대부분의 위험을 피할 수 있습니다. 이러한 도구들을 적절히 활용하면 C#으로도 시스템 수준의 고성능 애플리케이션을 구축할 수 있습니다.
