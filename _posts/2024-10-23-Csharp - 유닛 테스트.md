# C# 유닛 테스트와 xUnit

유닛 테스트는 소프트웨어 개발에서 코드의 정확성을 검증하고, 리팩토링의 안전성을 확보하며, 문서 역할을 하는 핵심 실천법입니다. xUnit은 .NET 생태계에서 가장 널리 사용되는 테스트 프레임워크로, 간결한 문법과 강력한 기능을 제공합니다.

---

## 테스트 프로젝트 설정

테스트를 시작하려면 솔루션에 테스트 전용 프로젝트를 추가합니다. xUnit 템플릿을 사용하면 필요한 패키지가 자동으로 포함됩니다.

```bash
dotnet new sln -n MyAppSolution
dotnet new classlib -n MyApp
dotnet new xunit -n MyApp.Tests

dotnet sln add MyApp/MyApp.csproj MyApp.Tests/MyApp.Tests.csproj
dotnet add MyApp.Tests reference MyApp
```

프로젝트 구조는 프로덕션 코드와 테스트 코드를 분리하는 것이 일반적입니다.

```
MyAppSolution/
├── MyApp/
│   ├── Services/
│   ├── Models/
│   └── Utilities/
└── MyApp.Tests/
    ├── Services/
    ├── Models/
    └── Utilities/
```

테스트 실행은 `dotnet test` 명령어로 수행합니다.

## 테스트 작성 기초

### AAA 패턴

각 테스트는 **Arrange-Act-Assert** 세 단계로 구성하는 것이 좋습니다.

- **Arrange**: 테스트에 필요한 객체나 데이터를 준비합니다.
- **Act**: 테스트 대상 메서드를 실행합니다.
- **Assert**: 예상 결과를 검증합니다.

```csharp
[Fact]
public void CalculateTotal_WithValidItems_ReturnsCorrectSum()
{
    // Arrange
    var calculator = new ShoppingCartCalculator();
    var items = new[] { new Item(100), new Item(200), new Item(300) };

    // Act
    var total = calculator.CalculateTotal(items);

    // Assert
    Assert.Equal(600, total);
}
```

### Fact와 Theory

- `[Fact]`는 입력 데이터 없이 하나의 시나리오를 검증합니다.
- `[Theory]`는 여러 입력 데이터에 대해 동일한 테스트 로직을 반복 실행합니다. `[InlineData]`로 데이터를 제공합니다.

```csharp
[Fact]
public void Add_TwoPositiveNumbers_ReturnsSum()
{
    var calc = new Calculator();
    var result = calc.Add(2, 3);
    Assert.Equal(5, result);
}

[Theory]
[InlineData(2, 3, 5)]
[InlineData(10, -5, 5)]
[InlineData(0, 0, 0)]
public void Add_VariousInputs_ReturnsSum(int a, int b, int expected)
{
    var calc = new Calculator();
    var result = calc.Add(a, b);
    Assert.Equal(expected, result);
}
```

### 테스트 격리성

xUnit은 각 테스트 메서드마다 테스트 클래스의 새 인스턴스를 생성합니다. 따라서 생성자에서 공통 설정을 하고 `IDisposable`에서 정리를 할 수 있습니다.

```csharp
public class CalculatorTests : IDisposable
{
    private readonly Calculator _calculator;

    public CalculatorTests()
    {
        _calculator = new Calculator();  // 각 테스트 전에 실행
    }

    [Fact]
    public void Add_SimpleValues_Calculates()
    {
        var result = _calculator.Add(2, 3);
        Assert.Equal(5, result);
    }

    public void Dispose()
    {
        // 각 테스트 후에 정리 작업
    }
}
```

## Assertions

xUnit은 다양한 검증 메서드를 제공합니다. 가장 자주 사용하는 것들입니다.

| 메서드 | 용도 |
|--------|------|
| `Equal` / `NotEqual` | 값 비교 |
| `True` / `False` | 조건 검증 |
| `Null` / `NotNull` | null 여부 |
| `Same` / `NotSame` | 참조 동일성 |
| `Throws` / `ThrowsAsync` | 예외 발생 확인 |
| `Contains` / `DoesNotContain` | 컬렉션 포함 여부 |
| `InRange` / `NotInRange` | 범위 확인 |

```csharp
[Fact]
public void AssertionExamples()
{
    // 값 비교
    Assert.Equal(5, 2 + 3);
    Assert.NotEqual(10, 2 + 3);

    // 조건
    Assert.True(5 > 3);
    Assert.False(5 < 3);

    // null
    string? s = null;
    Assert.Null(s);
    s = "hello";
    Assert.NotNull(s);

    // 참조 동일성
    var a = new object();
    var b = a;
    Assert.Same(a, b);

    // 예외
    Assert.Throws<DivideByZeroException>(() => { var x = 1 / 0; });

    // 컬렉션
    var list = new List<int> { 1, 2, 3 };
    Assert.Contains(2, list);
    Assert.DoesNotContain(5, list);

    // 범위
    Assert.InRange(10, 1, 20);
}
```

부동소수점 비교 시에는 정밀도를 지정할 수 있습니다.

```csharp
Assert.Equal(0.33333, 1.0 / 3.0, precision: 5);
```

## 비동기 테스트

비동기 메서드는 `async Task`를 반환하고 `await`를 사용하여 테스트합니다.

```csharp
[Fact]
public async Task LoadDataAsync_ValidUrl_ReturnsData()
{
    var service = new DataService();
    var data = await service.LoadDataAsync("https://api.example.com/data");
    Assert.NotNull(data);
}

[Fact]
public async Task ProcessAsync_CancelledToken_ThrowsCancellation()
{
    var processor = new DataProcessor();
    using var cts = new CancellationTokenSource();
    cts.Cancel();

    await Assert.ThrowsAsync<OperationCanceledException>(
        () => processor.ProcessAsync(cts.Token)
    );
}
```

## 데이터 주도 테스트

`Theory`와 함께 다양한 데이터 소스를 사용할 수 있습니다.

### InlineData

가장 간단한 방식으로, 테스트 데이터를 메서드 속성에 직접 나열합니다.

```csharp
[Theory]
[InlineData(1, 2, 3)]
[InlineData(-1, -1, -2)]
public void Add_SimpleInputs_ReturnsSum(int a, int b, int expected)
{
    var calc = new Calculator();
    var result = calc.Add(a, b);
    Assert.Equal(expected, result);
}
```

### MemberData

별도의 정적 속성이나 메서드에서 데이터를 제공합니다.

```csharp
public static IEnumerable<object[]> AdditionData =>
    new List<object[]>
    {
        new object[] { 1, 2, 3 },
        new object[] { -1, -1, -2 },
        new object[] { int.MaxValue, 0, int.MaxValue }
    };

[Theory]
[MemberData(nameof(AdditionData))]
public void Add_VariousInputs_ReturnsSum(int a, int b, int expected)
{
    var calc = new Calculator();
    var result = calc.Add(a, b);
    Assert.Equal(expected, result);
}
```

데이터를 별도 클래스로 분리하여 재사용할 수도 있습니다.

```csharp
public class MultiplicationTestData : IEnumerable<object[]>
{
    public IEnumerator<object[]> GetEnumerator()
    {
        yield return new object[] { 2, 3, 6 };
        yield return new object[] { 4, 5, 20 };
    }

    IEnumerator IEnumerable.GetEnumerator() => GetEnumerator();
}

[Theory]
[ClassData(typeof(MultiplicationTestData))]
public void Multiply_VariousInputs_ReturnsProduct(int a, int b, int expected)
{
    var calc = new Calculator();
    var result = calc.Multiply(a, b);
    Assert.Equal(expected, result);
}
```

## 테스트 픽스처 (공유 리소스)

테스트 간에 공유해야 하는 리소스(예: 데이터베이스 연결)가 있을 때는 픽스처를 사용합니다.

### 클래스 수준 픽스처 (IClassFixture)

하나의 테스트 클래스 내에서 모든 테스트가 동일한 픽스처 인스턴스를 공유합니다.

```csharp
public class DatabaseFixture : IDisposable
{
    public DatabaseConnection Connection { get; }

    public DatabaseFixture()
    {
        Connection = new DatabaseConnection("TestDatabase");
        Connection.Open();
    }

    public void Dispose()
    {
        Connection.Dispose();
    }
}

public class UserRepositoryTests : IClassFixture<DatabaseFixture>
{
    private readonly DatabaseFixture _fixture;

    public UserRepositoryTests(DatabaseFixture fixture)
    {
        _fixture = fixture;
    }

    [Fact]
    public void GetUser_ExistingId_ReturnsUser()
    {
        var repo = new UserRepository(_fixture.Connection);
        var user = repo.GetUser(1);
        Assert.NotNull(user);
    }
}
```

### 컬렉션 수준 픽스처 (ICollectionFixture)

여러 테스트 클래스에서 동일한 픽스처를 공유하려면 컬렉션을 정의합니다.

```csharp
[CollectionDefinition("Database collection")]
public class DatabaseCollection : ICollectionFixture<DatabaseFixture>
{
    // 빈 클래스
}

[Collection("Database collection")]
public class UserServiceTests
{
    private readonly DatabaseFixture _fixture;
    public UserServiceTests(DatabaseFixture fixture) => _fixture = fixture;
}

[Collection("Database collection")]
public class ProductServiceTests
{
    private readonly DatabaseFixture _fixture;
    public ProductServiceTests(DatabaseFixture fixture) => _fixture = fixture;
}
```

### 비동기 초기화 (IAsyncLifetime)

생성자에서 비동기 작업을 할 수 없을 때 `IAsyncLifetime`을 구현합니다.

```csharp
public class AsyncTests : IAsyncLifetime
{
    private HttpClient _client;

    public async Task InitializeAsync()
    {
        _client = new HttpClient();
        await SeedDatabaseAsync();
    }

    public async Task DisposeAsync()
    {
        _client?.Dispose();
    }

    private async Task SeedDatabaseAsync() { /* ... */ }

    [Fact]
    public async Task TestMethod()
    {
        // ...
    }
}
```

## 목(Mock)을 이용한 의존성 분리

테스트하려는 코드가 외부 의존성(데이터베이스, API 등)을 사용한다면, 이를 추상화하고 Mock으로 대체하여 단위 테스트의 격리성을 유지합니다.

먼저 의존성을 인터페이스로 정의합니다.

```csharp
public interface IEmailService
{
    Task SendAsync(string to, string subject, string body);
}
```

테스트 대상 클래스는 인터페이스를 주입받습니다.

```csharp
public class NotificationService
{
    private readonly IEmailService _emailService;

    public NotificationService(IEmailService emailService)
    {
        _emailService = emailService;
    }

    public async Task SendWelcomeEmail(string email)
    {
        await _emailService.SendAsync(email, "환영합니다", "가입해 주셔서 감사합니다.");
    }
}
```

### Moq 사용

```csharp
[Fact]
public async Task SendWelcomeEmail_CallsEmailService()
{
    // Arrange
    var mock = new Mock<IEmailService>();
    var service = new NotificationService(mock.Object);

    // Act
    await service.SendWelcomeEmail("test@example.com");

    // Assert
    mock.Verify(s => s.SendAsync(
        "test@example.com",
        "환영합니다",
        "가입해 주셔서 감사합니다."
    ), Times.Once);
}
```

### NSubstitute 사용

```csharp
[Fact]
public async Task SendWelcomeEmail_CallsEmailService()
{
    var emailService = Substitute.For<IEmailService>();
    var service = new NotificationService(emailService);

    await service.SendWelcomeEmail("test@example.com");

    await emailService.Received(1).SendAsync(
        "test@example.com",
        "환영합니다",
        "가입해 주셔서 감사합니다."
    );
}
```

## 통합 테스트: WebApplicationFactory

ASP.NET Core 애플리케이션의 통합 테스트는 `WebApplicationFactory<TEntryPoint>`를 사용합니다.

```bash
dotnet add MyApp.Tests package Microsoft.AspNetCore.Mvc.Testing
```

```csharp
public class OrderApiTests : IClassFixture<WebApplicationFactory<Program>>
{
    private readonly HttpClient _client;

    public OrderApiTests(WebApplicationFactory<Program> factory)
    {
        _client = factory.CreateClient();
    }

    [Fact]
    public async Task GetOrders_ReturnsOk()
    {
        var response = await _client.GetAsync("/api/orders");
        Assert.Equal(HttpStatusCode.OK, response.StatusCode);
    }
}
```

테스트용 데이터베이스를 분리하려면 `WebApplicationFactory`를 커스터마이징합니다.

```csharp
public class CustomWebApplicationFactory : WebApplicationFactory<Program>
{
    protected override void ConfigureWebHost(IWebHostBuilder builder)
    {
        builder.ConfigureServices(services =>
        {
            // 실제 DbContext 제거
            var descriptor = services.SingleOrDefault(
                d => d.ServiceType == typeof(DbContextOptions<AppDbContext>));
            if (descriptor != null) services.Remove(descriptor);

            // 테스트용 InMemory 데이터베이스 추가
            services.AddDbContext<AppDbContext>(options =>
                options.UseInMemoryDatabase("TestDb"));
        });
    }
}
```

## 테스트 조직화와 실행 제어

### 카테고리 분류

`Trait` 특성을 사용해 테스트를 분류할 수 있습니다.

```csharp
[Trait("Category", "Integration")]
[Trait("Priority", "High")]
public class IntegrationTests
{
    [Fact]
    public void DatabaseIntegrationTest() { }
}
```

실행 시 필터를 적용합니다.

```bash
dotnet test --filter "Category=Integration"
```

### 테스트 건너뛰기

`Skip` 속성을 사용하거나 조건부로 건너뛸 수 있습니다.

```csharp
[Fact(Skip = "임시로 건너뜀")]
public void SkippedTest() { }

[Fact]
public void WindowsOnlyTest()
{
    if (!OperatingSystem.IsWindows())
    {
        throw new SkipException("Windows에서만 실행됩니다");
    }
}
```

### 병렬 실행 제어

`xunit.runner.json` 파일을 추가하여 병렬 실행 설정을 변경할 수 있습니다.

```json
{
  "parallelizeTestCollections": true,
  "maxParallelThreads": 4
}
```

특정 컬렉션을 순차 실행하려면 `[Collection]`을 사용합니다.

```csharp
[Collection("NonParallelTests")]
public class SequentialTests { }
```

## 상태 검증과 행위 검증

- **상태 검증**: 메서드 실행 후 반환값이나 객체의 상태를 확인합니다. 테스트가 구현 세부 사항에 덜 의존하므로 권장됩니다.
- **행위 검증**: 특정 메서드가 호출되었는지 확인합니다. 외부 시스템과의 상호작용을 검증해야 할 때만 사용합니다.

```csharp
// 상태 검증 (권장)
[Fact]
public void AddItem_UpdatesTotalPrice()
{
    var cart = new ShoppingCart();
    cart.AddItem(new Item(100));
    Assert.Equal(100, cart.TotalPrice);
}

// 행위 검증 (필요한 경우)
[Fact]
public void Save_CallsRepository_WhenDataIsValid()
{
    var repoMock = new Mock<IRepository>();
    var service = new UserService(repoMock.Object);
    service.SaveUser(new User());
    repoMock.Verify(r => r.Insert(It.IsAny<User>()), Times.Once);
}
```

## 마무리

유닛 테스트는 단순한 검증 도구를 넘어 코드 설계를 개선하고 유지보수성을 높이는 핵심 수단입니다. xUnit을 활용할 때는 다음 원칙을 기억하면 좋습니다.

- **테스트는 독립적이어야 한다**: 한 테스트의 결과가 다른 테스트에 영향을 주지 않도록 설계합니다.
- **의미 있는 이름을 사용한다**: `메서드명_조건_기대결과` 형식으로 의도를 명확히 합니다.
- **Arrange-Act-Assert를 지킨다**: 테스트의 흐름을 일관되게 유지합니다.
- **의존성을 추상화하고 Mock으로 대체한다**: 외부 요소로부터 테스트 대상을 격리합니다.
- **상태 검증을 우선한다**: 행위 검증은 꼭 필요한 경우에만 사용합니다.

xUnit의 다양한 기능(Theory, Fixture, Async 지원 등)을 익히고, CI/CD 파이프라인에 통합하여 지속적으로 테스트를 실행하는 습관을 들이면 더욱 견고한 애플리케이션을 개발할 수 있습니다.
