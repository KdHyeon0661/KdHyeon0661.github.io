# C# 타입 추론과 메타프로그래밍

C#은 강력한 정적 타입 시스템을 기반으로 하면서도, 필요에 따라 동적 타입 처리와 메타프로그래밍을 지원하는 다재다능한 언어입니다. 이는 개발자가 정적 타입의 안전성과 동적 타입의 유연성 사이에서 최적의 균형점을 찾을 수 있게 해줍니다.

---

## 정적 타입과 타입 추론

C#의 기본은 정적 타입입니다. 변수, 매개변수, 반환값의 타입이 컴파일 타임에 결정되며, 이는 타입 안전성과 런타임 오류 감소로 이어집니다.

```csharp
// 정적 타입의 명시적 선언
string name = "Alice";
int age = 30;
List<int> numbers = new List<int>();

// 타입 추론 (var)
var inferredName = "Bob";        // string으로 추론
var inferredAge = 25;            // int로 추론
var inferredList = new List<int>(); // List<int>로 추론
```

`var`는 컴파일러가 오른쪽 표현식에서 타입을 추론하도록 지시합니다. 결과물은 정적 타입이므로 런타임 성능에 영향을 주지 않으며, 단지 코드를 더 간결하게 만들어 줍니다.

### var 사용의 적절한 경우

`var`는 타입이 오른쪽에서 명확히 드러날 때 사용하는 것이 좋습니다. 특히 생성자 호출이나 캐스트, LINQ 결과 등에서 유용합니다.

```csharp
// 좋은 예: 생성자 호출로 타입이 명확
var user = new User("Alice", 30);
var product = new Product { Name = "Laptop", Price = 1200m };

// LINQ 결과의 익명 타입은 var가 필수
var query = from p in products
            where p.Price > 1000
            select new { p.Name, p.Price };

// 나쁜 예: 반환 타입이 모호한 메서드
var data = GetData();   // GetData()가 무엇을 반환하는지 알기 어려움
// 대신 명시적 타입 사용
List<Customer> customers = GetCustomers();
```

**핵심**: `var`는 가독성을 해치지 않는 범위에서 사용합니다. 타입이 즉시 명확하지 않다면 명시적 타입 선언이 더 좋습니다.

## dynamic: 런타임 타입의 유연성

`dynamic` 키워드는 컴파일 타임 타입 검사를 우회하고 런타임에 멤버 바인딩을 수행합니다. 주로 COM 상호 운용, 동적 언어(DLR) 통합, JSON 파싱, 리플렉션 대체 등에 사용됩니다.

```csharp
// dynamic 선언
dynamic data = "Hello";
data = 42;                    // 타입 변경 가능
data = new { Id = 1, Name = "Test" };

// 런타임에 멤버 접근
Console.WriteLine(data.Name); // 컴파일 통과, 런타임에 Name 존재하면 정상
```

### 사용 사례

```csharp
// JSON 파싱 시 유연한 접근
dynamic json = JsonConvert.DeserializeObject(@"{""user"": {""name"": ""Alice""}}");
string name = json.user.name;

// COM 객체 접근 (예: Excel)
dynamic excel = Activator.CreateInstance(Type.GetTypeFromProgID("Excel.Application"));
excel.Visible = true;
dynamic workbook = excel.Workbooks.Add();
```

### 주의점

- `dynamic` 호출은 정적 호출보다 느립니다. (약 10~100배)
- 메서드나 프로퍼티가 존재하지 않으면 런타임 예외가 발생합니다.
- IDE의 코드 완성, 리팩토링 지원이 제한적입니다.

```csharp
dynamic calc = new Calculator();
try
{
    var result = calc.Add(5, 10);
}
catch (Microsoft.CSharp.RuntimeBinder.RuntimeBinderException ex)
{
    // Add 메서드가 없으면 예외 발생
}
```

**핵심**: `dynamic`은 반드시 필요한 경우(COM, DLR, 유연한 데이터 구조)에만 제한적으로 사용하고, 가능한 정적 타입을 우선시하세요.

## 리플렉션: 런타임 타입 탐색

리플렉션은 .NET의 메타데이터를 런타임에 읽고 조작하는 기능입니다. 타입 정보 조회, 멤버 호출, 인스턴스 생성 등이 가능합니다. 플러그인 시스템, 의존성 주입, ORM, 테스트 프레임워크 등에서 핵심 역할을 합니다.

### 기본 사용

```csharp
using System.Reflection;

Type type = typeof(string);
Console.WriteLine($"타입: {type.FullName}");

// 생성자 정보
foreach (var ctor in type.GetConstructors())
    Console.WriteLine(ctor);

// 메서드 정보
foreach (var method in type.GetMethods())
    if (!method.IsSpecialName)
        Console.WriteLine($"{method.ReturnType.Name} {method.Name}");
```

### 플러그인 시스템 예시

```csharp
public interface IPlugin
{
    string Name { get; }
    void Execute();
}

public class PluginLoader
{
    public List<IPlugin> LoadPlugins(string directory)
    {
        var plugins = new List<IPlugin>();
        foreach (var dll in Directory.GetFiles(directory, "*.dll"))
        {
            var assembly = Assembly.LoadFrom(dll);
            foreach (var type in assembly.GetTypes())
            {
                if (typeof(IPlugin).IsAssignableFrom(type) && !type.IsAbstract)
                {
                    var plugin = (IPlugin)Activator.CreateInstance(type);
                    plugins.Add(plugin);
                }
            }
        }
        return plugins;
    }
}
```

### 성능 최적화

리플렉션은 느리므로 캐싱과 델리게이트 생성을 통해 성능을 개선합니다.

```csharp
public class PropertyAccessor
{
    private static readonly Dictionary<string, Func<object, object>> _getterCache = new();

    public static Func<object, object> GetGetter(PropertyInfo prop)
    {
        string key = $"{prop.DeclaringType}.{prop.Name}";
        if (!_getterCache.TryGetValue(key, out var getter))
        {
            var instance = Expression.Parameter(typeof(object), "instance");
            var cast = Expression.Convert(instance, prop.DeclaringType);
            var property = Expression.Property(cast, prop);
            var convert = Expression.Convert(property, typeof(object));
            getter = Expression.Lambda<Func<object, object>>(convert, instance).Compile();
            _getterCache[key] = getter;
        }
        return getter;
    }
}
```

**핵심**: 리플렉션은 강력하지만 비용이 큽니다. 가능하면 캐시하고, 식 트리로 델리게이트를 생성해 성능을 확보하세요.

## 어트리뷰트: 메타데이터 부여

어트리뷰트는 코드 요소에 추가 정보를 첨부하는 방법입니다. 컴파일러, 런타임, 도구들이 이 정보를 활용할 수 있습니다.

### 사용자 정의 어트리뷰트 만들기

```csharp
[AttributeUsage(AttributeTargets.Class | AttributeTargets.Property)]
public class ValidationAttribute : Attribute
{
    public bool Required { get; set; }
    public int MinLength { get; set; } = 0;
}

public class User
{
    [Validation(Required = true, MinLength = 2)]
    public string Name { get; set; }

    [Validation(Required = true)]
    public string Email { get; set; }
}
```

### 어트리뷰트 활용 검증기

```csharp
public class Validator
{
    public static List<string> Validate(object obj)
    {
        var errors = new List<string>();
        var type = obj.GetType();

        foreach (var prop in type.GetProperties())
        {
            var attr = prop.GetCustomAttribute<ValidationAttribute>();
            if (attr == null) continue;

            var value = prop.GetValue(obj) as string;
            if (attr.Required && string.IsNullOrWhiteSpace(value))
                errors.Add($"{prop.Name}은 필수입니다.");
            else if (value != null && value.Length < attr.MinLength)
                errors.Add($"{prop.Name}은 최소 {attr.MinLength}자 이상이어야 합니다.");
        }
        return errors;
    }
}
```

**핵심**: 어트리뷰트는 선언적 프로그래밍을 가능하게 합니다. 검증, 매핑, 로깅, 권한 부여 등에 적극 활용하되, 과도하게 사용하면 복잡성이 증가할 수 있습니다.

## 메타프로그래밍 도구들

### ExpandoObject: 동적 속성 추가

```csharp
dynamic obj = new ExpandoObject();
obj.Name = "Alice";
obj.Age = 30;
obj.SayHello = (Action)(() => Console.WriteLine("Hello"));

obj.SayHello();
Console.WriteLine(obj.Name);
```

### 소스 생성기 (C# 9+)

소스 생성기는 컴파일 중에 코드를 생성하여 반복적인 보일러플레이트를 자동화합니다. 예를 들어 DTO 매핑, 직렬화 코드 등을 자동 생성할 수 있습니다.

```csharp
[Generator]
public class MyGenerator : ISourceGenerator
{
    public void Execute(GeneratorExecutionContext context)
    {
        // 구문 분석 및 코드 생성
        string source = @"
namespace Generated
{
    public static class Helper
    {
        public static void Log(string msg) => Console.WriteLine(msg);
    }
}";
        context.AddSource("Helper.g.cs", source);
    }

    public void Initialize(GeneratorInitializationContext context) { }
}
```

소스 생성기는 컴파일 시간에 코드를 추가하므로 런타임 오버헤드가 없고, 기존 코드와 완전히 통합됩니다.

## 실무 선택 기준

| 상황 | 권장 방식 | 이유 |
|------|----------|------|
| 타입이 명확한 변수 선언 | `var` | 코드 간결, 정적 타입 유지 |
| 타입이 불분명한 경우 | 명시적 타입 | 가독성과 유지보수성 |
| COM, DLR, 유연한 JSON | `dynamic` | 정적 타입으로 표현 어려움 |
| 플러그인, ORM, 도구 | 리플렉션 + 캐싱 | 런타임 타입 정보 필요 |
| 선언적 검증, 메타데이터 | 어트리뷰트 | 코드와 관심사 분리 |
| 반복적 코드 생성 | 소스 생성기 | 컴파일 시간 자동화 |

## 마무리

C#의 타입 시스템은 정적에서 동적까지 스펙트럼을 아우릅니다. 기본은 정적 타입으로 안전성을 확보하고, 필요한 영역에서만 `dynamic`, 리플렉션, 어트리뷰트, 소스 생성기 등의 메타프로그래밍 기능을 활용하면 더욱 표현력 있고 유지보수하기 쉬운 코드를 작성할 수 있습니다.

- **타입 추론(`var`)**은 가독성을 해치지 않는 선에서 사용합니다.
- **`dynamic`**은 정적 타입으로 해결하기 어려운 상호 운용성에만 제한합니다.
- **리플렉션**은 성능 최적화(캐싱, 델리게이트)를 반드시 고려합니다.
- **어트리뷰트**는 선언적 설계를 돕는 강력한 도구입니다.
- **소스 생성기**는 반복 코드를 컴파일 타임에 자동화합니다.

각 도구의 특성과 적합한 사용처를 이해하고, 상황에 맞게 조화롭게 활용할 때 C#의 진정한 힘이 발휘됩니다.
