# C# 병렬 처리 고급: Concurrent Collections와 Thread-Safe 설계

멀티스레드 환경에서는 여러 스레드가 동시에 같은 데이터를 읽고 쓰면서 데이터 무결성이 깨질 위험이 있습니다. C#은 이런 문제를 해결하기 위해 스레드 안전한 컬렉션(`System.Collections.Concurrent`)과 다양한 동기화 도구를 제공합니다.

---

## 일반 컬렉션의 문제

일반적인 컬렉션(`List<T>`, `Dictionary<TKey, TValue>` 등)은 다중 스레드 환경에서 동시에 접근하면 내부 상태가 손상됩니다. 다음 예제를 보겠습니다.

```csharp
List<int> numbers = new List<int>();

Parallel.For(0, 10000, i =>
{
    numbers.Add(i); // 여러 스레드가 동시에 Add 호출 → 데이터 손실 또는 예외 발생
});

Console.WriteLine(numbers.Count); // 10000이 아닐 수 있음
```

이 코드는 다음 문제를 일으킬 수 있습니다.
- **데이터 손실**: 두 스레드가 동시에 `Add`를 호출하면 한쪽의 추가가 무시될 수 있습니다.
- **예외 발생**: 내부 배열이 확장되는 도중 다른 스레드가 접근하면 `IndexOutOfRangeException`이 발생합니다.
- **메모리 손상**: 최악의 경우 메모리가 깨져 애플리케이션이 종료됩니다.

이러한 문제의 근본 원인은 일반 컬렉션이 **스레드 안전하게 설계되지 않았기** 때문입니다. 단일 스레드 환경에서 최고 성능을 내도록 설계되었으므로, 여러 스레드에서 공유하려면 직접 동기화하거나 전용 컬렉션을 사용해야 합니다.

---

## Concurrent 컬렉션 소개

.NET은 `System.Collections.Concurrent` 네임스페이스에서 스레드 안전한 컬렉션들을 제공합니다. 이들은 내부적으로 정교한 락 또는 락-프리 알고리즘을 사용하여 동시 접근을 안전하게 처리합니다.

| 컬렉션 타입 | 설명 | 주요 용도 |
|------------|------|----------|
| `ConcurrentQueue<T>` | FIFO(선입선출) 큐 | 작업 큐, 로그 버퍼, 생산자-소비자 패턴 |
| `ConcurrentStack<T>` | LIFO(후입선출) 스택 | 작업 취소, 백트래킹 |
| `ConcurrentBag<T>` | 순서가 없는 컬렉션 | 작업 항목 수집, 높은 병렬도 |
| `ConcurrentDictionary<TKey, TValue>` | 키-값 저장소 | 공유 캐시, 카운터, 상태 저장 |
| `BlockingCollection<T>` | 제한된 크기의 컬렉션 | 생산자-소비자 패턴 (백프레셔 지원) |

---

## ConcurrentQueue<T> – 안전한 FIFO 큐

`ConcurrentQueue<T>`는 여러 스레드가 동시에 항목을 추가하고 제거할 수 있는 스레드 안전 큐입니다.

```csharp
var queue = new ConcurrentQueue<int>();

// 생산자: 여러 스레드에서 동시에 추가
Parallel.For(0, 10000, i => queue.Enqueue(i));

// 소비자: 여러 스레드에서 동시에 제거
int total = 0;
Parallel.For(0, 4, _ =>
{
    while (queue.TryDequeue(out int item))
    {
        Interlocked.Increment(ref total); // 안전하게 카운트 증가
    }
});

Console.WriteLine($"처리된 항목 수: {total}");
```

`TryDequeue`는 항목이 없을 경우 `false`를 반환하므로, 락 없이 안전하게 소비할 수 있습니다.

---

## ConcurrentDictionary<TKey, TValue> – 스레드 안전 사전

`ConcurrentDictionary`는 키-값 쌍을 동시에 안전하게 조작할 수 있는 컬렉션입니다.

```csharp
var wordCounts = new ConcurrentDictionary<string, int>();
string[] words = { "apple", "banana", "apple", "orange", "banana", "apple" };

Parallel.ForEach(words, word =>
{
    // AddOrUpdate: 키가 없으면 추가, 있으면 업데이트
    wordCounts.AddOrUpdate(word, 1, (key, oldValue) => oldValue + 1);
});

foreach (var pair in wordCounts)
{
    Console.WriteLine($"{pair.Key}: {pair.Value}");
}
```

`GetOrAdd`는 키가 없으면 값을 생성하여 추가하고, 있으면 기존 값을 반환합니다. `TryRemove`는 안전하게 항목을 제거합니다.

## BlockingCollection<T> – 생산자-소비자 패턴

`BlockingCollection<T>`는 내부적으로 `ConcurrentQueue<T>`(기본값)를 사용하며, 생산자와 소비자 간의 속도 차이를 조절할 수 있는 **백프레셔** 기능을 제공합니다.

```csharp
var buffer = new BlockingCollection<int>(boundedCapacity: 10); // 최대 10개까지 저장

// 생산자
Task.Run(() =>
{
    for (int i = 0; i < 100; i++)
    {
        buffer.Add(i);       // 큐가 가득 차면 공간이 생길 때까지 블로킹
        Console.WriteLine($"생산: {i}");
        Task.Delay(50).Wait();
    }
    buffer.CompleteAdding(); // 더 이상 추가하지 않음을 알림
});

// 소비자
Task.Run(() =>
{
    foreach (var item in buffer.GetConsumingEnumerable())
    {
        Console.WriteLine($"소비: {item}");
        Task.Delay(100).Wait();
    }
    Console.WriteLine("모든 항목 소비 완료");
});
```

`boundedCapacity`를 설정하면 생산자가 큐의 용량을 넘어서려고 할 때 대기하게 되어, 소비자가 처리할 시간을 벌 수 있습니다. `GetConsumingEnumerable`은 큐가 완료될 때까지 항목을 계속 반환합니다.

## 저수준 동기화 메커니즘

### Interlocked 클래스 – 원자적 연산

`Interlocked`는 단일 변수에 대한 원자적 연산을 제공합니다. 락 없이도 스레드 안전하게 카운터를 증가시키거나 값을 교환할 수 있습니다.

```csharp
int counter = 0;
Parallel.For(0, 10000, _ => Interlocked.Increment(ref counter));
Console.WriteLine(counter); // 항상 10000
```

`Interlocked.CompareExchange`를 사용하면 조건부로 값을 교체할 수 있습니다.

### ReaderWriterLockSlim – 읽기/쓰기 락 분리

읽기 작업이 압도적으로 많고 쓰기 작업이 드문 경우, `ReaderWriterLockSlim`을 사용하면 여러 읽기 스레드가 동시에 접근할 수 있어 성능이 향상됩니다.

```csharp
private static readonly ReaderWriterLockSlim _rwLock = new();
private static int _sharedData = 0;

// 읽기
_rwLock.EnterReadLock();
try { Console.WriteLine(_sharedData); }
finally { _rwLock.ExitReadLock(); }

// 쓰기
_rwLock.EnterWriteLock();
try { _sharedData++; }
finally { _rwLock.ExitWriteLock(); }
```

읽기 락은 여러 스레드가 동시에 획득할 수 있고, 쓰기 락은 단독으로 획득합니다.

## 불변성을 통한 스레드 안전성

객체가 생성된 후 변경되지 않는다면(불변), 여러 스레드에서 공유해도 안전합니다. C# 9부터 도입된 `record` 타입은 불변 객체를 쉽게 만들 수 있게 해줍니다.

```csharp
public record SensorReading(DateTime Timestamp, string SensorId, double Value);

// Immutable 컬렉션 사용
var readings = System.Collections.Immutable.ImmutableList<SensorReading>.Empty;
readings = readings.Add(new SensorReading(DateTime.Now, "sensor-1", 25.5));
```

불변 컬렉션은 변경할 때마다 새로운 인스턴스를 생성하므로, 원자적 참조 교체만으로 스레드 안전하게 사용할 수 있습니다.

## 성능 측정과 교착 상태 방지

### 성능 측정

동시성 코드는 직관과 다르게 동작할 수 있으므로 반드시 측정해야 합니다.

```csharp
var sw = Stopwatch.StartNew();

Parallel.For(0, 1000000, _ => { /* 작업 */ });

sw.Stop();
Console.WriteLine($"시간: {sw.ElapsedMilliseconds}ms");
```

### 교착 상태 방지

교착 상태는 두 스레드가 서로가 가진 락을 기다리며 영원히 대기하는 현상입니다. 이를 방지하려면 **락 획득 순서를 통일**하거나, `Monitor.TryEnter`를 사용해 타임아웃을 설정합니다.

```csharp
if (Monitor.TryEnter(lockObj, TimeSpan.FromSeconds(1)))
{
    try { /* 임계 구역 */ }
    finally { Monitor.Exit(lockObj); }
}
else
{
    Console.WriteLine("락 획득 실패 - 타임아웃");
}
```

## 결론: 현명한 스레드 안전 설계 원칙

1. **가장 간단한 도구 선택**  
   카운터는 `Interlocked`, 공유 캐시는 `ConcurrentDictionary`, 생산자-소비자는 `BlockingCollection`을 사용하세요.

2. **불변성 활용**  
   가능하면 불변 객체와 불변 컬렉션을 사용해 동시성 문제를 원천 차단하세요.

3. **락 범위 최소화**  
   락을 사용해야 한다면 임계 구역을 가능한 한 작게 유지하고, I/O나 긴 계산은 락 밖에서 수행하세요.

4. **백프레셔 고려**  
   생산자-소비자 패턴에서 `BlockingCollection`의 용량을 제한하여 시스템 과부하를 방지하세요.

5. **성능 측정 필수**  
   병렬 처리가 항상 빠른 것은 아닙니다. 반드시 측정하고 병목 지점을 찾으세요.

6. **교착 상태에 주의**  
   락을 여러 개 사용할 때는 항상 같은 순서로 획득하거나, 타임아웃을 두어 방어하세요.

멀티스레드 프로그래밍은 복잡하지만, 올바른 도구와 원칙을 적용하면 안전하고 확장성 있는 애플리케이션을 만들 수 있습니다. 데이터 흐름을 이해하고, 경합 지점을 식별하며, 적절한 추상화를 선택하는 능력이 성공의 핵심입니다.
