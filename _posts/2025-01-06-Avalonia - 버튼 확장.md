# Avalonia 버튼 확장 기능

버튼은 사용자 인터페이스에서 가장 기본적인 상호작용 요소입니다. Avalonia에서는 버튼을 단순히 클릭 이벤트로 처리하는 대신 **MVVM 패턴**과 **명령(Command)** 을 활용하여 비동기 작업, 다이얼로그, 페이지 전환, 검증 등을 체계적으로 구성할 수 있습니다. 이 글에서는 버튼을 중심으로 다양한 확장 기법을 실전 예제와 함께 설명합니다.

---

## 예제 디렉터리 구조

```
MyAvaloniaApp/
├── App.axaml
├── App.axaml.cs
├── Models/
│   ├── UserSettings.cs
│   └── Person.cs
├── Services/
│   ├── IDialogService.cs
│   ├── DialogService.cs
│   ├── ISettingsService.cs
│   └── SettingsService.cs
├── ViewModels/
│   ├── ViewModelBase.cs
│   ├── DashboardViewModel.cs
│   ├── SettingsViewModel.cs
│   └── ShellViewModel.cs
└── Views/
    ├── DashboardView.axaml
    ├── SettingsView.axaml
    ├── MainWindow.axaml
    └── MainWindow.axaml.cs
```

이 구조는 관심사 분리와 테스트 용이성을 고려한 전형적인 MVVM 구성입니다. `Services` 폴더에는 플랫폼 의존 기능을 추상화한 인터페이스와 구현체를 두고, `ViewModels`에서 이를 사용합니다.

## 버튼과 MVVM의 기본 – ICommand로 일관되게

버튼의 `Click` 이벤트를 직접 처리하면 뷰와 로직이 강하게 결합됩니다. 대신 **`ICommand`** 인터페이스를 통해 바인딩하면 테스트 가능성이 높아지고, 뷰는 단순히 UI만 담당하게 됩니다.

Avalonia에서는 `ReactiveUI` 또는 `CommunityToolkit.Mvvm`을 주로 사용합니다. 여기서는 `ReactiveUI`를 기준으로 설명합니다.

**ViewModelBase (ReactiveUI 버전)**

```csharp
// ViewModels/ViewModelBase.cs
using ReactiveUI;

public class ViewModelBase : ReactiveObject { }
```

**DashboardViewModel – 간단한 비동기 버튼**

```csharp
// ViewModels/DashboardViewModel.cs
using ReactiveUI;
using System.Reactive;
using System.Threading.Tasks;

public sealed class DashboardViewModel : ViewModelBase
{
    private string _status = "대기";
    public string Status
    {
        get => _status;
        set => this.RaiseAndSetIfChanged(ref _status, value);
    }

    public ReactiveCommand<Unit, Unit> LoadDataCommand { get; }

    public DashboardViewModel()
    {
        LoadDataCommand = ReactiveCommand.CreateFromTask(async () =>
        {
            Status = "로딩 중...";
            await Task.Delay(1500); // 실제 I/O 대체
            Status = "완료";
        });
    }
}
```

**DashboardView.axaml – 버튼 바인딩**

```xml
<UserControl ...>
  <StackPanel Margin="16" Spacing="8">
    <Button Content="데이터 로드" Command="{Binding LoadDataCommand}"/>
    <TextBlock Text="{Binding Status}"/>
  </StackPanel>
</UserControl>
```

`ReactiveCommand.CreateFromTask`는 비동기 작업을 자동으로 관리하며, 실행 중일 때 버튼을 비활성화하는 등의 기능을 기본 제공합니다.

## 다이얼로그 서비스 – 메시지, 확인, 입력, 파일 선택

ViewModel에서 직접 `Window`를 생성하면 테스트가 어렵고 재사용성이 떨어집니다. 따라서 **다이얼로그 서비스 인터페이스**를 정의하고, 실제 구현체는 뷰 계층(예: `MainWindow`)에서 주입합니다.

**IDialogService 인터페이스**

```csharp
// Services/IDialogService.cs
using System.Threading.Tasks;

public interface IDialogService
{
    Task ShowMessageAsync(string title, string message);
    Task<bool> ShowConfirmAsync(string title, string message); // Yes/No
    Task<string?> ShowPromptAsync(string title, string message, string? defaultText = null);

    Task<string[]?> ShowOpenFilesAsync(string title, string? initialDir = null, params string[] filters);
    Task<string?>   ShowSaveFileAsync(string title, string? suggestedName = null, params string[] filters);
}
```

**DialogService 구현 (Owner 윈도우 필요)**

```csharp
// Services/DialogService.cs
using Avalonia.Controls;
using Avalonia.Platform.Storage;
using System.Linq;
using System.Threading.Tasks;

public sealed class DialogService : IDialogService
{
    private readonly Window _owner;

    public DialogService(Window owner) => _owner = owner;

    public async Task ShowMessageAsync(string title, string message)
    {
        var w = new Window
        {
            Title = title,
            Width = 360,
            Height = 180,
            Content = new TextBlock { Text = message, Margin = new Thickness(16) },
            WindowStartupLocation = WindowStartupLocation.CenterOwner
        };
        await w.ShowDialog(_owner);
    }

    public async Task<bool> ShowConfirmAsync(string title, string message)
    {
        // 간단한 확인 창 구현
        var dialog = new Window { Title = title, Width = 380, Height = 200, WindowStartupLocation = WindowStartupLocation.CenterOwner };
        var txt = new TextBlock { Text = message, Margin = new Thickness(16) };
        var btnYes = new Button { Content = "예", MinWidth = 80, Margin = new Thickness(8,0,8,0) };
        var btnNo  = new Button { Content = "아니오", MinWidth = 80, Margin = new Thickness(8,0,8,0) };
        var panel = new StackPanel { Margin = new Thickness(12) };
        panel.Children.Add(txt);
        panel.Children.Add(new StackPanel
        {
            Orientation = Orientation.Horizontal,
            HorizontalAlignment = Avalonia.Layout.HorizontalAlignment.Right,
            Spacing = 8,
            Children = { btnYes, btnNo }
        });
        dialog.Content = panel;

        var tcs = new TaskCompletionSource<bool>();
        btnYes.Click += (_, __) => { tcs.TrySetResult(true);  dialog.Close(); };
        btnNo.Click  += (_, __) => { tcs.TrySetResult(false); dialog.Close(); };
        await dialog.ShowDialog(_owner);
        return await tcs.Task;
    }

    // ShowPromptAsync, ShowOpenFilesAsync, ShowSaveFileAsync 구현 생략 (원문 참조)
}
```

> 실제 애플리케이션에서는 `MessageBox.Avalonia` 같은 라이브러리를 사용해도 좋지만, 순수 Avalonia로도 충분히 구현 가능합니다.

**서비스 주입 (App.axaml.cs)**

```csharp
// App.axaml.cs
public partial class App : Application
{
    public static ServiceProvider Services { get; private set; } = default!;

    public override void OnFrameworkInitializationCompleted()
    {
        var sc = new ServiceCollection();
        sc.AddTransient<DashboardViewModel>();
        sc.AddTransient<SettingsViewModel>();
        sc.AddSingleton<ShellViewModel>();

        Services = sc.BuildServiceProvider();

        if (ApplicationLifetime is IClassicDesktopStyleApplicationLifetime desktop)
        {
            var win = new Views.MainWindow();
            // DialogService는 Owner 윈도우를 인자로 받음
            var dialogService = new DialogService(win);
            win.DataContext = new ShellViewModel(
                dialogService,
                Services.GetRequiredService<DashboardViewModel>(),
                Services.GetRequiredService<SettingsViewModel>()
            );
            desktop.MainWindow = win;
        }
        base.OnFrameworkInitializationCompleted();
    }
}
```

## 로딩 애니메이션 – IsExecuting과 취소 토큰

비동기 명령의 실행 상태를 `IsExecuting` 속성으로 추적하여 로딩 표시를 할 수 있습니다. 또한 `CancellationTokenSource`를 이용해 사용자가 작업을 취소할 수 있도록 합니다.

**SettingsViewModel – 로딩 + 취소**

```csharp
public sealed class SettingsViewModel : ViewModelBase
{
    private CancellationTokenSource? _cts;
    private string _status = "대기";
    public string Status
    {
        get => _status;
        set => this.RaiseAndSetIfChanged(ref _status, value);
    }

    public ReactiveCommand<Unit, Unit> LoadCommand { get; }
    public ReactiveCommand<Unit, Unit> CancelCommand { get; }

    private readonly ObservableAsPropertyHelper<bool> _isBusy;
    public bool IsBusy => _isBusy.Value;

    public SettingsViewModel()
    {
        LoadCommand = ReactiveCommand.CreateFromTask(async () =>
        {
            _cts?.Cancel();
            _cts = new CancellationTokenSource();
            Status = "로딩 중...";
            await Task.Delay(2000, _cts.Token);
            Status = "완료";
        });

        CancelCommand = ReactiveCommand.Create(() => _cts?.Cancel());

        _isBusy = LoadCommand.IsExecuting
            .ToProperty(this, vm => vm.IsBusy, scheduler: RxApp.MainThreadScheduler);
    }
}
```

**View – 프로그레스바와 취소 버튼**

```xml
<StackPanel Spacing="8">
  <Button Content="불러오기" Command="{Binding LoadCommand}"/>
  <Button Content="취소" Command="{Binding CancelCommand}" IsEnabled="{Binding IsBusy}"/>
  <ProgressBar IsVisible="{Binding IsBusy}" IsIndeterminate="True" Height="6"/>
  <TextBlock Text="{Binding Status}"/>
</StackPanel>
```

## 페이지 전환 – ContentControl + DataTemplate

버튼을 이용해 여러 화면(뷰)을 전환하는 것은 `ContentControl`과 `DataTemplate`을 조합하면 간단합니다.

**ShellViewModel – 현재 뷰 관리**

```csharp
public sealed class ShellViewModel : ViewModelBase
{
    public ViewModelBase Current { get => _current; set => this.RaiseAndSetIfChanged(ref _current, value); }
    private ViewModelBase _current;

    public DashboardViewModel Dashboard { get; }
    public SettingsViewModel  Settings  { get; }

    public ReactiveCommand<Unit, Unit> GoDashboardCommand { get; }
    public ReactiveCommand<Unit, Unit> GoSettingsCommand  { get; }

    public ShellViewModel(IDialogService dialogs, DashboardViewModel dashboard, SettingsViewModel settings)
    {
        Dashboard = dashboard;
        Settings  = settings;
        Current = Dashboard;

        GoDashboardCommand = ReactiveCommand.Create(() => Current = Dashboard);
        GoSettingsCommand  = ReactiveCommand.Create(() => Current = Settings);
    }
}
```

**MainWindow.axaml – 버튼과 콘텐츠 영역**

```xml
<Window ...>
  <Grid RowDefinitions="Auto,*">
    <StackPanel Grid.Row="0" Orientation="Horizontal" Spacing="8" Margin="8">
      <Button Content="대시보드" Command="{Binding GoDashboardCommand}"/>
      <Button Content="설정"    Command="{Binding GoSettingsCommand}"/>
    </StackPanel>

    <Border Grid.Row="1" Margin="12" Padding="12">
      <ContentControl Content="{Binding Current}"/>
    </Border>
  </Grid>
</Window>
```

**App.axaml – 뷰-뷰모델 매핑**

```xml
<Application ...>
  <Application.DataTemplates>
    <DataTemplate DataType="{x:Type vm:DashboardViewModel}">
      <views:DashboardView/>
    </DataTemplate>
    <DataTemplate DataType="{x:Type vm:SettingsViewModel}">
      <views:SettingsView/>
    </DataTemplate>
  </Application.DataTemplates>
</Application>
```

이제 버튼 클릭 시 `Current` 속성이 바뀌면 `ContentControl`이 자동으로 적절한 뷰를 렌더링합니다.

## 설정 저장과 검증 – IValidatableObject

사용자 설정을 저장하고 불러올 때는 데이터 검증이 필요합니다. `IValidatableObject`를 이용해 뷰모델에서 검증 로직을 구현합니다.

**UserSettings 모델**

```csharp
// Models/UserSettings.cs
public class UserSettings
{
    public string UserName { get; set; } = "";
    public int Age { get; set; }
}
```

**ISettingsService 인터페이스**

```csharp
// Services/ISettingsService.cs
public interface ISettingsService
{
    Task SaveAsync(UserSettings settings);
    Task<UserSettings?> LoadAsync();
}
```

**SettingsService 구현 (JSON 파일 저장)**

```csharp
// Services/SettingsService.cs
using System.IO;
using System.Text.Json;
using System.Threading.Tasks;

public sealed class SettingsService : ISettingsService
{
    private const string FilePath = "user-settings.json";

    public async Task SaveAsync(UserSettings settings)
    {
        var json = JsonSerializer.Serialize(settings, new JsonSerializerOptions { WriteIndented = true });
        await File.WriteAllTextAsync(FilePath, json);
    }

    public async Task<UserSettings?> LoadAsync()
    {
        if (!File.Exists(FilePath)) return null;
        var json = await File.ReadAllTextAsync(FilePath);
        return JsonSerializer.Deserialize<UserSettings>(json);
    }
}
```

**SettingsViewModel – IValidatableObject 구현**

```csharp
using ReactiveUI;
using System.ComponentModel.DataAnnotations;
using System.Collections.Generic;
using System.Linq;
using System.Reactive;
using System.Threading.Tasks;

public sealed class SettingsViewModel : ViewModelBase, IValidatableObject
{
    private readonly ISettingsService _settings;

    public SettingsViewModel(ISettingsService settings)
    {
        _settings = settings;

        SaveCommand = ReactiveCommand.CreateFromTask(SaveAsync);
        LoadCommand = ReactiveCommand.CreateFromTask(LoadAsync);
    }

    public string UserName { get => _userName; set => this.RaiseAndSetIfChanged(ref _userName, value); }
    private string _userName = "";

    public int Age { get => _age; set => this.RaiseAndSetIfChanged(ref _age, value); }
    private int _age;

    public string Result { get => _result; private set => this.RaiseAndSetIfChanged(ref _result, value); }
    private string _result = "";

    public ReactiveCommand<Unit, Unit> SaveCommand { get; }
    public ReactiveCommand<Unit, Unit> LoadCommand { get; }

    private async Task SaveAsync()
    {
        var errors = ValidateAll();
        if (errors.Any())
        {
            Result = string.Join("\n", errors);
            return;
        }

        await _settings.SaveAsync(new UserSettings { UserName = UserName, Age = Age });
        Result = "저장 완료";
    }

    private async Task LoadAsync()
    {
        var loaded = await _settings.LoadAsync();
        if (loaded is null)
        {
            Result = "저장된 설정이 없습니다";
            return;
        }

        UserName = loaded.UserName;
        Age = loaded.Age;
        Result = "설정 불러오기 완료";
    }

    private IEnumerable<string> ValidateAll()
    {
        var results = new List<ValidationResult>();
        var ctx = new ValidationContext(this, null, null);
        Validator.TryValidateObject(this, ctx, results, true);
        return results.Select(r => r.ErrorMessage ?? "유효성 오류");
    }

    public IEnumerable<ValidationResult> Validate(ValidationContext validationContext)
    {
        if (string.IsNullOrWhiteSpace(UserName))
            yield return new ValidationResult("이름은 비어 있을 수 없습니다.", new[] { nameof(UserName) });
        if (Age <= 0)
            yield return new ValidationResult("나이는 0보다 커야 합니다.", new[] { nameof(Age) });
    }
}
```

**SettingsView.axaml**

```xml
<UserControl ...>
  <StackPanel Margin="16" Spacing="8">
    <TextBlock Text="사용자 설정" FontSize="18"/>
    <TextBox Watermark="이름" Text="{Binding UserName, Mode=TwoWay}"/>
    <TextBox Watermark="나이"  Text="{Binding Age, Mode=TwoWay}"/>
    <StackPanel Orientation="Horizontal" Spacing="8">
      <Button Content="저장" Command="{Binding SaveCommand}"/>
      <Button Content="불러오기" Command="{Binding LoadCommand}"/>
    </StackPanel>
    <TextBlock Text="{Binding Result}" TextWrapping="Wrap"/>
  </StackPanel>
</UserControl>
```

## 파일 다이얼로그와 결합된 버튼 동작

대시보드에서 파일을 선택하고 확인 후 처리하는 예제입니다.

```csharp
public sealed class DashboardViewModel : ViewModelBase
{
    private readonly IDialogService _dialogs;

    public ReactiveCommand<Unit, Unit> ImportCommand { get; }

    public DashboardViewModel(IDialogService dialogs)
    {
        _dialogs = dialogs;

        ImportCommand = ReactiveCommand.CreateFromTask(async () =>
        {
            var files = await _dialogs.ShowOpenFilesAsync("불러올 파일 선택", null, ".json", ".csv");
            if (files is null || files.Length == 0)
            {
                await _dialogs.ShowMessageAsync("결과", "선택된 파일이 없습니다");
                return;
            }

            var ok = await _dialogs.ShowConfirmAsync("확인", $"{files.Length}개 파일을 불러올까요?");
            if (!ok) return;

            // 실제 파일 처리 로직
            await _dialogs.ShowMessageAsync("결과", "불러오기 완료");
        });
    }
}
```

```xml
<Button Content="파일 불러오기" Command="{Binding ImportCommand}"/>
```

## CommunityToolkit.Mvvm 대안

`ReactiveUI` 대신 `CommunityToolkit.Mvvm`을 사용할 수도 있습니다. 이 경우 코드가 더 간결해집니다.

**SettingsViewModel (CommunityToolkit.Mvvm 버전)**

```csharp
using CommunityToolkit.Mvvm.ComponentModel;
using CommunityToolkit.Mvvm.Input;
using System.ComponentModel.DataAnnotations;
using System.Collections.Generic;
using System.Linq;

public partial class SettingsViewModel : ObservableValidator
{
    [ObservableProperty]
    [Required(ErrorMessage = "이름은 비어 있을 수 없습니다.")]
    private string userName = "";

    [ObservableProperty]
    [Range(1, int.MaxValue, ErrorMessage = "나이는 0보다 커야 합니다.")]
    private int age;

    [ObservableProperty]
    private string result = "";

    [RelayCommand]
    private void Save()
    {
        ValidateAllProperties();
        if (HasErrors)
        {
            Result = string.Join("\n", GetErrors().Select(e => e.ErrorMessage));
            return;
        }
        Result = "저장 완료";
    }
}
```

바인딩 방식은 동일하며, `ObservableValidator`는 `INotifyDataErrorInfo`를 자동으로 구현하여 오류 UI를 쉽게 표시할 수 있습니다.

## 자주 겪는 문제와 해결

- **Owner 없는 `ShowDialog`**: 포커스나 모달 동작이 불안정할 수 있습니다. 반드시 소유자 윈도우를 지정하여 `ShowDialog(owner)`를 호출하세요.
- **UI 스레드 차단**: 비동기 작업에는 `await`를 사용하고, `ObservableCollection` 변경은 UI 스레드에서 수행해야 합니다.
- **Command CanExecute**: ReactiveUI에서는 `canExecute` 관찰 가능 스트림을, Toolkit에서는 `[RelayCommand(CanExecute = nameof(CanSave))]`와 같은 방식으로 제어합니다.
- **디자인 타임 오류**: XAML 네임스페이스(`using:`)와 형식 전체 이름을 확인하고, `Design.DataContext`를 설정해 미리보기를 안정화합니다.
- **파일 다이얼로그 권한**: 플랫폼별로 저장소 제공자 특성이 다르므로 경로 처리에 유의합니다.

## 전체 흐름 요약

| 기능                     | 핵심 기술                                           | 패턴/구성 요소                     |
|--------------------------|-----------------------------------------------------|------------------------------------|
| 비동기 버튼              | `ReactiveCommand.CreateFromTask` / `ICommand`       | `IsExecuting` 바인딩               |
| 다이얼로그(메시지, 확인) | `IDialogService` + `Window.ShowDialog`              | 서비스 추상화, Owner 전달          |
| 파일 열기/저장           | `StorageProvider.OpenFilePickerAsync` / `SaveFilePickerAsync` | `IDialogService` 확장             |
| 로딩 애니메이션          | `ProgressBar IsIndeterminate` + `IsExecuting`       | `IsBusy` 속성 연동                 |
| 취소                     | `CancellationTokenSource` + 취소 버튼               | `CancelCommand` 실행               |
| 페이지 전환              | `ContentControl` + `DataTemplate`                   | `Current` 뷰모델 교체              |
| 검증                     | `IValidatableObject` / `ObservableValidator`        | `ValidateAllProperties()` 호출     |
| 설정 저장                | `JsonSerializer` + 파일 I/O                         | `ISettingsService` 인터페이스      |

버튼은 단순한 클릭 이상의 다양한 기능과 결합되어 애플리케이션의 핵심 상호작용을 이끕니다. 이 글에서는 버튼을 통해 **비동기 작업**, **다이얼로그 서비스**, **로딩 표시**, **취소**, **페이지 전환**, **검증**, **설정 저장**까지 실제 개발에 필요한 패턴을 정리했습니다. 이러한 구조는 테스트 가능성과 유지보수성을 높여주며, Avalonia의 MVVM 패턴과 자연스럽게 어우러집니다.

이제 여러분은 버튼을 중심으로 다양한 확장 기능을 손쉽게 구현할 수 있을 것입니다. 다음 단계로는 **진행률 보고**, **네비게이션 서비스 일반화**, **다국어 지원** 등을 적용해 더 견고한 애플리케이션을 만들어 보세요.
