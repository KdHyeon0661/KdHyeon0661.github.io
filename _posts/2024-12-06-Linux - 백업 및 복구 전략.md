# 백업 및 복구 전략

## 백업의 핵심 원칙

백업은 데이터를 안전하게 보관하고, 필요할 때 **복구할 수 있어야** 의미가 있다. 이 글에서는 실무에서 가장 많이 사용하는 `tar`, `rsync`, `dump/restore`를 중심으로 백업 스크립트 작성, 백업 검증, 원격 저장소 전송, 복구 테스트 개념을 다룬다.

---

## 1. tar 기반 백업

### 전체 백업과 증분 백업

`tar`는 전체 아카이브와 함께 `--listed-incremental` 옵션으로 증분 백업을 지원한다.

```bash
# 전체 백업 (레벨 0) – 스냅샷 파일 생성
sudo tar --listed-incremental=/backup/var.snar -czf /backup/var_full_$(date +%F).tar.gz /var

# 이후 증분 백업 (스냅샷 파일 갱신)
sudo tar --listed-incremental=/backup/var.snar -czf /backup/var_incr_$(date +%F).tar.gz /var
```

복원 시 전체 백업 → 증분 백업 순서로 풀어야 한다.

### 백업 검증 (tar 아카이브 무결성 확인)

```bash
# 아카이브 내용 나열 (손상 여부 확인)
tar -tzf /backup/var_full_2025-01-01.tar.gz > /dev/null && echo "OK" || echo "FAILED"

# 아카이브 내 파일 목록 출력
tar -tzf /backup/var_full_2025-01-01.tar.gz | head -20
```

### 원격 저장소 전송 (scp)

```bash
# 로컬 백업 파일을 원격 서버로 전송
scp /backup/var_full_*.tar.gz user@backup-server:/backup/
```

## 2. rsync 기반 백업

### 로컬 동기화 및 스냅샷

`rsync`는 변경된 파일만 효율적으로 복사하며, `--link-dest` 옵션으로 하드링크 기반 스냅샷을 생성할 수 있다.

```bash
# 기본 동기화 (소스 끝의 / 주의)
rsync -av --delete /home/ /backup/home/

# 하드링크 스냅샷 (공간 절약)
rsync -a --delete --link-dest=/backup/home/2025-01-01 /home/ /backup/home/2025-01-02
```

### 백업 검증 (rsync)

`rsync`는 자체적으로 전송 무결성을 검증하지만, 복사 후 파일 목록을 비교하거나 `--checksum` 옵션을 사용할 수 있다.

```bash
# 드라이런(dry-run)으로 차이 확인
rsync -avnc --delete /home/ /backup/home/ | grep -v '^\.'

# 전체 파일 체크섬 비교 (느림)
rsync -avc --delete /home/ /backup/home/
```

### 원격 저장소 전송 (rsync over SSH)

```bash
# 원격 서버로 동기화
rsync -avz -e ssh /backup/ user@backup-server:/backup/
```

## 3. dump/restore 기반 백업

`dump`는 ext2/3/4 파일시스템의 블록 레벨 백업을 수행하며, 증분 백업이 매우 효율적이다.

### 전체 및 증분 백업

```bash
# 전체 백업 (레벨 0)
sudo dump -0u -f - /dev/sda1 | gzip -c > /backup/root_0_$(date +%F).dump.gz

# 증분 백업 (레벨 1, 레벨 0 이후 변경 블록)
sudo dump -1u -f - /dev/sda1 | gzip -c > /backup/root_1_$(date +%F).dump.gz
```
- `-u` : `/etc/dumpdates`에 백업 기록 저장 (증분 관리)
- `-f -` : 표준 출력으로 전송 (파이프용)

### 백업 검증 (dump 파일)

```bash
# dump 파일 내용 확인 (헤더 정보 출력)
zcat /backup/root_0_2025-01-01.dump.gz | restore -t -f - | head
```

### 원격 저장소 전송

`dump` 결과를 파이프로 직접 원격 서버에 저장할 수 있다.

```bash
sudo dump -0u -f - /dev/sda1 | ssh user@backup-server "cat > /backup/root_0_$(date +%F).dump"
```

## 4. 백업 검증의 다양한 방법

| 방법 | 설명 | 명령어 예시 |
|------|------|------------|
| 목록 조회 | 아카이브 내용이 정상적으로 읽히는지 확인 | `tar -tzf backup.tar.gz > /dev/null` |
| 체크섬 | 파일별 해시를 저장하고 나중에 검증 | `sha256sum backup.tar.gz > backup.sha256`<br>`sha256sum -c backup.sha256` |
| 비교 | 원본과 백업을 비교 (복구 테스트와 유사) | `diff -r /home /mnt/restore` |
| 복구 테스트 | 실제로 다른 위치에 풀어서 검증 | `tar -xzf backup.tar.gz -C /tmp/test` |

### 체크섬 파일 생성 및 검증 스크립트 예시

```bash
# 백업 완료 후 체크섬 생성
sha256sum /backup/*.tar.gz > /backup/checksums.sha256

# 나중에 검증
sha256sum -c /backup/checksums.sha256
```

## 5. 원격 저장소 전송 전략

### scp (단순 파일 전송)

```bash
scp /backup/var_full_2025-01-01.tar.gz user@remote:/backup/
```

### rsync (증분 전송, 재시도, 대역폭 제한)

```bash
# 원격으로 동기화 (--partial로 중단 시 이어받기 가능)
rsync -avP --partial /backup/ user@remote:/backup/

# 대역폭 제한 (예: 10MB/s)
rsync -av --bwlimit=10240 /backup/ user@remote:/backup/
```

### rclone (클라우드 저장소)

```bash
# S3, Google Drive, Dropbox 등 지원
rclone sync /backup/ remote:bucket/backup/
```

## 6. 복구 테스트 개념

복구 테스트는 백업이 실제로 복원 가능한지 확인하는 유일한 방법이다. 정기적인 테스트를 통해 백업의 신뢰성을 확보한다.

### 복구 테스트 원칙

- **격리된 환경에서 테스트**: 실제 운영 환경에 영향을 주지 않도록 별도 디렉터리나 가상 머신에서 진행
- **전체 복구와 부분 복구 모두 테스트**
- **자동화된 테스트 스크립트 작성**

### 간단한 복구 테스트 예시 (tar)

```bash
#!/bin/bash
# 복구 테스트 스크립트 (tar)

BACKUP_FILE="/backup/home_2025-01-01.tar.gz"
TEST_DIR="/tmp/restore_test_$$"

mkdir -p "$TEST_DIR"
tar -xzf "$BACKUP_FILE" -C "$TEST_DIR"
diff -r /home "$TEST_DIR" > /tmp/diff_result
if [ $? -eq 0 ]; then
    echo "복구 테스트 성공: 원본과 일치"
else
    echo "복구 테스트 실패: 차이 발생"
    cat /tmp/diff_result
fi
rm -rf "$TEST_DIR"
```

### rsync 복구 테스트

```bash
# 빈 디렉터리에 동기화하여 원본과 비교
mkdir /tmp/restore_test
rsync -av /backup/home/ /tmp/restore_test/
diff -r /home /tmp/restore_test
```

### dump/restore 복구 테스트

```bash
# 빈 디렉터리에 복원
mkdir /tmp/restore_test
cd /tmp/restore_test
zcat /backup/root_0_2025-01-01.dump.gz | sudo restore -rf -
```

## 7. 통합 백업 스크립트 예시 (rsync + 검증 + 원격 전송)

```bash
#!/bin/bash
# /usr/local/bin/backup_strategy.sh

set -euo pipefail

# 설정
SOURCE="/home"
BACKUP_DIR="/backup/home"
REMOTE_USER="backupuser"
REMOTE_HOST="backup-server"
REMOTE_PATH="/backup/home"
DATE=$(date +%F)

# 1. 로컬 rsync 스냅샷
LATEST="$BACKUP_DIR/latest"
NEW="$BACKUP_DIR/$DATE"
rsync -a --delete --link-dest="$LATEST" "$SOURCE/" "$NEW/"
rm -f "$LATEST"
ln -s "$NEW" "$LATEST"

# 2. 체크섬 생성
find "$NEW" -type f -exec sha256sum {} \; > "$NEW/checksums.sha256"

# 3. 원격 동기화 (rsync)
rsync -av --delete "$BACKUP_DIR/" "$REMOTE_USER@$REMOTE_HOST:$REMOTE_PATH/"

# 4. 원격 체크섬 검증 (간단)
ssh "$REMOTE_USER@$REMOTE_HOST" "cd $REMOTE_PATH/$DATE && sha256sum -c checksums.sha256"

echo "백업 완료: $DATE"
```

## 8. 핵심 명령어 요약

| 도구 | 용도 | 검증 명령 | 원격 전송 명령 |
|------|------|-----------|---------------|
| `tar` | 아카이브 | `tar -tzf file.tar.gz > /dev/null` | `scp file user@host:path` |
| `rsync` | 동기화 | `rsync -avnc --delete src/ dst/` | `rsync -av src/ user@host:path` |
| `dump` | 파일시스템 | `zcat file.dump.gz \| restore -t -f -` | `dump ... \| ssh user@host "cat > file.dump"` |
| `sha256sum` | 무결성 | `sha256sum -c checksums.sha256` | 함께 전송 |

## 결론

성공적인 백업 전략은 **도구의 특성 이해 → 자동화 스크립트 작성 → 검증 → 원격 보관 → 정기 복구 테스트**로 이어지는 체계적인 흐름을 갖춰야 한다.

- **tar**: 간단한 파일 백업과 증분 백업에 적합
- **rsync**: 효율적인 동기화와 하드링크 스냅샷으로 공간 효율성 극대화
- **dump/restore**: 파일시스템 레벨의 정확한 증분 백업으로 시스템 전체 복구에 강점

가장 중요한 것은 **백업을 만든 후 반드시 검증**하고, **정기적으로 복구 테스트**를 수행하는 습관이다. 이러한 절차를 자동화하고 모니터링하면 데이터 손실 위험을 최소화할 수 있다.
