# 네트워크 스토리지 (NAS) 연동

네트워크 스토리지는 여러 서버가 물리적 디스크를 공유하지 않고도 중앙 집중식 저장소를 사용할 수 있게 해준다.  
초중급 수준에서는 **NFS**와 **iSCSI**를 중심으로 설정과 마운트 방법을 익히는 것이 목표다.  
추가로 CIFS(SMB), GlusterFS, Ceph 등도 있지만, 이 글에서는 가장 널리 사용되는 두 기술을 다룬다.

---

## NFS (Network File System)

NFS는 리눅스 간 파일 공유에 가장 널리 사용되는 프로토콜이다.  
파일 시스템 수준에서 원격 디렉터리를 마운트하여 로컬처럼 사용할 수 있다.

### NFS 서버 설정

```bash
sudo apt install nfs-kernel-server   # Debian/Ubuntu
sudo dnf install nfs-utils           # RHEL/Fedora
```

**공유 디렉터리 생성 및 권한 설정**
```bash
sudo mkdir -p /srv/nfs/share
sudo chown nobody:nogroup /srv/nfs/share   # 기본 익명 사용자
sudo chmod 755 /srv/nfs/share
```

**exports 파일 설정** (`/etc/exports`)
```conf
/srv/nfs/share 192.168.1.0/24(rw,sync,no_subtree_check)
```

- `rw` : 읽기-쓰기 허용
- `sync` : 동기 쓰기 (안정성)
- `no_subtree_check` : 하위 트리 검사 비활성화 (성능)
- `root_squash` (기본) : root 권한을 nobody로 매핑

**exports 적용 및 서비스 시작**
```bash
sudo exportfs -ra
sudo systemctl enable --now nfs-server
```

### NFS 클라이언트 마운트

```bash
# 패키지 설치 (클라이언트)
sudo apt install nfs-common          # Debian/Ubuntu
sudo dnf install nfs-utils           # RHEL/Fedora

# 임시 마운트
sudo mount -t nfs -o vers=4.2 192.168.1.10:/srv/nfs/share /mnt/nfs

# 자동 마운트 (fstab)
echo "192.168.1.10:/srv/nfs/share /mnt/nfs nfs defaults,_netdev,vers=4.2 0 0" | sudo tee -a /etc/fstab
sudo mount -a
```

**주요 마운트 옵션**
- `vers=4.2` : NFSv4.2 (보안, 성능)
- `_netdev` : 네트워크 준비 후 마운트 (부팅 지연 방지)
- `rsize=1048576,wsize=1048576` : 읽기/쓰기 버퍼 크기 (고성능 네트워크)
- `hard` vs `soft` : 서버 응답 없을 때 무한 재시도(`hard`) 또는 타임아웃 오류(`soft`)

### NFS 문제 해결

| 증상 | 확인 방법 |
|------|----------|
| 마운트 실패 | `showmount -e 서버IP`로 export 목록 확인 |
| 권한 거부 | `/etc/exports` 옵션, 서버 측 `root_squash` 확인 |
| 느린 속도 | `nfsstat`로 통계 확인, MTU/네트워크 점검 |

## iSCSI (Internet SCSI)

iSCSI는 SCSI 명령을 TCP/IP 네트워크로 전송하여 블록 수준의 스토리지를 제공한다.  
서버(이니시에이터)가 원격의 디스크(타겟)를 로컬 SCSI 디스크처럼 사용할 수 있다.

### iSCSI 타겟 (서버) 설정

```bash
sudo apt install tgt            # Debian/Ubuntu
sudo dnf install scsi-target-utils  # RHEL/Fedora
```

**설정 파일** (`/etc/tgt/targets.conf`)
```conf
<target iqn.2025-03.com.example:storage.lun1>
    backing-store /dev/sdb                # 실제 디스크 또는 파일
    initiator-address 192.168.1.0/24      # 접근 허용 네트워크
    incominguser username password        # CHAP 인증 (선택)
</target>
```
- `iqn` : iSCSI Qualified Name (전 세계 고유 식별자)
- `backing-store` : 블록 장치 또는 파일(예: `/var/lib/iscsi/disk.img`)

**서비스 시작**
```bash
sudo systemctl enable --now tgt
sudo tgt-admin --dump   # 설정 확인
```

### iSCSI 이니시에이터 (클라이언트) 설정

```bash
sudo apt install open-iscsi    # Debian/Ubuntu
sudo dnf install iscsi-initiator-utils  # RHEL/Fedora
```

**이니시에이터 이름 설정** (`/etc/iscsi/initiatorname.iscsi`)
```
InitiatorName=iqn.2025-03.com.example:client
```

**타겟 검색 및 로그인**
```bash
sudo iscsiadm -m discovery -t sendtargets -p 192.168.1.10
sudo iscsiadm -m node -T iqn.2025-03.com.example:storage.lun1 -p 192.168.1.10 -l
```

**마운트 준비**
```bash
# 로그인 후 새로운 블록 장치 확인 (예: /dev/sdc)
lsblk
sudo mkfs.ext4 /dev/sdc
sudo mount /dev/sdc /mnt/iscsi
```

**자동 로그인** (`/etc/iscsi/nodes/` 아래 설정 자동 저장)

### iSCSI 다중 경로 (Multipath)

여러 네트워크 경로를 통해 iSCSI 디스크에 접속하면 성능과 가용성이 높아진다.

```bash
sudo apt install multipath-tools
```

**설정** (`/etc/multipath.conf`)
```conf
defaults {
    user_friendly_names yes
}
blacklist {
    devnode "^(ram|loop|fd|md|dm-|sr|scd|st)[0-9]*"
}
```

**서비스 시작**
```bash
sudo systemctl enable --now multipathd
multipath -ll   # 다중 경로 장치 확인
```

## 기타 네트워크 스토리지 프로토콜

| 프로토콜 | 용도 | 특징 |
|----------|------|------|
| **CIFS/SMB** | Windows와 공유 | `mount -t cifs`, Samba 서버 |
| **GlusterFS** | 분산 파일 시스템 | 여러 서버를 하나의 볼륨으로 묶음 |
| **Ceph** | 오브젝트/블록/파일 | 클라우드 인프라에 적합 |
| **Rclone** | 클라우드 스토리지 마운트 | `rclone mount`로 Google Drive 등 마운트 |

## 핵심 명령어 요약표

| 작업 | NFS | iSCSI |
|------|-----|-------|
| 서버 설치 | `nfs-kernel-server` | `tgt` |
| 공유 정의 | `/etc/exports` | `/etc/tgt/targets.conf` |
| 클라이언트 설치 | `nfs-common` | `open-iscsi` |
| 마운트 | `mount -t nfs` | `iscsiadm -l` 후 `mount /dev/sdX` |
| 자동 마운트 | `fstab` (`_netdev`) | `iscsiadm` 설정으로 자동 로그인 후 `fstab` |
| 상태 확인 | `showmount -e`, `exportfs -v` | `tgt-admin --show`, `iscsiadm -m session` |

## 결론

네트워크 스토리지는 물리적 디스크를 여러 서버에서 공유하거나, 중앙 관리형 저장소를 구축하는 데 필수적이다.

- **NFS**는 파일 수준 공유로 리눅스 간 협업에 간편하게 사용할 수 있다. 서버에서 디렉터리를 export하고 클라이언트에서 마운트하는 방식이다.
- **iSCSI**는 블록 수준 공유로, 원격 디스크를 로컬 SCSI 디스크처럼 취급하여 파일시스템 생성, RAID 구성 등에 활용된다. 다중 경로를 구성하면 가용성을 높일 수 있다.

초중급 수준에서는 먼저 **NFS**로 파일 공유를 경험하고, **iSCSI**로 블록 장치를 연결해 보는 것이 좋다. 네트워크 대역폭, 지연 시간, 보안(인증, 암호화)을 고려하여 적절한 프로토콜을 선택하고, 필요한 경우 `_netdev` 옵션으로 부팅 순서를 조정하는 습관을 들이자.
