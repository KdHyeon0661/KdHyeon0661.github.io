# 빌드 시스템과 소스에서 설치

## 소스 빌드의 필요성

배포판 패키지로 제공되지 않는 최신 버전이 필요하거나, 특정 컴파일 옵션을 직접 지정해야 할 때 소스 코드에서 직접 빌드하여 설치한다. 이 글에서는 전통적인 Autotools부터 현대적인 CMake까지, 실제로 자주 사용되는 빌드 방식을 중심으로 설명한다.

---

## GNU 전통 빌드 시스템: configure → make → make install

Autotools 기반 프로젝트는 일반적으로 `configure` 스크립트를 포함한다. 이 스크립트는 시스템 환경을 검사하고 `Makefile`을 생성한다.

### 빌드 환경 준비

```bash
# Debian/Ubuntu
sudo apt install -y build-essential pkg-config

# RHEL/Fedora
# sudo dnf groupinstall "Development Tools"
# sudo dnf install pkgconf-pkg-config
```

### 표준 빌드 절차

```bash
tar -xzf program-1.2.3.tar.gz
cd program-1.2.3

# 환경 검사 및 Makefile 생성
./configure --prefix=/usr/local

# 병렬 컴파일 (코어 수만큼)
make -j"$(nproc)"

# 테스트 (선택)
make check

# 시스템 설치
sudo make install
```

### 자주 사용하는 configure 옵션

| 옵션 | 설명 |
|------|------|
| `--prefix=/usr/local` | 설치 경로 지정 (기본값) |
| `--sysconfdir=/etc` | 설정 파일 위치 |
| `--enable-XXX` / `--disable-XXX` | 기능 활성화/비활성화 |
| `--with-XXX` | 외부 라이브러리 경로 지정 |

### 안전한 설치: DESTDIR로 스테이징

실제 시스템에 직접 설치하기 전에 스테이징 디렉터리에 먼저 설치해 보는 것이 안전하다.

```bash
make -j"$(nproc)"
make DESTDIR="$PWD/_staging" install
tree _staging    # 설치될 파일 확인
```

이렇게 하면 어떤 파일이 어디에 설치되는지 확인할 수 있으며, 나중에 패키지로 만들기도 용이하다.

### 소프트웨어 삭제

`uninstall` 타겟이 있는 경우:
```bash
sudo make uninstall
```

없는 경우에는 스테이징 디렉터리로 패키징하여 관리하는 것이 좋다.

## CMake와 Ninja: 현대적 빌드 시스템

CMake는 플랫폼 독립적인 빌드 시스템 생성기이며, Ninja는 빠른 빌드 실행기다.

### 표준 워크플로우

```bash
sudo apt install -y cmake ninja-build

# out-of-tree 빌드 (소스와 빌드 디렉터리 분리)
mkdir build && cd build
cmake -G Ninja -DCMAKE_BUILD_TYPE=Release -DCMAKE_INSTALL_PREFIX=/usr/local ..
ninja -j"$(nproc)"
ctest --output-on-failure   # 테스트 실행
sudo ninja install
```

### DESTDIR로 스테이징

```bash
ninja
DESTDIR="$PWD/_stage" ninja install
```

### 간단한 CMakeLists.txt 예제

```cmake
cmake_minimum_required(VERSION 3.10)
project(myapp C)
add_executable(myapp src/main.c)
install(TARGETS myapp RUNTIME DESTINATION bin)
```

## 패키징: checkinstall과 기본 패키지 생성

소스 설치를 패키지로 관리하면 나중에 제거하기 편리하다.

### checkinstall (간편 패키징)

```bash
./configure && make -j"$(nproc)"
sudo checkinstall   # .deb 또는 .rpm 생성 및 설치
```

checkinstall은 `make install` 과정을 추적하여 패키지를 자동으로 생성한다.

### 수동 DEB 패키지 생성

디렉터리 구조:
```
mypkg/
├── DEBIAN/control
└── usr/local/bin/myapp
```

`DEBIAN/control` 파일:
```
Package: myapp
Version: 1.0.0
Section: utils
Priority: optional
Architecture: amd64
Maintainer: you@example.com
Description: My application
```

패키지 빌드:
```bash
dpkg-deb --build mypkg
sudo apt install ./mypkg.deb
```

## 공유 라이브러리와 링크

### 라이브러리 설치 후 시스템 인식

```bash
# /usr/local/lib를 라이브러리 경로에 등록
echo "/usr/local/lib" | sudo tee /etc/ld.so.conf.d/local.conf
sudo ldconfig

# 실행 파일의 라이브러리 의존성 확인
ldd /usr/local/bin/myapp
```

### pkg-config 사용

라이브러리 컴파일 옵션이 필요할 때:

```bash
pkg-config --cflags --libs libssl
```

## 실전 예제

### 예제 1: htop 소스 설치 (Autotools)

```bash
tar -xzf htop-3.2.2.tar.gz
cd htop-3.2.2
./configure --prefix=/usr/local
make -j"$(nproc)"
sudo make install
```

### 예제 2: checkinstall로 패키지화

```bash
cd htop-3.2.2
./configure && make -j"$(nproc)"
sudo checkinstall   # .deb 생성 및 설치
```

### 예제 3: CMake 프로젝트를 /opt에 설치

```bash
mkdir build && cd build
cmake -G Ninja -DCMAKE_BUILD_TYPE=Release -DCMAKE_INSTALL_PREFIX=/opt/myapp ..
ninja
sudo ninja install
```

## 일반적인 문제와 해결

| 문제 | 해결 |
|------|------|
| 헤더 파일 못 찾음 | `pkg-config --cflags libname`로 플래그 확인, `PKG_CONFIG_PATH` 점검 |
| 라이브러리 못 찾음 | 라이브러리 설치 후 `sudo ldconfig` 실행 |
| `uninstall` 타겟 없음 | DESTDIR 스테이징 + 패키징 방식으로 관리 |
| 실행 시 라이브러리 없음 | `ldd`로 의존성 확인, `LD_LIBRARY_PATH` 임시 설정 (디버깅용) |

---

## 핵심 명령어 요약

| 작업 | 명령어 |
|------|--------|
| Autotools 빌드 | `./configure --prefix=/usr/local && make -j$(nproc) && sudo make install` |
| 스테이징 설치 | `make DESTDIR=_stage install` |
| CMake + Ninja | `cmake -G Ninja -B build && cmake --build build -j$(nproc)` |
| checkinstall 패키징 | `sudo checkinstall` |
| 패키지 생성 (DEB) | `dpkg-deb --build mypkg` |
| 라이브러리 캐시 갱신 | `sudo ldconfig` |
| 의존성 확인 | `ldd /path/to/binary` |

## 결론

소스 코드에서 빌드하는 것은 최신 버전을 사용하거나 특정 옵션을 적용해야 할 때 유용하다.

- **전통적인 Autotools**: `./configure --prefix=/usr/local && make && sudo make install` 순서를 따른다.
- **현대적 CMake**: `cmake -B build -G Ninja && cmake --build build -j$(nproc)`로 빌드한다.
- **안전한 설치**: `DESTDIR`로 스테이징하여 설치될 파일을 미리 확인하고, 가능하면 `checkinstall`로 패키지화한다.
- **라이브러리 관리**: 설치 후 `sudo ldconfig`로 라이브러리 캐시를 갱신하고, `ldd`로 의존성을 확인한다.

소스 빌드는 처음에는 복잡해 보일 수 있지만, `configure --help`와 `make -j`만 익혀도 대부분의 프로젝트는 문제없이 설치할 수 있다. 패키지 관리자와 함께 적절히 활용하면 더욱 유연한 시스템 운영이 가능하다.
