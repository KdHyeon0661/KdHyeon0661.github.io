# Avalonia에서 플러그인 시스템 구현하기

## 왜 플러그인 시스템인가

플러그인 시스템은 애플리케이션의 기능을 **모듈 단위로 분리**하고, 실행 중에 새로운 기능을 추가하거나 수정할 수 있게 해준다. Avalonia 기반 데스크톱 앱에서 플러그인 아키텍처를 구현하면 다음과 같은 이점을 얻을 수 있다.

- 핵심 기능과 확장 기능을 분리하여 유지보수성 향상
- 외부 개발자가 기능을 독립적으로 개발할 수 있는 생태계 구축
- 필요에 따라 기능을 동적으로 로드/언로드하여 메모리 및 성능 최적화

이 글에서는 MVVM 패턴을 유지하면서 **안정적이고 테스트 가능한 플러그인 시스템**을 구축하는 방법을 단계별로 살펴본다.

## 용어 정리

| 용어 | 설명 |
|------|------|
| 호스트(Host) | 플러그인을 관리하는 메인 애플리케이션 |
| 플러그인(Plugin) | 호스트가 제공하는 계약을 구현한 독립 DLL |
| 계약(Contract) | 호스트와 플러그인 간 상호작용 규약 (인터페이스, DTO) |
| 매니페스트(Manifest) | 플러그인의 메타데이터 (ID, 버전, 의존성 등) |
| 로더(Loader) | 플러그인 탐색, 검증, 로드, 활성화, 언로드를 담당 |
| 확장 지점(Extension Point) | 호스트가 플러그인에 제공하는 UI/기능 확장 포인트 |

## 플러그인 계약 설계

### 기본 플러그인 인터페이스

모든 플러그인이 구현해야 할 최소한의 인터페이스다.

```csharp
public interface IPlugin
{
    string Id { get; }           // 고유 식별자 (예: "com.example.report")
    string Name { get; }         // 사용자에게 표시할 이름
    string Version { get; }      // SemVer 형식 권장 (예: "1.2.3")
    void Initialize(IPluginContext context);
    void Shutdown();             // 언로드 시 정리
}
```

### 플러그인 컨텍스트

플러그인이 호스트의 서비스에 접근할 수 있도록 주입되는 객체다.

```csharp
public interface IPluginContext
{
    IServiceProvider Services { get; }          // DI 컨테이너
    IEventBus EventBus { get; }                 // 메시지 버스 (옵션)
    IAuthorizationService Authorization { get; } // 권한 평가
    ISettingsService Settings { get; }          // 설정 저장소
    ILoggingFactory LoggerFactory { get; }      // 로깅
    CultureInfo UICulture { get; }              // UI 언어
}
```

### UI 확장 계약 (선택적)

플러그인이 UI를 제공하는 경우 다음 인터페이스 중 하나 이상을 구현한다.

```csharp
// 단일 뷰 제공
public interface IViewPlugin
{
    Control GetMainView();
}

// 메뉴 항목 기여
public interface IMenuContribution
{
    IEnumerable<MenuItemDescriptor> GetMenuItems();
}

// 네비게이션(탭/페이지) 기여
public interface INavigationContribution
{
    IEnumerable<NavigationItemDescriptor> GetNavigationItems();
}

// 명령형 기능 제공 (비 UI)
public interface ICommandPlugin
{
    IEnumerable<CommandDescriptor> GetCommands();
}
```

각 Descriptor는 UI 요소의 표현 정보를 담는다.

```csharp
public sealed record MenuItemDescriptor(
    string Header, string? IconKey, string? PolicyName, Action OnClick);

public sealed record NavigationItemDescriptor(
    string Title, Func<Control> ViewFactory, string? PolicyName);

public sealed record CommandDescriptor(
    string Name, string? PolicyName, Func<CancellationToken, Task> ExecuteAsync);
```

`PolicyName`은 권한 정책과 연동되어, 해당 기능을 보여줄지 말지를 호스트가 결정할 수 있게 한다.

## 플러그인 매니페스트

플러그인 디렉터리에 `plugin.json` 파일로 메타데이터를 제공한다.

```json
{
  "id": "com.example.report",
  "name": "보고서 플러그인",
  "version": "1.4.0",
  "entryType": "ReportPlugin.ReportPlugin, ReportPlugin",
  "targetHostVersion": ">=1.0.0 <2.0.0",
  "dependencies": [
    { "id": "com.example.core", "version": ">=1.2.0" }
  ],
  "policies": ["Reports.View", "Reports.Export"]
}
```

`entryType`은 `IPlugin` 구현 클래스의 정규화된 이름(어셈블리 포함)이다. 호스트는 이 정보를 사용해 플러그인을 인스턴스화한다.

## 플러그인 로더 아키텍처

로더는 플러그인 폴더를 탐색하고, 매니페스트를 검증한 후, `AssemblyLoadContext`를 사용해 플러그인을 로드한다. .NET 7 이상에서는 수거 가능한(collectible) ALC를 사용하여 플러그인을 언로드할 수 있다.

### 플러그인 전용 AssemblyLoadContext

```csharp
public sealed class PluginLoadContext : AssemblyLoadContext
{
    private readonly string _pluginDir;

    public PluginLoadContext(string pluginDir, bool isCollectible = true)
        : base(Path.GetFileName(pluginDir), isCollectible)
    {
        _pluginDir = pluginDir;
    }

    protected override Assembly? Load(AssemblyName assemblyName)
    {
        // 플러그인 디렉터리에서 DLL 우선 로드
        var candidate = Path.Combine(_pluginDir, assemblyName.Name + ".dll");
        if (File.Exists(candidate))
            return LoadFromAssemblyPath(candidate);

        return null; // 기본 컨텍스트로 위임
    }
}
```

### 로더 구현

```csharp
public interface IPluginLoader
{
    IReadOnlyList<LoadedPlugin> LoadAll(string pluginRoot, IPluginContext context);
    bool TryUnload(string pluginId);
}

public sealed class LoadedPlugin
{
    public PluginManifest Manifest { get; init; }
    public IPlugin Instance { get; init; }
    public AssemblyLoadContext LoadContext { get; init; }
    public Assembly Assembly { get; init; }
}

public sealed class PluginLoader : IPluginLoader
{
    private readonly Dictionary<string, LoadedPlugin> _loaded = new();

    public IReadOnlyList<LoadedPlugin> LoadAll(string root, IPluginContext ctx)
    {
        var result = new List<LoadedPlugin>();
        if (!Directory.Exists(root)) return result;

        foreach (var dir in Directory.GetDirectories(root))
        {
            var manifestPath = Path.Combine(dir, "plugin.json");
            if (!File.Exists(manifestPath)) continue;

            var manifest = JsonSerializer.Deserialize<PluginManifest>(
                File.ReadAllText(manifestPath));
            if (manifest == null) continue;

            if (!ValidateManifest(manifest)) continue;
            if (!CheckHostVersion(manifest)) continue;

            var mainDll = FindMainAssemblyPath(dir, manifest.EntryType);
            if (mainDll == null) continue;

            try
            {
                var alc = new PluginLoadContext(dir, isCollectible: true);
                var asm = alc.LoadFromAssemblyPath(mainDll);
                var type = asm.GetType(manifest.EntryType, throwOnError: true)!;

                if (Activator.CreateInstance(type) is not IPlugin plugin)
                    throw new InvalidOperationException("Entry type is not IPlugin.");

                plugin.Initialize(ctx);

                var loaded = new LoadedPlugin
                {
                    Manifest = manifest,
                    Instance = plugin,
                    LoadContext = alc,
                    Assembly = asm
                };
                _loaded[manifest.Id] = loaded;
                result.Add(loaded);
            }
            catch (Exception ex)
            {
                // 로깅
                Console.WriteLine($"플러그인 로드 실패: {dir} - {ex.Message}");
            }
        }
        return result;
    }

    public bool TryUnload(string pluginId)
    {
        if (!_loaded.TryGetValue(pluginId, out var loaded))
            return false;

        try
        {
            loaded.Instance.Shutdown();
        }
        catch (Exception ex)
        {
            Console.WriteLine($"플러그인 종료 오류: {pluginId} - {ex.Message}");
        }

        _loaded.Remove(pluginId);
        loaded.LoadContext.Unload();
        GC.Collect();
        GC.WaitForPendingFinalizers();
        return true;
    }

    private static bool ValidateManifest(PluginManifest m) => /* 간단 검증 */ true;
    private static bool CheckHostVersion(PluginManifest m) => /* SemVer 비교 */ true;

    private static string? FindMainAssemblyPath(string dir, string entryType)
    {
        var idx = entryType.IndexOf(',');
        if (idx > 0)
        {
            var asmName = entryType[(idx + 1)..].Trim();
            var path = Path.Combine(dir, asmName + ".dll");
            if (File.Exists(path)) return path;
        }
        return null; // 매니페스트에 올바른 어셈블리명이 없으면 실패
    }
}
```

## 호스트 측 서비스 구현 (DI, 권한, 설정 등)

플러그인 컨텍스트에서 사용할 서비스를 구현하고 DI 컨테이너에 등록한다.

```csharp
public class PluginContext : IPluginContext
{
    public IServiceProvider Services { get; }
    public IEventBus EventBus { get; }
    public IAuthorizationService Authorization { get; }
    public ISettingsService Settings { get; }
    public ILoggingFactory LoggerFactory { get; }
    public CultureInfo UICulture { get; }

    public PluginContext(IServiceProvider sp, IEventBus eventBus,
        IAuthorizationService auth, ISettingsService settings,
        ILoggingFactory loggerFactory, CultureInfo uiCulture)
    {
        Services = sp;
        EventBus = eventBus;
        Authorization = auth;
        Settings = settings;
        LoggerFactory = loggerFactory;
        UICulture = uiCulture;
    }
}
```

호스트의 `App.axaml.cs`에서 DI 컨테이너를 구성하고 플러그인 로더를 실행한다.

```csharp
public override void OnFrameworkInitializationCompleted()
{
    var services = new ServiceCollection();
    services.AddSingleton<AppAuthState>();
    services.AddSingleton<IAuthorizationService, AuthorizationService>();
    services.AddSingleton<IEventBus, SimpleEventBus>();
    services.AddSingleton<ILoggingFactory, SerilogLoggingFactory>();
    services.AddSingleton<ISettingsService, JsonSettingsService>();

    services.AddSingleton<IPluginLoader, PluginLoader>();
    services.AddSingleton<IPluginContext>(sp =>
        new PluginContext(sp,
            sp.GetRequiredService<IEventBus>(),
            sp.GetRequiredService<IAuthorizationService>(),
            sp.GetRequiredService<ISettingsService>(),
            sp.GetRequiredService<ILoggingFactory>(),
            CultureInfo.CurrentUICulture));

    var sp = services.BuildServiceProvider();
    var loader = sp.GetRequiredService<IPluginLoader>();
    var ctx = sp.GetRequiredService<IPluginContext>();
    var plugins = loader.LoadAll("Plugins", ctx);

    // 셸 ViewModel에 플러그인 정보 전달
    var shellVm = new ShellViewModel(loader, ctx);
    var mainWindow = new Window { Content = new ShellView(), DataContext = shellVm };
    mainWindow.Show();

    base.OnFrameworkInitializationCompleted();
}
```

## UI 통합: 동적 메뉴와 탭 생성

셸 ViewModel은 로드된 플러그인의 UI 확장 계약을 수집하여 동적 UI를 구성한다.

```csharp
public class ShellViewModel : ReactiveObject
{
    private readonly ObservableCollection<object> _navigationItems = new();
    public ReadOnlyObservableCollection<object> NavigationItems { get; }
    public ObservableCollection<MenuItem> DynamicMenus { get; } = new();

    public ShellViewModel(IPluginLoader loader, IPluginContext ctx)
    {
        NavigationItems = new(_navigationItems);

        foreach (var loaded in loader.LoadAll("Plugins", ctx))
        {
            if (loaded.Instance is INavigationContribution nav)
            {
                foreach (var item in nav.GetNavigationItems())
                {
                    if (string.IsNullOrEmpty(item.PolicyName) ||
                        ctx.Authorization.Evaluate(item.PolicyName))
                    {
                        _navigationItems.Add(new
                        {
                            item.Title,
                            ViewFactory = item.ViewFactory
                        });
                    }
                }
            }

            if (loaded.Instance is IMenuContribution menu)
            {
                foreach (var m in menu.GetMenuItems())
                {
                    if (!string.IsNullOrEmpty(m.PolicyName) &&
                        !ctx.Authorization.Evaluate(m.PolicyName)) continue;

                    var mi = new MenuItem { Header = m.Header };
                    mi.Click += (_, __) => m.OnClick();
                    DynamicMenus.Add(mi);
                }
            }
        }
    }
}
```

XAML에서는 `TabControl`과 `ContentControl`을 조합하여 동적 페이지를 표시한다.

```xml
<DockPanel>
  <Menu DockPanel.Dock="Top">
    <MenuItem Header="플러그인">
      <ItemsControl Items="{Binding DynamicMenus}" />
    </MenuItem>
  </Menu>

  <TabControl Items="{Binding NavigationItems}">
    <TabControl.ItemTemplate>
      <DataTemplate>
        <TextBlock Text="{Binding Title}" />
      </DataTemplate>
    </TabControl.ItemTemplate>
    <TabControl.ContentTemplate>
      <DataTemplate>
        <ContentControl Content="{Binding ViewFactory, Converter={StaticResource FuncToControlConverter}}" />
      </DataTemplate>
    </TabControl.ContentTemplate>
  </TabControl>
</DockPanel>
```

`FuncToControlConverter`는 `Func<Control>`을 호출해 Control 객체를 반환한다.

## 플러그인 구현 예시

### 매니페스트 (`Plugins/ReportPlugin/plugin.json`)

```json
{
  "id": "com.example.report",
  "name": "보고서 플러그인",
  "version": "1.0.0",
  "entryType": "ReportPlugin.ReportPlugin, ReportPlugin",
  "targetHostVersion": ">=1.0.0",
  "policies": ["Reports.View"]
}
```

### 코드 (`ReportPlugin.cs`)

```csharp
namespace ReportPlugin;

public sealed class ReportPlugin : IPlugin, INavigationContribution
{
    private IPluginContext _ctx = null!;

    public string Id => "com.example.report";
    public string Name => "보고서 플러그인";
    public string Version => "1.0.0";

    public void Initialize(IPluginContext context)
    {
        _ctx = context;
        var log = _ctx.LoggerFactory.CreateLogger("ReportPlugin");
        log.Info("보고서 플러그인 초기화됨");
    }

    public void Shutdown() { }

    public IEnumerable<NavigationItemDescriptor> GetNavigationItems()
    {
        yield return new NavigationItemDescriptor(
            "보고서",
            () => new ReportView(),   // Avalonia UserControl
            "Reports.View");
    }
}
```

`ReportView.xaml`은 플러그인 어셈블리에 포함되며, 표준 Avalonia XAML로 작성한다.

## 핫 리로드와 언로드

`FileSystemWatcher`를 사용해 플러그인 폴더의 변경을 감지하고, 해당 플러그인을 언로드한 후 다시 로드할 수 있다.

```csharp
public class PluginWatcher : IDisposable
{
    private readonly FileSystemWatcher _fsw;
    private readonly IPluginLoader _loader;
    private readonly IPluginContext _ctx;

    public PluginWatcher(string root, IPluginLoader loader, IPluginContext ctx)
    {
        _loader = loader;
        _ctx = ctx;
        _fsw = new FileSystemWatcher(root, "*.*")
        {
            IncludeSubdirectories = true,
            EnableRaisingEvents = true
        };
        _fsw.Changed += OnChanged;
    }

    private async void OnChanged(object sender, FileSystemEventArgs e)
    {
        // 간단한 딜레이 후 재로드 (실제 구현에서는 플러그인 ID를 추출)
        await Task.Delay(500);
        _loader.LoadAll("Plugins", _ctx); // 전체 재로드
    }

    public void Dispose() => _fsw.Dispose();
}
```

언로드 시에는 반드시 `Shutdown()`을 호출해 플러그인이 사용한 리소스를 해제하고, `AssemblyLoadContext.Unload()`를 호출한 후 가비지 수집을 강제한다.

## 보안 및 안정성

- **서명/해시 검증**: 플러그인 DLL과 매니페스트의 무결성을 확인한다.
- **권한 정책**: UI 표시 여부뿐 아니라, 실제 기능 실행 시에도 서버 측 권한 검증을 병행한다.
- **예외 격리**: 플러그인의 초기화, 메뉴 클릭, 뷰 생성 등에서 발생한 예외는 호스트가 로깅하고 계속 실행할 수 있도록 처리한다.
- **샌드박싱**: 고도 보안이 필요하다면 플러그인을 별도 프로세스에서 실행하고 IPC로 통신한다.

## 테스트 전략

| 테스트 대상 | 방법 |
|------------|------|
| 플러그인 계약 | 단위 테스트: Descriptor 직렬화, 정책 평가 |
| 로더 | 임시 폴더에 플러그인을 배치하고 `LoadAll` 호출, 예외 상황 검증 |
| 셸 통합 | Mock 플러그인을 로드하여 메뉴/탭이 올바르게 추가되는지 확인 |
| 언로드 | 플러그인 언로드 후 GC가 어셈블리를 수거하는지 검증 (소멸자 로그 등) |

## 배포 전략

| 방식 | 장점 | 단점 |
|------|------|------|
| DLL 폴더 | 간단, 빠른 배포 | 무결성 관리 별도 |
| Zip 패키지 | 단일 파일 배포, 버전 정보 포함 | 압축 해제 필요 |
| NuGet 피드 | 의존성 관리 용이 | 사설 피드 필요 |

운영 환경에서는 **서명된 Zip + 해시 검증**을 권장한다.

## 결론

Avalonia에서 플러그인 시스템을 구현하는 핵심은 다음과 같다.

- **계약과 수명주기를 명확히 정의**한다.
- **Collectible AssemblyLoadContext**를 활용해 동적 로드/언로드를 지원한다.
- **DI와 권한, 설정, 로깅**을 컨텍스트로 주입해 플러그인을 1급 시민으로 대우한다.
- **UI 확장 포인트를 Descriptor 기반으로 추상화**해 호스트와의 결합을 낮춘다.
- **핫 리로드와 예외 격리**로 운영 안정성을 높인다.

이 구조를 바탕으로 확장하면 플러그인 간 의존성, 버전 호환성, 더 세밀한 보안 정책 등을 점진적으로 추가할 수 있다.
