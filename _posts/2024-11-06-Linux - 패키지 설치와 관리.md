# 패키지 설치와 관리

## 리눅스 소프트웨어 설치 방식

리눅스에서 소프트웨어를 설치하는 가장 기본적인 방법은 배포판의 **패키지 관리자**를 사용하는 것이다. 패키지 관리자는 의존성 자동 해결, 패키지 서명 검증, 설치 이력 관리 등 여러 장점을 제공한다.

주요 배포판 계열과 패키지 관리자는 다음과 같다.

| 계열 | 배포판 | 고수준 도구 | 저수준 도구 |
|------|--------|-------------|-------------|
| Debian 계열 | Ubuntu, Debian, Linux Mint | `apt` | `dpkg` |
| RHEL 계열 | Fedora, RHEL, Rocky, Alma | `dnf` | `rpm` |

이 외에도 **Flatpak**, **Snap**, **AppImage** 같은 사용자 공간 격리형 패키징 방식과 언어별 패키지 관리자(`pip`, `npm` 등)가 존재한다. 이 글에서는 가장 널리 사용되는 APT와 DNF를 중심으로 설명한다.

---

## APT (Debian/Ubuntu 계열)

APT는 Debian 계열 배포판에서 사용하는 고수준 패키지 관리자다. 저수준 도구인 `dpkg` 위에서 동작하며, 의존성 해결과 저장소 관리를 자동으로 처리한다.

### 패키지 검색

```bash
apt search htop
apt search --names-only '^nginx$'
```

`apt search`는 패키지 이름과 설명에서 키워드를 검색한다. 정확한 이름을 알 때는 `--names-only`를 사용하거나 `apt-cache policy 패키지명`으로 상세 정보를 볼 수 있다.

### 설치, 업데이트, 제거

```bash
sudo apt update                 # 패키지 목록 갱신
sudo apt install htop           # 패키지 설치
sudo apt upgrade                # 설치된 패키지 업그레이드
sudo apt remove htop            # 패키지 제거 (설정 파일 유지)
sudo apt purge htop             # 설정 파일까지 완전 제거
```

`update`는 반드시 설치 전에 실행해야 최신 정보를 반영한다. `upgrade`는 보수적으로 업그레이드하며, `full-upgrade`는 의존성 변경이 필요한 경우 패키지를 교체하기도 한다.

### 캐시 정리

```bash
sudo apt autoremove             # 더 이상 필요 없는 의존성 제거
sudo apt clean                  # 다운로드한 .deb 파일 전부 삭제
sudo apt autoclean              # 오래된 .deb 파일만 삭제
```

### 실전 팁

```bash
# 재설치
sudo apt install --reinstall curl

# 추천 패키지 없이 최소 설치
sudo apt install --no-install-recommends nginx
```

## dpkg: 저수준 패키지 관리

`dpkg`는 .deb 패키지를 직접 다루는 도구다. APT가 의존성과 저장소를 관리하는 반면, `dpkg`는 개별 패키지 파일을 설치하거나 제거할 수 있다.

### 설치된 패키지 조회

```bash
dpkg -l | grep curl             # 설치된 패키지 목록에서 curl 검색
dpkg -L curl                    # curl 패키지가 설치한 파일 목록
dpkg -S /usr/bin/curl           # 특정 파일이 속한 패키지 확인
```

### 수동 .deb 파일 설치 (주의)

```bash
sudo dpkg -i package.deb        # .deb 파일 설치
sudo apt -f install             # 의존성 문제 자동 복구
sudo dpkg -r package            # 패키지 제거 (설정 유지)
sudo dpkg -P package            # 완전 제거 (purge)
```

일반적으로는 `apt` 사용을 권장하며, `dpkg`는 주로 패키지 상태 확인이나 문제 해결 시 활용한다.

## APT 저장소와 PPA

APT는 `/etc/apt/sources.list`와 `/etc/apt/sources.list.d/` 디렉터리에 정의된 저장소에서 패키지를 가져온다.

### PPA 추가 (Ubuntu)

Personal Package Archive(PPA)는 Launchpad에서 제공하는 개인 저장소다.

```bash
sudo add-apt-repository ppa:neovim-ppa/stable
sudo apt update
```

### GPG 키 관리

저장소 추가 시 GPG 키가 필요하다. 최신 방식은 키를 별도 파일로 저장하고 `signed-by` 옵션을 사용하는 것이다.

```bash
curl -fsSL https://example.com/key.gpg | sudo gpg --dearmor -o /usr/share/keyrings/example.gpg
echo "deb [signed-by=/usr/share/keyrings/example.gpg] https://repo.example.com/ubuntu noble main" | sudo tee /etc/apt/sources.list.d/example.list
sudo apt update
```

이전에 사용하던 `apt-key add` 방식은 더 이상 권장되지 않는다.

## DNF (RHEL/Fedora 계열)

DNF는 Fedora, RHEL, Rocky Linux 등에서 사용하는 패키지 관리자다. YUM의 후속으로 더 빠르고 의존성 해결이 정교하다.

### 기본 명령어

```bash
sudo dnf install nginx          # 설치
sudo dnf upgrade                # 전체 업그레이드
sudo dnf remove nginx           # 제거
dnf search nginx                # 검색
dnf info nginx                  # 패키지 상세 정보
```

### 패키지 정보 조회

RPM 기반에서는 `rpm` 명령으로도 정보를 확인할 수 있다.

```bash
rpm -qi nginx                   # 패키지 정보
rpm -ql nginx                   # 설치 파일 목록
rpm -qf /usr/sbin/nginx         # 파일이 속한 패키지 확인
```

### 히스토리와 롤백

```bash
sudo dnf history                # 트랜잭션 이력 확인
sudo dnf history info 25        # 특정 트랜잭션 상세
sudo dnf history undo 25        # 해당 트랜잭션 되돌리기
```

### 캐시 관리

```bash
sudo dnf clean all              # 캐시 삭제
sudo dnf makecache              # 메타데이터 캐시 생성
```

## DNF 저장소 관리

저장소 설정은 `/etc/yum.repos.d/` 디렉터리의 `.repo` 파일에 정의한다.

### EPEL 저장소 추가

Extra Packages for Enterprise Linux (EPEL)는 RHEL 계열에서 자주 사용하는 추가 저장소다.

```bash
sudo dnf install epel-release
```

### 수동 저장소 추가

```bash
sudo tee /etc/yum.repos.d/example.repo >/dev/null <<'EOF'
[example]
name=Example Repository
baseurl=https://repo.example.com/rpm/$releasever/$basearch
enabled=1
gpgcheck=1
gpgkey=https://repo.example.com/keys/RPM-GPG-KEY-example
EOF
sudo dnf makecache
```

## 대안 패키징 방식 (Flatpak, Snap)

시스템 패키지와 분리된 샌드박스 환경에서 애플리케이션을 실행할 수 있다.

### Flatpak

```bash
# 설치 (Ubuntu)
sudo apt install flatpak
flatpak remote-add --if-not-exists flathub https://flathub.org/repo/flathub.flatpakrepo

# 사용
flatpak install flathub org.mozilla.Firefox
flatpak list
flatpak update
```

### Snap

```bash
# 설치 (Ubuntu 기본 포함)
sudo snap install --classic code
snap list
sudo snap refresh
sudo snap remove code
```

### AppImage

AppImage는 실행 권한만 부여하면 바로 사용할 수 있는 단일 파일 실행 형식이다.

```bash
chmod +x AppName.AppImage
./AppName.AppImage
```

## 문제 해결 기본 루틴

### APT 의존성 깨짐

```bash
sudo apt -f install              # 의존성 복구 시도
sudo dpkg --configure -a         # 미처리 패키지 구성 재시도
sudo apt install --fix-broken
```

### APT 잠금 파일 오류

```bash
sudo rm /var/lib/apt/lists/lock /var/cache/apt/archives/lock
sudo apt update
```

### GPG 키 오류

저장소 키가 만료되었거나 등록되지 않은 경우, 키를 재다운로드하거나 `signed-by` 경로를 확인한다.

### RPM 데이터베이스 손상

```bash
sudo rpm --rebuilddb
```

### 파일이 속한 패키지 찾기

```bash
# Debian/Ubuntu
apt-file update
apt-file search bin/psql

# RHEL/Fedora
dnf provides */psql
```

## 명령어 요약 표

| 작업 | APT (Debian/Ubuntu) | DNF (RHEL/Fedora) |
|------|---------------------|-------------------|
| 패키지 목록 갱신 | `sudo apt update` | `sudo dnf makecache` |
| 패키지 설치 | `sudo apt install 패키지` | `sudo dnf install 패키지` |
| 패키지 제거 | `sudo apt remove 패키지` | `sudo dnf remove 패키지` |
| 완전 제거 (설정 포함) | `sudo apt purge 패키지` | `sudo dnf remove 패키지` (설정 파일도 삭제) |
| 전체 업그레이드 | `sudo apt upgrade` | `sudo dnf upgrade` |
| 검색 | `apt search 키워드` | `dnf search 키워드` |
| 패키지 정보 | `apt-cache policy 패키지` | `dnf info 패키지` |
| 파일이 속한 패키지 | `dpkg -S 파일` | `rpm -qf 파일` |
| 패키지 설치 파일 목록 | `dpkg -L 패키지` | `rpm -ql 패키지` |
| 불필요한 패키지 제거 | `sudo apt autoremove` | (별도 명령 없음) |
| 캐시 정리 | `sudo apt clean` | `sudo dnf clean all` |

## 결론

리눅스 패키지 관리는 배포판에 따라 도구는 다르지만 기본 원리는 같다. APT와 DNF 모두 의존성 해결, 저장소 관리, 보안 검증을 체계적으로 수행한다.

효율적인 패키지 관리를 위해 다음 사항을 기억하자.

* **신뢰할 수 있는 저장소만 사용**한다. 불필요한 외부 저장소는 시스템 불안정을 초래할 수 있다.
* **정기적으로 업데이트**하되, 프로덕션 환경에서는 주요 패키지 버전을 고정하는 것을 고려한다.
* **시스템 패키지는 배포판 관리자**로, 사용자 애플리케이션은 Flatpak/Snap 등으로 분리해 설치하면 관리가 편리하다.
* 문제 발생 시 **체계적인 진단**을 위해 `apt -f install`, `dpkg --configure -a`, `dnf history` 등을 활용한다.

패키지 관리에 익숙해지면 소프트웨어 설치, 업데이트, 제거가 훨씬 간편해지고 시스템 안정성을 유지할 수 있다.
