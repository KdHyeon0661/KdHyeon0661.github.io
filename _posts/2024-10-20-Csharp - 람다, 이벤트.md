# 람다와 이벤트

람다(Lambda)는 C#에서 익명 함수를 간결하게 표현하는 문법입니다. 이벤트(Event)는 객체 간의 느슨한 결합을 위한 발행-구독 패턴을 구현하는 핵심 도구로, 내부적으로는 델리게이트를 캡슐화합니다.

---

## 람다 표현식

람다 표현식은 `=>` 연산자를 사용하여 델리게이트나 식 트리에 전달할 익명 함수를 만듭니다. 이름 없는 메서드를 간결하게 정의할 수 있어 LINQ, 이벤트 핸들러, 콜백 등에서 널리 사용됩니다.

### 기본 문법

람다의 기본 형태는 `(매개변수) => 식` 또는 `(매개변수) => { 문장; }` 입니다.

```csharp
// 식 본문 람다: 단일 표현식
Func<int, int> square = x => x * x;
Console.WriteLine(square(5)); // 25

// 문 본문 람다: 여러 줄 가능
Action<string> greet = name =>
{
    string message = $"Hello, {name}!";
    Console.WriteLine(message);
};
greet("Alice");
```

매개변수가 하나일 때는 괄호를 생략할 수 있습니다. 매개변수가 없으면 빈 괄호 `()`를 사용합니다.

### 람다의 타입

람다는 자체 타입이 없으며, 할당되는 델리게이트나 식 트리의 타입에 맞춰 변환됩니다.

| 델리게이트 타입 | 람다 예시 |
|----------------|-----------|
| `Action` | `() => Console.WriteLine()` |
| `Action<T>` | `x => Console.WriteLine(x)` |
| `Func<TResult>` | `() => DateTime.Now` |
| `Func<T, TResult>` | `x => x.ToString()` |
| `Predicate<T>` | `x => x > 0` |

```csharp
Action<string> action = msg => Console.WriteLine(msg);
Func<int, int, int> func = (a, b) => a + b;
Predicate<int> predicate = n => n % 2 == 0;
```

### 람다와 LINQ

람다는 LINQ 쿼리에서 조건과 변환을 표현하는 데 가장 자주 사용됩니다.

```csharp
var numbers = new List<int> { 1, 2, 3, 4, 5 };
var evens = numbers.Where(n => n % 2 == 0).ToList();
var doubled = numbers.Select(n => n * 2);
var sum = numbers.Aggregate(0, (acc, n) => acc + n);
```

### 클로저 (Closure)

람다는 자신을 감싸는 외부 범위의 변수를 캡처할 수 있습니다. 이를 클로저라고 합니다. 캡처된 변수는 람다의 수명 동안 유지됩니다.

```csharp
int factor = 3;
Func<int, int> multiplier = x => x * factor;
Console.WriteLine(multiplier(10)); // 30

factor = 5;
Console.WriteLine(multiplier(10)); // 50 (변경된 factor가 반영됨)
```

이때 중요한 것은 캡처가 값이 아닌 **변수 참조**로 이루어진다는 점입니다. 따라서 변수 값이 나중에 변경되면 람다도 변경된 값을 사용합니다.

### 루프 변수 캡처의 함정

`for` 루프 안에서 람다가 루프 변수를 캡처할 때 주의해야 합니다.

```csharp
var actions = new List<Action>();
for (int i = 0; i < 3; i++)
{
    actions.Add(() => Console.WriteLine(i)); // i를 캡처
}
foreach (var a in actions) a(); // 3, 3, 3 출력 (모두 마지막 값)
```

이 문제는 루프 변수 `i`가 하나의 변수로 재사용되기 때문입니다. 해결 방법은 루프 내에서 로컬 복사본을 만드는 것입니다.

```csharp
for (int i = 0; i < 3; i++)
{
    int captured = i; // 지역 복사본
    actions.Add(() => Console.WriteLine(captured));
}
// 출력: 0, 1, 2
```

C# 5.0 이후의 `foreach`는 자동으로 이러한 복사본을 생성하지만, `for` 문은 여전히 주의해야 합니다.

## 이벤트

이벤트는 클래스가 특정 상황(버튼 클릭, 데이터 변경 등)이 발생했음을 외부에 알리는 메커니즘입니다. 델리게이트를 기반으로 하지만, 외부에서의 직접 호출과 무분별한 할당을 방지하기 위해 `event` 키워드로 캡슐화합니다.

### 이벤트 선언과 구독

이벤트는 델리게이트 타입을 기반으로 선언합니다.

```csharp
public class Button
{
    // 델리게이트 타입 선언 (또는 EventHandler 사용)
    public event EventHandler Clicked;
    
    public void Click()
    {
        Console.WriteLine("버튼 클릭됨");
        // 이벤트 발생 (null 체크 후 호출)
        Clicked?.Invoke(this, EventArgs.Empty);
    }
}

// 구독
Button button = new Button();
button.Clicked += (sender, e) => Console.WriteLine("이벤트 처리됨");
button.Click();
```

`event` 키워드가 붙은 멤버는 클래스 외부에서 다음과 같은 제약이 있습니다.
- `+=` 연산자로 구독만 가능 (`-=`로 해지 가능)
- `=` 연산자로 직접 할당 불가
- 외부에서 `Invoke()` 호출 불가 (클래스 내부에서만 가능)

### 표준 이벤트 패턴 (EventHandler)

.NET은 이벤트를 위한 표준 패턴을 제공합니다. `System.EventHandler<TEventArgs>`를 사용하는 것이 권장됩니다.

```csharp
// 이벤트 데이터 클래스 (EventArgs 상속)
public class TemperatureEventArgs : EventArgs
{
    public double Temperature { get; }
    public TemperatureEventArgs(double temp) => Temperature = temp;
}

public class Thermostat
{
    public event EventHandler<TemperatureEventArgs> TemperatureChanged;
    
    private double _temperature;
    public double Temperature
    {
        get => _temperature;
        set
        {
            if (_temperature != value)
            {
                _temperature = value;
                // 이벤트 발생
                TemperatureChanged?.Invoke(this, new TemperatureEventArgs(value));
            }
        }
    }
}

// 사용
var thermostat = new Thermostat();
thermostat.TemperatureChanged += (sender, e) =>
    Console.WriteLine($"온도 변화: {e.Temperature}°C");
thermostat.Temperature = 25.5;
```

표준 패턴의 장점:
- `sender`를 통해 이벤트 발생 객체를 전달
- `EventArgs`를 통해 필요한 데이터 전달
- 일관된 디자인으로 다른 개발자가 이해하기 쉬움

### 이벤트 접근자 (add / remove)

프로퍼티에 get/set이 있듯, 이벤트에도 add/remove 접근자를 정의할 수 있습니다. 이를 통해 구독 및 해지 시 추가 로직을 삽입할 수 있습니다.

```csharp
public class Logger
{
    private EventHandler<EventArgs> _handlers;
    
    public event EventHandler<EventArgs> Logged
    {
        add
        {
            Console.WriteLine($"구독자 추가: {value.Method.Name}");
            _handlers += value;
        }
        remove
        {
            Console.WriteLine($"구독자 제거: {value.Method.Name}");
            _handlers -= value;
        }
    }
    
    public void Write(string message)
    {
        _handlers?.Invoke(this, EventArgs.Empty);
        Console.WriteLine($"로그: {message}");
    }
}
```

이벤트 접근자는 특별한 구독 조건(예: 최대 구독자 수 제한)이나 디버깅 목적으로 유용합니다.

### 이벤트와 메모리 누수

이벤트를 구독한 후 해지하지 않으면, 발행자 객체가 구독자 객체를 계속 참조하게 되어 가비지 컬렉션이 되지 않을 수 있습니다. 이를 메모리 누수라고 합니다.

```csharp
public class Subscriber
{
    public void HandleEvent(object sender, EventArgs e) { }
}

var publisher = new SomePublisher();
var subscriber = new Subscriber();
publisher.SomeEvent += subscriber.HandleEvent;

// subscriber가 더 이상 필요 없을 때 반드시 해지
publisher.SomeEvent -= subscriber.HandleEvent;
```

약한 이벤트 패턴(Weak Event Pattern)을 사용하면 이러한 문제를 완화할 수 있지만, 일반적으로는 구독과 해지의 짝을 맞추는 것이 중요합니다.

## 람다와 이벤트의 결합

람다는 이벤트 핸들러를 간결하게 표현할 때 매우 유용합니다. 특히 일회성 핸들러나 간단한 로직에서 람다를 자주 사용합니다.

```csharp
button.Clicked += (sender, e) => Console.WriteLine("버튼 클릭됨");
```

하지만 람다로 등록한 핸들러는 나중에 해지하기 어렵다는 단점이 있습니다. 람다를 변수에 저장하지 않으면 `-=` 연산으로 제거할 수 없기 때문입니다.

```csharp
// 해지 불가능한 람다 핸들러
button.Clicked += (s, e) => Console.WriteLine("임시 핸들러");

// 해지하려면 델리게이트 변수에 저장
EventHandler handler = (s, e) => Console.WriteLine("저장된 핸들러");
button.Clicked += handler;
button.Clicked -= handler; // 해지 가능
```

따라서 명시적인 해지가 필요한 이벤트에서는 람다 대신 명명된 메서드를 사용하거나 델리게이트 변수에 저장하는 것이 좋습니다.

## 실전 예제: 타이머와 이벤트

아래는 `System.Timers.Timer`를 사용하여 주기적인 이벤트를 처리하는 예제입니다.

```csharp
using System.Timers;

public class PeriodicNotifier : IDisposable
{
    private Timer _timer;
    public event EventHandler<DateTime> Tick;
    
    public PeriodicNotifier(double intervalSeconds)
    {
        _timer = new Timer(intervalSeconds * 1000);
        _timer.Elapsed += OnTimerElapsed;
        _timer.AutoReset = true;
    }
    
    public void Start() => _timer.Start();
    public void Stop() => _timer.Stop();
    
    private void OnTimerElapsed(object sender, ElapsedEventArgs e)
    {
        Tick?.Invoke(this, e.SignalTime);
    }
    
    public void Dispose() => _timer?.Dispose();
}

// 사용
using var notifier = new PeriodicNotifier(1);
notifier.Tick += (sender, time) => Console.WriteLine($"틱: {time:HH:mm:ss}");
notifier.Start();

Console.WriteLine("5초 후 종료...");
Thread.Sleep(5000);
```

## 람다와 이벤트 성능 고려 사항

- **람다 생성 비용**: 람다가 외부 변수를 캡처하지 않으면 컴파일러가 정적 메서드로 캐시하여 생성 비용이 거의 없습니다. 하지만 변수를 캡처하면 인스턴스가 생성되어 약간의 오버헤드가 있습니다.
- **이벤트 호출 비용**: 이벤트 호출은 델리게이트 호출과 동일하며, 멀티캐스트 시 모든 구독자를 순회하므로 $$O(n)$$의 비용이 발생합니다. 구독자가 많을 경우 성능에 영향을 줄 수 있습니다.
- **메모리 사용**: 이벤트에 람다를 많이 추가하면 델리게이트 객체가 힙에 쌓입니다. 해지하지 않으면 계속 유지되므로 주의가 필요합니다.

## 마무리

람다와 이벤트는 C#에서 반응형 프로그래밍을 구현하는 핵심 요소입니다. 람다는 코드를 간결하게 만들고, 이벤트는 객체 간의 결합도를 낮춰 유연한 아키텍처를 가능하게 합니다.

| 개념 | 핵심 역할 |
|------|----------|
| 람다 | 익명 함수를 간결하게 표현, LINQ 및 콜백에 필수 |
| 클로저 | 외부 변수를 캡처하여 상태 유지, 주의해야 할 함정 존재 |
| 이벤트 | 발행-구독 패턴 구현, 델리게이트를 캡슐화 |
| 표준 패턴 | `EventHandler<TEventArgs>` 사용으로 일관성 확보 |
