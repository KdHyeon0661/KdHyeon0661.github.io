# 네트워크 기초와 트러블슈팅

## 체계적 네트워크 문제 해결 접근법

네트워크 문제를 효율적으로 해결하려면 단계별로 범위를 좁혀 나가는 체계적인 접근이 필요하다. 문제 원인은 크게 다섯 가지 계층으로 나눌 수 있다.

| 계층 | 원인 |
|------|------|
| 1. 로컬 시스템 | IP 주소, 라우팅 테이블, 방화벽, 프로세스 상태 |
| 2. LAN 환경 | 스위치, VLAN, 게이트웨이 연결, ARP |
| 3. WAN/ISP | 경로 문제, 패킷 손실, 지연 |
| 4. DNS | 도메인 해석 실패 또는 느림 |
| 5. 원격 서비스 | 서버 리스닝 상태, 방화벽, 애플리케이션 오류 |

### 빠른 5단계 점검 순서

문제가 발생했을 때 아래 순서대로 점검하면 원인을 빠르게 찾을 수 있다.

```bash
# 1단계: 로컬 네트워크 설정 확인
ip a                  # IP 주소 확인
ip r                  # 라우팅 테이블 확인

# 2단계: 게이트웨이 및 로컬 연결 확인
ip neigh              # ARP 테이블 확인
ping -c 3 <게이트웨이 IP>

# 3단계: 외부 연결성 확인
ping -c 3 8.8.8.8

# 4단계: DNS 해석 확인
dig +short example.com @1.1.1.1

# 5단계: 원격 서비스 접속 확인
nc -vz example.com 443
curl -vI https://example.com
```

각 단계에서 실패한 지점이 발견되면 해당 계층에 집중하여 진단한다.

## 핵심 네트워크 진단 도구

### ping — 기본 연결성 테스트

```bash
ping -c 4 naver.com            # 4회만 전송
ping -i 0.5 8.8.8.8           # 0.5초 간격
ping -s 1400 -M do 1.1.1.1    # MTU 탐지 (조각 금지)
```

- ICMP가 차단된 환경에서는 ping이 실패할 수 있으므로 TCP 기반 도구로 추가 확인 필요

### ip — 통합 네트워크 관리

```bash
ip a                          # 모든 인터페이스 주소
ip link set eth0 up           # 인터페이스 활성화
ip addr add 192.168.1.10/24 dev eth0   # IP 추가
ip r                          # 라우팅 테이블
ip neigh                      # ARP 테이블
```

### ss — 소켓 상태 확인

`netstat`을 대체하는 현대적 도구.

```bash
ss -tuln                      # 리스닝 포트
ss -tulnp | grep :80          # 포트 80 사용 프로세스
ss -ant | grep ESTAB          # ESTABLISHED 연결
ss -s                         # 소켓 통계 요약
```

### traceroute / mtr — 경로 분석

```bash
traceroute -n example.com     # 경로의 각 홉 확인
mtr -nzwc 100 example.com     # 실시간 경로별 손실/지연 분석
```

`mtr`은 간헐적 패킷 손실이 어느 구간에서 발생하는지 파악하는 데 유용하다.

### dig / nslookup — DNS 진단

```bash
dig +short example.com        # A 레코드 조회
dig @1.1.1.1 example.com      # 특정 DNS 서버 사용
resolvectl status             # systemd-resolved 상태 (최신 배포판)
```

### nmap — 포트 스캔 (허가 필요)

```bash
nmap -p 22,80,192.168.0.1     # 특정 포트 스캔
nmap -A example.com            # 서비스 버전 탐지
```

**주의**: 반드시 자신이 소유한 시스템이나 허가를 받은 환경에서만 사용해야 한다.

### tcpdump — 패킷 캡처

```bash
sudo tcpdump -ni eth0 tcp port 443 -c 50
sudo tcpdump -ni any host 8.8.8.8 and icmp
sudo tcpdump -ni eth0 -w capture.pcap   # 파일 저장
```

패턴 분석: SYN 패킷만 보내고 응답이 없으면 방화벽이나 경로 문제를 의심할 수 있다.

### curl / nc — 응용 계층 테스트

```bash
curl -vI https://example.com   # HTTP/HTTPS 상세 정보
nc -vz example.com 443         # TCP 연결 테스트
```

`curl -v`는 TLS 핸드셰이크, 리다이렉트, 헤더 등을 보여준다.

## 특수 네트워크 문제

### MTU와 PMTUD

큰 패킷 전송 시 연결이 끊기는 증상은 경로 MTU 문제일 수 있다.

```bash
ping -M do -s 1472 8.8.8.8      # MTU 테스트 (1500-28=1472)
ip link set dev eth0 mtu 1400   # 임시 MTU 낮춤
```

### 방화벽 점검

```bash
# ufw (Ubuntu)
sudo ufw status verbose
sudo ufw allow 443/tcp

# firewalld (RHEL/Fedora)
sudo firewall-cmd --list-all
sudo firewall-cmd --add-service=https --permanent

# nftables (현대적)
sudo nft list ruleset
```

### 인터페이스 드라이버 점검

```bash
sudo ethtool eth0               # 링크 속도, 듀플렉스
sudo ethtool -i eth0            # 드라이버 정보
sudo ethtool -S eth0            # 통계 (에러, 드롭 카운터)
```

### 컨테이너 네트워킹

Docker나 Podman 환경에서는 브리지와 NAT 규칙을 확인한다.

```bash
ip a | grep -E 'docker0|cni|br-'
sudo nft list ruleset | head -100
```

## 실전 트러블슈팅 시나리오

### 시나리오 A — 웹 서비스 느림/간헐적 끊김

```bash
# 경로별 지연/손실 확인
mtr -nzwc 200 example.com

# MTU 문제 확인
ping -M do -s 1472 example.com

# 서버 소켓 큐 상태 확인
ss -s
cat /proc/sys/net/core/somaxconn
```

### 시나리오 B — 외부에서 443 포트 접근 불가

```bash
# 리스닝 확인
ss -tulnp | grep ':443'

# 방화벽 및 SELinux
sudo ufw status
sudo semanage port -l | grep https

# 패킷 추적
sudo tcpdump -ni eth0 'tcp port 443 and (tcp[tcpflags] & (tcp-syn|tcp-ack) != 0)'
```

### 시나리오 C — DNS 정상이나 접속 실패

```bash
# DNS 해석 결과 확인
dig +short service.example.com

# HTTP 레벨 확인
curl -vI https://service.example.com
```

### 시나리오 D — VPN 이후 특정 사이트만 접속 불가 (MTU)

```bash
# VPN 인터페이스 MTU 확인
ip link show dev wg0

# MTU 테스트
ping -M do -s 1372 1.1.1.1

# MTU 조정
sudo ip link set dev wg0 mtu 1380
```

## 명령어 요약표

| 범주 | 도구 | 주요 용도 |
|------|------|----------|
| 연결성 | `ping` | 지연, 패킷 손실, MTU |
| 주소/라우팅 | `ip` | 인터페이스, 라우팅, ARP |
| 포트/소켓 | `ss` | 리스닝, 연결 상태, 통계 |
| 경로 | `traceroute`, `mtr` | 홉별 지연, 손실 |
| DNS | `dig`, `resolvectl` | 레코드 조회, 리졸버 상태 |
| 포트 스캔 | `nmap` | 서비스 탐지 (허가 필요) |
| 패킷 분석 | `tcpdump` | 실제 트래픽 캡처 |
| 응용 계층 | `curl`, `nc` | HTTP, TCP 연결 테스트 |
| 방화벽 | `ufw`, `firewall-cmd`, `nft` | 규칙 확인 및 관리 |
| 드라이버 | `ethtool` | NIC 정보, 에러 통계 |

## 결론

효과적인 네트워크 트러블슈팅은 체계적인 접근과 적절한 도구 사용에 달려 있다. 로컬 시스템(IP, 라우팅, 포트)부터 시작해 점차 외부로 범위를 넓혀 나가며 문제 지점을 특정한다.

`ip`, `ss`, `mtr`, `tcpdump`, `curl`의 조합은 대부분의 네트워크 문제를 진단하는 데 충분하다. 특히 MTU 문제, 방화벽, SELinux, 정책 라우팅 충돌은 간헐적이거나 환경 의존적 문제의 흔한 원인이므로 항상 염두에 두어야 한다.

각 도구가 제공하는 정보를 종합적으로 해석하고, 네트워크 스택의 각 계층을 하나씩 검증하는 과정을 통해 문제를 효율적으로 해결할 수 있다.
