# Avalonia - 디자인 타임 바인딩

Avalonia 애플리케이션을 개발할 때 **디자인 타임(design-time)** 에서 실제 데이터가 어떻게 표시될지 미리 보는 것은 생산성과 UI 품질을 크게 향상시킵니다. 데이터 바인딩이 적용된 복잡한 레이아웃, 리스트, 템플릿, 오류 상태 등을 실제 API 연결 없이도 검증할 수 있기 때문입니다. 이 글에서는 Avalonia에서 디자인 타임 바인딩을 구현하는 다양한 방법과 주의할 점을 초중급 개발자 기준으로 설명합니다.

---

## 디자인 타임 데이터가 중요한 이유

- **레이아웃 검증**: 실제 데이터가 들어왔을 때 컨트롤의 크기, 정렬, 줄바꿈 등이 의도한 대로 동작하는지 확인할 수 있습니다.
- **다양한 상태 테스트**: 빈 리스트, 긴 텍스트, 오류 메시지, 권한별 UI 분기 등 런타임에만 나타나는 상태를 디자인 단계에서 재현할 수 있습니다.
- **개발 속도 향상**: 디자이너와 개발자가 별도의 백엔드 없이 UI를 독립적으로 작업할 수 있습니다.

> **핵심 원칙**: 디자인 타임과 런타임을 명확히 분리하되, 런타임에 의존하는 코드(네트워크, 파일 I/O, 네이티브 라이브러리)는 디자인 타임에 실행되지 않도록 차단해야 합니다.

---

## 가장 간단한 방법: `d:DataContext`

Avalonia에서는 XAML 네임스페이스 `d:`를 통해 디자인 타임 전용 속성을 제공합니다. `d:DataContext`에 더미 ViewModel 인스턴스를 할당하면, 프리뷰어(Previewer)가 이를 사용해 UI를 렌더링합니다.

```xml
<UserControl xmlns="https://github.com/avaloniaui"
             xmlns:d="https://github.com/avaloniaui"
             xmlns:vm="clr-namespace:MyApp.ViewModels"
             d:DesignWidth="1024" d:DesignHeight="640">
    <!-- 디자인 타임에만 사용할 DataContext -->
    <UserControl.d:DataContext>
        <vm:MyViewModelDesign />
    </UserControl.d:DataContext>

    <StackPanel Spacing="8">
        <TextBlock Text="{Binding Title}" FontSize="24" />
        <ListBox Items="{Binding Items}" />
    </StackPanel>
</UserControl>
```

- `d:DesignWidth`, `d:DesignHeight`는 프리뷰어의 캔버스 크기를 지정합니다.
- `d:DataContext`는 **디자인 타임에만** 적용되며, 런타임에는 무시됩니다.
- `MyViewModelDesign`은 `MyViewModel`과 동일한 바인딩 가능 속성을 제공하는 클래스입니다.

## 디자인 전용 ViewModel 만들기

디자인 타임 ViewModel은 일반적으로 런타임 ViewModel을 상속하거나, 동일한 인터페이스를 구현하여 바인딩 경로가 일치하도록 합니다.

```csharp
// 런타임 ViewModel
public class MyViewModel : ReactiveObject
{
    private string _title = "로딩 중...";
    public string Title
    {
        get => _title;
        set => this.RaiseAndSetIfChanged(ref _title, value);
    }

    private ObservableCollection<string> _items = new();
    public ObservableCollection<string> Items
    {
        get => _items;
        set => this.RaiseAndSetIfChanged(ref _items, value);
    }

    // 런타임 생성자: API 호출, DI 등
    public MyViewModel(IDataService service)
    {
        // 실제 데이터 로드
    }
}

// 디자인 타임 ViewModel (상속)
public class MyViewModelDesign : MyViewModel
{
    public MyViewModelDesign() : base(null) // 디자인 타임에는 서비스 전달 안 함
    {
        Title = "디자인 타이틀";
        Items = new ObservableCollection<string>
        {
            "사과",
            "바나나 (긴 텍스트 테스트 - 줄바꿈 확인)",
            "포도"
        };
    }
}
```

이렇게 하면 디자인 타임에는 `MyViewModelDesign`의 더미 데이터가, 런타임에는 실제 `MyViewModel`이 바인딩되어 UI가 자연스럽게 보입니다.

## 디자인 타임 감지와 부수효과 차단

API 호출, 파일 읽기, 네이티브 라이브러리 로딩 등은 디자인 타임에 실행되면 프리뷰어가 멈추거나 오류를 발생시킵니다. `Design.IsDesignMode`를 사용해 이런 코드를 조건부로 실행합니다.

```csharp
using Avalonia.Controls;

public class MyViewModel : ReactiveObject
{
    public MyViewModel(IDataService service)
    {
        if (!Design.IsDesignMode)
        {
            // 실제 런타임에만 서비스 사용
            _ = LoadAsync(service);
        }
    }

    private async Task LoadAsync(IDataService svc)
    {
        var items = await svc.GetItemsAsync();
        Items = new ObservableCollection<string>(items);
    }
}
```

- `Design.IsDesignMode`는 프리뷰어에서 실행 중일 때 `true`를 반환합니다.
- 생성자, 속성 초기화, 명령 실행 등 모든 곳에서 이 조건을 사용하여 부수효과를 차단합니다.

## DI 컨테이너에서 디자인/런타임 분리

의존성 주입을 사용하는 경우, 컨테이너를 구성할 때 디자인 타임 여부에 따라 다른 서비스를 등록할 수 있습니다.

```csharp
// App.axaml.cs 또는 Program.cs
var services = new ServiceCollection();

if (Design.IsDesignMode)
{
    services.AddSingleton<IDataService, DummyDataService>();
    services.AddTransient<MyViewModel, MyViewModelDesign>();
}
else
{
    services.AddSingleton<IDataService, RealDataService>();
    services.AddTransient<MyViewModel>();
}
```

디자인 타임에는 `MyViewModelDesign`이 등록되므로 XAML의 `d:DataContext`를 생략해도 자동으로 더미 데이터가 주입될 수 있습니다. 단, 이 경우 코드비하인드에서 DataContext를 직접 설정할 때는 디자인 타임을 다시 체크해야 합니다.

```csharp
public partial class MyView : UserControl
{
    public MyView()
    {
        InitializeComponent();
        if (!Design.IsDesignMode)
        {
            DataContext = App.Services.GetRequiredService<MyViewModel>();
        }
    }
}
```

## 컬렉션, 템플릿, 에러 상태 미리보기

디자인 타임 데이터를 충분히 다양한 경우를 포함하도록 구성하면 UI의 견고성을 미리 검증할 수 있습니다.

### 다양한 항목 포함

```csharp
public class ComplexDesignVM
{
    public ObservableCollection<ComplexItem> Items { get; } = new()
    {
        new ComplexItem { Title = "일반 항목", Description = "짧은 설명", Count = 1, IsActive = true },
        new ComplexItem { Title = "아주아주 긴 제목이 들어간 항목", Description = "이것은 매우 긴 설명 텍스트로, 여러 줄에 걸쳐 줄바꿈이 되는지 확인합니다.", Count = 999, IsActive = false },
        new ComplexItem { Title = "", Description = "제목 없음", Count = 0, IsActive = false }
    };
}
```

### 빈 상태와 오류 상태

```csharp
public class StateDesignVM
{
    public bool HasError { get; set; } = true;
    public string ErrorMessage => HasError ? "데이터를 불러오지 못했습니다. 다시 시도해주세요." : "";
    public bool IsEmpty => !HasError && Items.Count == 0;

    public ObservableCollection<string> Items { get; } = new(); // 비어 있음
}
```

XAML에서는 `DataTrigger`로 상태에 따라 다른 콘텐츠를 보여줄 수 있습니다.

```xml
<ContentControl Content="{Binding}">
    <ContentControl.Styles>
        <Style Selector="ContentControl">
            <Style.Triggers>
                <DataTrigger Binding="{Binding HasError}" Value="True">
                    <Setter Property="Content">
                        <Setter.Value>
                            <TextBlock Text="{Binding ErrorMessage}" Foreground="Red" />
                        </Setter.Value>
                    </Setter>
                </DataTrigger>
                <DataTrigger Binding="{Binding IsEmpty}" Value="True">
                    <Setter Property="Content">
                        <Setter.Value>
                            <TextBlock Text="표시할 항목이 없습니다." Opacity="0.6" />
                        </Setter.Value>
                    </Setter>
                </DataTrigger>
            </Style.Triggers>
        </Style>
    </ContentControl.Styles>
</ContentControl>
```

## 명령(Command) 디자인 타임 처리

ReactiveCommand를 비롯한 명령이 디자인 타임에 실행되면 프리뷰어가 응답을 멈출 수 있습니다. 명령을 Noop(아무 동작도 하지 않는)으로 교체하거나 조건부로 생성합니다.

```csharp
public class CommandDesignVM
{
    public ICommand SaveCommand { get; }

    public CommandDesignVM()
    {
        SaveCommand = Design.IsDesignMode
            ? ReactiveUI.ReactiveCommand.Create(() => { }) // noop
            : ReactiveUI.ReactiveCommand.CreateFromTask(SaveAsync);
    }

    private Task SaveAsync() => Task.CompletedTask; // 실제 저장 로직
}
```

또는 XAML에서 `d:DataContext`로 명령이 없는 더미 ViewModel을 사용해도 됩니다.

## Previewer 친화 설계 체크리스트

- **디자인 타임에만 `d:DataContext` 사용**: DI를 통한 DataContext 주입은 런타임에만 하도록 합니다.
- **`Design.IsDesignMode`로 부수효과 차단**: 파일, 네트워크, 네이티브 라이브러리 접근은 모두 조건부로 실행합니다.
- **긴 텍스트, 빈 데이터, 오류 상태 포함**: 실제 발생할 수 있는 모든 상황을 디자인 타임 데이터에 담습니다.
- **`d:DesignWidth/Height` 지정**: 프리뷰어의 초기 크기를 적절히 설정합니다.
- **명령은 Noop 처리**: 비동기 명령이 디자인 타임에 실행되지 않도록 합니다.

## 자주 발생하는 문제와 해결

| 증상 | 원인 | 해결 |
|------|------|------|
| 프리뷰어가 아예 표시되지 않음 | 디자인 타임에 API 호출이나 파일 I/O가 실행됨 | `Design.IsDesignMode`로 해당 코드를 건너뛰도록 수정 |
| 바인딩 오류가 출력됨 | 디자인 타임 ViewModel이 런타임 ViewModel과 다른 속성 이름을 가짐 | 상속 또는 동일 인터페이스 구현으로 일치시킴 |
| 리스트가 너무 작게 보임 | 더미 데이터가 충분하지 않음 | 다양한 길이의 문자열, 여러 항목 추가 |
| 특정 테마(다크 모드)에서 가독성 문제 | 디자인 타임 테마가 고정됨 | 프리뷰어에서 테마 변경 기능 사용 (Avalonia Previewer 지원) |

## 컴파일 바인딩(Compiled Binding)과의 조화

Avalonia는 `x:DataType`을 사용한 컴파일 바인딩을 지원합니다. 디자인 타임에도 이 기능을 활용하려면 `d:DataContext`가 `x:DataType`으로 지정된 타입의 하위 타입이어야 합니다.

```xml
<UserControl x:DataType="vm:MyViewModel"
             d:DataContext="{x:Static vm:MyViewModelDesign.Instance}">
    <!-- 바인딩 경로가 컴파일 타임에 검증됨 -->
    <TextBlock Text="{Binding Title}" />
</UserControl>
```

디자인 ViewModel이 런타임 ViewModel을 상속하면 형식이 일치하므로 문제없이 작동합니다.

---

## 실전 예제: 마스터-디테일 화면

```csharp
// 런타임 ViewModel
public class ProductListViewModel : ReactiveObject
{
    public ObservableCollection<Product> Items { get; } = new();
    private Product _selected;
    public Product Selected { get => _selected; set => this.RaiseAndSetIfChanged(ref _selected, value); }

    public ProductListViewModel(IDataService svc)
    {
        if (!Design.IsDesignMode)
        {
            _ = LoadAsync(svc);
        }
    }

    private async Task LoadAsync(IDataService svc)
    {
        var data = await svc.GetProductsAsync();
        foreach (var p in data) Items.Add(p);
        Selected = Items.FirstOrDefault();
    }
}

// 디자인 ViewModel
public class ProductListDesignViewModel : ProductListViewModel
{
    public ProductListDesignViewModel() : base(null)
    {
        Items.Add(new Product { Name = "디자인 사과", Price = 1200 });
        Items.Add(new Product { Name = "아주 긴 이름의 바나나 (줄바꿈 확인)", Price = 2300 });
        Items.Add(new Product { Name = "", Price = 0 });
        Selected = Items[1];
    }
}
```

XAML:

```xml
<UserControl d:DataContext="{x:Static vm:ProductListDesignViewModel.Instance}">
    <Grid ColumnDefinitions="2*,3*">
        <ListBox Items="{Binding Items}" SelectedItem="{Binding Selected}">
            <ListBox.ItemTemplate>
                <DataTemplate>
                    <TextBlock Text="{Binding Name}" />
                </DataTemplate>
            </ListBox.ItemTemplate>
        </ListBox>
        <StackPanel Grid.Column="1">
            <TextBlock Text="{Binding Selected.Name}" FontSize="18" />
            <TextBlock Text="{Binding Selected.Price, StringFormat='가격: {0:C}'}" />
        </StackPanel>
    </Grid>
</UserControl>
```

## 결론

Avalonia의 디자인 타임 바인딩 기능을 적극 활용하면 실제 데이터 없이도 UI 레이아웃, 상태 전환, 템플릿 등을 빠르게 검증할 수 있습니다. 핵심은 **`d:DataContext`를 통한 더미 ViewModel 주입**과 **`Design.IsDesignMode`를 이용한 부수효과 차단**입니다. 디자인 타임 데이터를 풍부하게 구성하고, 빈 상태/오류 상태를 함께 검증하면 런타임에 발생할 수 있는 문제를 조기에 발견할 수 있습니다. 이 가이드를 바탕으로 자신의 프로젝트에 맞는 디자인 타임 전략을 세워보세요.
