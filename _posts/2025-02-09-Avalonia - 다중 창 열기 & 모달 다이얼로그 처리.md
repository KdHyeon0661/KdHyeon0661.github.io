# Avalonia: 다중 창 열기 및 모달 다이얼로그 처리

MVVM 패턴에서는 ViewModel이 직접 Window나 Dialog를 생성하는 것을 피해야 한다. 이 글에서는 Avalonia에서 **다중 창을 열고, 모달 다이얼로그를 통해 데이터를 주고받는 방법**을 MVVM 원칙에 맞게 구현하는 방법을 다룬다.

## 기본 개념: 창 열기와 모달

Avalonia에서 새 창을 여는 방법은 간단하다.

```csharp
var window = new MyWindow();
window.Show();           // 비모달 (모든 창과 상호작용 가능)
window.ShowDialog(owner); // 모달 (owner 창에 포커스가 잠김)
```

모달 다이얼로그는 **결과 값을 반환**할 수 있다. `ShowDialog<TResult>`를 사용하면 `Task<TResult>`를 반환받아 `await`로 결과를 기다릴 수 있다.

```csharp
bool result = await dialog.ShowDialog<bool>(owner);
```

## 단순 예제: 코드 비하인드로 창 열기 (학습용)

가장 기본적인 방식은 ViewModel에서 직접 Window를 생성하는 것이다. 이 방식은 MVVM 원칙에 위배되지만, 개념을 이해하는 데 도움이 된다.

**DetailWindow.xaml**

```xml
<Window xmlns="https://github.com/avaloniaui"
        x:Class="MyApp.Views.DetailWindow"
        Width="400" Height="300"
        WindowStartupLocation="CenterOwner">
  <StackPanel Margin="20" Spacing="8">
    <TextBlock Text="{Binding Title}" FontSize="18"/>
    <TextBlock Text="{Binding Description}"/>
    <Button Content="닫기" HorizontalAlignment="Right" Click="OnClose"/>
  </StackPanel>
</Window>
```

**DetailWindow.xaml.cs**

```csharp
public partial class DetailWindow : Window
{
    public DetailWindow() => InitializeComponent();
    private void OnClose(object? sender, RoutedEventArgs e) => Close();
}
```

**DetailViewModel**

```csharp
public class DetailViewModel : ReactiveObject
{
    public DetailViewModel(string title, string description)
    {
        Title = title;
        Description = description;
    }
    public string Title { get; }
    public string Description { get; }
}
```

**MainViewModel에서 호출**

```csharp
private void OpenDetail()
{
    var vm = new DetailViewModel("상세 정보", "MVVM으로 전달된 데이터입니다.");
    var win = new DetailWindow { DataContext = vm };
    win.Show(GetMainWindow()); // Owner 지정
}
```

이 방식은 ViewModel이 Window 타입을 직접 참조하게 되어 **UI 의존성이 생기고 테스트가 어렵다**. 따라서 실무에서는 추상화 계층을 도입한다.

## 모달 다이얼로그: 강타입 결과 반환

모달 다이얼로그는 `ShowDialog<TResult>`를 통해 결과를 받을 수 있다. 닫을 때는 `Close(result)`를 호출한다.

**ConfirmDialog.xaml**

```xml
<Window xmlns="https://github.com/avaloniaui"
        x:Class="MyApp.Views.ConfirmDialog"
        Width="300" Height="150"
        WindowStartupLocation="CenterOwner">
  <StackPanel Margin="20" Spacing="10">
    <TextBlock Text="{Binding Message}"/>
    <StackPanel Orientation="Horizontal" HorizontalAlignment="Center" Spacing="10">
      <Button Content="예" Click="YesClick"/>
      <Button Content="아니오" Click="NoClick"/>
    </StackPanel>
  </StackPanel>
</Window>
```

**ConfirmDialog.xaml.cs**

```csharp
public partial class ConfirmDialog : Window
{
    public ConfirmDialog() => InitializeComponent();
    private void YesClick(object? s, RoutedEventArgs e) => Close(true);
    private void NoClick(object? s, RoutedEventArgs e) => Close(false);
}
```

**ViewModel에서 호출**

```csharp
private async Task<bool> AskUserAsync(string question)
{
    var vm = new ConfirmDialogViewModel(question);
    var dlg = new ConfirmDialog { DataContext = vm };
    var owner = (Window)Application.Current?.ApplicationLifetime?.MainWindow;
    return await dlg.ShowDialog<bool>(owner);
}
```

> **주의**: X 버튼이나 ESC 키로 닫을 경우 `default(bool)` (즉 `false`)가 반환된다.

## MVVM 친화적 추상화: 서비스 계층 도입

ViewModel이 Window를 직접 생성하지 않도록 **창/대화상자 서비스**를 인터페이스로 분리한다.

```csharp
public interface IWindowService
{
    void ShowWindow(object viewModel, Window? owner = null);
}

public interface IDialogService
{
    Task<TResult> ShowDialogAsync<TResult>(object viewModel, Window? owner = null);
}
```

**ViewLocator**: ViewModel에 해당하는 Window를 생성해주는 역할

```csharp
public class ViewLocator
{
    public Window? BuildWindow(object viewModel)
    {
        return viewModel switch
        {
            DetailViewModel => new DetailWindow { DataContext = viewModel },
            ConfirmDialogViewModel => new ConfirmDialog { DataContext = viewModel },
            _ => null
        };
    }
}
```

**WindowService 구현**

```csharp
public class WindowService : IWindowService
{
    private readonly ViewLocator _locator = new();

    public void ShowWindow(object viewModel, Window? owner = null)
    {
        var window = _locator.BuildWindow(viewModel);
        if (window == null) throw new InvalidOperationException("No view found");

        window.Show(owner ?? GetMainWindow());
    }

    private static Window GetMainWindow() =>
        (Window)Application.Current!.ApplicationLifetime!.MainWindow!;
}
```

**DialogService 구현**

```csharp
public class DialogService : IDialogService
{
    private readonly ViewLocator _locator = new();

    public async Task<TResult> ShowDialogAsync<TResult>(object viewModel, Window? owner = null)
    {
        var window = _locator.BuildWindow(viewModel);
        if (window == null) throw new InvalidOperationException("No view found");

        return await window.ShowDialog<TResult>(owner ?? GetMainWindow());
    }

    private static Window GetMainWindow() =>
        (Window)Application.Current!.ApplicationLifetime!.MainWindow!;
}
```

**MainViewModel에서 사용**

```csharp
public class MainViewModel : ReactiveObject
{
    private readonly IWindowService _windowService;
    private readonly IDialogService _dialogService;

    public MainViewModel(IWindowService ws, IDialogService ds)
    {
        _windowService = ws;
        _dialogService = ds;
    }

    public ReactiveCommand<Unit, Unit> OpenDetailCommand { get; }
    public ReactiveCommand<Unit, Unit> DeleteCommand { get; }

    private void OpenDetail()
    {
        var vm = new DetailViewModel("제목", "내용");
        _windowService.ShowWindow(vm);
    }

    private async Task DeleteAsync()
    {
        var confirm = new ConfirmDialogViewModel("정말 삭제하시겠습니까?");
        bool ok = await _dialogService.ShowDialogAsync<bool>(confirm);
        if (ok) { /* 삭제 로직 */ }
    }
}
```

이제 ViewModel은 **테스트하기 쉬워진다**. Mock으로 서비스를 대체하여 호출 여부를 검증할 수 있다.

## 더 완벽한 분리: ReactiveUI Interaction

ReactiveUI는 `Interaction<TIn, TOut>` 클래스를 제공해 ViewModel이 UI 상호작용을 요청하고 View가 실제 UI를 띄우는 패턴을 지원한다.

**ViewModel**

```csharp
public class MainViewModel : ReactiveObject
{
    public Interaction<ConfirmDialogViewModel, bool> ConfirmInteraction { get; } = new();

    public ReactiveCommand<Unit, Unit> DeleteCommand { get; }

    public MainViewModel()
    {
        DeleteCommand = ReactiveCommand.CreateFromTask(DeleteAsync);
    }

    private async Task DeleteAsync()
    {
        var confirm = new ConfirmDialogViewModel("삭제하시겠습니까?");
        bool result = await ConfirmInteraction.Handle(confirm);
        if (result) { /* 삭제 */ }
    }
}
```

**View (MainView.xaml.cs)**

```csharp
public partial class MainView : UserControl
{
    public MainView() => InitializeComponent();

    protected override void OnDataContextChanged(EventArgs e)
    {
        base.OnDataContextChanged(e);
        if (DataContext is MainViewModel vm)
        {
            vm.ConfirmInteraction.RegisterHandler(async ctx =>
            {
                var dlg = new ConfirmDialog { DataContext = ctx.Input };
                var result = await dlg.ShowDialog<bool>(GetMainWindow());
                ctx.SetOutput(result);
            });
        }
    }

    private static Window GetMainWindow() =>
        (Window)Application.Current!.ApplicationLifetime!.MainWindow!;
}
```

장점: ViewModel은 UI 프레임워크에 대한 어떤 의존성도 없으며, 테스트에서는 `Interaction`을 직접 호출해 결과를 주입할 수 있다.

## 고급 UX: 창 위치/크기 복원, 닫기 방지

### 위치/크기 복원

창이 닫힐 때 위치와 크기를 저장하고, 다시 열 때 복원하는 기능은 사용자 경험을 크게 향상시킨다.

```csharp
public static class WindowPersistence
{
    private static string GetPath() =>
        Path.Combine(Environment.GetFolderPath(Environment.SpecialFolder.ApplicationData),
                     "MyApp", "window_state.json");

    public static void Save(Window window)
    {
        var state = new
        {
            window.Width,
            window.Height,
            X = window.Position.X,
            Y = window.Position.Y,
            window.WindowState
        };
        var json = JsonSerializer.Serialize(state);
        File.WriteAllText(GetPath(), json);
    }

    public static void Restore(Window window)
    {
        if (!File.Exists(GetPath())) return;
        try
        {
            var json = File.ReadAllText(GetPath());
            var state = JsonSerializer.Deserialize<dynamic>(json);
            if (state != null)
            {
                window.Width = state.Width;
                window.Height = state.Height;
                window.WindowStartupLocation = WindowStartupLocation.Manual;
                window.Position = new PixelPoint((int)state.X, (int)state.Y);
                window.WindowState = state.WindowState;
            }
        }
        catch { /* 무시 */ }
    }
}
```

Window 생성자에서 `Opened`와 `Closing` 이벤트에 연결한다.

```csharp
public partial class DetailWindow : Window
{
    public DetailWindow()
    {
        InitializeComponent();
        Opened += (_, _) => WindowPersistence.Restore(this);
        Closing += (_, _) => WindowPersistence.Save(this);
    }
}
```

### 닫기 방지 (ICloseGuard)

사용자가 저장하지 않은 변경사항이 있을 때 닫기를 막으려면 `ICloseGuard` 인터페이스를 정의하고 `Window.Closing` 이벤트에서 확인한다.

```csharp
public interface ICloseGuard
{
    bool CanClose();
}

public static class CloseGuardBehavior
{
    public static void Attach(Window window)
    {
        window.Closing += (s, e) =>
        {
            if (window.DataContext is ICloseGuard guard && !guard.CanClose())
                e.Cancel = true;
        };
    }
}
```

ViewModel에서 구현:

```csharp
public class EditViewModel : ReactiveObject, ICloseGuard
{
    private bool _isDirty;
    public bool IsDirty
    {
        get => _isDirty;
        set => this.RaiseAndSetIfChanged(ref _isDirty, value);
    }

    public bool CanClose() => !IsDirty;
}
```

Window 생성자에서 `CloseGuardBehavior.Attach(this);`를 호출한다.

## 파일/폴더 다이얼로그

Avalonia는 기본 파일/폴더 선택 다이얼로그를 제공한다.

```csharp
var ofd = new OpenFileDialog
{
    Title = "이미지 선택",
    AllowMultiple = false,
    Filters = { new FileDialogFilter { Name = "Images", Extensions = { "png", "jpg" } } }
};
var result = await ofd.ShowAsync(owner);
if (result?.Length > 0)
    selectedPath = result[0];
```

폴더 선택은 `OpenFolderDialog`를 사용한다.

```csharp
var fbd = new OpenFolderDialog { Title = "폴더 선택" };
var folder = await fbd.ShowAsync(owner);
```

## 의존성 주입 (DI) 설정

App.axaml.cs에서 서비스와 ViewModel을 등록한다.

```csharp
public override void OnFrameworkInitializationCompleted()
{
    var services = new ServiceCollection();
    services.AddSingleton<IWindowService, WindowService>();
    services.AddSingleton<IDialogService, DialogService>();
    services.AddTransient<MainViewModel>();
    services.AddTransient<DetailViewModel>();
    services.AddTransient<ConfirmDialogViewModel>();

    var sp = services.BuildServiceProvider();

    var mainWindow = new Window
    {
        Content = new MainView(),
        DataContext = sp.GetRequiredService<MainViewModel>()
    };
    mainWindow.Show();

    if (ApplicationLifetime is IClassicDesktopStyleApplicationLifetime desktop)
        desktop.MainWindow = mainWindow;

    base.OnFrameworkInitializationCompleted();
}
```

## 정리: 패턴별 권장 사항

| 상황 | 권장 패턴 |
|------|-----------|
| 단순한 창 열기 | `IWindowService` |
| 모달 다이얼로그 (결과 반환) | `IDialogService` 또는 ReactiveUI `Interaction` |
| 완전한 UI 분리 | ReactiveUI `Interaction` |
| 창 상태 복원 | `WindowPersistence` + `Opened`/`Closing` |
| 닫기 방지 | `ICloseGuard` + `Closing` 이벤트 |
| 파일/폴더 선택 | `OpenFileDialog` / `OpenFolderDialog` |

## 결론

Avalonia에서 다중 창과 모달 다이얼로그를 MVVM 패턴으로 구현하려면 **서비스 추상화**가 핵심이다. `IWindowService`와 `IDialogService`를 도입하면 ViewModel이 UI에 의존하지 않게 되어 테스트와 유지보수가 쉬워진다. 더 나아가 ReactiveUI의 `Interaction`을 사용하면 ViewModel에서 UI 상호작용을 선언적으로 표현할 수 있다. 추가로 창 상태 복원, 닫기 방지 등 사용자 경험을 높이는 기능도 함께 구현하면 완성도 있는 애플리케이션을 만들 수 있다.
