# 리눅스 시스템 시간 동기화

## 왜 시간 동기화가 중요한가

분산 시스템에서 서버 간 시간이 다르면 로그 분석이 어려워지고, SSL 인증서 검증, 데이터베이스 복제, 컨테이너 오케스트레이션 등 많은 서비스가 오작동할 수 있다.  
따라서 모든 시스템은 정확한 시간 기준(UTC)으로 동기화되어야 한다.

---

## 핵심 개념

| 용어 | 의미 |
|------|------|
| **오프셋(Offset)** | 내 시스템 시계와 기준 시간의 차이 (초) |
| **지연(Delay)** | NTP 요청-응답 왕복 시간 |
| **지터(Jitter)** | 시간 측정값의 변동성 (분산) |
| **스트라텀(Stratum)** | 시간 소스의 계층 (1=가장 정확, 2=1을 참조, …) |
| **Slew** | 시계 속도를 서서히 조정 (애플리케이션 영향 최소) |
| **Step** | 시계를 즉시 점프 (큰 오차 빠르게 수정, 일부 앱에 영향) |
| **드리프트(Drift)** | 하드웨어 오실레이터의 고유 오차 (driftfile로 보정) |

### NTP 기본 계산식

클라이언트가 NTP 서버에 요청을 보낼 때 각각의 타임스탬프:
- \(t_1\) : 클라이언트 전송 시간
- \(t_2\) : 서버 수신 시간
- \(t_3\) : 서버 전송 시간
- \(t_4\) : 클라이언트 수신 시간

왕복 지연 \(\delta\)와 오프셋 \(\theta\)는 다음과 같이 계산된다.

$$
\delta = (t_4 - t_1) - (t_3 - t_2),\quad
\theta = \frac{(t_2 - t_1) + (t_3 - t_4)}{2}
$$

\(\delta\)가 작을수록 네트워크 경로가 대칭적이며, \(\theta\) 추정이 정확해진다.

## NTP 도구 비교

| 도구 | 특징 | 권장 사용처 |
|------|------|------------|
| **ntpd** | 전통적 NTP 데몬, 안정성 높음 | 레거시 시스템, 특수 구성 |
| **chronyd** | 현대적 구현, 빠른 수렴, 가상 환경에 강함 | 대부분의 서버, VM, 클라우드 |
| **systemd-timesyncd** | systemd 내장, 간단한 클라이언트 | 단순 데스크톱, 임베디드 |

## chronyd (권장)

### 설치 및 상태 확인

```bash
sudo apt install chrony   # Debian/Ubuntu
sudo systemctl enable --now chronyd

# 상태 확인
chronyc tracking          # 오프셋, 드리프트, 참조 소스 등
chronyc sources -v        # NTP 서버 목록과 상태
```

`chronyc tracking` 출력 주요 항목:
- `Reference ID` : 현재 참조 중인 NTP 서버
- `Stratum` : 해당 서버의 계층
- `Offset` : 현재 시스템 시계와의 차이 (초)
- `Leap status` : 윤초 상태

### 기본 설정 파일 (`/etc/chrony/chrony.conf`)

```conf
# 한국 NTP 풀 사용 (iburst: 빠른 초기 동기화)
pool 0.kr.pool.ntp.org iburst
pool 1.kr.pool.ntp.org iburst

# 큰 오차(1초 이상)는 첫 3번까지 즉시 Step으로 수정
makestep 1.0 3

# 하드웨어 시계(RTC)에 드리프트 반영
rtcsync

# 드리프트 파일 위치
driftfile /var/lib/chrony/chrony.drift
```

### 수동 동기화

```bash
# 즉시 시간을 step으로 맞추기
sudo chronyc makestep
```

## ntpd (전통)

### 설치 및 기본 명령

```bash
sudo apt install ntp        # Debian/Ubuntu
sudo systemctl enable --now ntp

ntpq -p                     # 피어 상태 (서버 목록)
ntpstat                     # 동기화 상태 간략 출력
```

`ntpq -p` 출력에서 `*`는 현재 선택된 서버, `+`는 후보, `-`는 제외된 서버를 의미한다.

### 기본 설정 파일 (`/etc/ntp.conf`)

```conf
pool 0.kr.pool.ntp.org iburst
pool 1.kr.pool.ntp.org iburst

driftfile /var/lib/ntp/ntp.drift

# 접근 제한 (보안)
restrict default kod nomodify notrap nopeer noquery
restrict 127.0.0.1
```

### 큰 오차 한 번에 동기화

```bash
sudo systemctl stop ntp
sudo ntpd -gq        # -g: 큰 오차 허용, -q: 한 번 실행 후 종료
sudo systemctl start ntp
```

## systemd-timesyncd (경량 클라이언트)

### 설정 및 상태 확인

```bash
timedatectl status                     # NTP 활성화 여부 확인
timedatectl set-ntp true               # NTP 동기화 켜기
timedatectl set-timezone Asia/Seoul    # 시간대 설정
```

설정 파일 `/etc/systemd/timesyncd.conf`:

```conf
[Time]
NTP=0.kr.pool.ntp.org 1.kr.pool.ntp.org
FallbackNTP=ntp.ubuntu.com
```

```bash
sudo systemctl restart systemd-timesyncd
```

## 방화벽 및 보안

NTP는 UDP 123번 포트를 사용한다.  
- **클라이언트** : 외부 NTP 서버로의 아웃바운드 UDP/123 허용
- **서버** : 내부 클라이언트에서 인바운드 UDP/123 허용 + 특정 네트워크만 접근 허용

`chronyd`에서 특정 네트워크만 허용하려면 `/etc/chrony/chrony.conf`에 추가:

```conf
allow 192.168.1.0/24
```

## 가상 환경 및 컨테이너

- **가상 머신** : 하이퍼바이저가 시간을 공유하면 정밀도가 떨어질 수 있다. VM 내부에서 `chronyd`를 실행하고 `makestep`을 활성화하여 스냅샷 복원 후 빠르게 재동기화한다.
- **컨테이너(Docker, Kubernetes)** : 컨테이너는 호스트 커널의 시간을 공유한다. 따라서 **호스트**에서 NTP 데몬을 실행하고, 컨테이너 내부에서는 따로 설정하지 않는다.

## 모니터링 예제

간단한 오프셋 경고 스크립트 (`chronyc` 사용):

```bash
#!/bin/bash
THRESHOLD=0.100   # 100ms
OFFSET=$(chronyc tracking | awk '/Last offset/ {print $4}')
if (( $(echo "$OFFSET > $THRESHOLD" | bc -l) )); then
    echo "경고: 시간 오프셋이 ${OFFSET}초로 임계값(${THRESHOLD}초) 초과"
    exit 1
fi
```

## 결론

- **chronyd**는 빠른 수렴, 동적 환경 적응, 서버/클라이언트 모두에 적합한 현대적 도구이므로 대부분의 시스템에 권장된다.
- **ntpd**는 레거시 환경이나 특정 구성이 필요할 때 사용한다.
- **systemd-timesyncd**는 간단한 클라이언트 용도로 충분하다.
- 시간 동기화는 인증서 검증, 로그 분석, 분산 시스템 일관성의 기반이므로 방화벽 정책과 함께 운영 자동화(Ansible 등)의 대상으로 삼아야 한다.
