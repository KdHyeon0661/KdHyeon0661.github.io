# C# 포인터: unsafe 코드와 메모리 직접 접근

C#은 기본적으로 안전한 코드를 지향하지만, 성능 최적화나 네이티브 코드와의 상호 운용이 필요한 상황에서는 메모리를 직접 다루어야 할 때가 있습니다. 이때 C#은 `unsafe` 키워드를 통해 포인터 같은 저수준 기능을 제공합니다. 이 기능들은 강력하지만, 잘못 사용하면 메모리 손상, 보안 취약점, 애플리케이션 충돌 같은 심각한 문제를 일으킬 수 있습니다.

포인터를 이해하는 것은 최신 C#의 `Span<T>`, `Memory<T>` 같은 고성능 메모리 접근 기능을 이해하는 데도 도움이 됩니다.

---

## unsafe 컨텍스트와 포인터 기초

### 포인터란?

포인터는 메모리 주소를 저장하는 변수입니다. C#에서 포인터 타입은 타입 이름 뒤에 `*`를 붙여 표시합니다. 포인터를 사용하려면 `unsafe` 키워드로 표시된 블록이나 메서드 내에서 작업해야 합니다.

```csharp
unsafe static void Main()
{
    int value = 10;
    int* pointer = &value;   // value의 주소를 pointer에 저장
    
    Console.WriteLine($"값: {value}");            // 10
    Console.WriteLine($"주소: {(long)pointer:X}"); // 메모리 주소
    Console.WriteLine($"포인터를 통한 값: {*pointer}"); // 역참조: 10
    
    *pointer = 20;           // 포인터로 값 변경
    Console.WriteLine($"변경된 값: {value}");      // 20
}
```

프로젝트에서 unsafe 코드를 허용하려면 `.csproj` 파일에 다음을 추가합니다.

```xml
<PropertyGroup>
  <AllowUnsafeBlocks>true</AllowUnsafeBlocks>
</PropertyGroup>
```

### 주소 연산자(&)와 역참조 연산자(*)

- `&` : 변수의 메모리 주소를 얻습니다.
- `*` : 포인터가 가리키는 주소의 값을 읽거나 씁니다.

```csharp
unsafe static void Basics()
{
    int number = 100;
    int* ptr = &number;
    int value = *ptr;          // 역참조: 100
    *ptr = 200;                // 값 변경
    Console.WriteLine(number); // 200
}
```

### 포인터 산술

포인터에 정수를 더하거나 빼면 포인터 타입의 크기만큼 주소가 이동합니다. 예를 들어 `int*`에 1을 더하면 4바이트(32비트 환경)가 증가합니다.

```csharp
unsafe static void Arithmetic()
{
    int[] numbers = { 10, 20, 30, 40, 50 };
    fixed (int* ptr = &numbers[0])   // 배열 고정
    {
        int* second = ptr + 2;       // 세 번째 요소(인덱스 2)
        Console.WriteLine(*second);  // 30
        
        long diff = second - ptr;     // 요소 개수 차이: 2
        Console.WriteLine(diff);
        
        Console.WriteLine(ptr[3]);    // 인덱서 사용: 40
    }
}
```

### 구조체 포인터와 화살표 연산자(->)

구조체를 포인터로 다룰 때는 `->` 연산자를 사용하여 멤버에 접근합니다.

```csharp
unsafe struct Point { public int X; public int Y; }

unsafe static void StructPtr()
{
    Point point = new Point { X = 5, Y = 10 };
    Point* ptr = &point;
    Console.WriteLine($"X: {ptr->X}, Y: {ptr->Y}"); // X: 5, Y: 10
    ptr->X = 100;
    Console.WriteLine(point.X); // 100
}
```

## fixed: 가비지 컬렉터와의 상호작용

C#의 가비지 컬렉터(GC)는 메모리를 효율적으로 관리하기 위해 객체를 힙 내에서 이동시킬 수 있습니다. 따라서 관리되는 객체(배열, 문자열 등)의 주소를 포인터로 직접 가리키면 GC가 객체를 옮긴 후에 포인터가 잘못된 주소를 가리키게 됩니다.

이 문제를 해결하기 위해 `fixed` 키워드를 사용합니다. `fixed` 블록 내에서는 해당 객체가 GC에 의해 이동되지 않도록 **고정**합니다.

```csharp
unsafe static void FixedExample()
{
    int[] array = { 1, 2, 3, 4, 5 };
    
    fixed (int* ptr = array)   // 배열 고정
    {
        for (int i = 0; i < array.Length; i++)
            Console.WriteLine(ptr[i]); // 안전하게 접근
    } // 블록 끝에서 고정 해제
}
```

`fixed`는 여러 변수를 한 번에 고정할 수 있습니다.

```csharp
fixed (int* px = &x, py = &y, pz = &z)
{
    // ...
}
```

**주의**: `fixed` 블록을 가능한 짧게 유지하세요. 장시간 메모리를 고정하면 GC 효율이 저하되고 메모리 단편화를 일으킬 수 있습니다.

## stackalloc: 스택 메모리 할당

`stackalloc`은 스택에 메모리를 할당합니다. 할당된 메모리는 메서드가 반환될 때 자동으로 해제됩니다. 크기가 작고 수명이 짧은 임시 버퍼에 유용합니다.

```csharp
unsafe static void StackAllocExample()
{
    int* buffer = stackalloc int[10];   // 스택에 10개의 int 공간
    for (int i = 0; i < 10; i++)
        buffer[i] = i * 2;
    
    for (int i = 0; i < 10; i++)
        Console.WriteLine(buffer[i]);
}
```

C# 7.2부터는 `stackalloc`을 `Span<T>`와 함께 사용하면 `unsafe` 없이도 안전하게 사용할 수 있습니다.

```csharp
static void SafeStackAlloc()
{
    Span<int> buffer = stackalloc int[10];  // unsafe 불필요
    for (int i = 0; i < buffer.Length; i++)
        buffer[i] = i * 3;
    foreach (var v in buffer) Console.WriteLine(v);
}
```

**주의**: 스택은 크기가 제한되어 있으므로 큰 크기를 할당하면 스택 오버플로가 발생할 수 있습니다.

## IntPtr, nint, GCHandle: 포인터 래퍼

### IntPtr와 nint

`IntPtr`는 플랫폼에 따라 크기가 달라지는 정수 타입으로, 포인터를 안전하게 저장하고 전달하는 데 사용됩니다. `nint`(C# 9.0+)는 `IntPtr`의 네이티브 정수 형태입니다.

```csharp
unsafe static void IntPtrExample()
{
    int value = 42;
    int* ptr = &value;
    IntPtr intPtr = (IntPtr)ptr;          // 포인터 → IntPtr
    int* ptr2 = (int*)intPtr;             // IntPtr → 포인터
    Console.WriteLine(*ptr2);             // 42
}
```

### GCHandle: 수동 메모리 고정

`GCHandle`을 사용하면 `fixed` 블록 없이도 객체를 수동으로 고정할 수 있습니다. 주로 네이티브 코드에 메모리 주소를 전달할 때 사용합니다.

```csharp
unsafe static void GCHandleExample()
{
    byte[] data = new byte[100];
    GCHandle handle = GCHandle.Alloc(data, GCHandleType.Pinned);
    try
    {
        IntPtr address = handle.AddrOfPinnedObject();
        byte* ptr = (byte*)address;
        for (int i = 0; i < data.Length; i++)
            ptr[i] = (byte)i;
    }
    finally
    {
        handle.Free(); // 반드시 해제
    }
}
```

## Span<T>와 Memory<T>: 안전한 고성능 메모리 접근

`Span<T>`는 연속된 메모리 영역을 나타내는 값 타입입니다. 포인터보다 안전하면서도 비슷한 성능을 제공합니다. 힙, 스택, 비관리 메모리 등 다양한 곳에 있는 메모리를 표현할 수 있습니다.

```csharp
static void SpanExample()
{
    int[] array = { 1, 2, 3, 4, 5 };
    Span<int> span = array.AsSpan();          // 배열을 Span으로
    Span<int> slice = span.Slice(1, 3);       // 인덱스 1부터 3개
    slice[0] = 100;                           // 원본 배열도 변경됨
    Console.WriteLine(array[1]);              // 100
}
```

`ReadOnlySpan<char>`로 문자열을 효율적으로 처리할 수 있습니다.

```csharp
ReadOnlySpan<char> text = "Hello, World!".AsSpan();
ReadOnlySpan<char> hello = text.Slice(0, 5);
Console.WriteLine(hello.ToString()); // Hello
```

`Memory<T>`는 `Span<T>`와 유사하지만 비동기 코드나 클래스 필드에 저장할 수 있습니다. `MemoryPool<T>`를 사용하면 배열 풀에서 메모리를 임대할 수 있습니다.

```csharp
using System.Buffers;

static void MemoryExample()
{
    using IMemoryOwner<int> owner = MemoryPool<int>.Shared.Rent(100);
    Memory<int> memory = owner.Memory;
    Span<int> span = memory.Span;
    for (int i = 0; i < span.Length; i++)
        span[i] = i;
}
```

## 실전 예제: 포인터를 이용한 이미지 밝기 조정

다음 예제는 포인터를 사용하여 이미지 데이터의 밝기를 빠르게 조정합니다. `Span<T>` 버전과 함께 성능을 비교할 수 있습니다.

```csharp
unsafe class ImageProcessor
{
    public static void AdjustBrightness(byte[] imageData, float factor)
    {
        fixed (byte* ptr = imageData)
        {
            byte* current = ptr;
            byte* end = ptr + imageData.Length;
            while (current < end)
            {
                int val = (int)(*current * factor);
                *current = (byte)Math.Clamp(val, 0, 255);
                current++;
            }
        }
    }
    
    public static void AdjustBrightnessSpan(Span<byte> data, float factor)
    {
        for (int i = 0; i < data.Length; i++)
        {
            int val = (int)(data[i] * factor);
            data[i] = (byte)Math.Clamp(val, 0, 255);
        }
    }
}
```

## 주의사항과 모범 사례

### 포인터 사용 시 주의사항

- **잘못된 메모리 접근**: 포인터 연산으로 유효하지 않은 주소에 접근하면 애플리케이션이 충돌합니다.
- **GC 이동**: `fixed` 없이 관리 객체의 주소를 사용하지 마세요.
- **정렬**: 일부 플랫폼에서는 정렬되지 않은 메모리 접근이 느리거나 예외를 발생시킬 수 있습니다.
- **리소스 정리**: `GCHandle`이나 비관리 메모리를 사용한 후에는 반드시 정리하세요.

### 모범 사례

1. **필요할 때만 사용**: 대부분의 경우 `Span<T>`나 `Memory<T>`로 충분합니다.
2. **최소 범위**: `fixed` 블록을 가능한 짧게 유지하세요.
3. **경계 검사**: 포인터 연산 시 항상 범위를 확인하세요.
4. **코드 문서화**: unsafe 코드는 왜 필요한지 명확히 문서화하세요.

### 대안 우선 순위

성능이 중요한 작업을 할 때는 다음 순서로 접근하는 것이 좋습니다.

1. **일반적인 C# 코드**로 시작
2. 필요하면 **Span<T>/Memory<T>** 사용
3. 정말 필요할 때만 **unsafe 포인터** 사용

## 결론

C#의 포인터 기능은 네이티브 코드와의 상호 운용이나 극한의 성능 최적화가 필요할 때 매우 유용합니다. 하지만 올바르게 사용하지 않으면 메모리 손상이나 애플리케이션 충돌을 일으킬 수 있습니다.

**핵심 원칙**:
- **필요할 때만 사용하세요**: 먼저 `Span<T>` 같은 안전한 대안을 고려하세요.
- **안전을 최우선으로**: `fixed`로 GC 문제를 방지하고, 범위를 확인하세요.
- **성능 측정하세요**: 실제로 포인터가 필요한지 검증하세요.
- **최신 기능을 활용하세요**: `stackalloc`과 `Span<T>`의 조합 등 더 안전한 방법을 먼저 고려하세요.

포인터는 C#의 비상 탈출구와 같습니다. 필요한 상황에만 신중하게 사용하면 성능과 안전성 사이의 균형을 잘 유지할 수 있습니다.
