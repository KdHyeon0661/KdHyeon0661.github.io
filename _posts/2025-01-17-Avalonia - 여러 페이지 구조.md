# Avalonia MVVM: 여러 페이지 구조

Avalonia 애플리케이션에서 여러 화면(페이지)을 관리하는 방법은 프로젝트 규모와 요구사항에 따라 달라집니다. 이 글에서는 단순한 탭 방식부터 `ContentControl`을 활용한 동적 전환, 그리고 스택 기반 네비게이션 서비스를 통한 확장 가능한 구조까지 단계별로 설명합니다. 초중급 개발자를 대상으로 하며, ReactiveUI를 기반으로 MVVM 패턴을 적용합니다.

---

## 1. 간단한 탭 방식

가장 단순한 방법은 `TabControl`을 사용하는 것입니다. 페이지 수가 고정되어 있고 복잡한 전환이 필요 없는 경우에 적합합니다.

### MainView.axaml

```xml
<UserControl xmlns="https://github.com/avaloniaui"
             xmlns:views="clr-namespace:MyAvaloniaApp.Views"
             x:Class="MyAvaloniaApp.Views.MainView">

  <TabControl SelectedIndex="{Binding SelectedTab}">
    <TabItem Header="대시보드">
      <views:DashboardView />
    </TabItem>
    <TabItem Header="설정">
      <views:SettingsView />
    </TabItem>
    <TabItem Header="정보">
      <views:AboutView />
    </TabItem>
  </TabControl>
</UserControl>
```

### MainViewModel.cs

```csharp
using ReactiveUI;

public class MainViewModel : ReactiveObject
{
    private int _selectedTab;
    public int SelectedTab
    {
        get => _selectedTab;
        set => this.RaiseAndSetIfChanged(ref _selectedTab, value);
    }
}
```

**장점**: 구현이 매우 빠르고 직관적입니다.  
**단점**: 페이지가 동적으로 추가되거나, 화면 간 상태 공유, 뒤로 가기 등이 필요하면 확장이 어렵습니다.

## 2. 메뉴 + ContentControl (동적 전환)

Avalonia의 `ContentControl`과 `DataTemplate`을 활용하면 ViewModel만 교체해도 해당 View가 자동으로 표시됩니다. 이 방식은 대부분의 일반적인 다중 페이지 앱에 적합합니다.

### App.axaml – DataTemplate 등록

각 ViewModel 타입에 맞는 View를 매핑합니다.

```xml
<Application xmlns="https://github.com/avaloniaui"
             xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
             xmlns:views="clr-namespace:MyAvaloniaApp.Views"
             xmlns:vm="clr-namespace:MyAvaloniaApp.ViewModels"
             x:Class="MyAvaloniaApp.App">

  <Application.DataTemplates>
    <DataTemplate DataType="{x:Type vm:DashboardViewModel}">
      <views:DashboardView/>
    </DataTemplate>
    <DataTemplate DataType="{x:Type vm:SettingsViewModel}">
      <views:SettingsView/>
    </DataTemplate>
    <DataTemplate DataType="{x:Type vm:AboutViewModel}">
      <views:AboutView/>
    </DataTemplate>
  </Application.DataTemplates>

  <Application.Styles>
    <FluentTheme Mode="Light"/>
  </Application.Styles>
</Application>
```

### MainView.axaml

```xml
<UserControl xmlns="https://github.com/avaloniaui"
             xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
             x:Class="MyAvaloniaApp.Views.MainView">

  <DockPanel>
    <Menu DockPanel.Dock="Top">
      <MenuItem Header="페이지">
        <MenuItem Header="대시보드" Command="{Binding ShowDashboardCommand}" />
        <MenuItem Header="설정" Command="{Binding ShowSettingsCommand}" />
        <MenuItem Header="정보" Command="{Binding ShowAboutCommand}" />
      </MenuItem>
    </Menu>

    <ContentControl Content="{Binding CurrentViewModel}" />
  </DockPanel>
</UserControl>
```

### MainViewModel.cs

```csharp
using ReactiveUI;
using System.Reactive;

public class MainViewModel : ReactiveObject
{
    private object? _current;
    public object? CurrentViewModel
    {
        get => _current;
        set => this.RaiseAndSetIfChanged(ref _current, value);
    }

    public ReactiveCommand<Unit, Unit> ShowDashboardCommand { get; }
    public ReactiveCommand<Unit, Unit> ShowSettingsCommand  { get; }
    public ReactiveCommand<Unit, Unit> ShowAboutCommand     { get; }

    public MainViewModel()
    {
        ShowDashboardCommand = ReactiveCommand.Create(() => CurrentViewModel = new DashboardViewModel());
        ShowSettingsCommand  = ReactiveCommand.Create(() => CurrentViewModel = new SettingsViewModel());
        ShowAboutCommand     = ReactiveCommand.Create(() => CurrentViewModel = new AboutViewModel());

        CurrentViewModel = new DashboardViewModel(); // 초기 화면
    }
}
```

**장점**: ViewModel만 교체하면 되므로 확장이 쉽고, 각 화면의 수명 주기를 독립적으로 관리할 수 있습니다.

## 3. 네비게이션 서비스 도입 (스택 기반)

화면 간 앞/뒤 이동, 전환 가드, 파라미터 전달 등이 필요하면 네비게이션 서비스를 도입하는 것이 좋습니다. 여기서는 `INavigationService` 인터페이스와 간단한 스택 기반 구현을 소개합니다.

### INavigationService 인터페이스

```csharp
using System.Collections.Generic;

public interface INavigationService
{
    object? Current { get; }
    IReadOnlyList<NavigationEntry> BackStack { get; }
    IReadOnlyList<NavigationEntry> ForwardStack { get; }
    bool CanGoBack { get; }
    bool CanGoForward { get; }

    void Navigate(object viewModel);
    void GoBack();
    void GoForward();
    void Clear();
}

public sealed record NavigationEntry(object ViewModel, string? Title = null);
```

### NavigationService 구현

```csharp
using ReactiveUI;
using System.Collections.Generic;
using System.Linq;

public sealed class NavigationService : ReactiveObject, INavigationService
{
    private readonly Stack<NavigationEntry> _back = new();
    private readonly Stack<NavigationEntry> _forward = new();
    private object? _current;

    public object? Current
    {
        get => _current;
        private set => this.RaiseAndSetIfChanged(ref _current, value);
    }

    public IReadOnlyList<NavigationEntry> BackStack => _back.Reverse().ToList();
    public IReadOnlyList<NavigationEntry> ForwardStack => _forward.Reverse().ToList();

    public bool CanGoBack => _back.Count > 0;
    public bool CanGoForward => _forward.Count > 0;

    public void Navigate(object viewModel)
    {
        if (Current is not null)
            _back.Push(new NavigationEntry(Current));
        _forward.Clear();
        Current = viewModel;
        this.RaisePropertyChanged(nameof(CanGoBack));
        this.RaisePropertyChanged(nameof(CanGoForward));
    }

    public void GoBack()
    {
        if (!CanGoBack) return;
        if (Current is not null)
            _forward.Push(new NavigationEntry(Current));
        Current = _back.Pop().ViewModel;
        this.RaisePropertyChanged(nameof(CanGoBack));
        this.RaisePropertyChanged(nameof(CanGoForward));
    }

    public void GoForward()
    {
        if (!CanGoForward) return;
        if (Current is not null)
            _back.Push(new NavigationEntry(Current));
        Current = _forward.Pop().ViewModel;
        this.RaisePropertyChanged(nameof(CanGoBack));
        this.RaisePropertyChanged(nameof(CanGoForward));
    }

    public void Clear()
    {
        _back.Clear();
        _forward.Clear();
        this.RaisePropertyChanged(nameof(CanGoBack));
        this.RaisePropertyChanged(nameof(CanGoForward));
    }
}
```

### MainViewModel에 서비스 주입

```csharp
using ReactiveUI;
using System.Reactive;

public class MainViewModel : ReactiveObject
{
    private readonly INavigationService _nav;

    public object? CurrentViewModel => _nav.Current;

    public ReactiveCommand<Unit, Unit> ShowDashboard { get; }
    public ReactiveCommand<Unit, Unit> ShowSettings  { get; }
    public ReactiveCommand<Unit, Unit> ShowAbout     { get; }
    public ReactiveCommand<Unit, Unit> Back          { get; }
    public ReactiveCommand<Unit, Unit> Forward       { get; }

    public MainViewModel(INavigationService nav)
    {
        _nav = nav;

        ShowDashboard = ReactiveCommand.Create(() => _nav.Navigate(new DashboardViewModel()));
        ShowSettings  = ReactiveCommand.Create(() => _nav.Navigate(new SettingsViewModel()));
        ShowAbout     = ReactiveCommand.Create(() => _nav.Navigate(new AboutViewModel()));

        Back    = ReactiveCommand.Create(() => _nav.GoBack(),   this.WhenAnyValue(_ => _nav.CanGoBack));
        Forward = ReactiveCommand.Create(() => _nav.GoForward(), this.WhenAnyValue(_ => _nav.CanGoForward));

        this.WhenAnyValue(_ => _nav.Current).Subscribe(_ => this.RaisePropertyChanged(nameof(CurrentViewModel)));

        _nav.Navigate(new DashboardViewModel()); // 초기 페이지
    }
}
```

### MainView.axaml (뒤로/앞으로 버튼 포함)

```xml
<UserControl xmlns="https://github.com/avaloniaui"
             xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
             x:Class="MyAvaloniaApp.Views.MainView">

  <DockPanel>
    <StackPanel Orientation="Horizontal" DockPanel.Dock="Top" Spacing="8" Margin="8">
      <Button Content="←" Command="{Binding Back}" IsEnabled="{Binding CanGoBack}" />
      <Button Content="→" Command="{Binding Forward}" IsEnabled="{Binding CanGoForward}" />
      <Button Content="대시보드" Command="{Binding ShowDashboard}" />
      <Button Content="설정" Command="{Binding ShowSettings}" />
      <Button Content="정보" Command="{Binding ShowAbout}" />
    </StackPanel>

    <ContentControl Content="{Binding CurrentViewModel}" />
  </DockPanel>
</UserControl>
```

**장점**: 뒤로/앞으로 이동, 스택 관리, 가드 적용 등 확장이 용이합니다.

## 4. 화면 간 파라미터 전달

네비게이션 시 데이터를 함께 전달해야 할 때는 다음과 같은 패턴을 사용할 수 있습니다.

### 생성자 인자 방식

```csharp
public class ProfileViewModel
{
    public string UserId { get; }
    public ProfileViewModel(string userId) => UserId = userId;
}

// 네비게이션
_nav.Navigate(new ProfileViewModel("U-001"));
```

### 초기화 메서드 방식 (생성자 단순 유지)

```csharp
public interface IInitializable<T>
{
    void Initialize(T parameter);
}

public class ProfileViewModel : IInitializable<string>
{
    public string? UserId { get; private set; }
    public void Initialize(string parameter) => UserId = parameter;
}

// 네비게이션
var vm = new ProfileViewModel();
vm.Initialize("U-002");
_nav.Navigate(vm);
```

### Route + 팩토리 방식 (추천)

라우트 객체를 정의하고, 팩토리에서 ViewModel을 생성합니다.

```csharp
public sealed record Route(string Name, object? Parameter = null);

public interface IRouteFactory
{
    object Resolve(Route route);
}

public class RouteFactory : IRouteFactory
{
    public object Resolve(Route route) => route.Name switch
    {
        "Dashboard" => new DashboardViewModel(),
        "Settings"  => new SettingsViewModel(),
        "Profile"   => new ProfileViewModel((string)route.Parameter!),
        _           => new DashboardViewModel()
    };
}

// 네비게이션 서비스에서 라우트 사용
_nav.NavigateByRoute(new Route("Profile", "U-003"));
```

## 5. 화면 이탈 가드 (변경사항 저장 확인)

사용자가 현재 화면을 떠나기 전에 저장되지 않은 변경 사항이 있으면 경고해야 하는 경우, `INavigationGuard` 인터페이스를 도입합니다.

```csharp
public interface INavigationGuard
{
    Task<bool> CanLeaveAsync();
}

public class SettingsViewModel : INavigationGuard
{
    public bool IsDirty { get; set; }

    public async Task<bool> CanLeaveAsync()
    {
        if (!IsDirty) return true;
        // 다이얼로그 서비스를 통해 사용자 확인
        return await ShowSaveConfirmationAsync();
    }

    private Task<bool> ShowSaveConfirmationAsync() => Task.FromResult(true); // 실제 구현 필요
}
```

네비게이션 서비스에서 전환 시 가드 확인:

```csharp
public async Task<bool> TryNavigateAsync(object next)
{
    if (Current is INavigationGuard guard && !await guard.CanLeaveAsync())
        return false;
    Navigate(next);
    return true;
}
```

## 6. 비동기 전환과 로딩 UI

데이터 로딩이 필요한 화면으로 전환할 때는 잠시 `LoadingViewModel`을 표시한 후 실제 ViewModel로 교체합니다.

```csharp
public class LoadingViewModel
{
    public string Message { get; }
    public LoadingViewModel(string message = "로딩 중...") => Message = message;
}
```

### 로딩 화면을 위한 DataTemplate 등록

```xml
<Application.DataTemplates>
  <DataTemplate DataType="{x:Type vm:LoadingViewModel}">
    <views:LoadingView/>
  </DataTemplate>
  <!-- 기타 DataTemplate -->
</Application.DataTemplates>
```

### 네비게이션 서비스 확장

```csharp
public async Task NavigateWithLoadingAsync(Func<Task<object>> factory)
{
    Navigate(new LoadingViewModel());
    var vm = await factory();
    Navigate(vm);
}
```

사용 예:

```csharp
await _nav.NavigateWithLoadingAsync(async () =>
{
    await Task.Delay(1000); // 실제 데이터 로딩
    return new DashboardViewModel();
});
```

## 7. 의존성 주입 구성

`Microsoft.Extensions.DependencyInjection`을 사용해 서비스를 등록합니다.

```csharp
using Microsoft.Extensions.DependencyInjection;

public static class AppServices
{
    public static ServiceProvider Build()
    {
        var services = new ServiceCollection();
        services.AddSingleton<INavigationService, NavigationService>();
        services.AddSingleton<IRouteFactory, RouteFactory>();
        services.AddTransient<MainViewModel>();
        services.AddTransient<DashboardViewModel>();
        services.AddTransient<SettingsViewModel>();
        services.AddTransient<AboutViewModel>();
        return services.BuildServiceProvider();
    }
}
```

`App.axaml.cs`에서 서비스 컨테이너를 생성하고, 시작 윈도우의 DataContext를 설정합니다.

```csharp
public override void OnFrameworkInitializationCompleted()
{
    var services = AppServices.Build();
    var mainViewModel = services.GetRequiredService<MainViewModel>();

    if (ApplicationLifetime is IClassicDesktopStyleApplicationLifetime desktop)
    {
        desktop.MainWindow = new MainWindow { DataContext = mainViewModel };
    }
    base.OnFrameworkInitializationCompleted();
}
```

## 8. 단위 테스트

네비게이션 서비스는 ViewModel과 독립적으로 테스트할 수 있습니다.

```csharp
[Fact]
public void Navigate_PushesBackStack_AndUpdatesCurrent()
{
    var nav = new NavigationService();
    var a = new DashboardViewModel();
    var b = new SettingsViewModel();

    nav.Navigate(a);
    Assert.Same(a, nav.Current);

    nav.Navigate(b);
    Assert.Same(b, nav.Current);
    Assert.True(nav.CanGoBack);

    nav.GoBack();
    Assert.Same(a, nav.Current);
}
```

가드 로직도 별도로 테스트 가능합니다.

## 9. 성능 및 유지보수 팁

- **DataTemplate 매핑**: ViewModel과 View의 매핑은 `Application.DataTemplates`에 정적으로 선언하여 런타임 탐색 비용을 줄입니다.
- **스택 관리**: 백스택이 무한히 커지지 않도록 필요한 경우 `Clear()`를 호출하거나, 일정 깊이 이상에서 오래된 항목을 제거하는 정책을 추가하세요.
- **메모리 누수**: ViewModel이 이벤트 구독 등을 통해 장기간 유지되지 않도록 `WhenActivated`(ReactiveUI) 패턴을 활용하세요.
- **로딩 화면**: 비동기 전환 시 로딩 화면을 표시하면 사용자 경험이 향상됩니다.

## 10. 요약

| 방식 | 핵심 요소 | 적합한 상황 | 확장성 |
|------|-----------|-------------|--------|
| TabControl | 정적 탭 | 페이지 수 고정, 간단한 앱 | 낮음 |
| ContentControl + DataTemplate | CurrentViewModel, DataTemplate | 일반적인 다중 페이지 앱 | 높음 |
| NavigationService | 스택, 가드, 파라미터 | 중대형 앱, 복잡한 네비게이션 | 매우 높음 |

---

## 결론

Avalonia에서 여러 페이지를 관리하는 방법은 크게 세 가지로 나눌 수 있습니다. 간단한 앱에서는 `TabControl`이 충분하지만, 확장성을 고려한다면 `ContentControl`과 `DataTemplate`을 활용한 동적 전환이 좋은 선택입니다. 특히 네비게이션 스택, 가드, 파라미터 전달이 필요하다면 `NavigationService`를 도입하여 유지보수성과 테스트 용이성을 높이는 것이 바람직합니다. 이 글에서 소개한 패턴을 기반으로 자신의 프로젝트 규모에 맞는 구조를 선택해 보세요.
