# 고급 네트워크 — VLAN, Bonding, 브리지, 고급 IP/라우팅, DNS 캐싱

## 고급 네트워크의 필요성

기본적인 IP 설정만으로는 현대 인프라의 요구를 충족하기 어렵다. 여러 개의 논리적 네트워크 분리, 링크 이중화, 가상화 환경과의 통합, 복잡한 트래픽 제어 등이 필요할 때 고급 네트워크 기술이 사용된다. 이 글에서는 실제 운영 환경에서 자주 사용되는 기술을 중심으로 설명한다.

---

## VLAN — 논리적 네트워크 분리

VLAN(Virtual LAN)은 하나의 물리적 네트워크를 여러 개의 논리적 브로드캐스트 도메인으로 나눈다. 서버 측에서는 **Trunk 포트**를 통해 여러 VLAN이 들어오고, 운영체제에서 VLAN 서브 인터페이스를 생성하여 각 VLAN을 분리한다.

### 실시간 VLAN 인터페이스 생성

```bash
# eth0에 VLAN ID 10인 인터페이스 생성
sudo ip link add link eth0 name eth0.10 type vlan id 10

# IP 주소 할당
sudo ip addr add 192.168.10.2/24 dev eth0.10

# 인터페이스 활성화
sudo ip link set eth0.10 up
```

### 영구적인 VLAN 설정 (Netplan 예시)

```yaml
# /etc/netplan/01-vlan.yaml
network:
  version: 2
  ethernets:
    eth0: {}
  vlans:
    vlan10:
      id: 10
      link: eth0
      addresses: [192.168.10.2/24]
```
```bash
sudo netplan apply
```

### VLAN 문제 해결

```bash
# VLAN 태그 정보 확인
ip -d link show eth0.10

# VLAN 트래픽 캡처
tcpdump -ni eth0 vlan 10
```

VLAN을 사용할 때는 스위치 측에서 해당 VLAN이 Trunk에 허용되어 있는지 확인해야 한다.

## NIC Bonding — 링크 이중화 및 대역폭 확장

여러 개의 물리적 NIC를 하나의 논리적 인터페이스로 묶어 고가용성과 성능을 확보한다.

| 모드 | 이름 | 특징 | 스위치 설정 |
|------|------|------|-------------|
| 1 | active-backup | 하나만 활성, 장애 시 대체 | 불필요 |
| 4 | 802.3ad (LACP) | 링크 집합, 대역폭 증가 + 고가용성 | 필요 |
| 0 | balance-rr | 라운드로빈 전송 | 필요 없지만 호환성 주의 |

### active-backup (장애 조치) 예시 (Netplan)

```yaml
# /etc/netplan/02-bond.yaml
network:
  version: 2
  ethernets:
    eth0: {}
    eth1: {}
  bonds:
    bond0:
      interfaces: [eth0, eth1]
      addresses: [192.168.1.100/24]
      parameters:
        mode: active-backup
        primary: eth0
        mii-monitor-interval: 100
```

### LACP 모드 (802.3ad) 예시

```yaml
# 동일 파일에서 mode만 변경
        mode: 802.3ad
```

### 상태 확인

```bash
cat /proc/net/bonding/bond0
```

LACP를 사용할 경우 스위치에도 동일한 채널 그룹과 해시 정책이 설정되어야 한다.

## Linux Bridge — 가상 스위치

브리지는 소프트웨어 스위치로, 가상 머신이나 컨테이너를 물리적 네트워크에 연결할 때 사용된다. 물리적 NIC는 브리지에 포트로 연결되고, 브리지 자체가 IP 주소를 갖는다.

### 실시간 브리지 생성

```bash
# 브리지 생성
sudo ip link add name br0 type bridge

# 물리적 인터페이스를 브리지에 연결
sudo ip link set dev eth0 master br0

# 원래 eth0의 IP 제거
sudo ip addr flush dev eth0

# 브리지에 IP 할당
sudo ip addr add 192.168.1.10/24 dev br0

# 인터페이스 활성화
sudo ip link set br0 up
sudo ip link set eth0 up
```

### 영구적인 브리지 설정 (Netplan)

```yaml
# /etc/netplan/03-bridge.yaml
network:
  version: 2
  ethernets:
    eth0: {}
  bridges:
    br0:
      interfaces: [eth0]
      addresses: [192.168.1.10/24]
      parameters:
        stp: true
```

브리지 환경에서는 STP(Spanning Tree Protocol)를 활성화하여 루프를 방지하는 것이 좋다.

## 고급 IP 및 라우팅 — 정책 기반 라우팅, ECMP

### 정책 라우팅

여러 개의 인터페이스가 있을 때, 출발지 IP에 따라 다른 라우팅 테이블을 사용하도록 할 수 있다. 이를 **소스 기반 라우팅**이라고 한다.

```bash
# 커스텀 테이블 정의 (숫자와 이름 매핑)
echo "200 wan1" | sudo tee -a /etc/iproute2/rt_tables
echo "201 wan2" | sudo tee -a /etc/iproute2/rt_tables

# 규칙 추가: 10.10.10.0/24에서 오는 트래픽은 wan1 테이블 사용
sudo ip rule add from 10.10.10.0/24 table wan1
sudo ip route add default via 10.10.10.1 dev eth0 table wan1

# 규칙 확인
ip rule show
```

### ECMP (동등 비용 다중 경로)

두 개의 인터넷 회선이 있다면 ECMP를 통해 트래픽을 분산할 수 있다.

```bash
sudo ip route replace default scope global \
  nexthop via 10.10.10.1 dev eth0 weight 1 \
  nexthop via 10.10.20.1 dev eth1 weight 1
```

ECMP를 사용할 때는 반환 경로가 올바르게 설정되어야 하므로 `rp_filter`를 조정할 필요가 있다.

```bash
sudo sysctl -w net.ipv4.conf.all.rp_filter=2
```

## DNS 캐싱 — dnsmasq

dnsmasq는 경량 DNS 캐시 서버로, 로컬 네트워크의 DNS 쿼리를 캐싱하여 응답 속도를 높이고 외부 DNS 서버의 부하를 줄인다.

### 설치 및 기본 설정

```bash
sudo apt install -y dnsmasq
```

`/etc/dnsmasq.conf`:

```ini
domain-needed
bogus-priv
no-resolv
server=1.1.1.1
server=8.8.8.8
listen-address=127.0.0.1,192.168.1.10
cache-size=2000
```

```bash
sudo systemctl enable --now dnsmasq
```

### 클라이언트에서 사용하도록 resolv.conf 변경

```bash
echo "nameserver 192.168.1.10" | sudo tee /etc/resolv.conf
```

또는 NetworkManager에서 DNS 서버를 직접 지정할 수 있다.

### 내부 도메인 오버라이드

```ini
# /etc/dnsmasq.conf
address=/dev.local/10.0.0.100
address=/api.internal/10.0.5.20
```

## 네트워크 진단 및 성능 팁

### 기본 진단

```bash
# 인터페이스 통계 (드롭, 에러)
ip -s link

# 소켓 통계
ss -tulpen

# 링크 상태 및 오프로드 기능
ethtool eth0
ethtool -k eth0

# 경로 품질 측정
mtr -rw example.com
```

### MTU 설정

점보 프레임을 사용할 때는 모든 구간에서 일관된 MTU가 필요하다.

```bash
# MTU 확인
ip link show eth0

# MTU 변경
sudo ip link set eth0 mtu 9000

# 경로 MTU 테스트
ping -M do -s 8972 <대상 IP>
```

### 패킷 캡처

```bash
sudo tcpdump -ni eth0 -w capture.pcap host 8.8.8.8
```

## 결론

고급 네트워크 기술은 단일 물리적 인프라에서 논리적 분리, 링크 이중화, 가상화 통합, 정교한 트래픽 제어를 가능하게 한다. 이 글에서는 VLAN, Bonding, Linux Bridge, 정책 라우팅, DNS 캐싱을 중심으로 실무에서 바로 적용할 수 있는 방법을 다루었다.

- **VLAN**: 서버에서 `eth0.10` 같은 서브 인터페이스로 논리적 네트워크를 분리한다.
- **Bonding**: `active-backup`으로 장애 조치, `802.3ad`로 대역폭 집적을 구현한다.
- **Bridge**: KVM, 컨테이너 등을 물리적 네트워크에 연결하는 가상 스위치 역할을 한다.
- **정책 라우팅**: 출발지 IP에 따라 다른 경로를 사용하여 다중 인터페이스를 효율적으로 활용한다.
- **dnsmasq**: 로컬 DNS 캐시를 통해 응답 속도를 높이고 내부 도메인을 관리한다.

네트워크 구성 변경은 시스템의 핵심 인프라에 영향을 미치므로, 변경 전에 테스트 환경에서 검증하고 롤백 계획을 반드시 수립해야 한다. 문서화된 구성과 정기적인 점검을 통해 안정적이고 예측 가능한 네트워크 환경을 유지할 수 있다.
