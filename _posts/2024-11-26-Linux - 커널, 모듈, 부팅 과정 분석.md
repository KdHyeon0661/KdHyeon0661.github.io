# 커널·모듈·부팅 과정 분석

## 부팅 과정 개요

리눅스 시스템이 켜져서 사용자가 로그인할 때까지 여러 단계를 거친다. 각 단계에서 문제가 발생하면 원인을 파악하는 것이 중요하다.

1. **펌웨어 단계 (BIOS / UEFI)**  
   하드웨어를 초기화하고 부팅 장치를 선택한다. UEFI 환경에서는 ESP(EFI System Partition)에 있는 부트로더를 실행한다.

2. **부트로더 단계 (GRUB2)**  
   커널 이미지(`vmlinuz`)와 initramfs(`initrd.img`)를 메모리에 로드하고, 커널 명령줄(kernel command line)을 전달한다.

3. **커널 초기화 단계**  
   커널이 하드웨어 드라이버를 초기화하고 initramfs로 진입한다. initramfs는 루트 파일시스템을 마운트하는 데 필요한 드라이버(LVM, RAID, LUKS 등)를 포함한다.

4. **사용자 공간 초기화 (systemd)**  
   루트 파일시스템이 마운트된 후 systemd(PID 1)가 실행되어 서비스와 타겟을 시작한다.

5. **로그인 단계**  
   TTY, SSH, 또는 그래픽 디스플레이 매니저를 통해 로그인 화면이 제공된다.

## `/boot` 디렉토리와 GRUB

### `/boot` 디렉토리 구성

| 파일/디렉토리 | 역할 |
|---------------|------|
| `vmlinuz-<version>` | 압축된 커널 이미지 |
| `initrd.img-<version>` | 초기 램디스크 (initramfs) |
| `grub/` | GRUB 설정 파일과 모듈 |
| `config-<version>` | 커널 빌드 설정 |
| `System.map-<version>` | 커널 심볼 주소 (디버깅용) |

### GRUB 설정 변경

GRUB 설정은 `/etc/default/grub`와 `/etc/grub.d/` 디렉터리에서 관리한다.  
수정 후 설정 파일을 재생성한다.

```bash
# Debian/Ubuntu
sudo update-grub

# RHEL/Fedora
sudo grub2-mkconfig -o /boot/grub2/grub.cfg
```

### `/etc/default/grub` 주요 항목

```bash
GRUB_DEFAULT=0           # 기본 부팅 항목 (0번)
GRUB_TIMEOUT=5           # 메뉴 대기 시간(초)
GRUB_CMDLINE_LINUX_DEFAULT="quiet splash"   # 커널 명령줄
```

서버 환경에서는 `quiet`를 제거하고 로그 레벨을 높여 디버깅 정보를 얻을 수 있다.

### 커널 명령줄 파라미터

| 파라미터 | 용도 |
|----------|------|
| `root=UUID=...` | 루트 파일시스템 지정 |
| `ro` / `rw` | 루트 마운트 모드 |
| `systemd.unit=rescue.target` | 구조 모드로 부팅 (최소 서비스) |
| `emergency` | 비상 쉘 모드 (루트 읽기전용) |
| `nomodeset` | 그래픽 드라이버 문제 회피 |
| `loglevel=7` | 상세 커널 메시지 출력 |

## initramfs (초기 램디스크)

initramfs는 루트 파일시스템을 마운트하기 전에 필요한 드라이버와 도구를 포함하는 작은 파일시스템이다.  
LUKS, LVM, RAID, 네트워크 루트 등을 지원해야 할 때 필수적이다.

### initramfs 재생성

```bash
# Debian/Ubuntu
sudo update-initramfs -u -k all

# RHEL/Fedora
sudo dracut -f
```

### initramfs 내용 확인

```bash
# Ubuntu
lsinitramfs /boot/initrd.img-$(uname -r) | head

# RHEL/Fedora (압축 해제 후 확인)
mkdir /tmp/ir && cd /tmp/ir
zcat /boot/initramfs-$(uname -r).img | cpio -idmv
```

## 커널 모듈 관리

### 기본 명령어

```bash
lsmod                 # 로드된 모듈 목록
modinfo e1000e        # 모듈 정보 (의존성, 파라미터 등)
sudo modprobe e1000e  # 모듈 로드
sudo modprobe -r e1000e  # 모듈 제거
```

### 영구적 모듈 로드 및 블랙리스트

```bash
# 항상 로드할 모듈
echo e1000e | sudo tee /etc/modules-load.d/net.conf

# 블랙리스트 (사용하지 않을 모듈)
echo "blacklist nouveau" | sudo tee /etc/modprobe.d/blacklist.conf
```

변경 사항을 적용하려면 initramfs를 재생성한다.

### DKMS (외부 모듈 자동 빌드)

커널 업데이트 시 외부 드라이버(예: NVIDIA)를 자동으로 재컴파일해준다.

```bash
dkms status
sudo dkms autoinstall
```

## 커널 메시지 분석

### dmesg (커널 링 버퍼)

```bash
dmesg -T | grep -i error
```

### journalctl (systemd 저널)

```bash
journalctl -k -b          # 현재 부팅 커널 로그
journalctl -k -b -1       # 이전 부팅 커널 로그
```

## 간단한 트러블슈팅 시나리오

### 시나리오 A: 커널 업데이트 후 네트워크 드라이버 작동 안 함

1. `dkms status`로 드라이버 빌드 상태 확인
2. 빌드 실패 시 `sudo dkms autoinstall` 또는 패키지 재설치
3. `journalctl -k | grep -i firmware`로 펌웨어 누락 확인 → `linux-firmware` 업데이트

### 시나리오 B: GRUB 복구 모드

부팅이 되지 않을 때 라이브 USB로 복구:

```bash
# 루트 파티션 마운트
sudo mount /dev/mapper/vg-root /mnt
sudo mount /dev/sda1 /mnt/boot   # ESP가 분리된 경우

# chroot 준비
for i in /dev /proc /sys /run; do sudo mount --bind $i /mnt$i; done
sudo chroot /mnt

# GRUB 재설치
grub-install /dev/sda
update-grub
exit
sudo reboot
```

### 시나리오 C: LUKS/LVM 루트에서 비밀번호 프롬프트 안 뜸

- initramfs에 `cryptsetup`, `lvm`이 포함되어 있는지 확인 (`lsinitramfs`)
- 키맵, 콘솔 옵션 확인 (커널 명령줄에 `vconsole.keymap=...`)
- `update-initramfs -u`로 initramfs 재생성

| 작업 | 명령어 / 파일 |
|------|----------------|
| GRUB 설정 파일 생성 | `update-grub` (Debian), `grub2-mkconfig` (RHEL) |

| 커널 메시지 | `dmesg`, `journalctl -k` |
| DKMS 상태 | `dkms status` |

## 결론

리눅스의 부팅 과정은 펌웨어 → GRUB → 커널/initramfs → systemd → 로그인 순서로 진행된다.  
각 단계에서 발생하는 문제는 `/proc/cmdline`, `dmesg`, `journalctl -k` 등을 통해 진단할 수 있다.

- **GRUB 설정**은 `/etc/default/grub`에서 관리하고, 변경 후 반드시 설정 파일을 재생성한다.
- **initramfs**는 루트 파일시스템에 접근하기 위해 필요한 모듈을 포함하며, 필요 시 재생성할 수 있다.
- **커널 모듈**은 `lsmod`, `modprobe`로 관리하고, 블랙리스트로 충돌을 방지한다.
- **DKMS**는 커널 업데이트 후 외부 드라이버를 자동으로 유지해준다.

체계적인 접근과 예방적 유지보수를 통해 부팅 실패를 신속하게 복구하고 안정적인 시스템을 운영할 수 있다.
