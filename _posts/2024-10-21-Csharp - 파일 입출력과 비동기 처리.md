# C# 파일 입출력과 비동기 처리

파일 입출력(I/O)은 CPU 연산보다 수백 배 느린 작업입니다. 디스크 접근 시간은 메모리 접근의 수만 배에 달하기 때문에, I/O를 효율적으로 다루는 것은 애플리케이션 성능과 확장성의 핵심입니다. C#은 텍스트 파일, 바이너리 데이터, 대용량 스트리밍, 그리고 비동기 처리까지 파일 시스템을 제어하는 강력한 도구들을 제공합니다.

---

## 텍스트 파일 기본

가장 간단한 파일 읽기/쓰기는 `System.IO.File` 클래스의 정적 메서드로 처리합니다. 설정 파일이나 작은 텍스트 파일에 적합합니다.

```csharp
using System.IO;
using System.Text;

// 간단한 쓰기/읽기
File.WriteAllText("document.txt", "Hello, C#!");
string content = File.ReadAllText("document.txt");

// 여러 줄
var lines = new[] { "첫째 줄", "둘째 줄" };
File.WriteAllLines("multiline.txt", lines);
var allLines = File.ReadAllLines("multiline.txt");

// 인코딩 명시 (UTF-8 권장)
File.WriteAllText("utf8.txt", "유니코드", Encoding.UTF8);
```

**주의**: `ReadAllText`와 `ReadAllLines`는 파일 전체를 메모리에 로드합니다. 수백 MB 이상의 파일에는 사용하지 마십시오.

## 스트림 기반 접근

대용량 파일이나 실시간 데이터를 다룰 때는 **스트림(Stream)**을 사용합니다. 데이터를 조금씩 읽고 써서 메모리 부담을 줄입니다.

### StreamReader와 StreamWriter

텍스트 파일을 효율적으로 읽고 쓰는 클래스입니다.

```csharp
// 대용량 파일 한 줄씩 읽기
using var reader = new StreamReader("largefile.txt");
string? line;
while ((line = await reader.ReadLineAsync()) != null)
{
    ProcessLine(line);  // 한 줄씩 처리
}

// 버퍼 크기를 지정한 쓰기
using var writer = new StreamWriter("output.txt", append: true, Encoding.UTF8, bufferSize: 8192);
await writer.WriteLineAsync("로그 메시지");
```

### FileStream과 최적화 옵션

바이너리 데이터나 세밀한 제어가 필요할 때 `FileStream`을 사용합니다. 생성자 옵션으로 성능을 높일 수 있습니다.

```csharp
using var stream = new FileStream(
    path: "data.bin",
    mode: FileMode.OpenOrCreate,
    access: FileAccess.ReadWrite,
    share: FileShare.Read,
    bufferSize: 65536,                         // 64KB 버퍼
    options: FileOptions.Asynchronous | FileOptions.SequentialScan
);
```

- **Asynchronous**: 비동기 I/O 활성화
- **SequentialScan**: 순차 접근임을 OS에 알려 디스크 헤드 이동 최적화

## 비동기 I/O

동기 I/O는 디스크 작업이 완료될 때까지 스레드를 블로킹합니다. 비동기 I/O는 작업을 OS에 위임하고 스레드를 풀에 반환하여 응답성과 확장성을 높입니다.

### 진행률과 취소가 있는 파일 복사

```csharp
public async Task CopyFileWithProgressAsync(
    string sourcePath, string destPath,
    IProgress<double>? progress = null,
    CancellationToken cancellationToken = default)
{
    var fileInfo = new FileInfo(sourcePath);
    long totalBytes = fileInfo.Length;
    long bytesRead = 0;
    byte[] buffer = new byte[65536];

    await using var source = new FileStream(sourcePath, FileMode.Open, FileAccess.Read,
        FileShare.Read, buffer.Length, FileOptions.Asynchronous);
    await using var dest = new FileStream(destPath, FileMode.Create, FileAccess.Write,
        FileShare.None, buffer.Length, FileOptions.Asynchronous);

    int read;
    while ((read = await source.ReadAsync(buffer, cancellationToken).ConfigureAwait(false)) > 0)
    {
        cancellationToken.ThrowIfCancellationRequested();
        await dest.WriteAsync(buffer.AsMemory(0, read), cancellationToken).ConfigureAwait(false);
        bytesRead += read;
        progress?.Report((double)bytesRead / totalBytes * 100);
    }
}
```

**팁**: 라이브러리 코드에서는 `ConfigureAwait(false)`로 컨텍스트 캡처를 방지하여 성능을 개선합니다.

## 실전 엔터프라이즈 패턴

### 원자적 파일 업데이트 (Atomic Write)

설정 파일을 안전하게 덮어쓰려면 임시 파일에 쓴 후 교체합니다. 이렇게 하면 쓰기 도중 오류가 발생해도 원본 파일이 손상되지 않습니다.

```csharp
public async Task AtomicWriteAsync(string filePath, string content, bool keepBackup = false)
{
    string tempPath = filePath + ".tmp";
    string backupPath = filePath + ".backup";

    try
    {
        await File.WriteAllTextAsync(tempPath, content, Encoding.UTF8);

        if (OperatingSystem.IsWindows())
        {
            File.Replace(tempPath, filePath, backupPath, ignoreMetadataErrors: true);
        }
        else
        {
            File.Move(tempPath, filePath, overwrite: true);
        }

        if (!keepBackup && File.Exists(backupPath))
            File.Delete(backupPath);
    }
    finally
    {
        if (File.Exists(tempPath)) File.Delete(tempPath);
    }
}
```

### 로그 회전 (Rolling Log)

로그 파일이 일정 크기를 초과하면 백업하고 새 파일로 전환합니다.

```csharp
public class RollingFileLogger : IAsyncDisposable
{
    private readonly string _logDir;
    private readonly string _baseName;
    private readonly long _maxFileSize;
    private StreamWriter _writer;
    private long _currentSize;

    public RollingFileLogger(string logDir, string baseName, long maxFileSize = 10 * 1024 * 1024)
    {
        _logDir = logDir;
        _baseName = baseName;
        _maxFileSize = maxFileSize;
        Directory.CreateDirectory(logDir);
        OpenWriter();
    }

    private void OpenWriter()
    {
        string path = Path.Combine(_logDir, $"{_baseName}.log");
        _writer = new StreamWriter(path, append: true, Encoding.UTF8);
        _currentSize = new FileInfo(path).Length;
    }

    public async Task LogAsync(string message)
    {
        string line = $"[{DateTime.Now:yyyy-MM-dd HH:mm:ss}] {message}";
        long lineSize = Encoding.UTF8.GetByteCount(line + Environment.NewLine);

        if (_currentSize + lineSize > _maxFileSize)
        {
            await RotateAsync();
        }

        await _writer.WriteLineAsync(line);
        await _writer.FlushAsync();
        _currentSize += lineSize;
    }

    private async Task RotateAsync()
    {
        await _writer.FlushAsync();
        _writer.Dispose();

        string currentPath = Path.Combine(_logDir, $"{_baseName}.log");
        string archivePath = Path.Combine(_logDir, $"{_baseName}_{DateTime.Now:yyyyMMdd_HHmmss}.log");
        File.Move(currentPath, archivePath);

        // 선택적 압축 (GZip)
        await using var source = File.OpenRead(archivePath);
        await using var gz = File.Create(archivePath + ".gz");
        await using var gzip = new GZipStream(gz, CompressionMode.Compress);
        await source.CopyToAsync(gzip);
        File.Delete(archivePath);

        OpenWriter();
    }

    public async ValueTask DisposeAsync()
    {
        await _writer.DisposeAsync();
    }
}
```

### 대용량 JSON 스트리밍 ( .NET 6+ )

JSON 배열을 한 번에 메모리에 올리지 않고 하나씩 처리합니다.

```csharp
public async IAsyncEnumerable<Product> ReadJsonArrayAsync(string filePath)
{
    await using var fileStream = File.OpenRead(filePath);
    var options = new JsonSerializerOptions { PropertyNameCaseInsensitive = true };

    await foreach (var product in JsonSerializer.DeserializeAsyncEnumerable<Product>(
        fileStream, options))
    {
        if (product is not null) yield return product;
    }
}
```

## 방어적 파일 I/O: 재시도 로직

파일 I/O는 외부 환경(디스크, 백신 등)에 영향을 받아 예외가 자주 발생합니다. 특히 공유 위반(Sharing Violation)은 재시도로 방어합니다.

```csharp
public async Task<string> SafeReadFileAsync(string filePath)
{
    const int maxRetries = 5;
    int retry = 0;

    while (true)
    {
        try
        {
            return await File.ReadAllTextAsync(filePath, Encoding.UTF8).ConfigureAwait(false);
        }
        catch (IOException ex) when (ex.HResult == unchecked((int)0x80070020)) // 32: sharing violation
        {
            if (++retry >= maxRetries) throw;
            int delayMs = 100 * (int)Math.Pow(2, retry); // 지수 백오프
            await Task.Delay(delayMs).ConfigureAwait(false);
        }
    }
}
```

## 주요 클래스 요약

| 클래스 | 용도 |
|--------|------|
| `File` | 정적 메서드로 간단한 파일 작업 |
| `FileStream` | 바이너리 데이터, 세밀한 제어 |
| `StreamReader` / `StreamWriter` | 텍스트 파일 스트리밍 |
| `FileOptions` | 성능 최적화 옵션 (비동기, 순차 읽기 등) |
| `GZipStream` | 로그 압축 등 데이터 압축 |
| `JsonSerializer` | JSON 직렬화/역직렬화 (스트리밍 포함) |

## 마무리

파일 I/O는 성능과 안정성 모두에서 신중한 접근이 필요합니다.

- **메모리**: 큰 파일은 스트림으로 청크 단위 처리
- **비동기**: I/O 구간에서 스레드를 블로킹하지 말고 `async`/`await` 사용
- **자원 해제**: `using` 또는 `await using`으로 스트림 닫기
- **안전성**: 원자적 업데이트와 재시도 로직으로 데이터 무결성 확보

이 원칙들을 따르면, 대용량 파일 처리부터 안정적인 로그 시스템까지 다양한 요구사항을 효율적으로 구현할 수 있습니다.
