# 파일 시스템 고급 설정 및 점검

## 마운트 옵션: 성능과 보안의 균형

파일 시스템을 마운트할 때 옵션을 지정하면 성능, 보안, 안정성을 조정할 수 있다. 아래는 자주 사용되는 옵션이다.

| 옵션 | 효과 | 사용 예 |
|------|------|--------|
| `ro` / `rw` | 읽기 전용 / 읽기-쓰기 | 시스템 보호, 데이터 복구 |
| `noexec` | 파일 실행 금지 | `/tmp` 같은 공용 디렉터리 보안 |
| `nosuid` | setuid/setgid 비트 무시 | 멀티유저 서버 보안 |
| `nodev` | 장치 파일 무시 | 일반 파티션에 적용 |
| `noatime` | 접근 시간 갱신 안 함 (성능 향상) | 로그, 캐시 등에 유용 |
| `relatime` | 접근 시간 최적화 (기본값) | 대부분 환경에 적합 |
| `errors=remount-ro` | 오류 시 읽기 전용 재마운트 (ext4) | 데이터 손상 확산 방지 |
| `discard` | SSD TRIM 즉시 수행 | SSD 수명과 성능 |

### `/tmp` 보안 강화 예시

```bash
# 임시로 적용
sudo mount -o remount,noexec,nosuid,nodev /tmp
```

영구 적용을 위해 `/etc/fstab`에 아래와 같이 설정한다.

```fstab
tmpfs   /tmp   tmpfs   rw,nosuid,nodev,noexec,mode=1777,size=2G   0 0
```
- `mode=1777` : 누구나 쓰기 가능, 자신의 파일만 삭제 가능

### 바인드 마운트 (bind mount)

이미 마운트된 디렉터리를 다른 경로에 다시 연결한다.

```bash
sudo mount --bind /srv/app/data /var/www/data
```

보안 옵션을 추가하려면:

```bash
sudo mount -o remount,bind,ro /var/www/data
```

### OverlayFS (컨테이너, 임시 빌드)

읽기 전용 하위 레이어 위에 쓰기 가능 레이어를 얹는 파일 시스템이다.

```bash
sudo mkdir -p /overlay/{lower,upper,work,merged}
sudo mount -t overlay overlay \
  -o lowerdir=/overlay/lower,upperdir=/overlay/upper,workdir=/overlay/work \
  /overlay/merged
```
- `lowerdir`: 읽기 전용 베이스
- `upperdir`: 쓰기 가능 레이어
- `workdir`: 임시 작업 공간

## `/etc/fstab` — 영구 마운트 설정

`/etc/fstab` 파일은 부팅 시 자동 마운트할 장치와 옵션을 정의한다.

```fstab
# 장치             마운트점    타입   옵션                      dump  pass
UUID=xxxx-xxxx      /data       ext4   defaults,noatime         0     2
```

- **장치 지정**: `UUID`(권장) > `LABEL` > `/dev/sdX`
- **pass** : `1`=루트, `2`=기타, `0`=점검 안 함

UUID 확인:
```bash
sudo blkid
ls -l /dev/disk/by-uuid/
```

### 네트워크 파일 시스템 (NFS) 지연 마운트

부팅 시 네트워크가 준비되지 않으면 문제가 생길 수 있으므로 자동 마운트 대신 접근 시 마운트하는 방식이 좋다.

```fstab
server:/share  /mnt/nfs  nfs  noauto,_netdev,x-systemd.automount  0 0
```
- `_netdev` : 네트워크 준비 후 마운트
- `x-systemd.automount` : 디렉터리에 접근할 때 자동 마운트

## 파일 시스템 점검과 복구

### ext4: e2fsck

```bash
# 마운트 해제 후 점검
sudo umount /dev/sda1
sudo e2fsck -f /dev/sda1
```

점검 주기 설정:
```bash
sudo tune2fs -c 30 -i 1m /dev/sda1   # 30회 마운트 또는 1개월마다 점검
```

### XFS: xfs_repair

```bash
sudo umount /dev/sdb1
sudo xfs_repair -n /dev/sdb1   # 점검만 (수정 없음)
sudo xfs_repair /dev/sdb1      # 실제 복구
```

### Btrfs: scrub (온라인 무결성 검사)

```bash
sudo btrfs scrub start -Bd /mnt
```

### SSD TRIM

주기적 TRIM을 권장한다.
```bash
sudo systemctl enable --now fstrim.timer
```

## 디스크 공간 문제 해결

### 용량 확인
```bash
df -h
df -i               # 아이노드 사용량 (작은 파일 폭탄 감지)
```

### 큰 디렉터리 찾기
```bash
du -xh --max-depth=1 /var | sort -h
ncdu /var           # 대화형 탐색
```

### 삭제했는데 공간이 안 줄어드는 경우

프로세스가 파일을 열고 있는 상태에서 파일이 삭제되면(로그 파일 등) 공간이 반환되지 않는다.
```bash
lsof +L1 | grep deleted
```
해당 프로세스를 재시작하면 공간이 회수된다.

### 저널 로그 정리
```bash
journalctl --disk-usage
journalctl --vacuum-size=1G
journalctl --vacuum-time=7d
```

## 성능 튜닝과 예약 블록

### 예약 블록 (ext4)

루트가 아닌 데이터 전용 파티션은 예약 블록을 줄여 사용 가능 공간을 늘릴 수 있다.

```bash
# 현재 예약 블록 비율 확인
tune2fs -l /dev/sda1 | grep "Reserved block"

# 1%로 줄이기
sudo tune2fs -m 1 /dev/sda1
```

### 마운트 옵션 성능

- `noatime` : 접근 시간 기록 안 함 (쓰기 부담 감소)
- `relatime` : 기본값, 성능과 호환성의 균형

데이터베이스나 캐시 서버에서는 `noatime`을 고려해 볼 수 있다.

## 자동화와 모니터링

### 용량 임계치 알림 (간단한 스크립트)

```bash
#!/usr/bin/env bash
THRESH=90
df -hP | awk -v t=$THRESH 'NR>1 && $5+0 >= t {print $6, $5}'
```
크론에 등록하여 메일로 알림을 보낼 수 있다.

## 안전한 파일 시스템 작업 체크리스트

- `/etc/fstab` 수정 후 `sudo mount -a`로 구문과 접속 검증
- 네트워크 파일 시스템은 `_netdev` + `x-systemd.automount`로 부팅 지연 방지
- `/tmp`와 같은 공용 공간은 `noexec,nosuid,nodev` 적용
- 데이터 파티션은 `noatime`, 시스템 파티션은 `relatime` 유지
- 파일 시스템 점검은 **전용 도구**를 사용하고, **마운트 해제 후** 실행
- 작업 전 스냅샷 또는 백업 필수

## 결론

파일 시스템 관리는 리눅스 시스템 안정성의 핵심이다. 마운트 옵션을 적절히 선택하면 보안과 성능을 동시에 확보할 수 있다. `/etc/fstab`은 신중하게 구성하고, 변경 후 반드시 `mount -a`로 테스트해야 한다.

파일 시스템 점검은 각 타입별 전용 도구를 사용하고, 가능하면 마운트를 해제한 후 진행한다. 삭제된 파일로 인한 디스크 누수는 `lsof +L1`로 확인하고 해당 프로세스를 재시작한다.

정기적인 모니터링(용량, 아이노드, 저널)과 자동화된 정리 작업을 통해 예측 가능하고 안정적인 시스템 환경을 유지할 수 있다.
