# 컨테이너 & 시스템 가상화

## 개요

컨테이너와 가상화 기술은 현대 인프라의 핵심이다.  
**컨테이너**는 프로세스 수준에서 가벼운 격리를 제공하며, **가상 머신**은 하드웨어 수준에서 완전한 격리를 구현한다.

실습 환경 준비 (Debian/Ubuntu 기준):

```bash
sudo apt update
sudo apt install -y debootstrap systemd-container uidmap \
  lxc lxc-templates qemu-kvm libvirt-daemon-system virt-manager \
  bridge-utils uidmap podman docker.io
```

## chroot와 Namespace의 차이

### chroot: 파일 시스템 경로만 변경

```bash
sudo mkdir -p /srv/jail
sudo debootstrap stable /srv/jail http://deb.debian.org/debian
sudo chroot /srv/jail /bin/bash
```

- 파일 시스템만 격리됨
- PID, 네트워크, 사용자 정보는 호스트와 공유
- 보안 격리 용도로는 부적합

### Namespace: 리소스별 완전한 격리

Linux Namespace는 다양한 리소스를 독립된 공간으로 분리한다.

| 유형 | 격리 대상 |
|------|----------|
| `mnt` | 마운트 포인트 |
| `pid` | 프로세스 ID 공간 |
| `net` | 네트워크 인터페이스, 포트 |
| `uts` | 호스트명 |
| `user` | 사용자/그룹 ID 매핑 |
| `ipc` | 프로세스 간 통신 |
| `cgroup` | cgroup 계층 구조 |

직접 체험:

```bash
# 여러 네임스페이스를 격리한 셸 실행
sudo unshare --pid --net --mount --uts --ipc --fork /bin/bash
hostname isolated   # 격리된 공간에서만 변경됨
ip link             # 네트워크 인터페이스가 없음
```

## cgroup v2: 리소스 제어

cgroup은 프로세스 그룹의 CPU, 메모리, 프로세스 수 등을 제한한다.

```bash
# cgroup 디렉터리 생성
CG=/sys/fs/cgroup/demo
sudo mkdir -p $CG

# 현재 셸을 cgroup에 추가
echo $$ | sudo tee $CG/cgroup.procs

# 리소스 제한 설정
echo "500000 100000" | sudo tee $CG/cpu.max   # 5 vCPU 제한
echo 1073741824 | sudo tee $CG/memory.max     # 1GB 제한
echo 512 | sudo tee $CG/pids.max              # 최대 512개 프로세스
```

컨테이너 런타임(Docker, Podman 등)은 이러한 cgroup 설정을 자동으로 관리한다.

## 컨테이너 보안 요소

### Capabilities
루트 권한을 세분화하여 최소 권한 원칙을 적용한다.  
예: `CAP_NET_BIND_SERVICE` – 1024 미만 포트 바인딩 허용

### seccomp
허용된 시스템 호출만 사용하도록 제한한다.

### LSM (SELinux/AppArmor)
컨테이너와 호스트 간의 경계를 강화한다.

**보안 강화 컨테이너 실행 예시 (Docker)**:

```bash
docker run --read-only \
  --cap-drop=ALL --cap-add=NET_BIND_SERVICE \
  --security-opt no-new-privileges \
  --pids-limit=256 --memory=512m --cpus=1.5 \
  -v /srv/www:/srv/www:ro,Z -p 8080:8080 myimg
```

## OverlayFS: 컨테이너 이미지 레이어

OverlayFS는 여러 읽기 전용 레이어 위에 쓰기 가능 레이어를 얹는 파일 시스템이다.

```bash
mkdir -p lower upper work merged
sudo mount -t overlay overlay \
  -o lowerdir=lower,upperdir=upper,workdir=work merged
```

- `lowerdir`: 이미지 레이어 (읽기 전용)
- `upperdir`: 컨테이너 쓰기 레이어
- `merged`: 컨테이너에서 보이는 통합 뷰

## systemd-nspawn: 시스템 컨테이너

systemd와 잘 통합된 경량 컨테이너 도구.

```bash
# Debian 베이스 생성
sudo debootstrap stable /var/lib/machines/debian http://deb.debian.org/debian

# 컨테이너 실행
sudo systemd-nspawn -D /var/lib/machines/debian

# 관리
sudo machinectl list
sudo machinectl start debian
sudo machinectl login debian
```

## LXC: 전통적인 리눅스 컨테이너

```bash
# 컨테이너 생성 및 시작
sudo lxc-create -n myct -t download
sudo lxc-start -n myct
sudo lxc-attach -n myct
```

설정 파일 예시 (`/var/lib/lxc/myct/config`):

```ini
lxc.net.0.type = veth
lxc.net.0.link = lxcbr0
lxc.cap.drop = sys_admin sys_module
```

## Docker / Podman: 애플리케이션 컨테이너

### Dockerfile 예제

```dockerfile
FROM debian:stable-slim
RUN apt-get update && apt-get install -y nginx && rm -rf /var/lib/apt/lists/*
COPY site/ /usr/share/nginx/html
EXPOSE 8080
CMD ["nginx", "-g", "daemon off;"]
```

```bash
docker build -t myweb .
docker run -d --name web -p 8080:8080 myweb
```

Podman은 데몬리스이며 루트리스 실행을 기본으로 지원한다.

```bash
podman run -d --name web -p 8080:8080 myweb
```

### Docker Compose로 서비스 정의

```yaml
version: "3"
services:
  web:
    image: myweb
    ports: ["8080:80"]
    deploy:
      resources:
        limits:
          cpus: "1"
          memory: 512M
    read_only: true
    cap_drop: [ALL]
    cap_add: [NET_BIND_SERVICE]
```

## KVM과 QEMU: 완전한 가상화

### KVM 지원 확인

```bash
lsmod | grep kvm
egrep -c '(vmx|svm)' /proc/cpuinfo   # 0이면 지원 안 함
```

### QEMU로 가상 머신 실행

```bash
# 디스크 이미지 생성
qemu-img create -f qcow2 disk.qcow2 20G

# 가상 머신 실행
qemu-system-x86_64 -enable-kvm -cpu host -smp 2 -m 2048 \
  -drive file=disk.qcow2,if=virtio,format=qcow2,cache=none \
  -netdev user,id=n1 -device virtio-net-pci,netdev=n1
```

### libvirt로 관리

```bash
# 가상 머신 생성 (무인 설치)
virt-install --name vm1 --memory 4096 --vcpus 4 \
  --disk size=20,bus=virtio,format=qcow2 \
  --cdrom ~/isos/debian.iso --os-variant debian12 \
  --network network=default,model=virtio
```

## 컨테이너 vs 가상 머신: 선택 기준

| 요구사항 | 추천 기술 |
|----------|----------|
| 높은 밀도, 빠른 배포 | 컨테이너 (Docker/Podman) |
| 강력한 격리, 이기종 OS | KVM 가상 머신 |
| 시스템 수준 테스트 | systemd-nspawn / LXC |
| 고성능 네트워크, 패스스루 | KVM + VFIO |
| 규제/감사 요구 강함 | 가상 머신 우선 |

현대 아키텍처에서는 애플리케이션을 컨테이너로, 테넌트 간 경계를 가상 머신으로 구분하는 혼합 방식이 일반적이다.

## 문제 해결 가이드

### 컨테이너 네트워크 문제

```bash
# 호스트 네트워크 확인
ip a
docker network ls
docker inspect <container> | jq '.[0].NetworkSettings'

# 방화벽 확인
sudo nft list ruleset
```

### 파일 권한 / 보안 라벨

- SELinux: `ls -Z`로 컨텍스트 확인, 볼륨 마운트에 `:Z` 옵션 사용
- AppArmor: `aa-status`로 프로파일 상태 확인

### 가상 머신 성능 저하

- CPU: `-cpu host` 사용 여부 확인
- 디스크: `cache=none`, `if=virtio` 적용
- 메모리: HugePages, NUMA 로컬 할당 고려

## 실전 예제

### 1. 루트리스 Podman으로 정적 웹 서버

```bash
podman run --rm -d --name web -p 8080:80 \
  --userns=keep-id --read-only --cap-drop=ALL \
  -v ./public:/usr/share/nginx/html:ro,Z \
  docker.io/library/nginx:stable
```

### 2. systemd-nspawn으로 Debian 부팅

```bash
sudo debootstrap stable /var/lib/machines/deb http://deb.debian.org/debian
sudo systemd-nspawn -D /var/lib/machines/deb --boot --network-bridge=br0
sudo machinectl login deb
```

### 3. LXC 컨테이너에 리소스 제한

```ini
# /var/lib/lxc/myct/config
lxc.cgroup2.memory.max = 1G
lxc.cgroup2.pids.max   = 256
lxc.cgroup2.cpu.max    = 200000 100000
```

### 4. libvirt로 Ubuntu 가상 머신

```bash
virt-install --name lab1 --memory 4096 --vcpus 4 \
  --disk size=30,bus=virtio,format=qcow2 \
  --cdrom ~/isos/ubuntu-24.04.iso \
  --os-variant ubuntu24.04 --graphics spice \
  --network network=default,model=virtio
```

## 결론

컨테이너와 가상화 기술은 각기 다른 수준의 격리와 효율성을 제공한다.

- **컨테이너**는 네임스페이스, cgroup, capabilities, seccomp, LSM을 결합하여 프로세스 수준의 가벼운 격리를 구현한다. 빠른 시작, 높은 밀도, DevOps 친화적이다.
- **가상 머신**은 KVM과 QEMU를 통해 하드웨어 수준의 완전한 격리를 제공하며, 이기종 OS 실행, 강력한 보안 경계, 하드웨어 패스스루에 적합하다.

실무에서는 두 기술을 함께 사용하는 하이브리드 접근이 일반적이다. 애플리케이션은 컨테이너로, 테넌트 간 강한 격리가 필요한 부분은 가상 머신으로 구성한다.

어떤 기술을 선택하든 **최소 권한 원칙, 정책 기반 관리, 체계적인 모니터링**이 안정적인 운영의 핵심이다. 각 도구의 기본 원리를 이해하고, 실제 요구사항에 맞게 조정하며, 지속적으로 보안과 성능을 최적화하는 습관을 들이자.
