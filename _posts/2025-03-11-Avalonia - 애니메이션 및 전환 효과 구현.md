# Avalonia에서 애니메이션 및 전환 효과 구현

## 애니메이션의 역할과 MVVM과의 관계

사용자 인터페이스에서 애니메이션은 단순히 멋을 위한 것이 아니다. 페이지 전환, 항목 추가/제거, 오류 피드백 등에서 애니메이션은 **시각적 연속성**을 제공하고 사용자에게 상태 변화를 직관적으로 알려준다. Avalonia는 XAML 기반의 선언적 애니메이션 시스템을 제공하며, MVVM 패턴과 함께 사용하면 **코드 비하인드 없이도** 자연스러운 상호작용을 구현할 수 있다.

MVVM에서 애니메이션을 다루는 핵심 원칙은 다음과 같다.

- 애니메이션의 **실행 조건**은 ViewModel의 속성(플래그, 상태)으로 표현한다.
- 애니메이션 **정의**는 XAML 스타일이나 데이터 트리거에 선언적으로 작성한다.
- **재사용 가능한 애니메이션**은 서비스로 추상화하여 ViewModel에서 호출할 수 있다.

이 글에서는 이러한 원칙을 바탕으로 Avalonia에서 실무에 바로 적용할 수 있는 애니메이션 및 전환 기법을 소개한다.

## 페이지 전환: ContentControl과 Transitions

가장 흔한 시나리오는 메인 영역의 뷰를 전환할 때 부드러운 움직임을 주는 것이다. Avalonia의 `ContentControl`은 `Transitions` 속성을 통해 콘텐츠가 변경될 때 자동으로 전환 효과를 적용할 수 있다.

### 기본 구조

```xml
<ContentControl Content="{Binding CurrentPage}">
  <ContentControl.Transitions>
    <Transitions>
      <PageSlide Duration="0:0:0.35" SlideDirection="Left"/>
    </Transitions>
  </ContentControl.Transitions>
</ContentControl>
```

- `PageSlide`: 슬라이드 전환 (좌우/상하)
- `CrossFade`: 투명도 페이드 전환

ViewModel에서는 `CurrentPage` 속성을 바꾸기만 하면 전환이 자동으로 실행된다.

```csharp
public class MainWindowViewModel : ReactiveObject
{
    private object _currentPage;
    public object CurrentPage
    {
        get => _currentPage;
        set => this.RaiseAndSetIfChanged(ref _currentPage, value);
    }

    public ReactiveCommand<Unit, Unit> NextCommand { get; }
    public ReactiveCommand<Unit, Unit> PrevCommand { get; }

    public MainWindowViewModel()
    {
        CurrentPage = new Page1ViewModel();
        NextCommand = ReactiveCommand.Create(() => CurrentPage = new Page2ViewModel());
        PrevCommand = ReactiveCommand.Create(() => CurrentPage = new Page1ViewModel());
    }
}
```

### 재사용 가능한 전환 호스트

프로젝트에서 여러 곳에 동일한 전환 스타일을 적용하려면 `TransitionHost`라는 사용자 정의 컨트롤을 만드는 것이 좋다.

```csharp
public class TransitionHost : ContentControl
{
    public static readonly StyledProperty<bool> UseSlideProperty =
        AvaloniaProperty.Register<TransitionHost, bool>(nameof(UseSlide), true);

    public bool UseSlide
    {
        get => GetValue(UseSlideProperty);
        set => SetValue(UseSlideProperty, value);
    }

    protected override void OnApplyTemplate(TemplateAppliedEventArgs e)
    {
        base.OnApplyTemplate(e);
        Transitions = new Transitions
        {
            UseSlide
                ? new PageSlide { Duration = TimeSpan.FromMilliseconds(350), SlideDirection = PageSlide.SlideAxis.Left }
                : new CrossFade { Duration = TimeSpan.FromMilliseconds(250) }
        };
    }
}
```

XAML에서 간단히 사용할 수 있다.

```xml
<local:TransitionHost Content="{Binding CurrentPage}" UseSlide="True" />
```

## 개별 컨트롤 애니메이션: Transitions vs 키프레임

### 속성 전환(DoubleTransition)

버튼에 마우스를 올렸을 때 크기가 살짝 커지거나, 클릭 시 작아지는 효과는 `DoubleTransition`으로 쉽게 구현할 수 있다.

```xml
<Button Content="호버 효과">
  <Button.Transitions>
    <Transitions>
      <DoubleTransition Property="RenderTransform.(ScaleTransform.ScaleX)" Duration="0:0:0.2"/>
      <DoubleTransition Property="RenderTransform.(ScaleTransform.ScaleY)" Duration="0:0:0.2"/>
    </Transitions>
  </Button.Transitions>
  <Button.RenderTransform>
    <ScaleTransform ScaleX="1" ScaleY="1"/>
  </Button.RenderTransform>
  <Button.Styles>
    <Style Selector="Button:pointerover">
      <Setter Property="RenderTransform.(ScaleTransform.ScaleX)" Value="1.05"/>
      <Setter Property="RenderTransform.(ScaleTransform.ScaleY)" Value="1.05"/>
    </Style>
    <Style Selector="Button:pressed">
      <Setter Property="RenderTransform.(ScaleTransform.ScaleX)" Value="0.98"/>
      <Setter Property="RenderTransform.(ScaleTransform.ScaleY)" Value="0.98"/>
    </Style>
  </Button.Styles>
</Button>
```

이 방식은 **속성 변경 시 자동으로 보간**되므로 선언적이고 간결하다.

### 키프레임 애니메이션

더 정교한 움직임(흔들림, 여러 단계 변화)이 필요하다면 `Animation`과 `KeyFrame`을 사용한다. 예를 들어, 요소가 나타날 때 투명도와 위치를 동시에 조절하는 등장 애니메이션은 다음과 같다.

```xml
<Grid x:Name="Root">
  <Grid.RenderTransform>
    <TranslateTransform Y="0"/>
  </Grid.RenderTransform>
  <Grid.Styles>
    <Style>
      <Style.Animations>
        <Animation Duration="0:0:0.4" FillMode="Forward">
          <KeyFrame Cue="0%">
            <Setter Property="Opacity" Value="0"/>
            <Setter Property="RenderTransform.(TranslateTransform.Y)" Value="12"/>
          </KeyFrame>
          <KeyFrame Cue="100%">
            <Setter Property="Opacity" Value="1"/>
            <Setter Property="RenderTransform.(TranslateTransform.Y)" Value="0"/>
          </KeyFrame>
        </Animation>
      </Style.Animations>
    </Style>
  </Grid.Styles>
  <Animation.Animations>
    <StaticResource ResourceKey="EnterAnim"/>
  </Animation.Animations>
  <TextBlock Text="등장!"/>
</Grid>
```

`FillMode="Forward"`를 주면 애니메이션 종료 후 최종 값이 유지된다.

## MVVM과 애니메이션 결합하기

### DataTrigger를 이용한 플래그 기반 애니메이션

ViewModel에 `bool` 속성을 두고, 그 값이 `true`일 때만 애니메이션이 실행되도록 할 수 있다. 아래는 입력 검증 실패 시 흔들림 효과를 주는 예제다.

**ViewModel**

```csharp
public class FormViewModel : ReactiveObject
{
    private bool _hasError;
    public bool HasError
    {
        get => _hasError;
        set => this.RaiseAndSetIfChanged(ref _hasError, value);
    }

    public ReactiveCommand<Unit, Unit> ValidateCommand { get; }

    public FormViewModel()
    {
        ValidateCommand = ReactiveCommand.Create(() =>
        {
            HasError = true;
            RxApp.MainThreadScheduler.Schedule(TimeSpan.FromMilliseconds(400), () => HasError = false);
        });
    }
}
```

**XAML (Border에 DataTrigger 적용)**

```xml
<Border x:Name="ErrorBorder">
  <Border.RenderTransform>
    <TranslateTransform X="0"/>
  </Border.RenderTransform>
  <Border.Styles>
    <Style Selector="Border">
      <Style.Triggers>
        <DataTrigger Binding="{Binding HasError}" Value="True">
          <Setter Property="Animation.Animations">
            <Animations>
              <Animation Duration="0:0:0.3">
                <KeyFrame Cue="0%"><Setter Property="RenderTransform.(TranslateTransform.X)" Value="0"/></KeyFrame>
                <KeyFrame Cue="25%"><Setter Property="RenderTransform.(TranslateTransform.X)" Value="-8"/></KeyFrame>
                <KeyFrame Cue="50%"><Setter Property="RenderTransform.(TranslateTransform.X)" Value="8"/></KeyFrame>
                <KeyFrame Cue="75%"><Setter Property="RenderTransform.(TranslateTransform.X)" Value="-4"/></KeyFrame>
                <KeyFrame Cue="100%"><Setter Property="RenderTransform.(TranslateTransform.X)" Value="0"/></KeyFrame>
              </Animation>
            </Animations>
          </Setter>
        </DataTrigger>
      </Style.Triggers>
    </Style>
  </Border.Styles>
  <!-- 내부 UI -->
</Border>
```

`HasError`가 `true`가 되면 흔들림 애니메이션이 실행되고, 자동으로 `false`로 되돌려진다.

### 애니메이션 서비스 추상화 (테스트 가능하게)

복잡한 애니메이션 시퀀스를 ViewModel에서 직접 제어해야 한다면, `IAnimationService` 인터페이스를 만들어 의존성을 주입한다.

```csharp
public interface IAnimationService
{
    Task RunAsync(Control target, Animation animation, CancellationToken ct = default);
}

public class AnimationService : IAnimationService
{
    public Task RunAsync(Control target, Animation animation, CancellationToken ct = default)
        => animation.RunAsync(target, ct);
}
```

ViewModel에서 서비스를 사용하면 테스트 시 `Mock`으로 대체하여 애니메이션 시간을 스킵하고 로직만 검증할 수 있다.

```csharp
public class ToastViewModel : ReactiveObject
{
    private readonly IAnimationService _anim;
    public Control? Target { get; set; } // View에서 연결

    public ReactiveCommand<Unit, Unit> ShowToastCommand { get; }

    public ToastViewModel(IAnimationService anim)
    {
        _anim = anim;
        ShowToastCommand = ReactiveCommand.CreateFromTask(ShowAsync);
    }

    private async Task ShowAsync()
    {
        if (Target == null) return;
        var fadeIn = new Animation { Duration = TimeSpan.FromMilliseconds(300), /* 키프레임 생략 */ };
        await _anim.RunAsync(Target, fadeIn);
        await Task.Delay(1500);
        var fadeOut = new Animation { Duration = TimeSpan.FromMilliseconds(300), /* 키프레임 생략 */ };
        await _anim.RunAsync(Target, fadeOut);
    }
}
```

## 리스트 항목 애니메이션 (추가/제거 시 부드러운 등장)

`ItemsControl`의 각 항목이 컬렉션에 추가될 때 부드럽게 나타나도록 하려면 항목 템플릿에 `Transitions`를 걸어준다.

```xml
<ItemsControl Items="{Binding Notifications}">
  <ItemsControl.ItemTemplate>
    <DataTemplate>
      <Border Margin="0,4" Padding="8" CornerRadius="6">
        <Border.Transitions>
          <Transitions>
            <DoubleTransition Property="Opacity" Duration="0:0:0.25"/>
            <DoubleTransition Property="RenderTransform.(TranslateTransform.Y)" Duration="0:0:0.25"/>
          </Transitions>
        </Border.Transitions>
        <Border.RenderTransform>
          <TranslateTransform Y="10"/>
        </Border.RenderTransform>
        <StackPanel>
          <TextBlock Text="{Binding Title}" FontWeight="Bold"/>
          <TextBlock Text="{Binding Message}" Opacity="0.85"/>
        </StackPanel>
      </Border>
    </DataTemplate>
  </ItemsControl.ItemTemplate>
</ItemsControl>
```

새 항목이 추가되면 기본값(Opacity=1, Y=10)에서 시작해 Transitions가 최종 상태(Opacity=1, Y=0)로 보간해준다. 이때 항목은 **렌더링된 순간부터 자동으로 애니메이션**된다.

## 다이얼로그 및 오버레이 진입/퇴장

모달 다이얼로그나 오버레이 패널도 `Transitions`로 진입/퇴장 애니메이션을 적용할 수 있다. `IsVisible` 속성이 바뀔 때 `DoubleTransition`을 이용해 페이드 인/아웃을 구현한다.

```xml
<Border Background="#80000000" IsVisible="{Binding IsOverlayVisible}">
  <Border.Transitions>
    <Transitions>
      <DoubleTransition Property="Opacity" Duration="0:0:0.2"/>
    </Transitions>
  </Border.Transitions>
  <Border.Styles>
    <Style Selector="Border:visible">
      <Setter Property="Opacity" Value="1"/>
    </Style>
    <Style Selector="Border:not(:visible)">
      <Setter Property="Opacity" Value="0"/>
    </Style>
  </Border.Styles>
  <!-- 내용 -->
</Border>
```

## 성능과 UX 고려사항

| 요소 | 권장 사항 |
|------|-----------|
| 지속시간 | 0.2~0.5초가 적절. 0.7초 이상은 느리게 느껴짐 |
| 애니메이션 대상 속성 | `Opacity`, `RenderTransform`(Translate, Scale, Rotate) 위주로 사용. `Width`, `Height`, `Margin` 등 레이아웃에 영향을 주는 속성은 피할 것 |
| 저사양 기기 | 애니메이션 수를 제한하거나, 시스템 모션 축소 설정에 반응하도록 옵션 제공 |
| 중복 애니메이션 | 같은 요소에 여러 애니메이션이 동시에 실행되지 않도록 주의 |
| 접근성 | 사용자가 모션을 꺼둘 수 있도록 설정 UI를 제공 |

## 테스트 전략

- **ViewModel 로직 테스트**: 애니메이션과 무관한 상태 전환, 명령 실행은 일반적인 단위 테스트로 검증한다.
- **애니메이션 서비스 Mock**: `IAnimationService`를 Mock으로 대체해 애니메이션 실행 시간을 0으로 만들고, ViewModel의 `RunAsync` 호출 여부만 확인한다.
- **시각 회귀 테스트**: 전체 화면 캡처를 비교하는 도구(예: Avalonia의 스냅샷 테스트)로 전환 전후의 화면을 비교할 수 있다.

## 실전 통합 예시

다음은 탭 전환, 알림 리스트, 오류 피드백을 하나의 화면에 통합한 예제의 핵심 구조다.

**ViewModel (일부)**

```csharp
public class DashboardViewModel : ReactiveObject
{
    private object _currentTab;
    public object CurrentTab { get => _currentTab; set => this.RaiseAndSetIfChanged(ref _currentTab, value); }

    public ObservableCollection<NotificationItem> Notifications { get; } = new();

    private bool _hasError;
    public bool HasError { get => _hasError; set => this.RaiseAndSetIfChanged(ref _hasError, value); }

    public ReactiveCommand<Unit, Unit> AddNotificationCommand { get; }
    public ReactiveCommand<Unit, Unit> TriggerErrorCommand { get; }

    public DashboardViewModel()
    {
        CurrentTab = new OverviewTabViewModel();
        AddNotificationCommand = ReactiveCommand.Create(() =>
        {
            Notifications.Insert(0, new NotificationItem { Title = "알림", Message = DateTime.Now.ToString() });
            if (Notifications.Count > 50) Notifications.RemoveAt(Notifications.Count - 1);
        });
        TriggerErrorCommand = ReactiveCommand.Create(() =>
        {
            HasError = true;
            RxApp.MainThreadScheduler.Schedule(TimeSpan.FromMilliseconds(400), () => HasError = false);
        });
    }
}
```

**XAML (요약)**

- 좌측 영역: `TransitionHost`로 탭 전환
- 우측 영역: 알림 리스트(항목 Transitions 적용) + 오류 시 흔들림 효과

전체 코드는 지면상 생략하지만, 앞서 설명한 요소들을 조합하면 완성된다.

## 정리

Avalonia에서 애니메이션과 전환 효과를 구현하는 방법은 크게 세 가지로 나뉜다.

1. **`Transitions`**: 속성 변경 시 자동 보간 (간단한 호버, 페이지 전환에 적합)
2. **키프레임 애니메이션**: 복잡한 시퀀스, 다단계 변화 (등장/퇴장, 흔들림)
3. **MVVM 결합**: `DataTrigger`로 선언적 실행, 또는 `IAnimationService` 추상화로 테스트 가능한 코드 작성

이러한 기법을 적절히 활용하면 사용자 경험을 크게 향상시키면서도 MVVM 원칙을 깨지 않는 깔끔한 구조를 유지할 수 있다. 시작은 작은 전환 효과부터 적용해보고, 필요에 따라 점차 복잡도를 높여가길 권장한다.
