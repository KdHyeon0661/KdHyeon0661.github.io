# DNS & 호스트 설정

## 이름 해석 흐름

리눅스에서 호스트 이름을 IP 주소로 바꾸는 과정은 `/etc/nsswitch.conf` 파일이 결정한다. 대부분의 배포판에서 기본 설정은 다음과 같다.

```conf
hosts: files dns
```

- `files`: `/etc/hosts` 파일을 먼저 확인한다.
- `dns`: `/etc/resolv.conf`에 지정된 DNS 서버를 사용한다.

즉, **`/etc/hosts`가 DNS보다 항상 우선**한다. 이 순서는 `nsswitch.conf`를 수정하면 바꿀 수 있다.

---

## `/etc/hosts` — 로컬 정적 매핑

`/etc/hosts` 파일은 간단한 IP-이름 매핑을 저장한다. 테스트나 내부 통신에 자주 사용된다.

```conf
127.0.0.1   localhost
192.168.1.10 dev-server
::1         localhost
```

한 줄에 여러 별칭을 쓸 수 있다. 첫 번째 이름이 정식 이름(canonical name)이 된다.

```conf
192.168.1.100 webserver webserver.local
```

`/etc/hosts`는 변경 즉시 적용되며, DNS보다 우선하기 때문에 개발 환경에서 도메인을 강제로 특정 IP로 연결할 때 유용하다.

---

## hostnamectl — 호스트명 관리

`hostnamectl`은 systemd 기반 시스템에서 호스트명을 확인하고 변경하는 도구다.

```bash
# 현재 호스트명 확인
hostnamectl

# 호스트명 변경 (정적)
sudo hostnamectl set-hostname devbox
```

호스트명은 `/etc/hostname` 파일에도 저장된다. 변경 후에는 로그아웃하거나 재부팅해야 프롬프트에 반영될 수 있다.

---

## `/etc/resolv.conf` — DNS 리졸버 설정

DNS 서버 주소와 검색 도메인 등을 설정하는 파일이다.

```conf
nameserver 8.8.8.8
nameserver 8.8.4.4
search example.com
options timeout:2 attempts:2
```

- `nameserver`: DNS 서버 IP (최대 3개)
- `search`: 도메인 접미사 (예: `ping web` → `web.example.com` 시도)
- `options`: 타임아웃, 재시도 횟수 등

**주의**: 현대 리눅스 배포판(Ubuntu, Fedora 등)에서는 `/etc/resolv.conf`가 심볼릭 링크로 관리되는 경우가 많다. 예를 들어 systemd-resolved나 NetworkManager가 자동으로 생성한다. 따라서 이 파일을 직접 편집해도 재부팅이나 네트워크 재시작 시 덮어쓰일 수 있다.

---

## systemd-resolved — 통합 DNS 리졸버

많은 배포판에서 `systemd-resolved`가 DNS 캐싱과 분할 DNS 기능을 제공한다. 사용 여부는 다음으로 확인한다.

```bash
ls -l /etc/resolv.conf
# /run/systemd/resolve/stub-resolv.conf로 연결되어 있으면 resolved 사용 중
```

`systemd-resolved`를 사용 중이라면 설정은 `/etc/systemd/resolved.conf`에서 한다.

```ini
[Resolve]
DNS=1.1.1.1 8.8.8.8
FallbackDNS=9.9.9.9
```

변경 후 서비스를 재시작한다.

```bash
sudo systemctl restart systemd-resolved
```

상태와 질의는 `resolvectl`로 확인한다.

```bash
resolvectl status          # 현재 DNS 서버, 도메인 정보
resolvectl query example.com
```

## DNS 질의 도구

### dig
`dig`는 DNS 전문 조회 도구로, 가장 자세한 정보를 준다.

```bash
dig example.com               # 기본 A 레코드 조회
dig @1.1.1.1 example.com      # 특정 DNS 서버로 질의
dig example.com +short        # 짧은 출력
```

### nslookup
예전 도구지만 간단히 사용할 수 있다.

```bash
nslookup example.com
```

### getent hosts
`/etc/nsswitch.conf`에 정의된 순서를 따라 이름을 해석한다. 애플리케이션 관점에서 결과를 확인할 때 유용하다.

```bash
getent hosts example.com
```

## 트러블슈팅 흐름

DNS 관련 문제가 발생하면 다음 순서로 점검한다.

1. **호스트명과 /etc/hosts 확인**
   ```bash
   hostnamectl
   cat /etc/hosts
   ```

2. **이름 해석 순서 확인**
   ```bash
   cat /etc/nsswitch.conf | grep hosts
   ```

3. **/etc/resolv.conf가 어디서 오는지 확인**
   ```bash
   ls -l /etc/resolv.conf
   ```

4. **resolved 사용 시 상태 확인**
   ```bash
   resolvectl status
   ```

5. **직접 DNS 질의 테스트**
   ```bash
   dig @8.8.8.8 example.com
   getent hosts example.com
   ```

6. **로컬 DNS 캐시 초기화 (resolved 사용 시)**
   ```bash
   sudo systemctl restart systemd-resolved
   ```

7. **방화벽, 라우팅 확인**
   ```bash
   ip r
   sudo iptables -S   # 필요시
   ```

## 실전 예제

### 예제 1: `/etc/hosts`로 로컬 테스트 도메인 설정

```conf
# /etc/hosts
127.0.0.1   api.local auth.local
```

```bash
curl http://api.local:8080/health
```

### 예제 2: systemd-resolved에서 DNS 서버 변경

```ini
# /etc/systemd/resolved.conf
[Resolve]
DNS=1.1.1.1
```

```bash
sudo systemctl restart systemd-resolved
resolvectl status
```

### 예제 3: `/etc/resolv.conf`가 링크가 아닐 때 직접 설정

```conf
# /etc/resolv.conf
nameserver 8.8.8.8
search corp.example.com
```

```bash
# 설정 즉시 적용 (별도 재시작 불필요)
ping example.com
```

### 예제 4: 특정 도메인만 다른 DNS로 질의 (split DNS)

`systemd-resolved`에서 인터페이스별로 도메인과 DNS를 설정할 수 있다.

```bash
sudo resolvectl dns eth0 10.0.0.53
sudo resolvectl domain eth0 '~corp.example.com'
resolvectl status
```

이후 `*.corp.example.com`은 내부 DNS로, 나머지는 기본 DNS로 질의된다.

## 핵심 명령어 요약

| 작업 | 명령어 / 파일 |
|------|----------------|
| 호스트명 확인/변경 | `hostnamectl`, `/etc/hostname` |
| 로컬 정적 매핑 | `/etc/hosts` |
| DNS 해석 순서 | `/etc/nsswitch.conf` |
| DNS 서버 설정 (전통) | `/etc/resolv.conf` |
| systemd-resolved 관리 | `resolvectl`, `/etc/systemd/resolved.conf` |
| DNS 질의 | `dig`, `nslookup`, `getent hosts` |
| DNS 문제 진단 | `resolvectl status`, `dig +trace` |

## 결론

리눅스의 이름 해석은 **/etc/hosts → /etc/nsswitch.conf → /etc/resolv.conf (또는 systemd-resolved)** 순서로 동작한다. `/etc/hosts`를 먼저 확인하기 때문에, 개발이나 테스트 환경에서는 이를 이용해 도메인을 원하는 IP에 고정할 수 있다.

현대 배포판에서는 `/etc/resolv.conf`가 systemd-resolved나 NetworkManager에 의해 자동 관리되는 경우가 많으므로, 설정을 변경할 때는 해당 도구의 설정 파일을 수정하는 것이 올바르다.

DNS 문제가 발생하면 `resolvectl status`로 현재 상태를 확인하고, `dig`로 직접 질의하며, `getent hosts`로 애플리케이션 관점의 해석 결과를 비교하면 원인을 빠르게 파악할 수 있다.
