# Avalonia MVVM 패턴과 리스트 바인딩

## MVVM 패턴의 이해

### 패턴이 필요한 이유

전통적인 UI 개발에서는 코드 비하인드 파일에 이벤트 처리와 비즈니스 로직이 함께 존재했다. 이 방식은 다음과 같은 문제를 낳는다.

- UI와 로직이 강하게 결합되어 변경이 어렵다
- 자동화된 테스트를 작성하기 어렵다
- 같은 로직을 다른 UI에서 재사용할 수 없다

**MVVM(Model-View-ViewModel)** 패턴은 이러한 문제를 해결하기 위해 등장했다. UI와 비즈니스 로직 사이에 ViewModel 계층을 두어 관심사를 분리한다.

### 세 구성 요소

| 구성 요소 | 역할 | 구현 시 주의점 |
|-----------|------|----------------|
| Model | 데이터 구조, 비즈니스 규칙 | UI 프레임워크에 의존하지 않음 |
| View | 사용자 인터페이스 (XAML) | 로직 최소화, 바인딩으로 데이터 연결 |
| ViewModel | 상태와 명령 관리, 데이터 가공 | INotifyPropertyChanged와 ICommand 구현 |

### 데이터 흐름

```
사용자 입력 → View → ViewModel → Model
                ↑          ↑
            바인딩     데이터 갱신
```

View는 ViewModel의 속성과 명령에 바인딩한다. 사용자가 버튼을 클릭하면 ViewModel의 명령이 실행되고, ViewModel은 필요에 따라 Model을 갱신한다. Model이 변경되면 ViewModel이 이를 감지해 View에 반영한다.

## ViewModel 구현 기초

### INotifyPropertyChanged 구현

ViewModel의 핵심은 속성 변경을 View에 알리는 기능이다. ReactiveUI와 CommunityToolkit.Mvvm은 이를 간소화한다.

**ReactiveUI 방식**

```csharp
using ReactiveUI;

public class ViewModelBase : ReactiveObject
{
}

public class MainWindowViewModel : ViewModelBase
{
    private string _userName = "";
    public string UserName
    {
        get => _userName;
        set => this.RaiseAndSetIfChanged(ref _userName, value);
    }
}
```

**CommunityToolkit.Mvvm 방식**

```csharp
using CommunityToolkit.Mvvm.ComponentModel;

public partial class MainWindowViewModel : ObservableObject
{
    [ObservableProperty]
    private string _userName = "";
}
```

`[ObservableProperty]` 소스 생성기가 INotifyPropertyChanged 구현 코드를 자동으로 생성해준다.

### ICommand 구현

사용자 동작을 ViewModel에 전달하려면 명령 패턴이 필요하다.

**ReactiveUI**

```csharp
using ReactiveUI;
using System.Reactive;

public class MainWindowViewModel : ViewModelBase
{
    public ReactiveCommand<Unit, Unit> GreetCommand { get; }

    public MainWindowViewModel()
    {
        GreetCommand = ReactiveCommand.Create(() =>
        {
            UserName = $"안녕하세요, {UserName}님!";
        });
    }
}
```

**CommunityToolkit.Mvvm**

```csharp
using CommunityToolkit.Mvvm.Input;

public partial class MainWindowViewModel : ObservableObject
{
    [RelayCommand]
    private void Greet()
    {
        UserName = $"안녕하세요, {UserName}님!";
    }
}
```

## View에서 바인딩

XAML에서 ViewModel의 속성과 명령을 연결하는 방법은 다음과 같다.

```xml
<Window xmlns="https://github.com/avaloniaui"
        xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
        xmlns:vm="using:MyApp.ViewModels"
        x:Class="MyApp.Views.MainWindow"
        Title="MVVM 예제" Width="400" Height="200">
    
    <Window.DataContext>
        <vm:MainWindowViewModel/>
    </Window.DataContext>

    <StackPanel HorizontalAlignment="Center" VerticalAlignment="Center" Spacing="8">
        <TextBox Text="{Binding UserName, Mode=TwoWay}" Watermark="이름을 입력하세요"/>
        <Button Content="인사하기" Command="{Binding GreetCommand}" />
    </StackPanel>
</Window>
```

`Mode=TwoWay`는 텍스트 상자의 입력이 ViewModel로 전달되고, ViewModel의 변경이 텍스트 상자에 반영됨을 의미한다.

## 리스트 바인딩

### 컬렉션 관리

리스트 데이터는 `ObservableCollection<T>`로 관리한다. 이 컬렉션은 항목 추가/삭제 시 UI에 자동으로 반영된다.

```csharp
using ReactiveUI;
using System.Collections.ObjectModel;

public class Person
{
    public string Name { get; set; }
    public int Age { get; set; }
}

public class PeopleViewModel : ViewModelBase
{
    public ObservableCollection<Person> People { get; } = new();

    private Person? _selectedPerson;
    public Person? SelectedPerson
    {
        get => _selectedPerson;
        set => this.RaiseAndSetIfChanged(ref _selectedPerson, value);
    }

    public PeopleViewModel()
    {
        People.Add(new Person { Name = "홍길동", Age = 30 });
        People.Add(new Person { Name = "김철수", Age = 25 });
    }
}
```

### ListBox 바인딩

```xml
<ListBox Items="{Binding People}"
         SelectedItem="{Binding SelectedPerson, Mode=TwoWay}">
    <ListBox.ItemTemplate>
        <DataTemplate>
            <Grid ColumnDefinitions="*,80">
                <TextBlock Text="{Binding Name}"/>
                <TextBlock Grid.Column="1" Text="{Binding Age}" 
                           HorizontalAlignment="Right"/>
            </Grid>
        </DataTemplate>
    </ListBox.ItemTemplate>
</ListBox>
```

`ItemTemplate`으로 각 항목의 모양을 자유롭게 구성할 수 있다.

### 항목 추가와 삭제

ViewModel에 추가/삭제 명령을 구현한다.

```csharp
public partial class PeopleViewModel : ObservableObject
{
    [ObservableProperty]
    private string _nameInput = "";

    [ObservableProperty]
    private string _ageInput = "";

    [RelayCommand(CanExecute = nameof(CanAdd))]
    private void Add()
    {
        if (!int.TryParse(AgeInput, out var age)) return;
        People.Add(new Person { Name = NameInput.Trim(), Age = age });
        NameInput = "";
        AgeInput = "";
    }

    private bool CanAdd() => 
        !string.IsNullOrWhiteSpace(NameInput) && 
        int.TryParse(AgeInput, out var age) && age > 0;

    [RelayCommand(CanExecute = nameof(CanRemove))]
    private void Remove()
    {
        if (SelectedPerson != null)
            People.Remove(SelectedPerson);
    }

    private bool CanRemove() => SelectedPerson != null;
}
```

XAML에서는 버튼의 Command에 각각 바인딩한다.

```xml
<StackPanel Orientation="Horizontal" Spacing="6">
    <TextBox Text="{Binding NameInput, Mode=TwoWay}" Watermark="이름"/>
    <TextBox Text="{Binding AgeInput, Mode=TwoWay}" Watermark="나이"/>
    <Button Content="추가" Command="{Binding AddCommand}"/>
    <Button Content="삭제" Command="{Binding RemoveCommand}"/>
</StackPanel>
```

## 데이터 그리드 활용

열 헤더가 있는 테이블 형태가 필요하면 DataGrid를 사용한다. Avalonia.Controls.DataGrid 패키지를 추가해야 한다.

```xml
<DataGrid Items="{Binding People}"
          AutoGenerateColumns="False"
          SelectedItem="{Binding SelectedPerson}">
    <DataGrid.Columns>
        <DataGridTextColumn Header="이름" Binding="{Binding Name}" Width="*"/>
        <DataGridTextColumn Header="나이" Binding="{Binding Age}" Width="100"/>
    </DataGrid.Columns>
</DataGrid>
```

## 선택 인덱스 활용

선택된 항목의 인덱스가 필요한 경우 SelectedIndex를 함께 관리한다.

```csharp
private int _selectedIndex = -1;
public int SelectedIndex
{
    get => _selectedIndex;
    set => this.RaiseAndSetIfChanged(ref _selectedIndex, value);
}
```

XAML에서는 SelectedIndex 속성도 바인딩한다.

```xml
<ListBox Items="{Binding People}"
         SelectedItem="{Binding SelectedPerson}"
         SelectedIndex="{Binding SelectedIndex}"/>
```

## 필터링 구현

전체 컬렉션을 직접 변경하지 않고, 필터링된 결과를 별도 컬렉션으로 관리하는 방식이 일반적이다.

```csharp
public ObservableCollection<Person> People { get; } = new();
public ObservableCollection<Person> FilteredPeople { get; } = new();

private string _filterText = "";
public string FilterText
{
    get => _filterText;
    set
    {
        this.RaiseAndSetIfChanged(ref _filterText, value);
        ApplyFilter();
    }
}

private void ApplyFilter()
{
    FilteredPeople.Clear();
    foreach (var person in People)
    {
        if (string.IsNullOrWhiteSpace(FilterText) ||
            person.Name.Contains(FilterText, StringComparison.OrdinalIgnoreCase))
        {
            FilteredPeople.Add(person);
        }
    }
}
```

XAML에서는 ItemsSource를 FilteredPeople에 바인딩한다.

```xml
<TextBox Text="{Binding FilterText}" Watermark="이름 검색"/>
<ListBox Items="{Binding FilteredPeople}" SelectedItem="{Binding SelectedPerson}">
```

## 비동기 데이터 로딩

네트워크나 파일에서 데이터를 로드할 때는 비동기 명령을 사용한다.

**ReactiveUI**

```csharp
public ReactiveCommand<Unit, Unit> LoadCommand { get; }

public PeopleViewModel()
{
    LoadCommand = ReactiveCommand.CreateFromTask(async () =>
    {
        IsLoading = true;
        var data = await _service.GetPeopleAsync();
        People.Clear();
        foreach (var item in data) People.Add(item);
        IsLoading = false;
    });
}
```

**CommunityToolkit**

```csharp
[RelayCommand]
private async Task LoadAsync()
{
    IsLoading = true;
    var data = await _service.GetPeopleAsync();
    People.Clear();
    foreach (var item in data) People.Add(item);
    IsLoading = false;
}
```

XAML에서는 로딩 상태를 표시할 수 있다.

```xml
<Button Content="불러오기" Command="{Binding LoadCommand}"/>
<TextBlock Text="{Binding IsLoading, Converter={StaticResource BoolToText}}"/>
```

## 의존성 주입과 서비스 분리

실제 애플리케이션에서는 ViewModel이 외부 서비스에 의존한다. 의존성 주입을 사용해 이를 관리한다.

**App.axaml.cs**

```csharp
public partial class App : Application
{
    public static ServiceProvider Services { get; private set; } = null!;

    public override void OnFrameworkInitializationCompleted()
    {
        var services = new ServiceCollection();
        
        services.AddSingleton<IPeopleService, PeopleService>();
        services.AddTransient<PeopleViewModel>();
        services.AddSingleton<MainWindowViewModel>();
        
        Services = services.BuildServiceProvider();

        if (ApplicationLifetime is IClassicDesktopStyleApplicationLifetime desktop)
        {
            desktop.MainWindow = new MainWindow
            {
                DataContext = Services.GetRequiredService<MainWindowViewModel>()
            };
        }

        base.OnFrameworkInitializationCompleted();
    }
}
```

ViewModel 생성자에서 필요한 서비스를 주입받는다.

```csharp
public class PeopleViewModel : ViewModelBase
{
    private readonly IPeopleService _peopleService;

    public PeopleViewModel(IPeopleService peopleService)
    {
        _peopleService = peopleService;
    }
}
```

## 뷰 간 탐색

여러 화면을 전환하는 구조는 셸 ViewModel이 현재 ViewModel을 관리하는 방식으로 구현한다.

```csharp
public class MainWindowViewModel : ViewModelBase
{
    private ViewModelBase _currentViewModel;
    public ViewModelBase CurrentViewModel
    {
        get => _currentViewModel;
        set => this.RaiseAndSetIfChanged(ref _currentViewModel, value);
    }

    public ReactiveCommand<Unit, Unit> GoToHomeCommand { get; }
    public ReactiveCommand<Unit, Unit> GoToListCommand { get; }

    public MainWindowViewModel()
    {
        CurrentViewModel = new HomeViewModel();
        
        GoToHomeCommand = ReactiveCommand.Create(() => 
            CurrentViewModel = new HomeViewModel());
        GoToListCommand = ReactiveCommand.Create(() => 
            CurrentViewModel = new PeopleViewModel());
    }
}
```

XAML에서는 ContentControl을 사용한다.

```xml
<DockPanel>
    <StackPanel DockPanel.Dock="Top" Orientation="Horizontal" Spacing="8">
        <Button Command="{Binding GoToHomeCommand}" Content="홈"/>
        <Button Command="{Binding GoToListCommand}" Content="목록"/>
    </StackPanel>
    <ContentControl Content="{Binding CurrentViewModel}"/>
</DockPanel>
```

View와 ViewModel 연결은 App.axaml에 DataTemplate으로 정의한다.

```xml
<Application.DataTemplates>
    <DataTemplate DataType="{x:Type vm:HomeViewModel}">
        <views:HomeView/>
    </DataTemplate>
    <DataTemplate DataType="{x:Type vm:PeopleViewModel}">
        <views:PeopleView/>
    </DataTemplate>
</Application.DataTemplates>
```

## 입력 검증

사용자 입력을 검증할 때는 CommunityToolkit.Mvvm의 ObservableValidator를 활용한다.

```csharp
using CommunityToolkit.Mvvm.ComponentModel;
using System.ComponentModel.DataAnnotations;

public partial class PersonFormViewModel : ObservableValidator
{
    [ObservableProperty]
    [Required(ErrorMessage = "이름은 필수입니다.")]
    [MinLength(2, ErrorMessage = "이름은 2자 이상이어야 합니다.")]
    private string? _name;

    [ObservableProperty]
    [Required(ErrorMessage = "나이는 필수입니다.")]
    [Range(1, 120, ErrorMessage = "나이는 1에서 120 사이여야 합니다.")]
    private int? _age;

    partial void OnNameChanged(string? value) => ValidateProperty(value, nameof(Name));
    partial void OnAgeChanged(int? value) => ValidateProperty(value, nameof(Age));

    public bool HasErrors => GetErrors().Any();
}
```

XAML에서는 TextBox에 Validation.ErrorTemplate을 적용해 오류를 표시할 수 있다.

## 단위 테스트

MVVM의 큰 장점은 ViewModel을 View 없이 테스트할 수 있다는 점이다.

```csharp
using Xunit;

public class PeopleViewModelTests
{
    [Fact]
    public void Add_ValidInput_AddsPerson()
    {
        var vm = new PeopleViewModel();
        var initialCount = vm.People.Count;
        
        vm.NameInput = "테스터";
        vm.AgeInput = "25";
        vm.AddCommand.Execute(null);
        
        Assert.Equal(initialCount + 1, vm.People.Count);
        Assert.Contains(vm.People, p => p.Name == "테스터" && p.Age == 25);
    }

    [Fact]
    public void Remove_SelectedPerson_RemovesFromList()
    {
        var vm = new PeopleViewModel();
        vm.SelectedPerson = vm.People[0];
        var removedName = vm.SelectedPerson.Name;
        
        vm.RemoveCommand.Execute(null);
        
        Assert.DoesNotContain(vm.People, p => p.Name == removedName);
        Assert.Null(vm.SelectedPerson);
    }
}
```

## 성능 고려사항

| 상황 | 권장 방법 |
|------|-----------|
| 대량 데이터 표시 | 가상화 지원 컨트롤(ListBox, DataGrid) 사용 |
| 잦은 필터링 | 디바운스 적용, 불필요한 컬렉션 재생성 방지 |
| 복잡한 항목 템플릿 | 템플릿 단순화, 변환기 최소화 |
| 이미지 로딩 | 비동기 로딩, 캐싱 활용 |

## 자주 발생하는 문제

| 문제 | 해결 방법 |
|------|-----------|
| 바인딩이 동작하지 않음 | 출력 창에서 바인딩 오류 확인, 속성명 철자 검사 |
| 컬렉션 변경이 UI에 반영 안됨 | ObservableCollection 사용 확인 |
| 명령 버튼이 비활성화됨 | CanExecute 조건과 RaiseCanExecuteChanged 호출 확인 |
| DataTemplate이 적용되지 않음 | 네임스페이스와 타입명 정확히 지정 |

## 정리

MVVM 패턴은 Avalonia 애플리케이션 개발의 표준이다. 이 패턴을 적용함으로써 얻을 수 있는 이점은 다음과 같다.

- UI와 로직이 분리되어 유지보수성이 향상된다
- ViewModel 단위 테스트로 안정성을 높일 수 있다
- 동일 ViewModel을 다른 View에서 재사용할 수 있다
- 의존성 주입과 결합해 확장성 있는 구조를 만들 수 있다

리스트 바인딩은 MVVM에서 가장 빈번하게 사용되는 패턴 중 하나다. ObservableCollection과 DataTemplate, 명령 패턴을 조합하면 다양한 형태의 리스트 UI를 효율적으로 구현할 수 있다.
