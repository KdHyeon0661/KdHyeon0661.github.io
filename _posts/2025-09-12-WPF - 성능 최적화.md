# WPF 성능 최적화 실전 가이드

WPF 애플리케이션이 느려지는 이유는 다양하지만, 대부분은 **UI 스레드에서 무거운 작업을 실행하거나**, **비효율적인 렌더링**, **과도한 데이터 바인딩** 때문입니다. 이 글에서는 초중급 개발자가 실무에서 바로 적용할 수 있는 핵심 성능 최적화 기법을 정리합니다.

---

## 성능 저하의 주요 원인

| 원인 | 설명 |
|------|------|
| **UI 스레드 차단** | 네트워크/디스크 I/O, 복잡한 계산을 UI 스레드에서 수행 |
| **비효율적인 렌더링** | 개별 Shape 요소가 너무 많거나, 불필요한 효과 사용 |
| **과도한 바인딩** | 너무 많은 속성에 양방향 바인딩, 불필요한 업데이트 |
| **메모리 누수** | 이벤트 미구독, 정적 참조 등으로 GC 수거 불가 |
| **대용량 데이터 처리** | 가상화 없이 수천 개의 항목을 한 번에 표시 |

## 1. UI 스레드 차단 방지

### 비동기 프로그래밍
무거운 작업은 `async`/`await`로 백그라운드 스레드에서 실행합니다.

```csharp
// 나쁜 예 - UI 스레드 차단
private void LoadData()
{
    var data = _repository.GetAll(); // 동기 I/O
    Items = new ObservableCollection<Item>(data);
}

// 좋은 예 - 비동기 처리
private async Task LoadDataAsync()
{
    var data = await Task.Run(() => _repository.GetAll()); // 백그라운드 실행
    Items = new ObservableCollection<Item>(data); // UI 갱신은 Dispatcher에서
}
```

`Task.Run`으로 CPU 작업을 백그라운드로 보내고, UI 업데이트는 `Dispatcher.Invoke`나 `async` 메서드 내에서 자연스럽게 처리합니다.

### Dispatcher 우선순위
필요에 따라 우선순위를 조정하여 UI 응답성을 높일 수 있습니다.

```csharp
// 중요도 낮은 작업은 Background 우선순위로 실행
Dispatcher.CurrentDispatcher.InvokeAsync(() => UpdateStatusBar(),
    DispatcherPriority.Background);
```

## 2. 렌더링 성능 최적화

### UI 가상화
`ListBox`나 `ListView`에 수천 개의 항목을 표시할 때는 반드시 가상화를 활성화합니다.

```xml
<ListBox ItemsSource="{Binding Items}"
         VirtualizingStackPanel.IsVirtualizing="True"
         VirtualizingStackPanel.VirtualizationMode="Recycling"
         ScrollViewer.CanContentScroll="True">
</ListBox>
```

- `IsVirtualizing="True"` (기본값) : 화면에 보이는 항목만 생성
- `VirtualizationMode="Recycling"` : 항목 컨테이너 재사용 → 성능 향상
- `CanContentScroll="True"` : 항목 단위 스크롤, 가상화에 필요

### 그리기 요소 최적화
많은 개별 `Shape`(Path, Rectangle 등) 대신 `OnRender`로 한 번에 그리거나, `Drawing` 객체를 재사용합니다.

```csharp
// 1000개의 개별 Rectangle 대신 하나의 DrawingGroup으로 통합
protected override void OnRender(DrawingContext drawingContext)
{
    var pen = new Pen(Brushes.Black, 1);
    if (pen.CanFreeze) pen.Freeze(); // Freeze로 성능 향상

    for (int i = 0; i < 1000; i++)
    {
        drawingContext.DrawRectangle(null, pen, new Rect(i * 10, 0, 5, 5));
    }
}
```

### BitmapCache 사용
자주 변경되지 않는 복잡한 UI는 `BitmapCache`로 비트맵 캐시하여 다시 그리기 비용을 줄입니다.

```xml
<Border CacheMode="BitmapCache">
    <!-- 복잡한 콘텐츠 -->
</Border>
```

### 이미지 처리
고해상도 이미지를 작게 표시할 때는 `DecodePixelWidth`/`DecodePixelHeight`로 미리 크기를 줄여 메모리 사용을 절약합니다.

```csharp
var bitmap = new BitmapImage();
bitmap.BeginInit();
bitmap.UriSource = new Uri("large.jpg", UriKind.Relative);
bitmap.DecodePixelWidth = 200; // 실제 표시 크기로 디코딩
bitmap.EndInit();
bitmap.Freeze(); // 스레드 간 공유 가능, 성능 향상
```

## 3. 데이터 바인딩 최적화

### 불필요한 업데이트 방지
- `UpdateSourceTrigger=PropertyChanged`는 필요한 경우에만 사용 (기본값은 `LostFocus`)
- `Delay` 속성으로 빈번한 입력 중 업데이트 지연

```xml
<TextBox Text="{Binding SearchText, UpdateSourceTrigger=PropertyChanged, Delay=500}"/>
```

### 적절한 바인딩 모드
- 읽기 전용 속성은 `Mode=OneWay`
- 단순 표시만 필요하면 `Mode=OneTime` (초기 한 번만 평가)

### 값 변환기 성능
- `IValueConverter` 내에서 무거운 작업을 하지 않음
- 변환 결과를 캐시하거나 미리 계산된 속성을 ViewModel에 추가

```csharp
// 나쁜 예 - 변환기에서 복잡한 계산
public object Convert(object value, ...)
{
    return ExpensiveCalculation(value); // 매 바인딩 갱신 시 호출됨
}

// 좋은 예 - ViewModel에서 미리 계산
public string FormattedDate => Date.ToString("yyyy-MM-dd");
```

### 바인딩 디버깅
출력 창(Output)에 바인딩 오류가 표시됩니다. `PresentationTraceSources`로 상세 정보를 볼 수 있습니다.

```xml
<TextBlock Text="{Binding UserName, 
                  PresentationTraceSources.TraceLevel=High}"/>
```

## 4. 메모리 관리

### 이벤트 구독 해제
구독한 이벤트는 반드시 해제해야 메모리 누수를 방지할 수 있습니다.

```csharp
// 구독
_someObject.PropertyChanged += OnPropertyChanged;

// 해제 (예: Window Closed 이벤트에서)
_someObject.PropertyChanged -= OnPropertyChanged;
```

### 약한 이벤트 패턴
정적 이벤트나 장수명 객체의 이벤트를 구독할 때는 WeakEventManager를 사용합니다.

```csharp
WeakEventManager<INotifyPropertyChanged, PropertyChangedEventArgs>
    .AddHandler(_viewModel, nameof(INotifyPropertyChanged.PropertyChanged), OnViewModelChanged);
```

### 이미지 메모리 관리
`BitmapImage`를 사용 후 `Freeze()`하여 불필요한 복사본을 방지하고, 더 이상 필요 없으면 `null` 할당하여 GC를 유도합니다.

## 5. 컬렉션 업데이트 배치 처리

`ObservableCollection`에 항목을 하나씩 추가하면 UI 갱신이 매번 발생합니다. 대량 추가 시에는 배치 처리가 필요합니다.

```csharp
// 나쁜 예 - 1000번의 UI 갱신
foreach (var item in items)
    MyCollection.Add(item);

// 좋은 예 - 한 번에 추가
var newItems = items.ToList();
MyCollection.Clear();
foreach (var item in newItems)
    MyCollection.Add(item);
```

`CollectionView`를 사용할 때는 `DeferRefresh`로 임시로 갱신을 막을 수 있습니다.

```csharp
using (var defer = CollectionViewSource.GetDefaultView(MyCollection).DeferRefresh())
{
    // 여러 변경 작업 수행
    // defer 블록을 나가면 한 번에 갱신됨
}
```

## 6. 프로파일링과 진단

성능 문제를 정확히 파악하려면 도구를 활용합니다.

| 도구 | 용도 |
|------|------|
| **Visual Studio 진단 도구** | CPU 사용량, 메모리 누수 분석 |
| **Snoop** | 시각적 트리, 바인딩 오류 실시간 확인 |
| **WPF Performance Suite** | 프레임률, 레이아웃 비용 측정 |
| **IntelliTrace (엔터프라이즈)** | 이벤트 추적, 예외 분석 |

**간단한 성능 측정**:

```csharp
var sw = Stopwatch.StartNew();
await LoadHeavyDataAsync();
sw.Stop();
Debug.WriteLine($"Load time: {sw.ElapsedMilliseconds} ms");
```

## 결론

WPF 성능 최적화는 **측정 → 병목 지점 식별 → 최적화 → 검증**의 반복 과정입니다. 초중급 개발자가 실무에서 즉시 적용할 수 있는 핵심은 다음과 같습니다.

1. **비동기 프로그래밍**으로 UI 스레드 차단 제거
2. **UI 가상화**로 대용량 목록 처리
3. **이미지 처리 최적화** (적절한 크기로 디코딩, Freeze)
4. **바인딩 최적화** (OneWay, Delay, 불필요한 변환기 제거)
5. **이벤트 구독 해제**로 메모리 누수 방지

성능 문제가 발생하기 전에 예방하는 것이 가장 좋지만, 문제가 발생했을 때는 위 기법들을 적용해 점진적으로 개선해 나가면 됩니다. 모든 최적화는 실제 측정 데이터를 바탕으로 진행해야 하며, 과도한 최적화는 코드 가독성과 유지보수성을 해칠 수 있음을 기억하세요.
