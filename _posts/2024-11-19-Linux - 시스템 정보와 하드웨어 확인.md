# 시스템 정보와 하드웨어 확인

## 시스템 모니터링의 세 가지 접근 방식

시스템 상태를 확인하는 방법은 크게 세 가지로 나눌 수 있다. 상황에 따라 적절한 도구를 선택하면 문제 진단이 훨씬 쉬워진다.

1. **실시간 모니터링** : 현재 시스템의 CPU, 메모리, 디스크, 네트워크 사용량을 즉시 확인한다. (`top`, `vmstat`, `iostat`, `ip -s` 등)
2. **정적/상세 정보 수집** : 하드웨어 사양, 커널 버전, 장치 정보 등을 상세히 조회한다. (`lscpu`, `lsblk`, `lspci`, `dmidecode` 등)
3. **특화된 진단** : 디스크 건강 상태, 네트워크 대역폭, 온도 등을 집중적으로 측정한다. (`smartctl`, `iperf3`, `sensors` 등)

---

## 실시간 자원 사용 모니터링

### top / htop — 기본 실시간 모니터

`top`은 가장 널리 사용되는 실시간 모니터 도구다.

```bash
top
```

주요 단축키:
- `P` : CPU 사용률 기준 정렬
- `M` : 메모리 사용량 기준 정렬
- `1` : 개별 CPU 코어별 사용률 표시
- `k` : 프로세스 종료 (PID 입력)
- `q` : 종료

`htop`은 `top`의 향상된 버전으로, 색상과 마우스 조작, 더 직관적인 인터페이스를 제공한다.

```bash
sudo apt install htop   # 설치 후
htop
```

### free — 메모리 사용량

```bash
free -h
```

`available` 컬럼은 캐시와 버퍼를 고려한 실제 가용 메모리를 보여준다.

### vmstat — 시스템 성능 스냅샷

```bash
vmstat 2 5       # 2초 간격 5회 출력
```

주요 지표:
- `r` : 실행 대기 중인 프로세스 수
- `si`/`so` : 스왑 인/아웃
- `wa` : I/O 대기 시간 비율

### iostat — 디스크 I/O 성능

```bash
sudo apt install sysstat
iostat -xz 1 3
```

- `await` : I/O 요청 평균 대기 시간
- `%util` : 디스크 사용률 (100%에 가까우면 포화 상태)

### dstat — 종합 모니터링

```bash
sudo apt install dstat
dstat -cdngym --top-io
```

CPU, 디스크, 네트워크, 메모리 등을 한 화면에서 볼 수 있다.

### uptime — 부하 평균

```bash
uptime
```

1분, 5분, 15분 평균 부하를 보여준다. CPU 코어 수보다 지속적으로 높으면 과부하 상태일 수 있다.

## CPU, 메모리, 메인보드 정보

### lscpu — CPU 아키텍처 정보

```bash
lscpu
```

CPU 코어 수, 스레드 수, 모델명, 캐시 크기 등을 확인할 수 있다.

### 메모리 및 메인보드 정보

```bash
sudo dmidecode -t memory | less
sudo lshw -short | less
```

`dmidecode`는 메모리 슬롯, 용량, 속도 등 하드웨어 정보를, `lshw`는 종합 하드웨어 정보를 보여준다.

### 온도 및 전력 모니터링

```bash
sudo apt install lm-sensors
sudo sensors-detect   # 처음 한 번만 실행
sensors               # CPU/GPU 온도, 팬 속도 등 출력
```

## 스토리지 시스템 정보

### 블록 장치와 파티션

```bash
lsblk -o NAME,SIZE,TYPE,MOUNTPOINT,FSTYPE,MODEL
sudo blkid
df -hT
```

`lsblk`는 디스크 구조를 트리 형태로 보여준다. `df -hT`는 마운트된 파일시스템의 용량과 타입을 확인한다.

### 디스크 건강 상태

```bash
sudo apt install smartmontools
sudo smartctl -a /dev/sda
sudo smartctl -H /dev/sda
```

`smartctl`로 SATA/SAS 디스크의 건강 상태(재할당 섹터, 온도, 오류 로그 등)를 확인할 수 있다.

NVMe SSD는 `nvme-cli` 패키지를 사용한다.

```bash
sudo apt install nvme-cli
sudo nvme list
sudo nvme smart-log /dev/nvme0
```

## 네트워크 정보 확인

### 인터페이스와 연결 상태

```bash
ip -s link          # 패킷 드롭, 에러 통계
ss -tuln            # 리스닝 포트
ss -s               # 소켓 통계 요약
```

### 드라이버 및 링크 정보 (ethtool)

```bash
sudo ethtool eth0               # 링크 속도, 듀플렉스
sudo ethtool -i eth0            # 드라이버 정보
sudo ethtool -S eth0 | less     # 하드웨어 통계
```

### 네트워크 성능 테스트

```bash
sudo apt install iperf3 mtr
# 서버 측
iperf3 -s

# 클라이언트 측
iperf3 -c <서버IP> -P 4 -t 30

# 경로 품질 확인
mtr -rwzbc 100 8.8.8.8
```

## 프로세스 및 커널 수준 분석

### pidstat / mpstat

```bash
pidstat 1 5               # 프로세스별 CPU, 메모리, I/O 통계
mpstat -P ALL 1 5         # CPU 코어별 사용률
```

### 커널 메모리 및 인터럽트

```bash
slabtop                   # 커널 슬랩 메모리 사용 현황
cat /proc/interrupts | column -t
```

## 간단한 시스템 정보 수집 스크립트

```bash
#!/usr/bin/env bash
# sysinfo.sh

echo "== 호스트명 =="
hostnamectl
echo

echo "== CPU 정보 =="
lscpu
echo

echo "== 메모리 =="
free -h
echo

echo "== 디스크 =="
lsblk -o NAME,SIZE,TYPE,MOUNTPOINT,FSTYPE
df -hT
echo

echo "== 네트워크 =="
ip -br a
ss -tuln
```

실행 권한을 준 후 `./sysinfo.sh`로 실행하면 주요 정보를 한 번에 확인할 수 있다.

## 장애 시나리오별 점검

### 시스템 부하가 높을 때

1. `uptime`과 `top`으로 부하와 CPU 사용률 확인
2. `vmstat 1`로 r(실행 큐)과 wa(I/O 대기) 확인
3. `iostat -xz 1`로 디스크 병목 확인
4. `free -h`로 메모리 부족 여부 확인

### 디스크 성능 저하 의심

```bash
dmesg | grep -i error
iostat -xz 1 5
smartctl -H /dev/sda
```

`await` 값이 높거나 `%util`이 100%에 가깝고 `dmesg`에 오류가 있다면 디스크나 컨트롤러 문제일 수 있다.

### 네트워크 패킷 드롭

```bash
ip -s link
ethtool -S eth0 | grep -i drop
mtr -rwzbc 200 8.8.8.8
```

## 결론

시스템 정보 확인과 모니터링은 리눅스 관리의 가장 기본이면서도 중요한 작업이다.  
- **실시간 모니터링**(`top`, `vmstat`, `iostat`)으로 현재 상태를 빠르게 파악하고,  
- **상세 정보**(`lscpu`, `lsblk`, `smartctl`)로 하드웨어 구성을 확인하며,  
- **특화 도구**(`iperf3`, `mtr`)로 문제 구간을 좁혀나가는 흐름이 효과적이다.

자주 사용하는 명령어들을 익히고, 장애 발생 시 체계적으로 점검하는 습관을 들이면 안정적인 시스템 운영이 가능하다. 필요하다면 간단한 스크립트로 자주 보는 정보를 정리해 두는 것도 좋은 방법이다.
