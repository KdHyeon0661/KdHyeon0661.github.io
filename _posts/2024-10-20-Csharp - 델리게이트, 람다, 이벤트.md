# C# 델리게이트

델리게이트(Delegate)는 C#에서 메서드 자체를 변수에 저장하거나 매개변수로 전달할 수 있게 해주는 타입입니다. C++의 함수 포인터와 유사하지만, 타입 안전성과 객체 지향적인 캡슐화를 갖춘 고급 기능입니다. 델리게이트를 이해하면 콜백, 이벤트, LINQ 등 현대 C# 프로그래밍의 핵심 패턴을 자연스럽게 익힐 수 있습니다.

---

## 델리게이트의 기본 개념

델리게이트는 **메서드에 대한 참조**를 담는 타입입니다. 특정 시그니처(매개변수와 반환 타입)를 가진 메서드라면 어떤 메서드든지 델리게이트에 할당할 수 있습니다.

### 델리게이트 선언과 인스턴스화

델리게이트 타입을 선언하려면 `delegate` 키워드를 사용합니다. 이 타입은 마치 클래스처럼 사용됩니다.

```csharp
// 1. 델리게이트 타입 선언
public delegate void PrintDelegate(string message);
public delegate int CalculateDelegate(int a, int b);

// 2. 대상 메서드
static void ConsolePrint(string msg) => Console.WriteLine(msg);
static int Add(int x, int y) => x + y;

// 3. 델리게이트 인스턴스 생성
PrintDelegate print = ConsolePrint;
CalculateDelegate calc = Add;

// 4. 호출
print("Hello, Delegate!");
int result = calc(3, 5); // 8
```

델리게이트는 메서드의 시그니처(반환 타입과 매개변수 목록)가 완전히 일치해야만 할당할 수 있습니다. 이렇게 타입 안전성을 보장합니다.

### 델리게이트의 내부 구조

델리게이트는 내부적으로 `System.Delegate`를 상속받은 클래스입니다. 델리게이트 변수는 하나 이상의 메서드 참조를 담는 연결 리스트 역할을 합니다.

```text
[델리게이트 인스턴스의 내부 구조]

┌─────────────────────┐
│   Delegate 객체     │
├─────────────────────┤
│ _target : object    │ ── 대상 객체 (인스턴스 메서드인 경우)
│ _methodPtr : IntPtr │ ── 메서드 주소
│ _next : Delegate    │ ── 다음 델리게이트 체인
└─────────────────────┘
```

`_target`이 `null`이면 정적 메서드, 그렇지 않으면 인스턴스 메서드를 가리킵니다. 멀티캐스트 시 `_next`를 통해 연결됩니다.

## 델리게이트의 주요 특징

### 타입 안전성

델리게이트는 컴파일 시점에 시그니처를 검사합니다. 잘못된 시그니처의 메서드를 할당하려 하면 컴파일 오류가 발생합니다.

```csharp
static void WrongMethod(int num) { }

PrintDelegate print = ConsolePrint;   // OK
PrintDelegate bad = WrongMethod;      // 컴파일 오류: 반환 타입 불일치
```

### 정적 메서드와 인스턴스 메서드

델리게이트는 정적 메서드와 인스턴스 메서드를 모두 참조할 수 있습니다.

```csharp
public class Logger
{
    public void LogToConsole(string msg) => Console.WriteLine($"[LOG] {msg}");
    public static void LogToFile(string msg) => Console.WriteLine($"[FILE] {msg}");
}

Logger logger = new Logger();
PrintDelegate print = logger.LogToConsole;  // 인스턴스 메서드
PrintDelegate printStatic = Logger.LogToFile; // 정적 메서드
```

인스턴스 메서드가 할당되면 델리게이트는 해당 인스턴스와 메서드를 함께 저장합니다.

## 멀티캐스트 델리게이트 (Multicast Delegate)

델리게이트는 `+`와 `-` 연산자를 사용해 여러 메서드를 연결하거나 제거할 수 있습니다. 하나의 델리게이트 변수에 여러 메서드를 등록하면 호출 시 모든 메서드가 순서대로 실행됩니다.

```csharp
static void MethodA(string msg) => Console.WriteLine($"A: {msg}");
static void MethodB(string msg) => Console.WriteLine($"B: {msg}");
static void MethodC(string msg) => Console.WriteLine($"C: {msg}");

PrintDelegate multicast = MethodA;
multicast += MethodB;
multicast += MethodC;

multicast("Hello");
// 출력:
// A: Hello
// B: Hello
// C: Hello

// 체인에서 제거
multicast -= MethodB;
multicast("Again");
// 출력:
// A: Again
// C: Again
```

멀티캐스트 델리게이트의 반환값이 `void`가 아닌 경우, 마지막에 실행된 메서드의 반환값만 외부에 전달됩니다. 따라서 반환값이 필요한 델리게이트는 멀티캐스트보다는 단일 메서드에 사용하는 것이 일반적입니다.

### 체인의 안전한 호출

델리게이트 변수가 `null`일 때 호출하면 `NullReferenceException`이 발생합니다. `?.` 연산자로 안전하게 호출할 수 있습니다.

```csharp
PrintDelegate safe = null;
safe?.Invoke("안전");   // 아무 일도 일어나지 않음
```

## 델리게이트의 실무 활용 패턴

### 콜백 (Callback)

메서드에 다른 메서드를 전달하여 특정 시점에 실행되도록 하는 패턴입니다.

```csharp
public class FileProcessor
{
    // 콜백 델리게이트를 매개변수로 받음
    public void Process(string path, Action<string> onComplete)
    {
        Console.WriteLine($"파일 처리 중: {path}");
        // 작업 완료 후 콜백 호출
        onComplete?.Invoke(path);
    }
}

// 사용
var processor = new FileProcessor();
processor.Process("data.txt", filePath => 
    Console.WriteLine($"처리 완료: {filePath}"));
```

콜백은 비동기 처리, 이벤트 핸들링, LINQ 등에서 광범위하게 사용됩니다.

### 전략 패턴 (Strategy Pattern)

알고리즘을 델리게이트로 전달하여 런타임에 동작을 변경할 수 있습니다.

```csharp
public class SortHelper
{
    // 정렬 알고리즘을 델리게이트로 주입
    public void Sort<T>(List<T> list, Func<T, T, int> comparer)
    {
        list.Sort((a, b) => comparer(a, b));
    }
}

var names = new List<string> { "Charlie", "Alice", "Bob" };
var helper = new SortHelper();

// 내림차순 정렬 전략 전달
helper.Sort(names, (a, b) => b.CompareTo(a));
Console.WriteLine(string.Join(", ", names)); // Charlie, Bob, Alice
```

### 필터링과 변환

컬렉션 처리에서 델리게이트를 이용해 조건과 변환 로직을 분리할 수 있습니다.

```csharp
public class DataPipeline
{
    public List<int> Filter(List<int> data, Predicate<int> predicate)
    {
        var result = new List<int>();
        foreach (var item in data)
            if (predicate(item)) result.Add(item);
        return result;
    }
    
    public List<int> Transform(List<int> data, Func<int, int> transform)
    {
        var result = new List<int>();
        foreach (var item in data)
            result.Add(transform(item));
        return result;
    }
}

var pipeline = new DataPipeline();
var numbers = Enumerable.Range(1, 10).ToList();

var evens = pipeline.Filter(numbers, n => n % 2 == 0);
var squares = pipeline.Transform(numbers, n => n * n);
```

## 내장 델리게이트: Action, Func, Predicate

C# 프레임워크는 자주 사용되는 델리게이트 시그니처를 미리 정의해 제공합니다. 직접 `delegate`를 선언할 필요 없이 이 타입들을 사용하면 코드가 간결해집니다.

| 타입 | 시그니처 | 설명 |
|------|----------|------|
| `Action` | `void` 반환, 매개변수 0~16개 | 반환값이 없는 메서드 |
| `Func<TResult>` | `TResult` 반환, 매개변수 0~16개 | 반환값이 있는 메서드 (마지막 타입이 반환 타입) |
| `Predicate<T>` | `bool` 반환, `T` 매개변수 1개 | 조건 검사 메서드 (`Func<T, bool>`과 동일) |

```csharp
Action<string> print = msg => Console.WriteLine(msg);
Func<int, int, int> add = (a, b) => a + b;
Predicate<int> isEven = n => n % 2 == 0;

print($"3 + 5 = {add(3, 5)}");
Console.WriteLine(isEven(10)); // True
```

이 내장 델리게이트들은 `System` 네임스페이스에 정의되어 있어 별도의 `using` 없이 바로 사용할 수 있습니다.

## 델리게이트의 성능과 주의사항

### 박싱과 언박싱

델리게이트는 참조 타입이므로 값 형식의 메서드를 델리게이트에 저장할 때 박싱이 발생하지 않습니다. 단, 델리게이트가 인스턴스 메서드를 참조할 때는 대상 객체가 힙에 이미 존재하므로 추가 오버헤드는 거의 없습니다.

### 메모리 누수 방지

멀티캐스트 델리게이트에 메서드를 추가할 때는 `+=`, 제거할 때는 `-=`를 사용합니다. 특히 이벤트를 구독한 후 해지하지 않으면 델리게이트가 대상 객체를 계속 참조하여 가비지 컬렉션을 방해할 수 있습니다.

```csharp
public class Subscriber
{
    public void OnEvent() => Console.WriteLine("이벤트 발생");
}

var subscriber = new Subscriber();
Action handler = subscriber.OnEvent;

// 사용 후 반드시 참조 제거 (메모리 누수 방지)
handler = null;
```

### 람다 식과 클로저

람다 식에서 외부 변수를 캡처할 때는 델리게이트가 해당 변수의 수명을 연장시킵니다. 루프 안에서 람다를 생성할 때 변수를 복사하지 않으면 예상치 못한 동작이 발생할 수 있습니다.

```csharp
var actions = new List<Action>();
for (int i = 0; i < 3; i++)
{
    // i를 직접 캡처하면 모든 람다가 마지막 i 값(3)을 참조
    actions.Add(() => Console.WriteLine(i));   // 위험!
}
foreach (var a in actions) a(); // 3, 3, 3 출력

// 올바른 방법: 로컬 복사
for (int i = 0; i < 3; i++)
{
    int captured = i;
    actions.Add(() => Console.WriteLine(captured));
}
```

## 델리게이트와 이벤트의 관계

델리게이트는 이벤트의 기반이 됩니다. `event` 키워드는 델리게이트를 캡슐화하여 외부에서 `Invoke`를 호출하거나 직접 할당(`=`)하는 것을 막고, 오직 `+=`와 `-=`만 허용합니다. 이에 대한 자세한 내용은 이벤트 문서에서 다루겠습니다.

## 실전 예제: 작업 큐와 콜백

아래는 델리게이트를 활용한 간단한 작업 큐 예제입니다.

```csharp
public class WorkItem
{
    public string Name { get; set; }
    public Action Work { get; set; }
    public Action<string> OnComplete { get; set; }
}

public class Worker
{
    private Queue<WorkItem> _queue = new Queue<WorkItem>();
    
    public void AddWork(WorkItem item) => _queue.Enqueue(item);
    
    public void ProcessAll()
    {
        while (_queue.Count > 0)
        {
            var item = _queue.Dequeue();
            Console.WriteLine($"작업 시작: {item.Name}");
            item.Work?.Invoke();
            item.OnComplete?.Invoke(item.Name);
        }
    }
}

// 사용
var worker = new Worker();
worker.AddWork(new WorkItem
{
    Name = "데이터 로드",
    Work = () => Console.WriteLine("로딩 중..."),
    OnComplete = name => Console.WriteLine($"{name} 완료")
});

worker.ProcessAll();
```

## 마무리

델리게이트는 C#에서 메서드를 일급 객체로 다루는 핵심 도구입니다. 이를 통해 코드의 재사용성, 유연성, 모듈성을 크게 향상시킬 수 있습니다.

- 델리게이트는 타입 안전한 메서드 참조입니다.
- `Action`, `Func`, `Predicate` 내장 델리게이트를 적극 활용합니다.
- 멀티캐스트와 콜백 패턴을 통해 코드의 흐름을 제어합니다.
- 람다 식에서 변수 캡처의 함정을 주의합니다.
- 이벤트와 함께 사용할 때는 메모리 누수에 신경 씁니다.

델리게이트를 이해하면 C#의 함수형 프로그래밍 요소와 이벤트 기반 아키텍처를 자연스럽게 익힐 수 있으며, 더욱 깔끔하고 유지보수하기 쉬운 코드를 작성할 수 있습니다.
