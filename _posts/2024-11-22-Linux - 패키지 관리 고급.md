# 패키지 관리 고급

## 패키지 관리의 계층 구조

리눅스 패키지 관리는 여러 계층으로 구성되어 있다. 각 계층은 서로 다른 역할을 담당하며, 함께 동작한다.

- **고수준 패키지 관리자**: `apt`(Debian/Ubuntu), `dnf`(Fedora/RHEL) 등. 사용자 친화적 인터페이스와 의존성 해결, 저장소 관리를 담당한다.
- **저수준 패키지 관리자**: `dpkg`(DEB), `rpm`(RPM). 실제 패키지 설치, 제거, 조회 등 기본 작업을 수행한다.
- **저장소(리포지토리)**: 패키지 파일과 메타데이터를 제공하는 서버. 시스템은 여기서 패키지를 다운로드한다.
- **서명 및 신뢰 체계**: GPG 키를 사용해 패키지의 무결성과 출처를 검증한다.

## APT (Debian/Ubuntu) 고급 활용

### 캐시와 의존성 정리

```bash
sudo apt clean               # 다운로드된 패키지 캐시 전체 삭제
sudo apt autoclean           # 더 이상 필요 없는 오래된 캐시만 삭제
sudo apt autoremove          # 사용하지 않는 의존성 패키지 제거
```

### 패키지 정보 탐색

```bash
apt show nginx               # 패키지 상세 정보
apt-cache policy nginx       # 설치 가능한 버전 및 우선순위
apt-cache depends nginx      # 의존성 확인
apt-cache rdepends libssl3   # 이 패키지를 필요로 하는 다른 패키지
```

### 버전 관리 및 고정

특정 버전을 설치하거나 업데이트를 막아야 할 때가 있다.

```bash
# 특정 버전 설치
sudo apt install nginx=1.24.0-2ubuntu7

# 업데이트 방지 (hold)
sudo apt-mark hold nginx
sudo apt-mark unhold nginx

# 저장소 우선순위 설정 (pin)
# /etc/apt/preferences.d/99-pin 파일 생성
echo "Package: nginx
Pin: release a=stable
Pin-Priority: 700" | sudo tee /etc/apt/preferences.d/99-pin
```

### 소스 패키지와 빌드 의존성

```bash
sudo apt-get source nginx            # 소스 코드 다운로드
sudo apt-get build-dep nginx         # 빌드에 필요한 의존성 설치
```

### 저장소 및 GPG 키 관리

현대 APT에서는 `apt-key` 대신 `signed-by` 방식을 권장한다.

```bash
# GPG 키 다운로드 및 저장
sudo curl -fsSL https://repo.example.com/key.gpg -o /usr/share/keyrings/vendor.gpg

# 저장소 추가 (signed-by 사용)
echo "deb [signed-by=/usr/share/keyrings/vendor.gpg] https://repo.example.com/ubuntu noble main" | sudo tee /etc/apt/sources.list.d/vendor.list

sudo apt update
```

### 자동 업데이트 (서버)

```bash
sudo apt install unattended-upgrades
sudo dpkg-reconfigure unattended-upgrades
```

### 문제 해결

```bash
sudo apt -f install            # 깨진 의존성 복구
sudo dpkg --configure -a       # 중단된 패키지 구성 완료
sudo apt install --reinstall pkg  # 패키지 재설치
```

## DNF (Fedora/RHEL) 고급 활용

### 캐시와 이력 관리

```bash
sudo dnf clean all
sudo dnf autoremove
dnf history                     # 작업 이력 확인
sudo dnf history undo 23        # 특정 작업 되돌리기
```

### 패키지 정보 탐색

```bash
dnf info nginx
dnf repoquery --requires nginx
dnf provides /usr/bin/curl      # 파일을 제공하는 패키지 찾기
```

### 저장소 관리

저장소 설정은 `/etc/yum.repos.d/*.repo` 파일에 저장된다.

```bash
sudo rpm --import https://repo.example.com/RPM-GPG-KEY
sudo dnf repolist
```

### 모듈 (애플리케이션 스트림)

```bash
dnf module list nodejs
sudo dnf module enable nodejs:20
sudo dnf module install nodejs:20/minimal
```

### 버전 잠금

```bash
sudo dnf install 'dnf-command(versionlock)'
sudo dnf versionlock add nginx-1:1.24.*
sudo dnf versionlock list
```

### 패키지 다운그레이드

```bash
sudo dnf downgrade nginx
```

## 저장소 운영 최적화

### APT 미러 변경 (속도 향상)

```bash
sudo sed -i 's|archive.ubuntu.com|mirror.kakao.com|g' /etc/apt/sources.list
sudo apt update
```

### DNF 설정 최적화

`/etc/dnf/dnf.conf`에 추가:

```ini
[main]
fastestmirror=True
max_parallel_downloads=10
defaultyes=True
keepcache=True
```

## 모던 패키지 형식

### Snap

Snap은 강력한 샌드박싱과 자동 업데이트를 제공한다.

```bash
sudo snap install vlc
snap list
snap connections vlc
sudo snap connect vlc:camera
sudo snap refresh vlc
sudo snap revert vlc
```

사용하지 않는 리비전 정리:

```bash
snap list --all | awk '/disabled/{print $1, $3}' | while read name rev; do sudo snap remove "$name" --revision="$rev"; done
```

### Flatpak

Flatpak은 여러 배포판에서 동작하는 샌드박스 애플리케이션 형식이다.

```bash
sudo apt install flatpak
flatpak remote-add --if-not-exists flathub https://flathub.org/repo/flathub.flatpakrepo

flatpak install flathub org.gimp.GIMP
flatpak list
flatpak update
flatpak uninstall --unused
```

권한 관리:

```bash
flatpak override --user --filesystem=home org.gimp.GIMP
flatpak override --show
```

### AppImage

AppImage는 단일 실행 파일로 제공되는 휴대용 애플리케이션이다.

```bash
chmod +x AppName.AppImage
./AppName.AppImage
```

설치가 필요 없고, 루트 권한도 필요 없다. 업데이트는 파일 교체 방식으로 이루어진다.

## 패키지 형식 비교

| 기준 | APT/DNF (전통) | Snap | Flatpak | AppImage |
|------|---------------|------|---------|----------|
| 대상 | 시스템 전체 | 시스템/사용자 | 시스템/사용자 | 사용자 로컬 |
| 의존성 | 공유 라이브러리 | 번들 포함 | 런타임 + 앱 | 완전 번들 |
| 격리 수준 | 낮음 | 강함 | 강함 | 없음 |
| 롤백 | 제한적 (`dnf history`) | `revert` | 런타임 버전 교체 | 파일 교체 |
| 서버 적합성 | ★★★★★ | ★★ | ★★ | ★ |
| 데스크톱 앱 | ★★ | ★★★★ | ★★★★★ | ★★★ |

## 핵심 명령어 요약

| 작업 | APT | DNF |
|------|-----|-----|
| 특정 버전 설치 | `apt install pkg=1.2.3` | `dnf downgrade pkg` |
| 업데이트 방지 | `apt-mark hold pkg` | `dnf versionlock add pkg-1.2` |
| 파일 소유 패키지 찾기 | `dpkg -S /path/file` | `dnf provides /path/file` |
| 패키지 의존성 | `apt-cache depends pkg` | `dnf repoquery --requires pkg` |
| 작업 되돌리기 | (스냅샷 권장) | `dnf history undo ID` |

## 결론

패키지 관리는 리눅스 시스템 운영의 핵심이다. 단순한 설치를 넘어, **버전 고정, 핀 설정, 자동 업데이트, 롤백 전략** 등을 통해 시스템의 안정성과 보안을 유지할 수 있다.

전통적인 패키지 관리자(APT/DNF)는 서버 환경에 강점이 있으며, 모던 패키지 형식(Snap, Flatpak, AppImage)은 데스크톱 애플리케이션 배포와 격리 측면에서 장점이 있다. 상황에 맞는 도구를 선택하고, 문제 발생 시 빠르게 원인을 진단하며, 문서화된 롤백 절차를 마련해 두는 것이 좋다.

정기적으로 시스템 상태를 점검하고, 업데이트 정책을 명확히 하면 예측 가능하고 안정적인 운영 환경을 유지할 수 있다.
