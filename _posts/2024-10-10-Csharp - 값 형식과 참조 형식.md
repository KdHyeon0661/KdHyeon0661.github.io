# C# 값 형식과 참조 형식

C#에서 모든 데이터 타입은 값 형식(Value Type)과 참조 형식(Reference Type)으로 구분됩니다. 이 구분은 변수의 동작 방식, 메모리 할당 위치, 그리고 성능 특성에 직접적인 영향을 미칩니다. 단순히 “구조체는 스택, 클래스는 힙”이라는 암기식 이해를 넘어, 내부 메커니즘을 정확히 파악해야 실무에서 효율적인 코드를 작성할 수 있습니다.

---

## 값 형식과 참조 형식의 본질

값 형식은 변수 자체가 데이터의 실체를 직접 보관합니다. 기본 자료형(`int`, `double`, `bool`), 구조체(`struct`), 열거형(`enum`)이 여기에 속합니다.

참조 형식은 변수 안에 실제 데이터가 있는 힙(Heap) 메모리의 주소(참조)를 저장합니다. 클래스(`class`), 인터페이스(`interface`), 대리자(`delegate`), 배열, 그리고 `string`이 이에 해당합니다.

```csharp
// 값 형식: 데이터가 변수에 직접 저장됨
int a = 10;
int b = a;   // a의 값이 b로 복사됨
b = 20;
Console.WriteLine(a); // 10

// 참조 형식: 변수는 힙 객체의 주소를 저장
var c = new List<int>();
var d = c;    // 주소가 복사됨 (같은 객체를 가리킴)
d.Add(5);
Console.WriteLine(c.Count); // 5
```

값 형식의 대입은 **데이터의 완전한 복사**를 의미합니다. 반면 참조 형식의 대입은 **참조(주소)만 복사**하므로 여러 변수가 하나의 객체를 공유하게 됩니다.

---

## 메모리 할당 위치: 스택과 힙의 진실

많은 개발자가 “값 형식은 스택, 참조 형식은 힙”이라고 알고 있지만, 이는 절대적인 규칙이 아닙니다. 정확한 원칙은 다음과 같습니다.

- 참조 형식의 **실제 객체**는 항상 힙에 할당됩니다.
- 값 형식의 저장 위치는 **선언된 문맥**에 따라 달라집니다.
  - 메서드 내 지역 변수나 매개변수로 선언된 값 형식 → 스택(Stack)
  - 클래스의 필드(멤버)로 선언된 값 형식 → 그 클래스 객체가 저장된 힙 내부

```text
[값 형식이 힙에 포함되는 예시]

public class Wrapper 
{ 
    public Point P;   // Point는 struct (값 형식)
}

Stack 메모리                       Heap 메모리
[ 지역변수 w (주소)     ]  ───>  [ Wrapper 객체 본체 ]
                                   [ └─ 필드 P (X:0, Y:0) ]
```

따라서 구조체가 반드시 스택에만 존재한다는 고정관념은 버려야 합니다. 클래스 내부에 포함된 구조체는 힙에 함께 위치하게 됩니다.

## 박싱과 언박싱

값 형식을 참조 형식(`object` 또는 인터페이스)으로 변환할 때 **박싱(Boxing)** 이 발생합니다. 반대로 박싱된 객체에서 다시 값 형식을 꺼낼 때는 **언박싱(Unboxing)** 이 일어납니다.

```csharp
int number = 123;
object obj = number;   // 박싱: 힙에 새로운 객체 생성, 값 복사
int unboxed = (int)obj; // 언박싱: 힙에서 값을 꺼내 스택에 복사
```

박싱은 힙 할당과 메모리 복사를 동반하므로 성능 저하의 주요 원인이 됩니다. 특히 반복문 안에서 박싱이 발생하면 가비지 컬렉터(GC) 부담이 커집니다.

이 문제를 해결한 것이 **제네릭(Generic)** 입니다. `ArrayList` 대신 `List<T>`를 사용하면 내부적으로 값 형식의 배열을 유지하므로 박싱이 전혀 발생하지 않습니다.

```csharp
// 박싱 발생
ArrayList list = new ArrayList();
list.Add(10);   // int → object 박싱

// 박싱 없음
List<int> list2 = new List<int>();
list2.Add(10);  // int[] 배열 사용
```

## 특수한 참조 형식: 문자열 (string)

`string`은 클래스(참조 형식)이지만, 값 형식처럼 동작하는 불변(Immutable) 객체입니다. 한 번 생성된 문자열은 절대 변경할 수 없습니다. 문자열을 수정하는 연산은 새로운 문자열 객체를 생성합니다.

```csharp
string a = "Hello";
string b = a;          // 주소 복사 (같은 객체)
b = "World";           // 새로운 객체 생성, b의 참조 변경
Console.WriteLine(a);  // "Hello" (a는 여전히 원본)
```

또한 `string`은 `==` 연산자를 내용 비교로 오버로딩하고 있어, 참조 형식이면서도 값 비교가 직관적으로 동작합니다.

## 최신 C#의 고성능 struct 기능

C# 7.0부터 성능 최적화를 위한 구조체 관련 기능이 지속적으로 추가되었습니다.

### readonly struct

`readonly struct`는 구조체가 불변(Immutable)임을 선언합니다. 모든 인스턴스 필드는 `readonly`여야 합니다. 이 키워드는 컴파일러에게 해당 구조체가 절대 변경되지 않음을 알려주어, `in` 매개변수 전달 시 불필요한 방어적 복사(Defensive Copy)를 제거합니다.

```csharp
public readonly struct Point
{
    public int X { get; }
    public int Y { get; }
    
    public Point(int x, int y)
    {
        X = x;
        Y = y;
    }
}
```

### ref struct

`ref struct`는 스택에만 존재해야 하는 구조체를 정의합니다. 이 타입은 힙으로 탈출할 수 없으며(박싱 불가, 클래스 필드로 사용 불가), 고성능 시나리오에서 임시 버퍼를 안전하게 다루는 데 사용됩니다. `Span<T>`가 대표적인 예입니다.

```csharp
public ref struct TempBuffer
{
    private Span<byte> _buffer;
    public TempBuffer(int size)
    {
        _buffer = stackalloc byte[size];
    }
}
```

### 구조체의 매개변수 없는 생성자 (C# 10+)

C# 10부터 구조체에 명시적인 매개변수 없는 생성자를 정의할 수 있게 되었습니다. 이전에는 모든 구조체가 암시적으로 모든 필드를 

$$0$$

으로 초기화하는 기본 생성자를 가졌습니다.

```csharp
public struct Point
{
    public int X;
    public int Y;
    
    public Point()  // C# 10부터 허용
    {
        X = -1;
        Y = -1;
    }
}
```

## 실무 선택 기준: class vs struct

어떤 타입을 선택할지는 데이터의 성격과 성능 요구사항에 따라 결정합니다.

1. **데이터 크기**
   구조체는 메서드에 전달될 때 복사됩니다. 크기가 
   $$16$$
    바이트를 넘어서면 복사 비용이 참조 전달 비용보다 커질 수 있습니다. 큰 데이터는 클래스를 사용하세요.

2. **불변성**
   점(Point), 색상(Color) 등 논리적으로 하나의 ‘값’을 나타낸다면 구조체가 적합합니다. 가능하면 `readonly struct`로 설계하세요.

3. **상속/다형성 필요 여부**
   구조체는 상속을 지원하지 않습니다. 객체 지향적인 계층 구조가 필요하면 클래스를 사용해야 합니다.

4. **생성 빈도와 수명**
   게임 파티클처럼 수만 개가 짧은 시간 생성되고 소멸된다면, 힙 할당과 GC 부담을 피하기 위해 구조체가 유리합니다.

## 마무리

값 형식과 참조 형식의 차이는 단순히 “어디에 저장되는가”를 넘어, 변수 간의 동작 방식, 메모리 사용 패턴, 성능에 깊은 영향을 줍니다. 박싱/언박싱의 비용을 이해하고, 제네릭을 적극 활용하며, 불변 구조체와 `ref struct` 같은 현대적 기능을 적재적소에 사용하는 것이 중요합니다.

메모리의 동작 원리를 머릿속에 그리며 코딩하는 습관은 C# 개발자로 성장하는 데 큰 도움이 됩니다.
