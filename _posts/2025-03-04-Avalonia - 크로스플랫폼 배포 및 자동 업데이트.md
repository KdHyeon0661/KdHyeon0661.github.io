# Avalonia 크로스플랫폼 배포 및 자동 업데이트

Avalonia 애플리케이션을 Windows, macOS, Linux에 배포하고, 자동 업데이트 기능을 추가하는 방법을 다룹니다. 초중급 개발자가 실제로 적용할 수 있도록 **Self-contained 단일 파일 배포**, **플랫폼별 패키징(MSIX, DMG, AppImage)**, **자동 업데이트 구현(Squirrel, 커스텀)**, **CI/CD 연동**까지 핵심을 정리합니다.

---

## 빌드 전략: Self-contained vs Framework-dependent

| 유형 | 런타임 포함 | 장점 | 단점 | 권장 |
|------|------------|------|------|------|
| Self-contained | 포함 | 대상 PC에 .NET 사전 설치 불필요 | 바이너리 커짐 | 배포용 |
| Framework-dependent | 미포함 | 크기 작음 | 런타임 별도 설치 필요 | 개발/내부 배포 |

실전에서는 **Self-contained + PublishSingleFile** 조합을 기본으로 사용합니다.

---

## 플랫폼별 빌드 명령

공통 명령 형태:

```bash
dotnet publish MyApp.csproj -c Release -r <RID> \
  --self-contained true \
  -p:PublishSingleFile=true \
  -p:IncludeNativeLibrariesForSelfExtract=true \
  -p:DebugType=embedded
```

### 주요 RID (Runtime Identifier)

| 플랫폼 | RID |
|--------|-----|
| Windows x64 | win-x64 |
| Linux glibc x64 | linux-x64 |
| Linux ARM64 | linux-arm64 |
| macOS Intel | osx-x64 |
| macOS Apple Silicon | osx-arm64 |

## Windows 배포

### 단일 EXE

```bash
dotnet publish -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -o out/win-x64
```

결과물: `out/win-x64/MyApp.exe`

### MSIX (엔터프라이즈)

- **장점**: 배포·업데이트 체계, 파일 격리, 서명 필수
- **구성**: `AppxManifest.xml` 작성 → 코드 서명 → `makeappx`로 패키징 → `signtool` 서명

### Squirrel.Windows (자동 업데이트 포함)

**도구 설치**

```bash
dotnet tool install --global Squirrel
```

**Releasify**

```bash
dotnet publish -c Release -r win-x64 --self-contained true -o publish/win
squirrel --releasify publish/win/MyApp.exe --releaseDir artifacts/squirrel
```

산출물: `Setup.exe`, `RELEASES`, `MyApp-1.2.3-full.nupkg`

**앱에서 업데이트 코드**

```csharp
using Squirrel;

public static async Task CheckAndApplyUpdatesAsync()
{
    using var mgr = new UpdateManager("https://example.com/myapp/releases");
    var updates = await mgr.CheckForUpdate();
    if (updates.ReleasesToApply.Any())
    {
        await mgr.DownloadReleases(updates.ReleasesToApply);
        await mgr.ApplyReleases(updates);
        UpdateManager.RestartApp();
    }
}
```

## Linux 배포

### AppImage (배포 간편)

**AppDir 구성**

```
AppDir/
  AppRun
  MyApp.desktop
  MyApp.png
  usr/bin/MyApp
```

**AppRun** (실행 스크립트)

```bash
#!/usr/bin/env bash
DIR="$(dirname "$(readlink -f "$0")")"
exec "$DIR/usr/bin/MyApp" "$@"
```

**MyApp.desktop**

```ini
[Desktop Entry]
Type=Application
Name=MyApp
Exec=MyApp
Icon=MyApp
Categories=Utility;
```

**AppImage 생성**

```bash
chmod +x AppDir/AppRun
appimagetool AppDir MyApp-x86_64.AppImage
```

### DEB (Ubuntu/Debian)

디렉터리 구조 예:

```
MyApp_1.2.0/
  DEBIAN/control
  usr/share/myapp/
  usr/bin/myapp
  usr/share/applications/myapp.desktop
  usr/share/icons/hicolor/256x256/apps/myapp.png
```

`DEBIAN/control`:

```
Package: myapp
Version: 1.2.0
Section: utils
Priority: optional
Architecture: amd64
Maintainer: You <you@example.com>
Description: My cross-platform Avalonia app
```

패키징:

```bash
dpkg-deb --build MyApp_1.2.0
```

### RPM / Flatpak / Snap

- **RPM**: `rpmbuild` 스펙 파일로 빌드
- **Flatpak**: `flatpak-builder`로 매니페스트 기반 빌드 (샌드박스)
- **Snap**: `snapcraft` YAML 기반 빌드 (스냅 스토어)

## 자동 업데이트 전략

### Squirrel.Windows (Windows 전용)

위에서 설명한 Squirrel을 사용합니다.

### Avalonia.Extensions.Update (크로스플랫폼)

**패키지 설치**

```bash
dotnet add package Avalonia.Extensions.Update
```

**사용 예**

```csharp
var svc = new UpdateService(new UpdateOptions
{
    Endpoint = "https://example.com/myapp/updates.json",
    AppName = "MyApp"
});

var info = await svc.CheckUpdateAsync();
if (info.IsAvailable)
{
    await svc.DownloadAsync(info, p => Console.WriteLine($"{p:P0}"));
    await svc.ApplyAsync(info);
    Environment.Exit(0); // 재시작 유도
}
```

**업데이트 메타데이터 (JSON)**

```json
{
  "latest": "1.2.0",
  "files": {
    "win-x64": "https://cdn.example.com/MyApp-1.2.0-win.zip",
    "osx-arm64": "https://cdn.example.com/MyApp-1.2.0-osx-arm64.zip",
    "linux-x64": "https://cdn.example.com/MyApp-1.2.0-linux-x64.tar.gz"
  },
  "sha256": {
    "win-x64": "08c4...ef",
    "osx-arm64": "a1b2...34",
    "linux-x64": "de9f...84"
  },
  "notes": "버그 수정 및 성능 개선"
}
```

### 커스텀 업데이트 (Zip 기반)

서버에서 버전 파일을 제공하고, 클라이언트가 다운로드 후 압축 해제 및 적용합니다.

```csharp
public async Task<UpdateInfo?> CheckAsync(Uri jsonUri, Version current)
{
    var json = await _http.GetStringAsync(jsonUri);
    var info = JsonSerializer.Deserialize<UpdateInfo>(json);
    if (info == null) return null;
    return new Version(info.version) > current ? info : null;
}

public async Task DownloadAndApplyAsync(UpdateInfo info, string appDir)
{
    // 다운로드, 해시 검증, 압축 해제, 파일 교체
}
```

> **중요**: Windows에서는 실행 중인 파일을 교체할 수 없으므로, 별도의 업데이터 프로세스를 사용합니다.

## 업데이트 UX 설계

### ViewModel 예시

```csharp
public sealed class UpdateViewModel : ReactiveObject
{
    private readonly IAppUpdateService _updater;

    public bool IsChecking { get; private set; }
    public bool IsAvailable { get; private set; }
    public string? LatestVersion { get; private set; }
    public double Progress { get; private set; }
    public string? Notes { get; private set; }

    public ReactiveCommand<Unit, Unit> CheckCommand { get; }
    public ReactiveCommand<Unit, Unit> ApplyCommand { get; }

    public UpdateViewModel(IAppUpdateService updater)
    {
        _updater = updater;

        CheckCommand = ReactiveCommand.CreateFromTask(async () =>
        {
            IsChecking = true; this.RaisePropertyChanged(nameof(IsChecking));
            var result = await _updater.CheckAsync();
            IsChecking = false; this.RaisePropertyChanged(nameof(IsChecking));

            IsAvailable = result.available;
            LatestVersion = result.version;
            Notes = result.notes;
            this.RaisePropertyChanged(nameof(IsAvailable), nameof(LatestVersion), nameof(Notes));
        });

        ApplyCommand = ReactiveCommand.CreateFromTask(async () =>
        {
            await _updater.DownloadAsync(p => { Progress = p; this.RaisePropertyChanged(nameof(Progress)); });
            await _updater.ApplyAsync();
        }, this.WhenAnyValue(x => x.IsAvailable));
    }
}
```

### XAML View

```xml
<StackPanel Spacing="8" Margin="16">
  <Button Content="업데이트 확인" Command="{Binding CheckCommand}" />
  <TextBlock Text="{Binding LatestVersion, StringFormat=새 버전: {0}}" />
  <ScrollViewer MaxHeight="150">
    <TextBlock Text="{Binding Notes}" TextWrapping="Wrap"/>
  </ScrollViewer>
  <ProgressBar Minimum="0" Maximum="1" Value="{Binding Progress}" Height="8"/>
  <Button Content="업데이트 적용" Command="{Binding ApplyCommand}" IsEnabled="{Binding IsAvailable}"/>
</StackPanel>
```

## CI/CD: GitHub Actions 매트릭스 빌드

```yaml
name: build-release

on:
  push:
    tags:
      - 'v*.*.*'

jobs:
  publish:
    runs-on: ${{ matrix.os }}
    strategy:
      matrix:
        include:
          - os: windows-latest
            rid: win-x64
            ext: zip
          - os: ubuntu-latest
            rid: linux-x64
            ext: tar.gz
          - os: macos-latest
            rid: osx-arm64
            ext: zip
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-dotnet@v4
        with:
          dotnet-version: '8.0.x'
      - run: dotnet publish src/MyApp/MyApp.csproj -c Release -r ${{ matrix.rid }} --self-contained true -p:PublishSingleFile=true -o publish/${{ matrix.rid }}
      - name: Pack artifact
        shell: bash
        run: |
          cd publish/${{ matrix.rid }}
          if [ "${{ matrix.ext }}" = "zip" ]; then
            7z a ../../MyApp-${{ matrix.rid }}.zip *
          else
            tar -czf ../../MyApp-${{ matrix.rid }}.tar.gz *
          fi
      - name: Upload release
        uses: softprops/action-gh-release@v2
        with:
          files: |
            MyApp-${{ matrix.rid }}.zip
            MyApp-${{ matrix.rid }}.tar.gz
        env:
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
```

## 성능 및 용량 튜닝

| 옵션 | 설명 | 주의 |
|------|------|------|
| ReadyToRun | 시작 속도 개선 | 바이너리 크기 증가 |
| PGO | 프로파일 기반 최적화 | 수집 및 적용 필요 |
| PublishTrimmed | 미사용 코드 제거 | 리플렉션/XAML 사용 시 위험 |
| InvariantGlobalization | ICU 제외로 용량 감소 | 다국어 기능 제한 |

예:

```bash
dotnet publish -c Release -r win-x64 --self-contained true \
  -p:PublishSingleFile=true -p:ReadyToRun=true -p:InvariantGlobalization=true
```

## 플랫폼별 체크리스트

### Windows

- 코드서명 인증서 준비 (EV 권장)
- Squirrel 또는 MSIX 선택
- SmartScreen 경고 대응 (평판 필요)

### macOS

- Apple Developer 계정
- 서명 + 노터라이즈 필수
- DMG 패키징 및 Gatekeeper 통과

### Linux

- AppImage: 가장 간단
- DEB/RPM: 배포 리포지토리 운영 시
- Flatpak/Snap: 스토어 생태계 활용

## 결론

- **배포**는 Self-contained + SingleFile을 기본으로 하고, 플랫폼별 패키징(MSIX, DMG, AppImage)을 추가합니다.
- **자동 업데이트**는 Windows에서 Squirrel, 크로스플랫폼에서는 Avalonia.Extensions.Update 또는 커스텀 Zip 기반을 사용합니다.
- **CI/CD**로 빌드·패키징·릴리즈를 자동화하면 운영 부담을 크게 줄일 수 있습니다.

이 구조를 바탕으로 실제 프로젝트에 적용하면, 사용자에게 일관된 설치 및 업데이트 경험을 제공할 수 있습니다.
