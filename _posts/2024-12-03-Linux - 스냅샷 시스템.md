# 스냅샷 시스템(Btrfs, ZFS)과 공간 절약 전략

## 스냅샷의 본질: Copy-on-Write와 참조

스냅샷은 특정 시점의 파일 시스템 상태를 보존하는 기술이다. **Copy-on-Write(CoW)** 메커니즘을 사용한다. 스냅샷 생성 시에는 실제 데이터를 복사하지 않고 **메타데이터(블록 맵)만 복제**하므로 즉시 완료되고 저장 공간도 거의 사용하지 않는다. 이후 데이터가 변경되면 원본 블록은 그대로 두고 **새 블록에 변경 내용을 기록**한다. 따라서 스냅샷과 현재 버전은 변경되지 않은 블록을 공유하게 된다.

### 공간 사용 모델

스냅샷 생성 후 추가로 사용되는 공간 \(S\)는 데이터 총량 \(D\)와 변경 비율 \(p\)에 근사한다:

$$
S \approx p \cdot D
$$

스냅샷이 많을수록 중복 참조가 늘어나며, 오래된 스냅샷을 삭제하면 **유일하게 참조되는 블록만** 공간이 회수된다.

## Btrfs: 서브볼륨과 스냅샷

Btrfs는 **서브볼륨(subvolume)** 단위로 스냅샷을 생성한다. 일반적으로 루트에 여러 서브볼륨을 두고 관리한다.

### 서브볼륨과 스냅샷 기본 명령

```bash
# Btrfs 파일시스템 마운트
sudo mount /dev/sdX1 /mnt

# 서브볼륨 생성
sudo btrfs subvolume create /mnt/@
sudo btrfs subvolume create /mnt/@home

# 읽기-쓰기 스냅샷
sudo btrfs subvolume snapshot /mnt/@ /mnt/@_snap_$(date +%F)

# 읽기-전용 스냅샷 (백업/전송용 권장)
sudo btrfs subvolume snapshot -r /mnt/@ /mnt/@_ro_$(date +%F)

# 스냅샷 목록 보기
sudo btrfs subvolume list /mnt

# 스냅샷 삭제
sudo btrfs subvolume delete /mnt/@_ro_2025-11-11

# 공간 사용량 확인
sudo btrfs filesystem df /mnt
```

### 자동 마운트 설정 (fstab)

```fstab
UUID=<UUID>  /          btrfs  subvol=@,compress=zstd:3,noatime  0  0
UUID=<UUID>  /home      btrfs  subvol=@home,compress=zstd:3,noatime  0  0
UUID=<UUID>  /.snapshots btrfs  subvol=@snapshots,ro  0  0
```

- `compress=zstd`: zstd 압축 (레벨 3~6 권장)
- `noatime`: 읽기 성능 향상
- `ro`: 스냅샷 저장소는 읽기 전용으로 노출

### 증분 전송 (원격 백업)

```bash
# 읽기전용 스냅샷을 원격으로 전송
sudo btrfs send /mnt/@_ro_base | ssh backup 'btrfs receive /backup'

# 증분 전송 (부모 스냅샷 기준)
sudo btrfs send -p /mnt/@_ro_2025-11-01 /mnt/@_ro_2025-11-11 | ssh backup 'btrfs receive /backup'
```

## ZFS: 데이터셋과 스냅샷

ZFS는 **풀(zpool)** 위에 **데이터셋(dataset)** 을 생성하고 관리한다. 스냅샷은 `dataset@snapshot` 형태로 표현된다.

### 풀과 데이터셋 생성

```bash
# 미러 풀 생성 (예: 두 개 디스크)
sudo zpool create -o ashift=12 tank mirror /dev/sdb /dev/sdc

# 데이터셋 생성 및 압축 설정
sudo zfs create -o compression=lz4 -o atime=off tank/home
sudo zfs create -o compression=zstd tank/data

# 데이터셋 목록
sudo zfs list
```

### 스냅샷, 클론, 롤백

```bash
# 스냅샷 생성
sudo zfs snapshot tank/data@daily-2025-11-11

# 스냅샷 목록
sudo zfs list -t snapshot

# 롤백 (스냅샷 시점으로 되돌리기)
sudo zfs rollback tank/data@daily-2025-11-11

# 클론 (쓰기 가능한 복제본)
sudo zfs clone tank/data@daily-2025-11-11 tank/data-test

# 스냅샷 삭제
sudo zfs destroy tank/data@daily-2025-11-01
```

### 증분 전송

```bash
# 전체 전송 (초기)
sudo zfs send tank/data@base | ssh backup 'zfs receive backup/data'

# 증분 전송 (부모 스냅샷 기준)
sudo zfs send -i tank/data@base tank/data@daily-2025-11-11 | ssh backup 'zfs receive backup/data'

# 중간 스냅샷 모두 포함한 증분
sudo zfs send -I tank/data@base tank/data@daily-2025-11-11 | ssh backup 'zfs receive -u backup/data'
```

### 무결성 검사

```bash
sudo zpool scrub tank
sudo zpool status
```

## 공간 절약 전략

### 압축

- **Btrfs**: 마운트 옵션에 `compress=zstd` 추가
- **ZFS**: 데이터셋에 `compression=zstd` 또는 `compression=lz4` 설정

압축률 \(r\)에 따라 저장 공간 \(D'\)는:
$$
D' \approx r \cdot D
$$
텍스트, 로그, 소스코드는 높은 압축률을 보이고, 이미지나 동영상은 압축 효과가 낮다.

### 중복 제거 (Deduplication)

- **ZFS**: `dedup=on` 옵션으로 활성화 가능하나 메모리와 CPU 비용이 매우 큼. 아카이브처럼 중복이 극도로 많은 워크로드에만 사용.
- **Btrfs**: 사용자 공간 도구(`duperemove`, `beesd`)를 통해 오프라인 중복 제거 가능.

### CoW 최적화 (NOCOW)

데이터베이스, VM 이미지처럼 무작위 쓰기가 많은 파일은 CoW가 오버헤드가 될 수 있다. 파일 생성 **이전**에 NOCOW 속성을 부여하면 CoW를 비활성화할 수 있다.

```bash
# 디렉터리에 대해 NOCOW 설정 (이후 생성되는 파일에 적용)
sudo chattr +C /var/lib/mydb
```

주의: NOCOW는 Btrfs의 체크섬, 스크럽 기능 일부를 상쇄한다. 꼭 필요한 곳에만 사용하라.

## 보존 정책 예시 (간단한 스크립트)

### Btrfs 일일 스냅샷 + 14일 보존

```bash
#!/bin/bash
SRC=/home
DST=/.snapshots/home
DATE=$(date +%F)

sudo btrfs subvolume snapshot -r "$SRC" "$DST/@home_$DATE"

# 15일 이상된 스냅샷 삭제
find "$DST" -maxdepth 1 -type d -name '@home_*' -mtime +14 -print0 | xargs -0r sudo btrfs subvolume delete
```

### ZFS 일일 스냅샷 + 30일 보존

```bash
#!/bin/bash
SRC="tank/data"
SNAP="daily-$(date +%F)"

sudo zfs snapshot ${SRC}@${SNAP}

# 30일 이전 스냅샷 삭제
sudo zfs list -t snapshot -o name -s creation -H | grep "^${SRC}@" | head -n -30 | xargs -r sudo zfs destroy
```

## 주의 사항

1. **스냅샷 ≠ 백업**  
   스냅샷은 같은 디스크/풀에 저장되므로 디스크 고장이나 랜섬웨어에 취약하다. **반드시 원격 증분 전송** 등 오프사이트 백업을 병행하라.

2. **밸런스/스크럽은 적절히**  
   Btrfs balance, ZFS scrub는 과도하게 자주 실행하지 말고, 필요에 따라 계획적으로 수행한다.

3. **NOCOW 사용은 최소화**  
   무결성 보호를 포기하는 만큼, 정말 필요한 워크로드에만 제한적으로 사용한다.

4. **부트 통합**  
   루트 서브볼륨을 스냅샷으로 교체할 때는 GRUB 파라미터 `rootflags=subvol=@new` 등이 올바르게 전달되어야 한다.

## 핵심 명령어 요약표

| 작업 | Btrfs | ZFS |
|------|-------|-----|
| 스냅샷 생성 (ro) | `btrfs subvolume snapshot -r src dst` | `zfs snapshot dataset@name` |
| 스냅샷 목록 | `btrfs subvolume list /path` | `zfs list -t snapshot` |
| 스냅샷 삭제 | `btrfs subvolume delete /path/@snap` | `zfs destroy dataset@name` |
| 증분 전송 | `btrfs send -p parent snap \| receive` | `zfs send -i parent snap \| receive` |
| 압축 설정 | 마운트 옵션 `compress=zstd` | `zfs set compression=zstd dataset` |
| 무결성 검사 | `btrfs scrub start /mnt` | `zpool scrub tank` |

## 결론

Btrfs와 ZFS는 CoW 기반 스냅샷을 통해 빠르고 경제적인 데이터 보호 수단을 제공한다. 스냅샷은 즉시 생성되며 공간을 거의 사용하지 않지만, 시간이 지나면서 변경된 블록만큼 공간을 소모한다. 압축과 중복 제거를 적절히 활용하면 저장 효율을 더욱 높일 수 있다.

운영 시에는 **정기적인 스냅샷 생성 및 보존 정책**을 자동화하고, **원격 증분 전송**으로 재해 복구를 준비해야 한다. 스냅샷은 로컬 복구에 탁월하지만 디스크 자체의 물리적 고장이나 랜섬웨어로부터는 보호해주지 않으므로 반드시 오프사이트 백업과 결합하라.

각 파일시스템의 특성과 자신의 워크로드에 맞는 설정(압축 레벨, 레코드 크기, NOCOW 적용 여부)을 찾아가는 것이 안정적인 운영의 핵심이다.
