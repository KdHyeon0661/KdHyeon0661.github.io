# 마운트

## 리눅스 파일 시스템 구조

리눅스는 모든 파일과 장치를 하나의 트리 구조로 관리한다. 최상위 디렉터리 `/`를 기준으로 물리적 디스크, 파티션, 네트워크 공유 등을 특정 디렉터리(마운트 지점)에 연결하여 사용한다.

| 디렉터리 | 용도 |
|----------|------|
| `/` | 루트 파일시스템 |
| `/home` | 사용자 홈 디렉터리 |
| `/var` | 로그, 캐시 등 가변 데이터 |
| `/etc` | 설정 파일 |
| `/mnt`, `/media` | 임시/자동 마운트 지점 |
| `/dev` | 장치 파일 (예: `/dev/sda1`) |

---

## 디스크와 파티션 정보 확인

```bash
lsblk -f                     # 디스크, 파티션, 파일시스템, UUID, 마운트점 한눈에
sudo blkid                   # UUID, TYPE 등 상세 정보
df -hT                       # 마운트된 파일시스템 용량과 타입
du -sh *                     # 현재 디렉터리 하위 항목 용량 요약
```

- **UUID**: 파일시스템 고유 식별자, `/etc/fstab`에서 장치명 대신 사용하기에 안정적
- **TYPE**: ext4, xfs, vfat 등 파일시스템 종류

---

## mount와 umount 기본

```bash
# 마운트
sudo mount /dev/sdb1 /mnt/data

# 마운트 해제
sudo umount /mnt/data
```

### 자주 쓰는 마운트 옵션

| 옵션 | 설명 |
|------|------|
| `ro` | 읽기 전용 |
| `rw` | 읽기-쓰기 (기본) |
| `noexec` | 바이너리 실행 금지 (보안) |
| `nosuid` | setuid/setgid 비트 무시 |
| `nodev` | 장치 파일 무시 |
| `uid=1000,gid=1000` | FAT/NTFS 등에 소유자 지정 |
| `noatime` | 파일 접근 시간 갱신 안 함 (성능 향상) |

```bash
sudo mount -o rw,noexec,nosuid,nodev /dev/sdb1 /mnt/data
```

### 마운트 해제가 안 될 때

```bash
lsof +f -- /mnt/data          # 파일을 열고 있는 프로세스 확인
fuser -vm /mnt/data           # 점유 중인 프로세스 ID 확인
sudo umount -l /mnt/data      # lazy unmount (사용 중인 핸들이 닫히면 해제)
```

## 영구 마운트: /etc/fstab

`/etc/fstab` 파일에 등록하면 부팅 시 자동 마운트된다.

```
# <장치>          <마운트점>  <타입>  <옵션>            <dump> <fsck>
UUID=xxx-xxx      /mnt/data   ext4    defaults,noatime  0      2
```

- **장치**: `/dev/sdb1` 대신 UUID 권장 (`sudo blkid`로 확인)
- **fsck 순서**: 루트는 1, 다른 로컬 파일시스템은 2, 네트워크는 0

### fstab 설정 테스트

```bash
sudo mount -a          # fstab의 모든 항목 마운트 시도 (구문 오류 검증)
```

---

## 파일시스템 생성과 점검

### 파일시스템 만들기

```bash
sudo mkfs.ext4 /dev/sdb1      # ext4
sudo mkfs.xfs /dev/sdb2       # xfs
sudo mkfs.vfat -F32 /dev/sdc1 # FAT32 (USB 등)
```

### 파일시스템 점검 (fsck)

**마운트 해제 후** 실행해야 한다.

```bash
sudo fsck -f /dev/sdb1
```

---

## 임시 메모리 파일시스템: tmpfs

메모리(RAM) 위에 파일시스템을 만들어 빠른 임시 저장소로 사용한다.

```bash
sudo mount -t tmpfs -o size=2G tmpfs /mnt/ram
```

재부팅 시 사라진다. `/etc/fstab`에도 등록 가능하다.

```
tmpfs /mnt/ram tmpfs defaults,size=2G,mode=1777 0 0
```

## 이미지 파일 마운트 (loop)

ISO나 디스크 이미지를 파일처럼 마운트할 수 있다.

```bash
sudo mount -o loop disk.iso /mnt/iso
```

## 네트워크 마운트

### NFS

```bash
sudo apt install nfs-common        # 클라이언트 패키지
sudo mount -t nfs 10.0.0.10:/export /mnt/nfs -o vers=4.1,_netdev
```

### CIFS (Windows 공유)

```bash
sudo apt install cifs-utils
sudo mount -t cifs //server/share /mnt/share -o username=user,vers=3.1.1,uid=1000,gid=1000
```

자격증명 파일을 만들어 사용하면 더 안전하다.

```bash
# /etc/samba/cred 파일
username=user
password=secret
domain=WORKGROUP
```
```bash
sudo mount -t cifs //server/share /mnt/share -o credentials=/etc/samba/cred,vers=3.1.1
```

## 바인드 마운트 (bind mount)

이미 마운트된 디렉터리를 다른 위치에 다시 연결한다.

```bash
sudo mount --bind /var/log/app /srv/app-logs
```

## 디스크 공간 부족 시 대처

```bash
df -hT               # 전체 사용량 확인
sudo du -xhd1 /      # 루트 아래에서 가장 큰 디렉터리 찾기
```

- 로그 파일 정리: `journalctl --vacuum-time=7d`
- 불필요 패키지 제거: `sudo apt autoremove`
- 대용량 파일 찾기: `find / -type f -size +100M -exec ls -lh {} \; 2>/dev/null`

## 실전 예제

### 예제 1: USB 메모리 마운트

```bash
lsblk -f                     # USB 장치 확인 (예: /dev/sdc1)
sudo mkdir -p /mnt/usb
sudo mount -o uid=1000,gid=1000 /dev/sdc1 /mnt/usb
```

### 예제 2: fstab에 데이터 파티션 등록

```bash
sudo blkid /dev/sdb1         # UUID 복사
echo "UUID=복사한값 /mnt/data ext4 defaults,noatime 0 2" | sudo tee -a /etc/fstab
sudo mount -a
```

### 예제 3: ISO 파일 마운트

```bash
sudo mount -o loop ubuntu-24.04.iso /mnt/iso
```

### 예제 4: 읽기 전용으로 재마운트

```bash
sudo mount -o remount,ro /mnt/data
```

## 트러블슈팅

### 마운트가 안 될 때

- 장치명이 바뀌었는지 확인: `lsblk`
- 파일시스템 손상 여부: `sudo fsck /dev/sdb1` (마운트 해제 후)
- 옵션 오류: `dmesg | tail`로 커널 메시지 확인

### fstab 오류로 부팅이 느려질 때

- 복구 모드에서 `/etc/fstab`의 문제 항목에 `nofail` 옵션을 추가
```
UUID=xxx /mnt/data ext4 defaults,nofail 0 2
```

## 핵심 명령어 요약

| 작업 | 명령어 |
|------|--------|
| 장치/파티션 확인 | `lsblk -f`, `blkid` |
| 마운트 | `mount [옵션] 장치 마운트점` |
| 마운트 해제 | `umount 마운트점` |
| fstab 테스트 | `mount -a` |
| 디스크 사용량 | `df -hT`, `du -sh *` |
| 파일시스템 생성 | `mkfs.ext4 /dev/sdb1` |
| 파일시스템 점검 | `fsck /dev/sdb1` (마운트 해제) |

## 결론

마운트는 리눅스에서 저장 장치를 시스템에 통합하는 기본적인 방법이다. 처음에는 `lsblk`로 장치를 확인하고, `mount` 명령으로 수동 마운트하는 연습을 한 후, 안정적인 운영을 위해 `/etc/fstab`에 등록하는 순서로 익히는 것이 좋다.

네트워크 공유나 특수 파일시스템(tmpfs, loop)도 같은 원리로 동작한다. 장애 발생 시 `df`, `du`, `lsof`, `dmesg` 등을 활용해 원인을 찾고, 불필요한 마운트 옵션을 배제하는 것이 안정성에 도움이 된다. 마운트 개념을 확실히 이해하면 디스크 관리, 백업, 서비스 격리 등 다양한 작업을 유연하게 수행할 수 있다.
