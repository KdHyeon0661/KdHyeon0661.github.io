# Avalonia 개요

Avalonia는 .NET 기반의 크로스 플랫폼 UI 프레임워크입니다. XAML로 UI를 설계하고 MVVM 패턴을 자연스럽게 지원하며, Windows, Linux, macOS에서 동일한 코드베이스로 실행할 수 있습니다. WPF와 유사한 개발 경험을 제공하지만 WPF가 Windows 전용인 반면, Avalonia는 다양한 데스크톱 환경을 아우릅니다.

## 주요 특징

- **XAML 기반 UI** – WPF 개발자가 빠르게 적응 가능  
- **MVVM 패턴** – 관심사 분리와 테스트 용이성  
- **하드웨어 가속 렌더링** – 부드러운 UI  
- **스타일링·리소스 시스템** – 전역 테마와 컨트롤별 스타일  
- **오픈소스 생태계** – 활발한 커뮤니티와 지속적인 개선  

## 왜 Avalonia인가?

| 이유 | 설명 |
|------|------|
| 크로스 플랫폼 | Windows, Linux, macOS 단일 코드베이스로 개발 |
| WPF 친화성 | XAML, 바인딩, 리소스 등 기존 지식 재사용 |
| MVVM 지원 | `INotifyPropertyChanged`, `ICommand` 기반 구조 |
| 배포 유연성 | self-contained, 단일 파일, 네이티브 패키징 가능 |

## 개발 환경 준비

### .NET SDK 설치

Avalonia는 .NET 6 이상에서 동작합니다. 최신 LTS 버전을 권장합니다. 설치 후 다음 명령으로 확인합니다.

```bash
dotnet --version
```

### Avalonia 템플릿 설치

```bash
dotnet new install Avalonia.Templates
```

설치된 템플릿 목록을 확인하려면 `dotnet new --list`를 실행하고 `Avalonia`가 포함된 항목을 찾습니다.

### VS Code 확장

- **C#** (C# Dev Kit 또는 OmniSharp 계열)  
- **Avalonia for Visual Studio Code** – XAML 인텔리센스 지원

## 첫 프로젝트 만들기

터미널에서 다음 명령을 실행합니다.

```bash
dotnet new avalonia.app -o MyAvaloniaApp
cd MyAvaloniaApp
dotnet run
```

기본 창이 나타나면 정상적으로 실행된 것입니다.

### 프로젝트 구조

```
MyAvaloniaApp/
  Program.cs          # 앱 진입점
  App.axaml           # 전역 리소스, 스타일, 테마
  App.axaml.cs        # 앱 초기화 코드
  MainWindow.axaml    # 첫 화면 레이아웃
  MainWindow.axaml.cs # 첫 화면 코드 비하인드
```

`Program.cs`는 `AppBuilder`를 구성하고, `App.axaml`은 애플리케이션 전반에 적용할 스타일과 리소스를 정의합니다. `MainWindow.axaml`은 실제 사용자 인터페이스를 담당합니다.

## MVVM 구조로 확장하기

Avalonia는 MVVM 패턴과 잘 어울립니다. 여기서는 `CommunityToolkit.Mvvm` 패키지를 사용해 간결하게 구현합니다.

### 패키지 설치

```bash
dotnet add package CommunityToolkit.Mvvm
```

### 폴더 구조 예시

```
MyAvaloniaApp/
  Models/       # 데이터 모델
  ViewModels/   # 뷰모델 (로직)
  Views/        # XAML 뷰
```

### Model 예제

```csharp
// Models/TodoItem.cs
namespace MyAvaloniaApp.Models
{
    public sealed class TodoItem
    {
        public string Title { get; }
        public bool IsDone { get; private set; }

        public TodoItem(string title, bool isDone = false)
        {
            Title = title;
            IsDone = isDone;
        }

        public void Toggle() => IsDone = !IsDone;
    }
}
```

### ViewModel 예제

```csharp
// ViewModels/MainViewModel.cs
using System.Collections.ObjectModel;
using CommunityToolkit.Mvvm.ComponentModel;
using CommunityToolkit.Mvvm.Input;
using MyAvaloniaApp.Models;

namespace MyAvaloniaApp.ViewModels
{
    public partial class MainViewModel : ObservableObject
    {
        [ObservableProperty]
        private string? newTitle;

        public ObservableCollection<TodoItem> Items { get; } = new();

        public MainViewModel()
        {
            Items.Add(new TodoItem("첫 번째 작업"));
            Items.Add(new TodoItem("두 번째 작업"));
        }

        [RelayCommand(CanExecute = nameof(CanAdd))]
        private void Add()
        {
            if (!string.IsNullOrWhiteSpace(NewTitle))
            {
                Items.Add(new TodoItem(NewTitle));
                NewTitle = string.Empty;
            }
        }

        private bool CanAdd() => !string.IsNullOrWhiteSpace(NewTitle);
    }
}
```

### DataContext 연결

`MainWindow.xaml.cs`에서 뷰모델을 생성해 `DataContext`에 할당합니다.

```csharp
// MainWindow.axaml.cs
using Avalonia.Controls;
using MyAvaloniaApp.ViewModels;

namespace MyAvaloniaApp
{
    public partial class MainWindow : Window
    {
        public MainWindow()
        {
            InitializeComponent();
            DataContext = new MainViewModel();
        }
    }
}
```

### 바인딩 UI (XAML)

XAML에서 뷰모델의 속성과 명령을 바인딩합니다.

```xml
<Window xmlns="https://github.com/avaloniaui"
        xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
        xmlns:vm="using:MyAvaloniaApp.ViewModels"
        x:Class="MyAvaloniaApp.MainWindow"
        Width="560" Height="360"
        Title="Todo Sample">
  <Design.DataContext>
    <vm:MainViewModel/>
  </Design.DataContext>

  <StackPanel Margin="16" Spacing="12">
    <TextBlock Text="할 일 추가" FontSize="20" />
    <DockPanel>
      <TextBox Text="{Binding NewTitle, Mode=TwoWay, UpdateSourceTrigger=PropertyChanged}"
               Watermark="새 작업 입력..." Width="360" />
      <Button Content="추가" Command="{Binding AddCommand}" Margin="8,0,0,0" />
    </DockPanel>

    <ItemsControl Items="{Binding Items}">
      <ItemsControl.ItemTemplate>
        <DataTemplate>
          <DockPanel Margin="0,4">
            <TextBlock Text="{Binding Title}" />
            <TextBlock Text="{Binding IsDone}" DockPanel.Dock="Right" />
          </DockPanel>
        </DataTemplate>
      </ItemsControl.ItemTemplate>
    </ItemsControl>
  </StackPanel>
</Window>
```

> `Design.DataContext`는 디자인 타임에 바인딩 힌트를 제공해 XAML 편집을 돕습니다.

## 스타일링과 리소스

### 전역 리소스 딕셔너리

`App.axaml`에 리소스를 등록하면 애플리케이션 전체에서 사용할 수 있습니다.

```xml
<Application ...>
  <Application.Resources>
    <SolidColorBrush x:Key="BrandBrush" Color="#3B82F6" />
    <Thickness x:Key="PagePadding">24</Thickness>

    <Style Selector="Button.confirm">
      <Setter Property="Background" Value="{StaticResource BrandBrush}" />
      <Setter Property="Foreground" Value="White" />
    </Style>
  </Application.Resources>
</Application>
```

사용 예:

```xml
<Button Classes="confirm" Content="확인" Padding="{StaticResource PagePadding}" />
```

### 컨트롤 타깃 스타일

특정 컨트롤 타입에 일괄 스타일을 적용할 수 있습니다.

```xml
<Style Selector="TextBlock">
  <Setter Property="FontSize" Value="14" />
</Style>
```

## Converter와 Validation

### IValueConverter

데이터를 표시하기 전에 변환해야 할 때는 컨버터를 사용합니다.

```csharp
// Converters/BoolToTextConverter.cs
using System;
using Avalonia.Data.Converters;
using System.Globalization;

namespace MyAvaloniaApp.Converters
{
    public class BoolToTextConverter : IValueConverter
    {
        public object? Convert(object? value, Type targetType, object? parameter, CultureInfo culture)
            => value is bool b && b ? "완료" : "진행 중";

        public object? ConvertBack(object? value, Type targetType, object? parameter, CultureInfo culture)
            => (value as string) == "완료";
    }
}
```

XAML에서 등록하고 바인딩합니다.

```xml
<Window xmlns:conv="using:MyAvaloniaApp.Converters">
  <Window.Resources>
    <conv:BoolToTextConverter x:Key="BoolToText"/>
  </Window.Resources>
  <TextBlock Text="{Binding IsDone, Converter={StaticResource BoolToText}}"/>
</Window>
```

### Validation

`CommunityToolkit.Mvvm`의 `ObservableValidator`를 상속받아 속성에 `[Required]` 등의 검증 특성을 추가합니다. 바인딩 오류는 `Validation.Errors`로 표시할 수 있습니다.

## 리스트와 그리드

### ListBox

항목을 나열하고 선택을 관리할 때 `ListBox`를 사용합니다.

```xml
<ListBox Items="{Binding Items}" SelectedItem="{Binding SelectedItem, Mode=TwoWay}">
  <ListBox.ItemTemplate>
    <DataTemplate>
      <StackPanel Orientation="Horizontal" Spacing="8">
        <CheckBox IsChecked="{Binding IsDone}"/>
        <TextBlock Text="{Binding Title}"/>
      </StackPanel>
    </DataTemplate>
  </ListBox.ItemTemplate>
</ListBox>
```

### DataGrid

대량 데이터나 컬럼 단위 편집이 필요하면 `DataGrid`를 사용합니다. 먼저 패키지를 설치합니다.

```bash
dotnet add package Avalonia.Controls.DataGrid
```

XAML에서 다음과 같이 정의합니다.

```xml
<DataGrid Items="{Binding Items}" AutoGenerateColumns="False">
  <DataGrid.Columns>
    <DataGridTextColumn Header="Title" Binding="{Binding Title}" />
    <DataGridCheckBoxColumn Header="Done" Binding="{Binding IsDone}" />
  </DataGrid.Columns>
</DataGrid>
```

## DI 컨테이너 구성

간단한 애플리케이션에서는 뷰모델을 직접 생성해도 되지만, 규모가 커지면 의존성 주입(DI)을 활용하는 것이 좋습니다. `Microsoft.Extensions.DependencyInjection` 패키지를 추가합니다.

```bash
dotnet add package Microsoft.Extensions.DependencyInjection
```

`App.axaml.cs`에서 서비스 컬렉션을 구성하고 `ServiceProvider`를 생성합니다.

```csharp
public partial class App : Application
{
    public static ServiceProvider Services { get; private set; } = default!;

    public override void Initialize()
    {
        AvaloniaXamlLoader.Load(this);
        var sc = new ServiceCollection();
        sc.AddSingleton<MainViewModel>();
        Services = sc.BuildServiceProvider();
    }

    public override void OnFrameworkInitializationCompleted()
    {
        if (ApplicationLifetime is IClassicDesktopStyleApplicationLifetime desktop)
        {
            var vm = Services.GetRequiredService<MainViewModel>();
            desktop.MainWindow = new MainWindow { DataContext = vm };
        }
        base.OnFrameworkInitializationCompleted();
    }
}
```

이제 어디서든 `App.Services.GetRequiredService<T>()`로 필요한 인스턴스를 가져올 수 있습니다.

## 핫 리로드와 디버깅

### dotnet watch

개발 중에는 `dotnet watch`를 사용하면 코드나 XAML 변경 시 앱이 자동으로 재시작되어 생산성을 높일 수 있습니다.

```bash
dotnet watch
```

### VS Code 디버깅

`.vscode/launch.json` 파일을 만들어 디버그 구성을 추가합니다.

```json
{
  "version": "0.2.0",
  "configurations": [
    {
      "name": ".NET Launch",
      "type": "coreclr",
      "request": "launch",
      "preLaunchTask": "build",
      "program": "${workspaceFolder}/bin/Debug/net8.0/MyAvaloniaApp.dll",
      "args": [],
      "cwd": "${workspaceFolder}"
    }
  ]
}
```

빌드 작업을 위해 `.vscode/tasks.json`도 작성합니다.

```json
{
  "version": "2.0.0",
  "tasks": [
    { "label": "build", "command": "dotnet", "type": "process", "args": [ "build" ] }
  ]
}
```

## 배포

### Self-contained 배포

애플리케이션을 특정 런타임에 종속된 단일 디렉터리로 배포하려면 `dotnet publish` 명령을 사용합니다.

Windows x64:

```bash
dotnet publish -c Release -r win-x64 --self-contained true
```

Linux x64:

```bash
dotnet publish -c Release -r linux-x64 --self-contained true
```

macOS x64:

```bash
dotnet publish -c Release -r osx-x64 --self-contained true
```

출력물은 `bin/Release/<TFM>/<RID>/publish/`에 생성됩니다.

### 단일 파일 배포

`-p:PublishSingleFile=true` 옵션을 추가하면 하나의 실행 파일로 묶을 수 있습니다.

```bash
dotnet publish -c Release -r win-x64 -p:PublishSingleFile=true --self-contained true
```

## WebAssembly와 모바일 (간략 방향)

- **WebAssembly**: 별도의 템플릿을 사용해 브라우저 타깃 프로젝트를 생성합니다. 공통 로직(모델, 서비스)은 공유 라이브러리로 분리합니다.
- **모바일**: Android/iOS 프로젝트를 추가하고 공유 라이브러리를 참조합니다. 네이티브 권한, 해상도 대응, 앱 스토어 배포 등 추가 작업이 필요합니다.

## 테스트 전략

### ViewModel 단위 테스트 (xUnit)

ViewModel은 순수 C# 코드이므로 UI 없이 단위 테스트를 작성할 수 있습니다. 테스트 프로젝트를 생성하고 참조를 추가합니다.

```bash
dotnet new xunit -o MyAvaloniaApp.Tests
cd MyAvaloniaApp.Tests
dotnet add reference ../MyAvaloniaApp/MyAvaloniaApp.csproj
```

테스트 예:

```csharp
using MyAvaloniaApp.ViewModels;
using Xunit;

public class MainViewModelTests
{
    [Fact]
    public void AddCommand_ShouldAddItem_WhenNewTitleIsValid()
    {
        var vm = new MainViewModel();
        vm.NewTitle = "테스트";
        vm.AddCommand.Execute(null);

        Assert.Contains(vm.Items, it => it.Title == "테스트");
    }
}
```

이러한 테스트는 CI 환경에서 빠르게 실행할 수 있어 코드 안정성을 높입니다.

## GitHub Actions CI 예시

`.github/workflows/build.yml` 파일을 생성해 지속적 통합을 구성합니다.

```yaml
name: build
on:
  push:
    branches: [ main ]
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-dotnet@v4
        with:
          dotnet-version: '8.0.x'
      - run: dotnet restore
      - run: dotnet build --configuration Release --no-restore
      - run: dotnet test --no-build --verbosity normal
```

## 자주 겪는 문제와 해결

- **XAML 네임스페이스 오류**  
  `xmlns="https://github.com/avaloniaui"`가 정확히 지정되었는지 확인합니다.

- **디자인 타임 바인딩 미작동**  
  `Design.DataContext`에 뷰모델 인스턴스를 제공하고, 네임스페이스가 올바른지 확인합니다.

- **바인딩 실패**  
  출력 창(로그)에서 바인딩 오류 메시지를 확인합니다. 프로퍼티 이름, `INotifyPropertyChanged` 구현 여부를 점검합니다.

- **단일 파일 실행 속도**  
  `PublishSingleFile` 옵션은 실행 시 압축 해제 과정이 추가되어 시작 속도에 영향을 줄 수 있습니다. 필요에 따라 해제할 수 있습니다.

- **macOS 배포**  
  애플리케이션을 배포하려면 코드 서명과 노타라이즈(notarize) 과정이 필요합니다.

- **Linux 배포**  
  배포 대상의 glibc 버전 등 런타임 호환성을 확인해야 합니다.

## 마무리

이 가이드는 Avalonia의 기본 설치부터 MVVM 구조, 스타일링, DI, 배포까지 초중급 개발자가 바로 활용할 수 있도록 핵심을 정리했습니다. WPF 경험이 있다면 빠르게 적응할 수 있으며, 이후 WebAssembly나 모바일로 확장할 때도 동일한 설계 원칙을 적용할 수 있습니다.
