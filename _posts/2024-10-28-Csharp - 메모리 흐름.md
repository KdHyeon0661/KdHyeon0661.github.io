# C# 메서드 호출과 메모리 관리: 성능 최적화의 기초

C#에서 메서드가 호출될 때 내부적으로 어떤 일이 일어나는지 이해하면, 성능 병목을 찾고 최적화하는 데 큰 도움이 됩니다. 이 글에서는 메모리 관점에서 메서드 호출을 살펴보고, 성능을 높이는 몇 가지 실용적인 기법을 소개합니다.

## 스택 프레임: 메서드 호출의 기본 단위

메서드가 호출되면 런타임은 **스택**이라는 메모리 영역에 **프레임**을 생성합니다. 이 프레임에는 다음과 같은 정보가 저장됩니다.

- **반환 주소**: 메서드 실행이 끝난 후 돌아갈 위치
- **매개변수**: 호출자가 전달한 값
- **지역 변수**: 메서드 내에서 선언된 변수
- **이전 프레임 포인터**: 호출한 메서드의 프레임을 가리킴

```csharp
public int Add(int a, int b)
{
    int result = a + b;   // result는 지역 변수
    return result;
}

public void Caller()
{
    int x = 10;
    int y = 20;
    int sum = Add(x, y);   // Add 호출 시 스택 프레임 생성
}
```

`Add`가 실행되는 동안 `Caller`의 프레임은 잠시 대기 상태가 됩니다. `Add`가 반환되면 자신의 프레임이 스택에서 제거되고, `Caller`가 다시 실행을 이어갑니다.

이 구조는 재귀 호출에서 잘 드러납니다. 재귀가 너무 깊어지면 스택 공간이 부족해 **StackOverflowException**이 발생합니다.

```csharp
public void Recursive(int depth)
{
    if (depth > 0)
        Recursive(depth - 1);   // 호출할 때마다 새 프레임 생성
}
```

스택은 속도가 빠르지만 크기가 제한적이므로, 많은 데이터를 스택에 쌓는 설계는 피해야 합니다.

## 값 전달과 참조 전달의 성능 차이

메서드 매개변수를 전달하는 방식은 성능에 직접적인 영향을 줍니다.

### 값 타입은 복사된다

구조체(struct)를 매개변수로 넘기면 **값이 복사**됩니다. 구조체가 클수록 복사 비용이 커집니다.

```csharp
public struct LargeData
{
    public long Value1, Value2, Value3, Value4;   // 32바이트
}

public long Process(LargeData data)   // data가 복사됨
{
    return data.Value1 + data.Value2;
}
```

`Process`를 수천 번 호출하면 불필요한 메모리 복사가 누적됩니다.

### 참조 전달로 복사 제거

C#은 `ref`, `in`, `out` 키워드를 제공해 값의 복사 없이 원본 데이터를 직접 다룰 수 있습니다.

| 키워드 | 의미 | 사용 예 |
|--------|------|---------|
| `ref` | 읽기/쓰기 참조 | `void Modify(ref LargeData data)` |
| `in` | 읽기 전용 참조 (C# 7.2+) | `long Sum(in LargeData data)` |
| `out` | 출력 전용, 호출 전 초기화 불필요 | `bool TryCreate(out LargeData data)` |

```csharp
public long Sum(in LargeData data)   // 복사 없이 읽기만
{
    return data.Value1 + data.Value2;
}

public void Modify(ref LargeData data)   // 원본 수정 가능
{
    data.Value1 = 100;
}
```

큰 구조체를 읽기만 할 때는 `in`을 사용하면 성능 이점이 큽니다. 다만 `in`으로 전달된 인자는 수정할 수 없습니다.

## Span<T>와 stackalloc: 힙 할당을 줄이는 방법

### Span<T>로 메모리 조각내기

`Span<T>`는 배열, 문자열, 스택 메모리 등 연속된 메모리 영역을 **할당 없이** 가리킬 수 있는 구조체입니다. 예를 들어 문자열의 일부만 처리할 때 `Substring`을 사용하면 새로운 문자열이 힙에 할당되지만, `ReadOnlySpan<char>`를 사용하면 할당이 발생하지 않습니다.

```csharp
public int CountSpaces(ReadOnlySpan<char> text)
{
    int count = 0;
    foreach (char c in text)
        if (c == ' ') count++;
    return count;
}

// 사용 예
string message = "Hello World";
int spaces = CountSpaces(message.AsSpan());   // 할당 없음
```

### stackalloc으로 스택 버퍼 사용

작은 임시 버퍼가 필요할 때 `stackalloc`을 사용하면 힙 할당 없이 스택에 메모리를 확보할 수 있습니다.

```csharp
Span<byte> buffer = stackalloc byte[256];
// buffer를 사용한 작업...
```

스택 할당은 매우 빠르지만, 버퍼 크기를 너무 크게 잡으면 스택 오버플로우를 유발할 수 있습니다. 또한 비동기 메서드(`async`)에서는 사용할 수 없습니다.

## ref struct: 스택에만 존재하는 타입

`ref struct`는 힙에 할당될 수 없는 구조체입니다. 이 타입은 항상 스택에만 존재하므로 GC의 대상이 되지 않습니다. `Span<T>`가 대표적인 `ref struct`입니다.

```csharp
public ref struct StackOnly
{
    private int _value;
    public StackOnly(int value) => _value = value;
    public int GetValue() => _value;
}
```

`ref struct`는 다음과 같은 제약이 있습니다.
- 힙에 저장할 수 없음 (예: `List<StackOnly>` 불가)
- 박싱할 수 없음
- 인터페이스를 구현할 수 없음

이러한 제약 덕분에 `ref struct`는 안전하게 스택 전용으로 사용됩니다.

## 실전 최적화 패턴

### 1. Try-패턴으로 예외 회피

예외는 발생 시 스택 추적 등 무거운 작업이 수반됩니다. 자주 실패할 수 있는 작업(예: 문자열 파싱)은 예외를 던지기보다 Try-패턴을 사용하는 것이 좋습니다.

```csharp
public bool TryParseInt(ReadOnlySpan<char> input, out int result)
{
    result = 0;
    if (input.Length == 0) return false;

    int sign = 1;
    int start = 0;
    if (input[0] == '-')
    {
        sign = -1;
        start = 1;
    }

    long value = 0;
    for (int i = start; i < input.Length; i++)
    {
        if (input[i] < '0' || input[i] > '9') return false;
        value = value * 10 + (input[i] - '0');
        if (value > int.MaxValue) return false;
    }

    result = (int)(sign * value);
    return true;
}
```

### 2. 버퍼 풀링으로 재사용

빈번하게 생성되는 배열은 풀에서 빌려와 사용하면 GC 부담을 줄일 수 있습니다. `System.Buffers.ArrayPool<T>`를 사용할 수 있습니다.

```csharp
byte[] buffer = ArrayPool<byte>.Shared.Rent(1024);
try
{
    // buffer 사용
}
finally
{
    ArrayPool<byte>.Shared.Return(buffer);
}
```

### 3. 상황별 버퍼 할당 전략

데이터 크기에 따라 다른 전략을 적용합니다.

- **매우 작음(256바이트 미만)**: `stackalloc`으로 스택 버퍼
- **중간 크기**: `ArrayPool`에서 대여
- **큰 데이터**: 직접 `new` 할당

## 성능 측정: 최적화의 첫걸음

최적화는 반드시 측정을 기반으로 해야 합니다. `Stopwatch`를 사용해 간단히 측정하거나, `BenchmarkDotNet` 같은 도구로 정밀하게 측정합니다.

```csharp
var sw = Stopwatch.StartNew();
for (int i = 0; i < 1_000_000; i++)
{
    // 테스트할 코드
}
sw.Stop();
Console.WriteLine(sw.ElapsedMilliseconds);
```

측정 없이 감으로 최적화하면 오히려 복잡도만 늘어나는 경우가 많습니다.

## 최적화 체크리스트

성능을 개선하기 전에 다음을 점검해 보세요.

1. **구조체 크기** - 16바이트 이상이면 참조 전달(`in`) 고려
2. **반복적인 힙 할당** - 풀링 또는 스택 할당으로 대체 가능한지
3. **예외 발생** - 핫 경로에서 예외를 던지는 패턴은 Try-패턴으로 변경
4. **문자열/배열 조작** - `Substring` 대신 `AsSpan()` 사용
5. **비동기 메서드** - `stackalloc`을 쓸 수 없으므로 `MemoryPool` 고려

## 마무리

C#의 메모리 관리와 성능 최적화는 단순한 문법 지식을 넘어 설계와 관련된 영역입니다. 현대 C#에서는 `Span<T>`, `ref struct`, `in` 매개변수 등 성능을 높이면서도 안전성을 유지할 수 있는 도구들이 많이 제공됩니다.

중요한 것은 **측정하고, 병목을 찾고, 필요한 부분에만 최적화를 적용하는 것**입니다. 모든 코드를 저수준으로 최적화하려 하기보다, 가독성을 해치지 않는 선에서 핵심 경로에 집중하는 것이 좋습니다.

이 글에서 소개한 기법들이 실제 코드에서 성능 병목을 해소하는 데 도움이 되기를 바랍니다.
