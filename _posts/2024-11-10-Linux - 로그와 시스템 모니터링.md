# 로그와 시스템 모니터링

## 리눅스 로그의 종류

리눅스 시스템에서 로그는 주로 다음 위치에 저장된다.

| 로그 파일 | 설명 |
|----------|------|
| `/var/log/syslog` 또는 `/var/log/messages` | 시스템 전반적인 로그 (배포판에 따라 다름) |
| `/var/log/auth.log` 또는 `/var/log/secure` | 인증 및 보안 관련 이벤트 |
| `/var/log/dmesg` | 부팅 초기 커널 메시지 |
| 서비스별 디렉터리 | `/var/log/nginx/`, `/var/log/mysql/` 등 |

대부분의 현대 리눅스 배포판은 systemd의 journald가 로그를 먼저 수집하며, 필요에 따라 전통적인 syslog 데몬(rsyslog)과 병행한다.

---

## journald: 시스템 로그 관리자

### 저장 방식

journald는 두 가지 방식으로 로그를 저장한다.
- **휘발성**: `/run/log/journal` - 재부팅 시 사라짐
- **영구**: `/var/log/journal` - 재부팅 후에도 보존

영구 보존을 활성화하려면 다음을 실행한다.

```bash
sudo mkdir -p /var/log/journal
sudo systemd-tmpfiles --create --prefix /var/log/journal
sudo systemctl restart systemd-journald
```

### 설정 파일

`/etc/systemd/journald.conf`에서 주요 옵션을 설정할 수 있다.

```ini
Storage=persistent      # persistent, volatile, auto
SystemMaxUse=2G         # 전체 사용량 상한
SystemKeepFree=1G       # 디스크 여유 공간 보장
MaxRetentionSec=3month  # 최대 보존 기간
```

설정 변경 후 서비스를 재시작한다.

```bash
sudo systemctl restart systemd-journald
```

### 디스크 사용량 확인 및 정리

```bash
journalctl --disk-usage                     # 사용량 확인
sudo journalctl --vacuum-time=30d           # 30일 이전 로그 삭제
sudo journalctl --vacuum-size=2G            # 2GB 초과 시 정리
```

## journalctl: 로그 조회 도구

### 부팅별 로그 확인

```bash
journalctl --list-boots      # 부팅 목록
journalctl -b                # 현재 부팅 로그
journalctl -b -1             # 직전 부팅 로그
```

### 서비스와 PID 필터링

```bash
journalctl -u ssh             # ssh 서비스 로그
journalctl -u nginx -f        # 실시간 로그 (tail -f)
journalctl _PID=1234          # 특정 PID 로그
journalctl _UID=1000          # 특정 사용자 로그
```

### 시간 범위 지정

```bash
journalctl --since "2025-11-10 09:00" --until "2025-11-10 18:00"
journalctl --since "1 hour ago"
journalctl -S today -U now    # -S: since, -U: until
```

### 로그 레벨 필터링

로그 레벨은 `emerg`(0)부터 `debug`(7)까지 있다. 일반적으로 `err`(3) 이상을 확인한다.

```bash
journalctl -p err              # 에러 이상
journalctl -p 3                # 숫자로도 가능
```

### 출력 형식과 검색

```bash
journalctl -n 100 -o short-iso       # 최근 100줄, ISO 시간 형식
journalctl -o cat -u nginx           # 메시지만 출력
journalctl -u myapp --grep='error'   # 문자열 검색
```

## dmesg: 커널 메시지 확인

부팅 과정이나 하드웨어 관련 문제를 확인할 때 사용한다.

```bash
dmesg -T                     # 사람이 읽기 쉬운 시간 형식
dmesg --level=err            # 에러 레벨 이상만
dmesg -wH                    # 실시간 모니터링
```

일반적인 필터 예시:

```bash
dmesg | grep -i oom          # 메모리 부족 관련
dmesg | grep -i nvme         # NVMe 디스크 관련
```

> 최신 배포판에서는 `dmesg` 대신 `journalctl -k`를 사용할 수 있다.

```bash
journalctl -k -b -p warning
```

## logrotate: 로그 파일 회전

로그 파일이 무한정 커지는 것을 방지하기 위해 주기적으로 파일을 교체(회전)하고 압축한다.

### 설정 파일

- 전역 설정: `/etc/logrotate.conf`
- 서비스별 설정: `/etc/logrotate.d/`

### 기본 설정 예시 (NGINX)

```conf
/var/log/nginx/*.log {
    daily
    rotate 14
    compress
    delaycompress
    missingok
    notifempty
    create 0640 www-data adm
    postrotate
        kill -USR1 $(cat /run/nginx.pid)
    endscript
}
```

- `daily`: 매일 회전
- `rotate 14`: 14개 보관
- `compress`: gzip 압축
- `postrotate`: 회전 후 실행할 명령 (로그 파일 재오픈)

### 용량 기준 회전

```conf
/var/log/app/*.log {
    size 100M
    rotate 10
    compress
}
```

### 상태 확인 및 강제 실행

```bash
sudo logrotate -d /etc/logrotate.conf   # 드라이런 (테스트)
sudo logrotate -f /etc/logrotate.conf   # 강제 실행
```

## 시스템 모니터링 기본 도구

### uptime: 부하 평균

```bash
uptime
# 예: 1분, 5분, 15분 평균 부하. CPU 코어 수보다 지속적으로 높으면 과부하
```

### free: 메모리 사용량

```bash
free -h
# available 컬럼이 실제 가용 메모리
```

### df: 디스크 사용량

```bash
df -hT
# -T: 파일시스템 타입 표시
```

### du: 디렉터리 용량

```bash
du -sh *           # 현재 디렉터리 항목별 요약
sudo du -xhd1 /var | sort -h   # /var 아래 큰 디렉터리 찾기
```

### vmstat: 시스템 상태

```bash
vmstat 1 5
# r: 실행 대기 중인 프로세스, si/so: 스왑 입출력, us/sy/id/wa: CPU 사용률
```

### iostat: 디스크 I/O

```bash
sudo apt install sysstat   # 설치 필요
iostat -x 1 3
# %util: 디스크 사용률, await: 응답 대기 시간
```

### iotop: I/O 상위 프로세스

```bash
sudo iotop -o -d 2   # I/O가 있는 프로세스만 2초 간격
```

### glances: 종합 모니터링

```bash
glances
```

## 장애 시나리오별 진단

### 서비스 에러 확인

```bash
journalctl -u myapp -b -p err              # 현재 부팅 중 에러
journalctl -u myapp --since "-10min"       # 최근 10분
```

### 메모리 부족 (OOM)

```bash
journalctl -k --since "-1h" | grep -i "out of memory"
free -h
```

### 디스크 I/O 병목

```bash
iostat -x 1 5          # await와 %util 확인
sudo iotop -o -d 1
```

### 인증 실패 확인

```bash
journalctl -u ssh --since today --grep='Failed'
sudo grep "Failed" /var/log/auth.log
```

### 로그가 너무 빠르게 증가할 때

```bash
journalctl -u noisy.service --since "-5min" | wc -l   # 로그량 확인
sudo du -xhd1 /var/log | sort -hr | head              # 큰 파일 찾기
```

```bash

tail -f /var/log/syslog
```

## 결론

리눅스 시스템에서 로그는 문제 진단의 가장 중요한 단서다. journald와 journalctl을 통해 로그를 중앙에서 관리하고, 서비스별로 필터링하여 필요한 정보를 빠르게 찾는 것이 핵심이다.

정기적인 로그 정리 정책을 설정하는 것도 중요하다. journald의 보존 기간과 용량을 설정하고, logrotate로 파일 기반 로그를 관리하면 디스크 공간 부족을 예방할 수 있다.

시스템 모니터링 도구(vmstat, iostat, glances 등)를 함께 사용하면 부하의 원인을 더 정확히 파악할 수 있다. 로그와 성능 지표를 함께 분석하는 습관을 들이면 장애 대응 능력이 크게 향상된다.
