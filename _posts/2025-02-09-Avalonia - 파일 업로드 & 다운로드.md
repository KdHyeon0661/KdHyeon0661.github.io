# Avalonia 파일 업로드 및 다운로드 (HttpClient 연동)

파일 전송은 현대 애플리케이션에서 빠질 수 없는 기능입니다. Avalonia에서 MVVM 패턴을 유지하면서 안정적인 업로드/다운로드를 구현하려면 **서비스 계층**을 통해 네트워크 로직과 UI를 분리하고, 진행률 보고와 취소, 재시도 정책까지 함께 고려해야 합니다. 이 글에서는 초중급 개발자 기준으로 실제 동작하는 파일 업로드/다운로드 구조를 단계별로 설명합니다.

---

## 프로젝트 구조

```
MyApp/
├── App.axaml / App.axaml.cs
├── Views/
│   └── FileTransferView.axaml / .cs
├── ViewModels/
│   └── FileTransferViewModel.cs
├── Services/

│   ├── IFilePickerService.cs
│   ├── FilePickerService.cs
│   └── BackoffPolicy.cs
└── Models/
    └── FileRecord.cs
```

- **IFileService**: 업로드/다운로드 핵심 로직 (진행률, 취소 지원)
- **IFilePickerService**: 운영체제 파일 다이얼로그 추상화 (ViewModel에서 직접 Window를 몰라도 됨)
- **BackoffPolicy**: 일시적 네트워크 오류에 대한 재시도 정책

## 서비스 인터페이스 설계

### 파일 서비스 (IFileService)

```csharp
public interface IFileService
{
    Task<FileRecord> UploadAsync(
        string filePath,
        IDictionary<string, string>? metadata = null,
        IProgress<double>? progress = null,
        CancellationToken ct = default);

    Task<IReadOnlyList<FileRecord>> UploadManyAsync(
        IReadOnlyList<string> filePaths,
        IDictionary<string, string>? commonMetadata = null,
        IProgress<(int index, double percent)>? progress = null,
        CancellationToken ct = default);

    Task DownloadAsync(
        int fileId,
        string savePath,
        IProgress<double>? progress = null,
        CancellationToken ct = default);

```

`IProgress<double>`는 0.0 ~ 100.0 사이의 진행률을 전달합니다. `UploadManyAsync`는 여러 파일을 순차 업로드하며 각 파일별 진행률을 튜플로 전달합니다.

### 파일 선택 서비스 (IFilePickerService)


## 파일 선택 서비스 구현

```csharp
public sealed class FilePickerService : IFilePickerService
{
    private static Window GetOwner()
    {
        var lifetime = (IClassicDesktopStyleApplicationLifetime)Application.Current!.ApplicationLifetime!;
        return lifetime.MainWindow!;
    }

    public async Task<string[]?> PickOpenAsync(
        string title,
        IEnumerable<(string Name, string[] Extensions)>? filters = null,
        bool allowMultiple = false)
    {
        var dlg = new OpenFileDialog { Title = title, AllowMultiple = allowMultiple };
        if (filters != null)
        {
            dlg.Filters = filters.Select(f => new FileDialogFilter
            {
                Name = f.Name,
                Extensions = f.Extensions.ToList()
            }).ToList();
        }
        return await dlg.ShowAsync(GetOwner());
    }

    public async Task<string?> PickSaveAsync(
        string title,
        string suggestedFileName,
        IEnumerable<(string Name, string[] Extensions)>? filters = null)
    {
        var dlg = new SaveFileDialog
        {
            Title = title,
            InitialFileName = suggestedFileName
        };
        if (filters != null)
        {
            dlg.Filters = filters.Select(f => new FileDialogFilter
            {
                Name = f.Name,
                Extensions = f.Extensions.ToList()
            }).ToList();
        }
        return await dlg.ShowAsync(GetOwner());
    }
}
```

`GetOwner()`는 현재 애플리케이션의 메인 윈도우를 반환해 다이얼로그가 올바른 소유자 아래 뜨도록 합니다.

## 백오프/재시도 정책

네트워크 요청은 일시적으로 실패할 수 있으므로, **지수 백오프**를 적용한 재시도 유틸을 준비합니다.

```csharp
public static class BackoffPolicy
{
    public static async Task RunAsync(
        Func<Task> action,
        int maxRetries = 3,
        TimeSpan? initialDelay = null,
        Func<Exception, bool>? isTransient = null,
        CancellationToken ct = default)
    {
        initialDelay ??= TimeSpan.FromMilliseconds(300);
        isTransient ??= (ex => ex is HttpRequestException or IOException or TaskCanceledException);

        var delay = initialDelay.Value;

        for (int attempt = 0; ; attempt++)
        {
            ct.ThrowIfCancellationRequested();
            try
            {
                await action();
                return;
            }
            catch (Exception ex) when (attempt < maxRetries && isTransient(ex))
            {
                await Task.Delay(delay, ct);
                delay = TimeSpan.FromMilliseconds(Math.Min(delay.TotalMilliseconds * 2, 5000));
            }
        }
    }
}
```

이 함수는 `action`을 최대 `maxRetries`회 반복하며, 재시도 간격을 점차 늘립니다.

## 파일 업로드 서비스 구현

업로드 시 `MultipartFormDataContent`를 사용하고, 스트림을 읽으면서 진행률을 보고합니다.

### 진행률 스트림 래퍼 (ProgressStreamContent)

```csharp
public sealed class ProgressStreamContent : HttpContent
{
    private readonly Stream _stream;
    private readonly int _bufferSize;
    private readonly Action<long> _onProgress;
    private long _sent;

    public ProgressStreamContent(Stream stream, int bufferSize, Action<long> onProgress)
    {
        _stream = stream;
        _bufferSize = bufferSize;
        _onProgress = onProgress;
        Headers.ContentLength = stream.CanSeek ? stream.Length : null;
    }

    protected override async Task SerializeToStreamAsync(Stream stream, TransportContext? context)
    {
        var buffer = new byte[_bufferSize];
        int read;
        while ((read = await _stream.ReadAsync(buffer.AsMemory(0, _bufferSize))) > 0)
        {
            await stream.WriteAsync(buffer.AsMemory(0, read));
            _sent += read;
            _onProgress(_sent);
        }
    }

    protected override bool TryComputeLength(out long length)
    {
        if (_stream.CanSeek)
        {
            length = _stream.Length;
            return true;
        }
        length = -1;
        return false;
    }
}
```

### FileApiService (업로드 부분)

```csharp
public sealed class FileApiService : IFileService
{
    private readonly HttpClient _http;

    public FileApiService(HttpClient http) => _http = http;

    public async Task<FileRecord> UploadAsync(
        string filePath,
        IDictionary<string, string>? metadata = null,
        IProgress<double>? progress = null,
        CancellationToken ct = default)
    {
        if (!File.Exists(filePath))
            throw new FileNotFoundException(filePath);

        var fileName = Path.GetFileName(filePath);
        var fileLength = new FileInfo(filePath).Length;

        using var fs = File.OpenRead(filePath);
        using var streamContent = new ProgressStreamContent(fs, 81920, bytes =>
        {
            if (fileLength > 0 && progress != null)
            {
                var pct = (double)bytes / fileLength * 100.0;
                progress.Report(Math.Min(100.0, pct));
            }
        });

        streamContent.Headers.ContentType = new MediaTypeHeaderValue("application/octet-stream");
        streamContent.Headers.ContentDisposition = new ContentDispositionHeaderValue("form-data")
        {
            Name = "\"file\"",
            FileName = "\"" + fileName + "\""
        };

        using var multi = new MultipartFormDataContent();
        multi.Add(streamContent, "file", fileName);

        if (metadata != null && metadata.Count > 0)
        {
            var metaJson = System.Text.Json.JsonSerializer.Serialize(metadata);
            multi.Add(new StringContent(metaJson, Encoding.UTF8, "application/json"), "meta");
        }

        FileRecord? result = null;

        await BackoffPolicy.RunAsync(async () =>
        {
            using var req = new HttpRequestMessage(HttpMethod.Post, "/api/files/upload") { Content = multi };
            using var res = await _http.SendAsync(req, HttpCompletionOption.ResponseHeadersRead, ct);
            res.EnsureSuccessStatusCode();

            var json = await res.Content.ReadAsStringAsync(ct);
            result = System.Text.Json.JsonSerializer.Deserialize<FileRecord>(json)
                     ?? throw new InvalidOperationException("Invalid server response");
        }, ct: ct);

        progress?.Report(100.0);
        return result!;
    }

    // UploadManyAsync, DownloadAsync는 생략 (유사한 패턴)
}
```

- `ProgressStreamContent`는 업로드 중 전송된 바이트 수를 콜백으로 알려줍니다.
- `BackoffPolicy.RunAsync`로 네트워크 장애 시 재시도합니다.
- 성공 후 진행률을 100%로 마무리합니다.

## 파일 다운로드 서비스 구현

다운로드는 `HttpCompletionOption.ResponseHeadersRead`를 사용해 응답 헤더만 먼저 읽고, 이후 본문을 스트리밍 방식으로 저장합니다. 임시 파일(`.partial`)에 쓰고, 완료 후 원자적 교체로 덮어쓰기 위험을 줄입니다.

```csharp
public async Task DownloadAsync(
    int fileId,
    string savePath,
    IProgress<double>? progress = null,
    CancellationToken ct = default)
{
    Directory.CreateDirectory(Path.GetDirectoryName(savePath)!);
    var tempPath = savePath + ".partial";

    await BackoffPolicy.RunAsync(async () =>
    {
        using var req = new HttpRequestMessage(HttpMethod.Get, $"/api/files/download/{fileId}");
        using var res = await _http.SendAsync(req, HttpCompletionOption.ResponseHeadersRead, ct);
        res.EnsureSuccessStatusCode();

        var contentLength = res.Content.Headers.ContentLength ?? -1L;

        await using var src = await res.Content.ReadAsStreamAsync(ct);
        await using var dst = new FileStream(tempPath, FileMode.Create, FileAccess.Write, FileShare.None, 81920, useAsync: true);

        var buffer = new byte[81920];
        long total = 0;
        int read;
        while ((read = await src.ReadAsync(buffer.AsMemory(0, buffer.Length), ct)) > 0)
        {
            await dst.WriteAsync(buffer.AsMemory(0, read), ct);
            total += read;

            if (contentLength > 0 && progress != null)
            {
                var pct = total * 100.0 / contentLength;
                progress.Report(Math.Min(100.0, pct));
            }
        }
    }, ct: ct);

    // 임시 파일을 최종 위치로 교체
    if (File.Exists(savePath)) File.Delete(savePath);
    File.Move(tempPath, savePath);
    progress?.Report(100.0);
}
```

- `ResponseHeadersRead`를 사용해 응답 본문이 도착하기 전에 헤더를 읽어 `ContentLength`를 얻습니다.
- 스트림을 읽으면서 진행률을 계산합니다.
- 완료 후 임시 파일을 최종 경로로 이동합니다.

## ViewModel (파일 전송 상태 관리)

ViewModel은 서비스들만 주입받고, 사용자 상호작용에 따라 업로드/다운로드를 시작합니다. 진행률과 상태 메시지는 바인딩 가능한 속성으로 노출하며, 취소 기능을 위해 `CancellationTokenSource`를 관리합니다.

```csharp
public sealed class FileTransferViewModel : ReactiveObject
{
    private readonly IFileService _fileService;
    private readonly IFilePickerService _filePicker;
    private CancellationTokenSource? _cts;

    public FileTransferViewModel(IFileService fileService, IFilePickerService filePicker)
    {
        _fileService = fileService;
        _filePicker = filePicker;

        UploadCommand = ReactiveCommand.CreateFromTask(UploadAsync);
        UploadManyCommand = ReactiveCommand.CreateFromTask(UploadManyAsync);
        DownloadCommand = ReactiveCommand.CreateFromTask(DownloadAsync);
        CancelCommand = ReactiveCommand.Create(Cancel);
    }

    private double _progress;
    public double ProgressPercent
    {
        get => _progress;
        private set => this.RaiseAndSetIfChanged(ref _progress, value);
    }

    private string _status = "";
    public string StatusMessage
    {
        get => _status;
        private set => this.RaiseAndSetIfChanged(ref _status, value);
    }

    public ReactiveCommand<Unit, Unit> UploadCommand { get; }
    public ReactiveCommand<Unit, Unit> UploadManyCommand { get; }
    public ReactiveCommand<Unit, Unit> DownloadCommand { get; }
    public ReactiveCommand<Unit, Unit> CancelCommand { get; }

    private async Task UploadAsync()
    {
        var files = await _filePicker.PickOpenAsync(
            title: "업로드할 파일 선택",
            filters: new[] { ("모든 파일", new[] { "*" }) },
            allowMultiple: false);

        if (files is null || files.Length == 0) return;

        _cts = new CancellationTokenSource();
        ProgressPercent = 0;
        StatusMessage = "업로드 시작";

        try
        {
            var progress = new Progress<double>(p => ProgressPercent = p);
            var metadata = new Dictionary<string, string> { ["uploader"] = Environment.UserName };
            var record = await _fileService.UploadAsync(files[0], metadata, progress, _cts.Token);
            StatusMessage = $"업로드 성공: #{record.Id} {record.Name}";
        }
        catch (OperationCanceledException)
        {
            StatusMessage = "업로드 취소됨";
        }
        catch (Exception ex)
        {
            StatusMessage = $"업로드 실패: {ex.Message}";
        }
        finally
        {
            _cts = null;
        }
    }

    private async Task UploadManyAsync()
    {
        var files = await _filePicker.PickOpenAsync(
            "여러 파일 업로드",
            new[] { ("이미지", new[] { "png", "jpg", "jpeg", "gif" }), ("모든 파일", new[] { "*" }) },
            allowMultiple: true);

        if (files is null || files.Length == 0) return;

        _cts = new CancellationTokenSource();
        ProgressPercent = 0;
        StatusMessage = "다중 업로드 시작";

        try
        {
            var progress = new Progress<(int index, double percent)>(p =>
            {
                // 전체 평균 진행률
                ProgressPercent = (p.index + p.percent / 100.0) * 100.0 / files.Length;
            });

            var records = await _fileService.UploadManyAsync(files, null, progress, _cts.Token);
            StatusMessage = $"업로드 완료: {records.Count}개";
        }
        catch (OperationCanceledException)
        {
            StatusMessage = "다중 업로드 취소됨";
        }
        catch (Exception ex)
        {
            StatusMessage = $"다중 업로드 실패: {ex.Message}";
        }
        finally
        {
            _cts = null;
        }
    }

    private async Task DownloadAsync()
    {
        // 실제로는 파일 ID를 선택하는 UI가 필요합니다. 여기서는 고정값 사용
        int fileId = 1;

        var savePath = await _filePicker.PickSaveAsync(
            "저장 위치 선택",
            suggestedFileName: "downloaded.bin",
            filters: new[] { ("모든 파일", new[] { "*" }) });

        if (string.IsNullOrWhiteSpace(savePath)) return;

        _cts = new CancellationTokenSource();
        ProgressPercent = 0;
        StatusMessage = "다운로드 시작";

        try
        {
            var progress = new Progress<double>(p => ProgressPercent = p);
            await _fileService.DownloadAsync(fileId, savePath, progress, _cts.Token);
            StatusMessage = "다운로드 완료";
        }
        catch (OperationCanceledException)
        {
            StatusMessage = "다운로드 취소됨";
        }
        catch (Exception ex)
        {
            StatusMessage = $"다운로드 실패: {ex.Message}";
        }
        finally
        {
            _cts = null;
        }
    }

    private void Cancel()
    {
        _cts?.Cancel();
    }
}
```

## 보안 및 안전성 체크리스트

| 항목 | 설명 |
|------|------|
| 경로 검증 | 사용자 입력 경로는 `Path.GetFullPath`로 정규화 후, 애플리케이션 허용 디렉터리 내에 있는지 확인합니다. |
| 덮어쓰기 방지 | 다운로드 시 임시 파일(`.partial`)에 저장 후 완료되면 원자적 교체(`File.Move`)로 안전하게 처리합니다. |
| 임시 파일 정리 | 실패하거나 취소된 경우 `.partial` 파일을 삭제합니다. |
| 사이즈 제한 | 업로드 전에 파일 크기를 확인하고, 서버의 제한보다 작은 경우만 전송합니다. |
| 인증 | `HttpClient`에 `Authorization` 헤더를 추가해 필요한 권한을 전달합니다. |
| 재시도 | 일시적 오류에 대해 지수 백오프로 재시도하며, 무한 재시도는 피합니다. |

## 이어받기 (Range 요청) 개요

서버가 `Range` 헤더를 지원한다면, 다운로드 중단 후 이어서 받을 수 있습니다. 간략한 흐름은 다음과 같습니다.

1. 임시 파일(`.partial`)의 크기를 확인해 시작 위치 `start`를 구합니다.
2. 요청 헤더에 `Range: bytes=start-`를 추가합니다.
3. 서버가 `206 Partial Content`로 응답하면 해당 위치부터 스트림을 이어씁니다.
4. 서버가 `200 OK`로 전체 파일을 보내면 기존 임시 파일을 삭제하고 새로 받습니다.

이를 구현하려면 `DownloadAsync` 내에서 `File.Exists(tempPath)` 여부를 확인하고, `Range` 헤더를 조건부로 추가하면 됩니다.

## 테스트 전략

### HttpClient 목킹

`HttpMessageHandler`를 상속받은 가짜 핸들러를 만들어 `HttpClient`에 주입합니다.

```csharp
public class FakeHandler : HttpMessageHandler
{
    private readonly Func<HttpRequestMessage, HttpResponseMessage> _responder;
    public FakeHandler(Func<HttpRequestMessage, HttpResponseMessage> responder) => _responder = responder;

    protected override Task<HttpResponseMessage> SendAsync(HttpRequestMessage request, CancellationToken cancellationToken)
        => Task.FromResult(_responder(request));
}
```

사용 예:

```csharp
var handler = new FakeHandler(req =>
{
    if (req.RequestUri!.PathAndQuery == "/api/files/upload" && req.Method == HttpMethod.Post)
    {
        var json = "{\"id\":1,\"name\":\"test.txt\",\"size\":100}";
        return new HttpResponseMessage(HttpStatusCode.Created)
        {
            Content = new StringContent(json, Encoding.UTF8, "application/json")
        };
    }
    return new HttpResponseMessage(HttpStatusCode.NotFound);
});
var http = new HttpClient(handler) { BaseAddress = new Uri("https://fake") };
var service = new FileApiService(http);
// 테스트 실행
```

### ViewModel 테스트

`IFileService`와 `IFilePickerService`를 모킹하여 ViewModel의 명령 실행 시 올바른 동작을 검증합니다.

```csharp
var pickerMock = new Mock<IFilePickerService>();
```

## 트러블슈팅

| 증상 | 원인/해결 |
|------|-----------|
| 업로드 중 `TaskCanceledException` | `HttpClient.Timeout`이 너무 짧거나, `CancellationToken`이 의도치 않게 취소됨. 타임아웃 증가, 취소 토큰 확인. |
| 다운로드 속도 느림 | `HttpCompletionOption.ResponseContentRead`를 사용하면 전체 응답을 메모리에 적재하므로 속도 저하. `ResponseHeadersRead` 사용 확인. |
| 파일이 깨져서 저장됨 | 텍스트 인코딩 문제. 바이너리 데이터는 반드시 스트림으로 처리해야 함. |
| `413 Payload Too Large` | 서버 업로드 제한 초과. 서버 설정 확인 또는 클라이언트에서 파일 크기 사전 차단. |
| 덮어쓰기 경쟁 조건 | 여러 다운로드 동시 실행 시 `.partial` 파일 충돌. 파일 이름에 고유 식별자 추가 또는 동기화 필요. |

## 결론

Avalonia에서 파일 업로드/다운로드를 구현할 때는 **서비스 계층 분리**, **진행률 보고**, **취소 지원**, **재시도 정책**, **임시 파일 안전 처리**가 핵심입니다. 위에서 소개한 구조를 따르면 ViewModel은 순수한 MVVM을 유지하면서도 안정적인 파일 전송 기능을 제공할 수 있습니다. 추가로 Range 요청을 통한 이어받기, 드래그 앤 드롭 확장, 대역폭 제어 등도 같은 패턴 위에서 쉽게 덧붙일 수 있습니다.
