# 압축과 백업

## 아카이빙과 압축의 개념

리눅스에서 데이터를 다룰 때는 두 가지 기본 개념을 알아야 한다.

* **아카이빙(archive)**: 여러 파일과 디렉터리를 하나의 파일로 묶는 작업. `tar`, `cpio` 등이 있다.
* **압축(compress)**: 데이터의 크기를 줄이는 작업. `gzip`, `bzip2`, `xz`, `zstd` 등이 있다.

실무에서는 보통 아카이빙과 압축을 함께 사용하며, `.tar.gz`, `.tar.xz`, `.tar.zst` 같은 형식이 흔하다.

---

## tar: 아카이브의 기본

`tar`는 리눅스에서 가장 널리 쓰이는 아카이빙 도구다.

### 기본 사용법

```bash
# 아카이브 생성 (압축 없이)
tar -cf archive.tar dir/

# 아카이브 풀기
tar -xf archive.tar

# 압축과 함께 사용
tar -czf archive.tar.gz dir/      # gzip 압축
tar -cjf archive.tar.bz2 dir/     # bzip2 압축
tar -cJf archive.tar.xz dir/      # xz 압축
tar --zstd -cf archive.tar.zst dir/  # zstd 압축
```

### 자주 쓰는 옵션

| 옵션 | 설명 |
|------|------|
| `-c` | 아카이브 생성 |
| `-x` | 아카이브 풀기 |
| `-f` | 파일 지정 |
| `-z` | gzip 압축/해제 |
| `-j` | bzip2 압축/해제 |
| `-J` | xz 압축/해제 |
| `-v` | 처리 과정 출력 |
| `-C` | 지정한 디렉터리로 이동 후 작업 |

### 실무에서 유용한 옵션

```bash
# 파일 제외
tar -czf src.tar.gz src/ --exclude='*.o' --exclude-from=.tarignore

# 경로 일부 제거하고 풀기
tar -xzf archive.tar.gz -C /target --strip-components=1

# 아카이브 내용 확인
tar -tvf archive.tar.gz
```

## 단일 파일 압축 도구

각 도구는 속도와 압축률이 다르다. 상황에 맞게 선택하면 된다.

| 도구 | 확장자 | 속도 | 압축률 | 특징 |
|------|--------|------|--------|------|
| `gzip` | .gz | 빠름 | 낮음 | 가장 보편적 |
| `bzip2` | .bz2 | 보통 | 중간 | |
| `xz` | .xz | 느림 | 높음 | 높은 압축률 |
| `zstd` | .zst | 매우 빠름 | 중간~높음 | 최신 도구, 병렬 처리 가능 |

```bash
gzip -k file.txt        # file.txt.gz 생성 (-k: 원본 유지)
bzip2 -k file.txt
xz -k file.txt
zstd -k file.txt

gunzip file.txt.gz      # 압축 해제
unxz file.txt.xz
zstd -d file.txt.zst
```

병렬 압축이 필요하다면 다음 도구를 사용할 수 있다.

```bash
pigz -9 -p 8 bigfile    # gzip 병렬 버전
zstd -T0 -19 bigfile    # 모든 CPU 코어 사용
```

## zip: Windows 호환성

Windows 환경과 파일을 주고받아야 할 때는 `zip`이 편리하다.

```bash
zip -r archive.zip folder/
unzip archive.zip
```

암호를 걸 수도 있지만, 레거시 방식이라 보안에 취약하다. 민감한 데이터라면 다른 방법을 고려하는 것이 좋다.

---

## rsync: 증분 동기화

`rsync`는 파일을 효율적으로 동기화하는 도구다. 변경된 부분만 전송하므로 네트워크 백업에 특히 유용하다.

### 기본 사용법

```bash
# 로컬 동기화
rsync -av --delete /src/ /dst/

# 원격 동기화 (SSH)
rsync -av -e ssh /src/ user@server:/dst/
```

### 주요 옵션

| 옵션 | 설명 |
|------|------|
| `-a` | 아카이브 모드 (권한, 타임스탬프 등 보존) |
| `-v` | 상세 정보 출력 |
| `--delete` | 대상에 없는 파일 삭제 |
| `--exclude` | 특정 파일/디렉터리 제외 |
| `--bwlimit` | 대역폭 제한 (KB/s) |
| `--dry-run` | 실제 실행 없이 결과만 확인 |

### 하드링크 스냅샷 패턴

`--link-dest` 옵션을 사용하면 변경되지 않은 파일은 이전 백업의 하드링크를 재사용해 저장 공간을 절약할 수 있다.

```bash
# 오늘 날짜 스냅샷 생성
rsync -a --delete --link-dest=/backup/yesterday/ /data/ /backup/today/

# 다음날 실행할 때 yesterday를 오늘로 교체
```

## dd: 블록 단위 복제

`dd`는 저수준에서 블록 단위로 데이터를 복사한다. 디스크 이미지 생성이나 부트 레코드 백업에 사용한다.

```bash
# 디스크 전체 복제 (대상 디스크 완전 덮어쓰기)
sudo dd if=/dev/sda of=/dev/sdb bs=4M status=progress

# 부트 레코드 백업
sudo dd if=/dev/sda of=boot.img bs=512 count=1

# ISO 파일 USB에 기록
sudo dd if=ubuntu.iso of=/dev/sdX bs=4M status=progress && sync
```

`ddrescue`는 읽기 오류가 있는 디스크에서 데이터를 복구할 때 사용한다.

```bash
# 1단계: 읽을 수 있는 블록부터 복사
sudo ddrescue -f -n /dev/sda /backup/sda.img /backup/ddrescue.log

# 2단계: 오류 구간 재시도
sudo ddrescue -d -r3 /dev/sda /backup/sda.img /backup/ddrescue.log
```

---

## 파일시스템 인식 이미징

`dd`는 전체 디스크를 복사하지만, `partclone`은 사용 중인 블록만 복사한다. 이미지 크기가 작아지는 장점이 있다.

```bash
# ext4 파티션 백업
sudo partclone.ext4 -c -s /dev/sda1 -o sda1.img

# 복원
sudo partclone.ext4 -r -s sda1.img -o /dev/sda1
```

## 전문 백업 도구: restic과 borg

정기적인 백업이 필요하다면 `restic`이나 `borgbackup` 같은 전문 도구를 고려할 수 있다. 이들은 증분 백업, 암호화, 중복 제거를 통합적으로 제공한다.

**restic 예시**:

```bash
# 저장소 초기화
restic -r /backup/restic init

# 백업
restic -r /backup/restic backup /data

# 스냅샷 목록
restic -r /backup/restic snapshots

# 복원
restic -r /backup/restic restore latest -t /restore
```

**borgbackup 예시**:

```bash
# 저장소 초기화
borg init --encryption=repokey-blake2 /backup/borg

# 백업
borg create /backup/borg::daily-$(date +%F) /data

# 목록 확인
borg list /backup/borg

# 복원
borg extract /backup/borg::daily-2025-01-01
```

## 무결성과 암호화

### 체크섬 확인

```bash
# SHA256 체크섬 생성
sha256sum backup.tar.zst > backup.tar.zst.sha256

# 검증
sha256sum -c backup.tar.zst.sha256
```

### 간단한 암호화 (GPG)

```bash
# 대칭키 암호화
gpg --symmetric --cipher-algo AES256 backup.tar

# 복호화
gpg --decrypt backup.tar.gpg > backup.tar
```

## 실전 백업 예제

### 예제 1: tar로 전체 디렉터리 백업

```bash
tar --xattrs --acls --numeric-owner -czf /backup/etc_$(date +%F).tar.gz /etc
```

### 예제 2: rsync로 원격 서버 백업

```bash
rsync -av --delete /data/ user@backup-server:/backup/data/
```

### 예제 3: cron으로 주기적 백업

```crontab
# 매일 새벽 2시 백업
0 2 * * * /usr/local/bin/backup.sh >> /var/log/backup.log 2>&1
```

백업 스크립트 예시:

```bash
#!/bin/bash
set -euo pipefail
BACKUP_DIR="/backup/$(date +%F)"
mkdir -p "$BACKUP_DIR"
rsync -a /data/ "$BACKUP_DIR/"
```

## 핵심 명령어 요약

| 작업 | 명령어 |
|------|--------|
| tar 아카이브 생성 | `tar -czf archive.tar.gz dir/` |
| tar 아카이브 풀기 | `tar -xzf archive.tar.gz` |
| 단일 파일 압축 | `gzip file`, `zstd file` |
| 파일 동기화 | `rsync -av src/ dst/` |
| 디스크 이미지 | `dd if=/dev/sda of=disk.img bs=4M` |
| 백업 도구 | `restic`, `borg` |
| 체크섬 생성 | `sha256sum file > file.sha256` |
| 암호화 | `gpg --symmetric file` |

## 결론

데이터 백업은 시스템 운영에서 가장 기본적이면서도 중요한 작업이다. 압축과 아카이빙을 통해 저장 공간을 효율적으로 사용하고, `rsync`를 활용해 증분 동기화를 하며, `dd`나 `restic` 같은 도구로 시스템 전체를 보호할 수 있다.

가장 중요한 원칙은 **백업은 복원이 가능할 때만 의미가 있다**는 점이다. 정기적으로 복원 테스트를 수행하고, 백업 로그를 확인하는 습관을 들여야 한다. 처음에는 간단한 `tar`로 시작해 점차 `rsync`, `restic` 등으로 확장해 나가는 것이 좋다.
