# WPF 데이터 바인딩 모드 심화

WPF의 데이터 바인딩은 UI 요소와 데이터 소스(ViewModel, 객체 등)를 연결하는 핵심 메커니즘입니다. 바인딩의 가장 중요한 설정 중 하나가 **바인딩 모드(BindingMode)**입니다. 모드는 데이터 흐름의 방향을 결정하며, 각 모드는 특정 시나리오에 최적화되어 있습니다. 적절한 모드를 선택하면 성능과 유지보수성을 크게 향상할 수 있습니다.

---

## OneWay 바인딩 (소스 → 타겟)

- **데이터 흐름**: 데이터 소스(ViewModel)에서 UI 타겟으로만 단방향으로 흐릅니다. 소스의 변경사항은 UI에 자동 반영되지만, UI에서 발생한 변경은 소스에 영향을 주지 않습니다.
- **주요 용도**: 읽기 전용 데이터를 표시하는 모든 컨트롤에 적합합니다. 예를 들어 사용자 이름, 제품 가격, 상태 메시지 등이 있습니다.
- **성능**: 소스의 변경이 있을 때마다 UI를 갱신하므로 오버헤드가 있지만, 양방향에 비해 부담이 적습니다.

```xml
<TextBlock Text="{Binding UserName, Mode=OneWay}" />
```

위 예시에서 `UserName` 속성이 변경되면 TextBlock의 텍스트가 갱신됩니다. 하지만 TextBlock은 사용자가 편집할 수 없으므로 소스로의 변경은 발생하지 않습니다.

---

## TwoWay 바인딩 (소스 ↔ 타겟)

- **데이터 흐름**: 데이터 소스와 UI 타겟 간에 양방향으로 실시간 동기화가 이루어집니다. 소스의 변경은 UI에, UI의 사용자 입력은 소스에 모두 반영됩니다.
- **주요 용도**: 사용자 입력을 받아 데이터 모델을 직접 수정해야 하는 폼 기반 컨트롤에 필수적입니다. TextBox, CheckBox, Slider 등 편집 가능한 컨트롤의 기본 바인딩 모드입니다.
- **중요 속성**: `UpdateSourceTrigger` 속성과 함께 사용하여 소스 업데이트 시점(예: `PropertyChanged`, `LostFocus`)을 제어할 수 있습니다.

```xml
<TextBox Text="{Binding UserName, Mode=TwoWay, UpdateSourceTrigger=PropertyChanged}" />
```

이 바인딩에서는 사용자가 입력할 때마다 `UserName` 속성이 즉시 갱신되고, 코드에서 `UserName`을 변경하면 TextBox의 텍스트도 즉시 바뀝니다.

---

## OneTime 바인딩 (초기값만)

- **데이터 흐름**: 바인딩이 설정되는 초기화 시점에 딱 한 번만 데이터 소스의 값을 UI 타겟에 복사합니다. 이후 소스가 변경되더라도 UI는 갱신되지 않습니다.
- **주요 용도**: 애플리케이션 실행 중에 변하지 않는 정적 데이터를 표시할 때 성능 최적화를 위해 사용합니다. 예를 들어 애플리케이션 버전 정보, 고정된 레이블 텍스트 등입니다.
- **성능**: 최초 한 번만 바인딩되므로 변경 감지 오버헤드가 전혀 없습니다.

```xml
<TextBlock Text="{Binding AppVersion, Mode=OneTime}" />
```

이 경우 앱 시작 시 `AppVersion` 값이 표시되지만, 이후 해당 속성이 변경되어도 TextBlock은 갱신되지 않습니다.

---

## OneWayToSource 바인딩 (타겟 → 소스)

- **데이터 흐름**: OneWay의 정반대 방향으로, UI 타겟에서 데이터 소스로만 단방향 흐름이 발생합니다. UI의 변경사항은 소스를 업데이트하지만, 소스의 변경은 UI에 반영되지 않습니다.
- **주요 용도**: UI 컨트롤의 현재 상태나 값을 데이터 소스에 기록해야 하지만, 그 반대 방향의 동기화는 필요하지 않은 특수한 경우에 사용합니다. 예를 들어 Slider의 현재 위치를 ViewModel에 저장하지만, ViewModel에서 슬라이더 위치를 제어할 필요가 없을 때 사용합니다.

```xml
<Slider Value="{Binding SliderValue, Mode=OneWayToSource}" />
```

슬라이더를 움직이면 `SliderValue` 속성이 변경되지만, 코드에서 `SliderValue`를 변경해도 슬라이더 위치는 바뀌지 않습니다.

---

## 바인딩 모드 비교 및 선택 가이드

| 모드 | 데이터 흐름 | 주요 사용 사례 | 성능 고려사항 |
|------|-------------|----------------|----------------|
| **OneWay** | 소스 → 타겟 | 레이블, 읽기 전용 텍스트, 리스트 아이템 표시 | 소스 변경 시 UI 갱신 오버헤드 존재 |
| **TwoWay** | 소스 ↔ 타겟 | 텍스트 상자, 체크박스, 콤보박스 등 사용자 입력 컨트롤 | 양방향 동기화로 인한 오버헤드 가장 큼 |
| **OneTime** | 초기값 전달 | 고정된 설정값, 버전 정보, 변하지 않는 데이터 | 최초 한 번만 바인딩되어 성능 가장 효율적 |
| **OneWayToSource** | 타겟 → 소스 | UI 상태 기록, 특수한 사용자 상호작용 저장 | UI 이벤트 발생 시에만 소스 업데이트 |

### 추가 고려사항

- **기본 모드**: TextBox, CheckBox, Slider 등 대부분의 편집 가능 컨트롤은 기본적으로 `TwoWay`입니다. 반면 TextBlock, Label 등은 기본이 `OneWay`입니다. 그러나 명시적으로 모드를 지정하는 것이 가독성과 유지보수에 좋습니다.
- **UpdateSourceTrigger**: `TwoWay` 바인딩에서 소스 업데이트 시점을 조절합니다. `PropertyChanged`는 입력 즉시, `LostFocus`는 포커스를 잃었을 때 업데이트합니다. 성능이나 사용성에 따라 선택하세요.
- **성능 팁**: 변경되지 않는 데이터에는 `OneTime`을 사용하여 불필요한 속성 변경 감지를 피하세요. 또한 `OneWay`나 `TwoWay` 바인딩이 많은 대규모 리스트에서는 가상화와 함께 적절한 모드를 선택하는 것이 중요합니다.

---

## 결론

바인딩 모드는 단순한 기술적 설정이 아니라, **애플리케이션의 데이터 흐름과 의도를 명확히 정의하는 도구**입니다. 읽기 전용에는 `OneWay`, 사용자 입력에는 `TwoWay`, 정적 데이터에는 `OneTime`, UI에서 소스로만 전달이 필요하면 `OneWayToSource`를 사용하세요. 각 모드의 특성을 이해하고 의도적으로 선택하면 성능 최적화와 유지보수성 향상 모두를 얻을 수 있습니다.
