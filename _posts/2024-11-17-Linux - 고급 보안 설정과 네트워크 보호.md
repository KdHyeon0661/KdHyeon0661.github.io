# 고급 보안 설정과 네트워크 보호

## 보안 운영의 기본 원칙

리눅스 시스템을 안전하게 운영하려면 단순히 도구를 설치하는 것보다 몇 가지 원칙을 이해해야 한다.

* **기본 정책은 거부(DROP)** : 명시적으로 허용하지 않은 모든 트래픽은 차단한다.
* **필요한 서비스만 허용** : 실제 운영에 필요한 포트만 열고 나머지는 모두 닫는다.
* **상태 추적(Stateful) 활용** : 이미 맺어진 연결(ESTABLISHED, RELATED)은 자동으로 허용하여 정상 통신을 보장한다.
* **ICMP는 합리적으로 허용** : 핑(Ping)을 완전히 막으면 PMTU(Path MTU Discovery) 등 중요한 네트워크 기능이 손상될 수 있다.
* **관리 포트 강화** : SSH는 키 인증, IP 제한, fail2ban 등으로 보호한다.
* **로그는 속도 제한** : 로그를 남길 때는 초당 5회 같은 제한을 걸어 로그 폭탄을 방지한다.

## iptables 방화벽 기초

iptables는 리눅스 커널의 넷필터를 제어하는 도구다. 기본적으로 세 가지 테이블을 자주 사용한다.

| 테이블 | 용도 | 주요 체인 |
|--------|------|-----------|
| filter | 패킷 허용/차단 | INPUT, OUTPUT, FORWARD |
| nat | 네트워크 주소 변환 | PREROUTING, POSTROUTING |
| mangle | 패킷 헤더 수정 | PREROUTING, FORWARD 등 |

### 최소 보안 정책 템플릿

다음은 기본적으로 적용할 수 있는 방화벽 규칙이다.

```bash
# 기본 정책: INPUT과 FORWARD는 DROP, OUTPUT은 ACCEPT
sudo iptables -P INPUT DROP
sudo iptables -P FORWARD DROP
sudo iptables -P OUTPUT ACCEPT

# 루프백 인터페이스 허용 (내부 통신)
sudo iptables -A INPUT -i lo -j ACCEPT

# 이미 연결된 트래픽 허용 (상태 추적)
sudo iptables -A INPUT -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT

# SSH, HTTP, HTTPS 허용
sudo iptables -A INPUT -p tcp -m multiport --dports 22,80,443 -m conntrack --ctstate NEW -j ACCEPT

# 필수 ICMP 허용 (ping, 목적지 도달 불가, 시간 초과)
sudo iptables -A INPUT -p icmp --icmp-type echo-request -j ACCEPT
sudo iptables -A INPUT -p icmp --icmp-type destination-unreachable -j ACCEPT
sudo iptables -A INPUT -p icmp --icmp-type time-exceeded -j ACCEPT

# 거부된 패킷 로깅 (레이트 제한)
sudo iptables -A INPUT -m limit --limit 5/second -j LOG --log-prefix "FW DROP: "

# 나머지 모두 차단
sudo iptables -A INPUT -j DROP
```

**규칙 순서가 중요하다** : 먼저 허용할 것을 명시하고, 마지막에 기본 DROP을 적용해야 한다.

### SSH 접근 제한

특정 IP 대역에서만 SSH를 허용하려면 다음과 같이 한다.

```bash
sudo iptables -I INPUT 3 -p tcp -s 203.0.113.0/24 --dport 22 -j ACCEPT
```

### 규칙 영구 저장

재부팅 후에도 유지하려면 저장 도구를 사용한다.

```bash
# Debian/Ubuntu
sudo apt install iptables-persistent
sudo netfilter-persistent save

# 수동 저장
sudo iptables-save | sudo tee /etc/iptables/rules.v4
```

## fail2ban: 반복 공격 차단

fail2ban은 로그를 감시하여 비밀번호 틀림 같은 반복 실패를 감지하고 해당 IP를 일시적으로 차단한다.

### 설치 및 기본 설정

```bash
sudo apt install fail2ban
sudo systemctl enable --now fail2ban
```

`/etc/fail2ban/jail.local` 파일을 만들어 설정한다.

```ini
[DEFAULT]
bantime = 15m           # 차단 시간
findtime = 10m          # 감지 기간
maxretry = 5            # 최대 실패 횟수
ignoreip = 127.0.0.1/8 10.0.0.0/8   # 차단 제외 IP

[sshd]
enabled = true
port = ssh
logpath = /var/log/auth.log
```

### 상태 확인 및 차단 해제

```bash
sudo fail2ban-client status           # 전체 jail 상태
sudo fail2ban-client status sshd      # 특정 jail 상태
sudo fail2ban-client set sshd unbanip 192.168.1.100
```

## OpenVPN 기초

VPN은 암호화 터널을 통해 안전한 원격 접속을 제공한다. OpenVPN은 널리 사용되는 솔루션이다.

### 서버 구성 핵심

```bash
sudo apt install openvpn easy-rsa
# 인증서 생성 (easy-rsa 사용, 여기서는 생략)
```

`/etc/openvpn/server.conf`의 주요 내용:

```conf
port 1194
proto udp
dev tun

# 암호화 (현대적 권장)
cipher AES-256-GCM
auth SHA256

# VPN 서브넷
server 10.8.0.0 255.255.255.0

# 클라이언트에 전달할 설정
push "redirect-gateway def1"          # 모든 트래픽을 VPN으로
push "dhcp-option DNS 1.1.1.1"

# 연결 유지
keepalive 10 60
user nobody
group nogroup
```

### IP 포워딩 및 NAT

```bash
# IP 포워딩 활성화
echo "net.ipv4.ip_forward=1" | sudo tee /etc/sysctl.d/99-vpn.conf
sudo sysctl --system

# NAT 설정 (클라이언트 인터넷 접속 허용)
sudo iptables -t nat -A POSTROUTING -s 10.8.0.0/24 -o eth0 -j MASQUERADE
```

### 서비스 시작

```bash
sudo systemctl enable --now openvpn@server
```

## WireGuard 간단히

WireGuard는 구성이 단순하고 성능이 좋은 VPN이다.

### 서버 설정

```bash
sudo apt install wireguard
wg genkey | tee /etc/wireguard/server.key | wg pubkey > /etc/wireguard/server.pub
```

`/etc/wireguard/wg0.conf`:

```conf
[Interface]
Address = 10.9.0.1/24
ListenPort = 51820
PrivateKey = (서버 개인키)
```

### 클라이언트 설정

```conf
[Interface]
Address = 10.9.0.2/24
PrivateKey = (클라이언트 개인키)

[Peer]
PublicKey = (서버 공개키)
AllowedIPs = 0.0.0.0/0          # 모든 트래픽을 VPN으로
Endpoint = vpn.example.com:51820
PersistentKeepalive = 25
```

## SSH 보안 강화

`/etc/ssh/sshd_config`에서 다음 설정을 권장한다.

```bash
Port 22
PermitRootLogin prohibit-password   # 루트는 키 인증만
PasswordAuthentication no           # 비밀번호 인증 금지
PubkeyAuthentication yes
AllowUsers devkim opsuser           # 특정 사용자만 허용
MaxAuthTries 3
```

설정 후 SSH 서비스를 재시작한다.

```bash
sudo systemctl restart ssh
```

## 로깅과 모니터링

방화벽 로그를 수집하려면 rsyslog 설정을 추가한다.

```bash
# /etc/rsyslog.d/20-iptables.conf
:msg, contains, "FW DROP:" -/var/log/iptables_drop.log
& stop
```

```bash
sudo systemctl restart rsyslog
tail -f /var/log/iptables_drop.log
```

서비스 로그는 `journalctl`로 확인한다.

```bash
journalctl -u fail2ban -f
journalctl -u openvpn@server -f
```

## 커널 튜닝 (간단한 예)

`/etc/sysctl.d/99-net.conf`에 다음을 추가하면 네트워크 안정성과 성능에 도움이 된다.

```conf
net.ipv4.tcp_syncookies = 1          # SYN 플러드 방지
net.core.somaxconn = 4096            # 연결 대기 큐 증가
net.ipv4.tcp_fin_timeout = 30        # FIN 대기 시간 감소
net.ipv4.ip_local_port_range = 1024 65000
```

적용:

```bash
sudo sysctl --system
```

## 실전 시나리오

### 시나리오 1: HTTPS 접속 불가

1. `ss -tuln | grep :443`로 서비스 리스닝 확인
2. `sudo iptables -S`로 방화벽 규칙 순서 확인
3. 클라우드 환경이라면 보안 그룹(security group) 확인
4. `tcpdump -i eth0 port 443`로 패킷 흐름 확인

### 시나리오 2: SSH 무차별 대입 공격

1. `fail2ban` 설치 및 `sshd` jail 활성화
2. `bantime.increment` 설정으로 재범 시 차단 시간 증가
3. SSH 비밀번호 인증 비활성화, 키 인증만 허용

### 시나리오 3: VPN 연결은 되는데 인터넷 안 됨

1. 서버에서 IP 포워딩과 NAT 설정 확인
2. 클라이언트 설정에 `redirect-gateway def1` 또는 `AllowedIPs = 0.0.0.0/0` 포함 여부 확인
3. 클라이언트 DNS 설정 확인 (VPN 서버가 DNS를 push하고 있는지)

## 결론

리눅스 시스템의 보안은 여러 계층을 쌓아 올리는 방식으로 접근해야 한다. 방화벽으로 기본 트래픽을 통제하고, fail2ban으로 반복적인 공격을 차단하며, SSH와 VPN 같은 원격 접속 서비스를 강화한다.

가장 중요한 원칙은 **최소 권한**과 **명시적 허용**이다. 필요한 것만 열고 나머지는 모두 닫는 태도가 기본이다. 또한 설정을 변경한 후에는 반드시 재부팅 테스트나 `systemctl restart`로 적용 여부를 확인하고, 규칙 영구 저장을 잊지 말아야 한다.

보안은 완성되는 것이 아니라 지속적으로 점검하고 조정해 나가는 과정이다. 이 문서에서 제시한 템플릿을 바탕으로 자신의 환경에 맞게 조정하고, 정기적으로 로그를 확인하는 습관을 들이면 안정적인 시스템 운영이 가능하다.
